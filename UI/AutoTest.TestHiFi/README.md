## 如何启动

Windows .NET 10 SDK，仓库根目录：

```powershell
git fetch origin
git switch --track origin/ui/workspace-files-v01
dotnet build UI/AutoTest.TestHiFi/AutoTest.TestHiFi.csproj -c Debug
dotnet run --project UI/AutoTest.TestHiFi/AutoTest.TestHiFi.csproj
```

EXE：`UI/AutoTest.TestHiFi/bin/Debug/net10.0-windows/AutoTest.TestHiFi.exe`。

本批代码已通过源代码/XAML/事件接线静态审查，**未在当前非 Windows 环境编译或启动**，需要使用者 Windows 真实运行后再确认。**没有修改 `main`，没有设备操作或真正的 TEST 运行后端**。

## UI-02｜真实磁盘操作，但仅 UI 工作区格式

- **新建/打开**：使用 `*.atui-project.json` 文件，清单 `Format=AutoTest.UI.Workspace/1`；不同于正式 AutoTest PROJECT 工程的 `project.autotest-project.json`。
- **文件**：资源文件保存在工程目录下 `ui-assets/`，资源 ID 固定，路径是以 GUID 派生的稳定文件名；树中名称可以改，但重命名只修改资源标签，不擅自改动现有引用路径。
- **资源类型**：TEST 文本草稿、公共流程文本草稿、DBC 文本、波形 CSV、输入/UDS/Flash 配置文本和说明。导入支持 `.dbc/.json/.csv/.txt/.md` **文本** 文件，并复制进新工程；原文件不改。当前不解析或校验真实 DBC 与 TEST 业务 Schema。
- **编辑与保存**：双击树中文件打开中央编辑器；直接修改文本（不是假输入框）；标签出现未保存标记；Ctrl+S 保存，Ctrl+Shift+S 保存全部；保存操作将文件写入磁盘，保留 `.bak` 后备副本。另存资源副本会产生新 ID/新文件。
- **工程操作**：新建、复制/粘贴资源、重命名、删除（移入项目 `ui-trash/`）、当前会话撤销/重做元数据操作；文本编辑支持 Ctrl+Z/Y 和工具栏共用历史。
- **保护**：无效项目格式/资源路径越界拒绝打开；文件读写异常明确提示；文件修改后关闭/切工程/退出，提供保存、丢弃、取消三选项；会话保存最近工程、打开文档、活动页、TEST 选择和面板尺寸。
- **异常恢复**：未保存文件在本机 `%LOCALAPPDATA%/AutoTest/UiWorkbench/recovery.json` 中按延时保存快照，再次打开对应文件会询问是否恢复。正式文件只在明确保存时更新。
- **边界**：本批不将 UI 草稿文本转换成正式测试程序、不执行真实 DUT 测试、不声称完整专业工具已完成、不伪造 PASS/FAIL。**真实 PROJECT/TEST 数据层适配仍需 UI-03 及后端合同审查。**

## 建议集中验收（先编译，后做这 10 步）

1. 启动确认 TEST 白色界面保留、紫色标签消失、主控板显示未连接。
2. 选中测试 16 步 CAN 与 18 步 ELSE：右侧 CAN 字段只在 CAN 判定显示。
3. 点击专业工具打开 CAN、UDS、DBC，中央出现不同标签；返回 TEST 后原用例和选中步骤保留，左侧资源导航未被覆盖。
4. 文件→新建 UI 工程，选择磁盘目录，确认生成 `*.atui-project.json`。
5. 点击左侧「工程文件」→＋，建立一个 TEST 草稿和一个 DBC 草稿；右键菜单应能打开、重命名、复制和删除。
6. 双击 TEST 草稿，输入多行内容，标签出现「●」，按 Ctrl+S 保存；在资源所在目录检查真实磁盘内容。
7. 使用 Ctrl+Z/Y 编辑撤销/重做，另存为独立副本；复制文件 ID 不等于原文件 ID。
8. 未保存编辑时关闭文档、切工程和退出，确认保存/丢弃/取消按意图执行。
9. 删除一个文件后 Ctrl+Z（在无待撤销文本编辑时）恢复；检查原文件返回及 ui-trash 文件位置。
10. 重启程序后检查最近工程、活动页、打开的文档、选择的测试步骤及面板尺寸恢复；对未保存草稿确认恢复提示。
