# ADR-20261109｜真实按键电压、20 Key 合成与真实台架操作模型

- **类型**：已确认的用户需求/硬件事实之遗漏补录与旧 UI 语义纠正。
- **来源**：AutoTest 主对话《交接AutoTest进展整理》及其历史软硬件讨论；2026-11-09 用户再次明确纠正。
- **状态**：`USER_CONFIRMED / BASELINE_AMENDMENT_RECORDED`。新增文档是对既有需求的归档；不自动把已批准 G3/G4 原工作产品改为接受新版本，不代表实机五路电压验收。
- **优先规则**：本记录的真实按键业务语义取代此前“真实台架直接操作 K01～K20”的过时表达；应追溯原始记录，不删历史。

## A. 已确认硬件/业务语义——不再跨对话重复询问

1. **真实按键**：对于目前测试的 ECU，真实按键操作的电气作用是向 ECU 的对应按键检测输入提供特定**模拟电压**。ECU 根据实际接收通道和电压判定区间识别真实按键/控制状态；不同 ECU 型号及版本的识别通道、阈值、真实按键数量、名字和行为可以不同。这是当前项目明确的输入原理，不表示所有车型或任一真实开关的内部结构都已被验证。
2. **20 Key 电阻网络**：现役 KEY_SIM 板的 20 个 Key 是**底层电阻网络组合控制位**，不是 20 个用户直接面对的真实按键。通过**多个 Key 同时闭合并持续保持**可以合成某一目标模拟电压；组合关系与实测输出须由固件/原理图/台架标定确认。不可假定“一 Key = 一真实键”或按每四 Key 一组固定划分。
3. **5 路模拟电压输出**：板上的五路输出用来适配各 ECU 不同的接收通道及电压输入要求，并非 5 路随意设定电压的 DAC。每种 ECU/Profile 指定使用哪个输出、接至哪一 ECU 输入、各真实键所需电压及识别上下限；不必全部五路都被某 ECU 使用。
4. **真实台架操作对象**：操作者必须操作**当前 ECU/Profile 对应的真实控制器、真实按键或实际控制状态**，不是直接操作 20 个底层 Key。默认真实台架 UI 依配置动态生成真实按键，允许按下、松开、短按、长按、持续保持、锁存/回弹等经配置明确的行为。20 Key 位操作只进入**高级映射/标定/DEVICE 原始调试界面**，不作为真实按键操作面板。
5. **同一映射路径**：手动真实台架与自动 TestProgram 使用同一版本化真实键→底层组合映射、同一 Station/DEVICE 发送和安全路径；不能双重实现、偷偷硬编码 EPB 示例或因不同入口导致不同模拟电压。

## B. 强制的业务—电气链路

```text
选择 DUT ECU/Profile + Station + Controller/State + 已保存 Revision
  → 验证输出通道、目标电压窗口、StateHardwareMapping 和可执行性
  → 映射成按键板完整的 20-bit KeyMask（允许多位同时置位并保持）
  → Windows HOST 经 USB 向主控发送 CAN_SEND
  → 主控 CAN0（KeypadCan 角色）发按键板内部 CAN 0x730
  → KEY_SIM 组合开关、电阻网络形成五路输出中的目标电压
  → 对应 DUT 真实按键检测输入接收电压
  → DUT 根据该型号的电压识别区间判定状态
  → DUT CAN/其他反馈、仪表实测和业务判定独立取证
```

这里有五种不能互相冒充的事实：`RequestIssued`（用户操作/请求）、`TransportAccepted`（USB/CAN 被接受）、`PhysicalObserved`（真实电压被测到）、`EcuResponded`（DUT 回应）、`BusinessVerified`（满足用例）。未配置目标 ≠ 目标错误；未测到电压 ≠ 已测到 0V；设备 ACK ≠ DUT 已识别。

## C. 需版本化的配置资产与操作合同

| 资源 | 核心含义 |
| --- | --- |
| BoardCapability | 物理模拟板型号、固件、20 Key Mask 能力、五路输出、端口角色、Station/端点、供电接线条件 |
| ECU/Profile | ECU 型号/版本、实际连接的电压输入通道、识别上下限及来源，不同型号独立配置 |
| ControllerDefinition / ControlState | 可任意数量定义控制器、按键/状态、名称、顺序、真实语义与动作策略，不固定“驻车/释放/无操作” |
| StateHardwareMapping | `controllerId + stateId + revision → boardType + full20bitMask + outputChannel(s)`；每个状态明确电压合成组合和验证版本 |
| VoltageAcceptance | 目标模拟电压、实际参与比较的 V1～V5 通道、允许上下限、单位、适用 ECU 条件和来源 |
| MeasurementFact | 每通道实测值与测量时间、仪表、接线、供电、负载、操作人员、硬件和配置 Revision；无 ADC 不得制造实时值 |
| OperationPolicy | 按下/保持/释放/恢复、互斥、超时/断连、多个控制器共享电阻网络的资源仲裁 |

- 测试步骤和保存的手动动作均引用稳定 `controllerId/stateId/revision`，映射过期、配置缺失、ECU/Profile 不匹配和未保存草稿不能驱动真实硬件。
- 设置状态是发送**完整目标 KeyMask**，不是在未知历史状态上增量相加。多个控制器共享网络时，未验证的 Mask 不能直接按位 OR。
- 按下→等待→明确释放/恢复是不同动作。WAIT 不会隐式放开已经施加的 Key 组合；松开也需物理发送和取证。
- USB 断连、超时、取消、重连后不得把历史 Mask 或目标电压标成“已确认保持/已确认释放”，应显示 `UNKNOWN/UNCERTAIN`，实物恢复按受控流程确认。
- 原始底层调试、真实台架 UI、自动测试需要分别呈现，但应复用设备发送能力；用户仍可以独立发送 DUT CAN 报文并监控 DUT CAN/DBC 反馈。DUT CAN 与 KeySim 内部 CAN 是两条不同链路。

## D. 已知现役协议与证据边界

历史固件资料：主控 USB `CAN_SEND=0x40`，payload 为 15B `channel/ide/id32LE/dlc/data8`；主控 CAN0→KeySim、CAN1→DUT（实际接线/版本须复核）；KeySim 接受标准帧 `0x730`、DLC 8，`Byte0=0x01, Byte1..3=20-bit little-endian mask, Byte4..7=0`；`Byte0=0x80`、其余零为释放/复位。此前资料**未确认** KeySim 有执行 ACK、20 Key 状态回读或五路板载电压 ADC。不能据 CAN 发送成功声称模拟电压已经正确形成。

**已确定且无需用户重复解释**：真实 ECU 以模拟电压识别当前项目的按键；20 Key 是电压合成手段且可以多位保持；现役五路电压输出；不同 ECU 输入通道/电压范围不同；真实台架只操作真实按键/状态；手动自动共用映射。

**需以实物证据补齐而非重复问需求**：具体 ECU 的真实键和电压窗口、每个状态的完整 Mask 和 V1～V5 实测值、负载/接地/线束/供电、组合冲突、无操作参考状态、断连后真实物理输出、是否存在额外测量途径。

## E. 验收与跨专业约束

软件验证至少包含：两种 ECU/Profile 不同输出通道/电压区间；一个真实键由多个底层 Key 组合保持；真实台架按钮动态生成；保存重开及 Revision；短按/长按/保持/释放；多控制器共用电阻网络时的冲突；自动测试与手动路径一致；失败/断连/取消/重连后 UNKNOWN；无 ADC/测量时拒绝物理 PASS。物理 B3 验收另须真实电压/原始帧/ECU 识别证据，不得用 Mock 测试替代。

**跨对话规则**：每个专业读本 ADR 后直接继承用户已澄清的内容，只可就缺失的精确电气参数和未验证的实际现象提出必要实测需求；如发现此前规范冲突，标记 `SUPERSEDED` 并追踪 CR，不再让用户从头解释真实按键。归档后续变更须明确来源、涉及工作产品、验证缺口、旧新状态及 Git SHA。
