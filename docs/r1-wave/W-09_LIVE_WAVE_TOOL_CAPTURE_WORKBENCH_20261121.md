# W-09｜WAVE 独立专业采集工具、实时显示与数据记录的完整产品设计

> 日期 2026-11-21；Issue #71；最新核对 `R1@8e6aaa556e70ce025a18c20abeb331fa812b055d`。研究候审，未实现或实测；归属 `research/r1-wave-judgement-20261120`。与 W-04 的产品任务模型和 W-05 的采样质量/时序数学互补。

## 1. WAVE 工具应该成为专业采集/分析台，不是报告浏览器

**独立工具用途**：工程师即使不在执行 TEST、没有参考波形和正式判定配置，也可以选取当前项目的 ECU CAN/DBC 信号，在同一个独立、受主窗口管理的工作台里连续观察、开始记录、停止、测量、保存、回放、叠加，并把经过审查的采集作为 TEST 参考候选。不能将此工具做成另一套 CAN 驱动、DBC 编辑器、TEST 执行器或 RECORD 库。

**当前源码差距（R1 只读工具）**：
- `Desktop/Shell/WaveWorkbenchWindow.xaml` 当前只有 `刷新实际证据`、`波形配置与参考建立` 两个主要入口；左侧已有证据、右侧一张波形图；没有实时 DBC 信号选择/开始停止采集、触发、预采样、质量详情、叠加、当前采集结果保存/参考审核/比较入口。
- `WaveWorkbenchViewModel` 负责枚举磁盘 `wave-records/evidence` 和 `references`、加载已存曲线，并依 `WaveChartAnalysis` 实现两个光标数值差；2026-11-21 新增异步读取、取消和投影性能处理，这部分可保留。
- `WaveWorkbenchWindow.xaml.cs` 用一个 `Polyline` 绘图；**对枚举/布尔离散状态也画斜线**，会给人视觉上不存在的连续中间状态。图形层也必须按信号语义选择阶梯线/离散事件轨道或连续折线。
- 当前 `WaveChartAnalysis.InWindow` 将用于绘制的点数限制且按桶保留极值，这个方向正确；**只允许可视化降采样，不允许丢弃录制事实或拿 UI 投影作为判定输入**。
- `WaveCaptureService.StartAsync` 已具有限时会话和 bounded buffer，`WaveTimeQuality` 有基本 Gap/Overflow/无效校验；但它们还不是带触发、预采、数据质量解释和文件恢复的专业录波产品。当前生产 `ConfiguredWavePort` 主要由 TEST 调用；不能误称工具已实现自由采集。
- `LiveDbcSignalService.OpenAsync` 生成捕获时间起点并返回异步序列，真正的内部 `ObserveAsync` 订阅发生在该序列被消费时；目前没有显式的 `SubscriptionReadyAcknowledgement`/源高水位，因此精确捕获开始边界需要补充有证据的实际订阅就绪握手。
- `CanFrameHub` 订阅者与 `LiveDbcSignalService` Sink 都是有界队列，overflow 可计数和传播 gap，但“无溢出”不是硬件端零漏帧保证；需要把每一级队列和目标源更新纳入可见质量状态。

## 2. 独立 WAVE 工具的建议布局与操作语义

在保留现有浅色 Fluent 专业窗口和工程上下文的前提下：

### 顶部：采集控制与来源

- **工位连接信息**：当前 USB/主控身份、ECU CAN Role/物理通道、设置的波特率和实际读回、当前工程及 DBC 资源修订。
- **信号选择**：从工程当前有效 DBC 搜索信号（含中文别名）、报文 CAN ID/扩展帧/名称/单位；支持同一画布多条信号，但每条保持其自己的 CAN ID/到达时间序列，**不假装多路物理同步采样**。
- **采集**：`实时监视`、`开始记录`、`停止并保存`、`触发采集`、`打开记录`；运行状态 `未连接/已订阅待帧/采集中/已停止/质量不完整/归档完成` 清晰。
- **范围**：显示最近 N 秒/完整记录、可选固定时长、点数/文件空间上限；预计空间用估算值而不是承诺无损。
- **来源警示**：`时间基准：Windows 主机接收（非 ECU 事件时间）`；明确 CAN 报告量不是外部探头量。

### 左侧：信号树与波形资源

分清 `实时信号 / 本次采集 / 已保存采集 / 参考候选 / 已批准参考`。每项可显示质量和来源、时段、版本；搜索保持工程上下文，选中后中央叠加，不强迫用户通过多级配置窗口找资源。

### 中部：真正好用的波形查看器

- 时间轴显示 `相对捕获时间` 或 `相对触发时间`，切换后保证已保存原始时间不变；每条波形有真实单位的 Y 轴，**不同单位默认分轨，绝不把 A/V/布尔混在同一个无标注 Y 轴上**；
- 离散 enum/布尔显示阶梯/状态带，并明确从前一帧持有多久；超出 `MaxAge` 的区间画断开/灰色未知，不画连续平滑变化；
- 数值信号可选散点+折线，但折线只是观察趋势，不代表采样间确实存在那条物理曲线；
- 支持缩放、平移、适合窗口、框选区间、双光标 `Δt、Δvalue`，点击样本查看原始 CAN ID/8/64字节（以真实帧格式为准）、DBC bit/scale/offset/枚举/原始值/时间/source evidence；
- 明确显示 **参考叠加**、上下容差带、差值/误差、触发锚点、报警/不合格区段、缺帧断档带；实际/参考均可单独开关；
- 原始数据下采样只为显示，光标跳原始最近真实样本；最多图形点数可因窗口缩放重计算，不修改存储；
- 多条信号允许跨时间查看，但不允许在未验证时钟对齐时直接给“多信号同时发生”的精确事件判断；
- 导出图片仅是呈现，导出的 `Wave Capture JSON+manifest+raw CAN+SHA` 才是事实。

### 下部或右侧：质量、属性、判定结果

以用户能理解的指标呈现 `信号是否更新、真实帧数、有效样本数、首末有效帧、相邻帧间隔 median/p95/max、持续缺口、USB/Hub/Decoder 队列丢失差分、Timestamp Source、DBC SHA、采集结束原因、是否可评价`。分析方式可选 `状态事件 / 数值窗口 / 与批准参考比较`；**观察工具的临时比较不能冒充正式生产 PASS**。

### 参考候选流程

选中实际录波 → 查看来源、时间质量、信号/工程版本、样件合格事实 → `建立参考候选` → 确定适用型号、状态/数值窗口/工位/负载和标注 → 工程审核并冻结 `RefId/Revision/SHA`。没有合格实物或强证据只能是`开发参考/候选`；Replay/Simulation 不允许发布为`真实生产参考`。

## 3. 采集模式：都使用相同原始接收源

1. `LiveMonitor`（实时浏览）：接入当前工程共享 ECU CAN/DBC stream，在画面上实时滚动。未按开始记录按钮，不自动生成正式 Reference 和 TEST Verdict。
2. `ManualRecording`（主动录波）：操作者点击开始、确定采集已就绪，再控制 KEY/IGN/ECU（来自现有手动台架工具），点击停止，保存时间窗和原始证据；**只读波形窗口不拥有物理控制授权**。
3. `TimedRecording`（限时）：正式订阅就绪后按已批准时长采集；自然结束与人工提前停止必须标记不同 `EndReason`，短于要求窗口不能自动通过。
4. `TriggeredRecording`（触发）：先 `ARMED`，收集允许的预触发真实缓存，收到用户指定 `manual/test action/新鲜 SignalEdge/指定 CAN ID帧` 后，记录触发证据与前后时窗；不是系统在事后凭最后一帧倒推的“真实物理发生点”。
5. `TestOwnedRecording`（现有 TEST 波形）：TEST 通过 `RealRunCoordinator` 设定 StepOccurrence/已批准 profile、订阅与动作事件，工具可以**只读观看**同一采集，但不能更改 TEST 冻结的触发/容差/参数或停止正式用例采集。
6. `OfflineReview`（历史分析）：读取已归档不可变录波、参考、报告，允许另建独立 `DerivedAnalysis`（附算法版本与来源 SHA），但不篡改历史运行 Verdict。

## 4. 实时采集线程架构：采集和显示强制分离

原则来源：NI 官方 Data Acquisition Reference Design 允许为了保证日志完整而牺牲显示更新，从而避免 UI 消费过慢导致采集数据丢失：https://www.ni.com/en/support/documentation/supplemental/10/data-acquisition-reference-design-for-labview.html 。

建议最小数据路径：

`Physical USB CAN RX → immutable RawFrame+EvidenceRef → shared CAN hub → DBC decoded Observation → WaveRecordingBuffer/append-only store → analysis`；

平行的 `WaveUIProjection` 从**录制数据的只读副本**按视窗裁剪，限速绘制，长曲线做显示极值保留/抽稀。UI 卡顿不能阻断 USB/CAN 接收；UI 绘图追不上时应丢弃**显示帧**，不是悄悄丢弃**真实录制样本**。

R1 为单 PC 单工位：不必重新造多节点总线或多工位队列。可先为 Wave 单录制会话提供受控定额的内存 buffer + 持续增量文件写入；磁盘不足/写入中断/超容量/排队丢失必须 `RECORDING_INCOMPLETE` 并给出错误，不让之前成功采样覆盖尾部失败。不能宣称任何系统“永不丢帧”。

优先保留：
- 原始 CAN 事实优先、DBC 解码可复核；
- 录制/归档有独立受控队列与质量信息，避免多个慢 UI 消费者改变真实源；
- 每个真实来源帧带 `USB Generation/StationEpoch/Monotonic+UTC/EvidenceId`；
- 多信号采用同一主机接收时钟语义，数据本身异步；图层叠加不会产生同步采样证据；
- 真正开始记录以前先确认流订阅已建立，触发前环形缓存只有已订阅后的真实样本，不能补造历史；
- 手动台架/TEST/Flash 等物理操作共享安全调度，Wave **工具本身只能读**；单工位不增加第二套动作执行器或 USB 接收器。

## 5. 精度细节：按「字节→数值→时间→质量→显示」逐层核验

1. **原始字节**：目标通道、CAN ID、标准/扩展、实际 DLC 和 Data；如果 ECU 有 alive counter、CRC/信号无效标记，则按协议启用；没有不能假装识别所有丢帧。
2. **DBC**：冻结 Asset ID/Rev/SHA，验证 endian、signedness、factor、offset、multiplex、length 和物理单位；严禁工具和 TEST 用两套解码实现。保存原始值与物理值映射以供人工核查。
3. **时间**：真实 USB 0x41 只有主机观察时间与 monotonic ticks，UI 显示标签写明；UTC 可显示但 elapsed 正式算法需同一时钟域的 monotonic frequency/epoch 支持；USB reconnect 后不能拼接两段采集。
4. **完整性**：记录缓冲、源帧、订阅丢失、最大无更新时间、首尾窗口、Stop/Timeout/Disconnect/Cancelled；图形越好看不代表数据够。
5. **显示**：状态量阶梯/离散条；连续上报量折线/散点+原始点提示；不同单位不同轴；不以 UI 插值/下采样结果做真实数值判定。

## 6. 实际操作示例（只用于解释，不是已验证的具体 ECU 帧 ID）

- 工程师打开项目 → `工具 > 波形分析` → 选 `ECU CAN / EPBStatus`（真实名字要以用户 DBC 为准）→ `实时监视` 看得见新帧与时间质量；
- 点击 `开始记录` → 确认“订阅已就绪” → 在**现有手动台架**按下 EPB 施加 KEY → 波形工具观察状态变更与关联动作事件；
- 点击 `停止并保存` → 打开本次实际波形，双光标测量主机观察意义的响应间隔、最大 Gap，查看每点关联的原始 CAN；
- 设定该合格 ECU 和适用工况，将记录送入`参考候选`；经人工审核后冻结，不默认为生产 Reference；
- 进入 TEST 步骤右侧 Inspector，从同一信号/已批准参考与 profile 选择评价方法 → 实际运行 → 按 W-05/06 质量+判定+原始证据完成正式报告。

| WT-05 | 查看不同单位的电流/状态 | 多轴/轨显示单位，不混轴 |
| WT-06 | 连续多次录波及循环 TEST 同时只读观看 | 结果分别归属 CaptureSession，不串样本 |
| WT-07 | 记录时断开 USB/切工程/关主窗口 | 记录安全终止，保留故障状态，下一次须新 session |

## 8. 实施顺序（不扩大首版范围）

- **工具 P0-1**：独立真实信号选择、LiveMonitor、手动录制/停止、真实数据质量可见、原始帧/信号/单位；
- **工具 P0-2**：专用独立采集 Session、时窗/触发、保存完整性、取消/断连/重复录制；
- **工具 P0-3**：图形状态阶梯、多信号显示/光标、参考与实际叠加、窗口/错误区间；
- **工具 P0-4**：候选→审核/冻结参考、将引用提供给 TEST、证据/报告互跳；
- **工具 P1**：复杂跨通道触发、外部格式 MF4 导入导出、大批量分析、统计包络自动化；这些不应阻止首版真正采集。

*结论：WAVE 工具是采集和分析的独立操作入口，但数据源、DBC、正式 TEST 和 RECORD 仍共享 R1 的唯一真相链。当前 WPF 仅有只读证据查看，距离上述成熟采集工具仍有明确缺口。未编译、未现场验收。*
