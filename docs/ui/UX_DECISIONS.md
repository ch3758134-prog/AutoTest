## 用户已明确的设计方向

1. **产品主线：** AutoTest 为通用 ECU 测试与开发环境。用户界面主要围绕自动测试展开；测试工程 → 测试项目 → 测试用例 → 准备/测试/清理 → 步骤，UI 不再单独创造“测试程序”对象。
2. **选择性执行：** 测试项目可勾选本次要执行的用例，用于工程师研发、调试与抽检；与项目默认启用及扫码生产规定工序区分。扫码成功、预检及工位安全条件满足后生产流程自动启动，不能将原型预演当成实体运行。
3. **左侧工程树：** 测试项目下可直接展开其测试用例；自动测试优先，DBC、按键配置、波形、UDS 等资源分组紧凑；层级靠缩进、字重、图标、焦点而非长期解释文本识别。次要帮助采用悬停提示与按需帮助。
4. **编辑器效率：** 高密度步骤表、主要参数摘要、明确嵌套流程层级、选中后右侧常驻 Inspector、行内常用参数编辑、键盘快速导航与右键编辑；新增步骤应可立即配置，避免反复弹窗和滚动。
5. **步骤语义：** 当前 KEY_SIM 对应用户动作称“按键动作”，引用工程定义的输入模拟映射与时序；不能以 K01～K20 或 EPB “驻车/释放”作为通用动作。UDS 作为交互服务步骤命名“UDS 服务”，不预设每次调用都是诊断用途。
6. **读取与等待：** 按 ecu.test 的灵活性保留独立“等待 CAN 报文”（可只按指定 ID 匹配新帧）、“读取信号”（可选期望检查及保存变量）与“变量/计算”高级能力；不强制拆开简单信号检查，也不因简化 UI 删掉底层灵活性。具体 UI 后续由用户实测调整。
7. **手动台架：** 是综合人工 ECU 调试场所，不是按键专用工具。左侧 CAN 实时观察、中间已配置外部输入及 IGN/夹具、右侧 DBC/CAN 发送。允许直接新增并配置按键动作，组合施加/恢复的输入状态与延迟、保持、等待。无输入配置时不显示假功能按钮，但其他工位能力独立保留。
8. **专业工具：** DBC、UDS、波形、Flash 及手动台架按各自任务组织专业工作台，用户倾向真实独立弹窗/窗口；不强行继承测试步骤布局。取消独立 CAN 工具产品义务，CAN 收发与观察由手动台架承担。
9. **数据与硬件边界：** KEY_SIM 20 个内部开关形成五路电阻网络输入，不是 20 个业务功能键或五路任意 DAC；DUT 外部主电源不受 HOST 控制。操作请求、ACK、ECU 响应及独立物理测量不能混用。
10. **解释去冗余：** 正式操作区仅显示当前对象、动作、必要状态、错误和结果；研究理由、历史基线及演示局限转入设计说明/帮助；必要“离线未接设备”状态仍需明确。

## 尚待用户试用与专题继续研究

- **DBC：** 现行默认离线样例载入用户上传的 `LvTong.dbc`，原始文件标注“未实机校验”；既有浏览器保存工程不会被自动改写，可在 DBC 编辑器按需点击“载入 LvTong 示例”，替换前提示引用风险。当前仅解析 BO_/SG_/CM_/VAL_ 常见字段，需另做完整 DBC 标准与无损保存技术研究。
- **KEY_SIM 20 路：** 任意长度的开关控制序列，单步直接勾选 K01～K20 与保持时间，允许纯等待、复制、重排、删除。**不要求创建开关组，不强制施加/恢复，不自动追加断开步骤**；旧命名状态仅作为可选模板。20 路为硬件开关而非 ECU 业务按键，五路模拟电压与板卡响应需实测。
- **中央编辑效率：** 流程控制 IF/ELSE、SWITCH、WHEN、异常和子程序的实际插入、移动、折叠、错误与断点定位；一步修改多个信号及读取/保存/期望的完整参数体验。
- **工程配置呈现：** DUT 绑定和工位事实是技术上必要的数据/检查对象，但用户认为左树独立入口多余；先从主要导航移除，保留工程内按需访问，再结合真实任务决定是否进一步合并。
- **专业窗口：** 现行原型以 IDE 内专业页签为主要入口，工程树不被覆盖、切回测试用例保留编辑定位；独立浏览器窗口为辅助入口。后续仍须研究资源实时同步、多显示器和 WPF 正式窗口行为；原型新窗口不代表多窗口编辑同步已验收。
- **UDS：** 服务目录、可复用 Job、诊断短序列、请求/响应与 NRC、ISO-TP 实际限制及历史联动，不重复自动测试与 Flash 工作流。
- **波形：** 现代网页式大绘图区、多轨、全局时间导航、游标、原始样本/参考比较、时间质量与判定分层。
- **真实集成：** HTML 仅界面标准，不是 USB/CAN/烧录/实体测试已实现证据。后续 G4 的 WPF 必须另受技术与审批约束。

### 2026-11-17｜手动台架 CAN 多报文 HTML 交互方案：用户批准
- **用户明确批准：**“可以，html我通过了”。批准对象限定为 `docs/ui/AutoTest_UI.html` 的**手动台架 CAN 发送区**，对应设计源 Git SHA `1bd4f823c1b436c31d09598ab627be383bb021fd`。
- 本次批准的界面合同：**左侧多报文 CAN1 发送列表 / 中间工位控制与 KEY 动作 / 右侧 CAN 实时监控**；发送列表为主视角，能够多报文分别选择、单发、周期任务操作以及批量启停。新增默认原始 CAN 帧编辑；DBC 仅在选中某条报文并进入编辑时作为辅助编辑方式，不默认显示整套 DBC 信号表。
- 界面交互原则：主列表显示 CAN ID、DATA 摘要、周期、状态；详细编辑不替代操作列表；各条配置独立，允许复制/删除；人工控制和接收监控保持独立信息区。
- **批准不等于实机验收：**该 HTML 发送/周期启停是离线交互预演；任何实体 CAN 发送必须复用现行 DEVICE/USB 物理授权；主控 `0x50 SET_BROADCAST` 整表替换且最多 8 条，需要管理完整活动集合、单条停止和断连 UNKNOWN。没有批准绕过服务端门禁的宿主周期线程；USB ACK 也不能代表 DUT 响应或 PASS。
- **下一执行关口：**在 G4 功能分支复用现有 WPF 手动台架与硬件 Service 实现该已批准 UI；本地 Codex 负责 Windows 编译/测试和现场证据；先做原始/DBC 编辑与多行调度 UI，周期物理接线仍由 TEST/DEVICE 合同限制。不可将整个 UI V3、测试编辑器或其他 HTML 设计一并声明为用户批准。
