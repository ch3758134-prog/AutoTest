输入：[研究依据](RESEARCH_STEP_HIERARCHY_COMMANDS_VISUAL_20261119.md)、[40 步真实密度内容](TEST_TASK_AND_DENSE_CONTENT_FIXTURE_20261119.md)、[A/B 比较](../V02-01/DESIGN_COMPARISON_TEST_EDITOR_20261119.md)、R04、V01。

## 1. 设计目标与非目标

**目标**：工程师在一个 TEST 工作空间中，能够快速看懂自己正在编辑的测试用例与步骤结构，直接修改不同类型步骤参数、处理控制流程和专业引用，得到清楚的反馈，并无损切换对象。每一个操作可见、一致、有明确作用范围。

**非目标**：不在设计阶段发明新的 TEST DSL/执行器；不假设旧 G4 MainWindow 或新的临时 UiSession 是正式工程模型；不在纯 UI 里假装 CAN 发送成功、ECU/USB ACK、烧录完成；不在本轮锁死控件像素或宣布 A/B 布局用户批准。

## 2. 基础对象和视觉层级

| 对象 | 常驻信息 | 主要视觉角色 | 操作入口 |
|---|---|---|---|
| 当前文档 / 用例 | 文件名、当前用例、未保存、问题数 | 一条清楚的文档身份带（不重复大标题） | 保存、检查、搜索、用例切换 |
| 阶段 | 准备/测试/清理、折叠、步骤计数、添加目标 | 结构章节条，较步骤行有明显重量与间隔 | 单击选择阶段、展开箭头、添加 |
| 容器步骤 | IF/WHEN/SWITCH/循环/TRY、关键条件摘要 | 结构节点头，展开状态与分支提示 | 插入分支、编辑条件、复制/移动子树 |
| 分支 | THEN/ELSE/CASE/超时/CATCH/FINALLY | 容器子级的命名槽位，保持父子边界 | 插入此分支、前后插入（合法时） |
| 叶步骤 | 类型、可读名称、核心参数摘要、问题/禁用/断点 | 可扫描的正文行；选中清楚 | 修改、复制、上/下移动、删除、禁用 |
| 属性 Inspector | 对象标题+身份，类型相关字段及验证 | 持续编辑的工作区，而不是纯说明卡片 | Tab、资源选择、局部修正、帮助 |
| Problems | 问题数、级别、资源/步骤/字段定位 | 按需展开的辅助信息，不遮挡主结构 | 点击问题跳精确字段 |
| 运行状态 | 真实 Run 的任务、阶段、进度、StepOccurrence | 独立运行视图，不抢编辑选择语义 | 实体执行后端接线后才启用 |

## 3. 两套布局下共同的组成和内容

### 3.1 宽屏默认候选 A：「用例导航—结构主区—常驻属性」

    ┌ 当前工作身份 / 用例名 / 保存与检查 / 问题数 ┐
    │[用例选择，可收]│ 步骤结构与摘要（主区）       │ 当前步骤详情   │
    │               │ [添加步骤] [类型搜索] [...]   │ T18 · 等待     │
    │ 12 条用例     │ 准备阶段（6）                 │ 等待时间       │
    │ --------------│ 测试阶段（29）                │ [20x] 无效草稿 │
    │ 运行勾选独立  │ └ IF → THEN / ELSE ...       │ 字段错误与修正 │
    │               │ 清理阶段（5）                 │ 类型相关参数   │
    └ 可调整分隔条 / Problems 按需展开 / 状态条 ┘

操作理由：TEST 高频任务是「看结构、选步骤、看字段、改字段」的横向往返，故左用例导航和右参数都作为可调整的辅助区，步骤结构具有优先伸缩权。

视觉禁止：左侧多个按钮挤成几行、树放入狭窄固定栏、中间没有对象却大面积空白、右侧显示与当前选择不相符的提示。

### 3.2 对照候选 B：「宽步骤结构—下方参数工作台」

    ┌ 当前工作身份 / 用例名 / 保存与检查 / 问题数 ┐
    │ 用例选择（可收） │ 步骤结构宽表/摘要             │
    │                │ 准备 / 测试 / 清理 + 分支       │
    │                │ 多列：名称、操作摘要、状态     │
    ├────────────────┴─────────────────────────────────┤
    │ 当前步骤 T18 · 等待 | 类型化参数 | 错误与说明      │
    └──────────────────────────────────────────────────┘

操作理由：大量行的横向摘要对照更好，但小屏下容易挤掉大量步骤行。应在明确的“检视结构”类任务中比较，而不因为 NI 下方 Step Settings 就默认照搬。

### 3.3 窄屏退化（不是新的永久独立窗口）

在近 910×512 DIP 这类布局预算下，三列 A 可能已不成立，B 也面临高度不足。候选机制：

- 主结构区**始终优先可见**；全局导航缩至可召回入口，用例列表暂收。
- 属性编辑在同一工作区内选择性地变成“详情视图/可展开停靠面”，但不再打开模态属性对话框；可以一键回到结构。
- 当前用例名、选中步骤名、问题数以及“添加步骤”始终可辨，不能因压缩而消失；显示可见的“编辑详情”入口。
- 切换窄屏布局不重建文档/撤销栈，也不丢失输入半成品；恢复宽屏时还原选择与滚动。
- **这里仍是候选行为**，需用具体 WPF 测量决定：不可预先承诺同屏三面板或者在单屏内显示全部参数。

## 4. 组件规格：结构节点而不是拼接 TreeViewItem

### 4.1 阶段组
- 左：展开/折叠命中区，单击不更改编辑对象；单击阶段主体选择合法插入范围。
- 中：清楚的阶段名「准备」「测试」「清理」，后面是自然的步骤数与局部问题数。
- 右：小型就近「添加步骤」语义入口；没有步骤时显示“在此阶段添加第一步”的可点击空状态。
- 语义：阶段本身不是执行步骤，也不应该允许直接作为普通步骤复制。

### 4.2 结构容器、分支槽
- IF 是可选中的步骤：显示核心条件、打开/收起和整体移动； THEN/ELSE 是 IF 的结构槽位，不当成同类型的普通“等待步骤”。
- 插入时必须能清楚选择分支和落点；键盘与鼠标执行同一作用域。
- SWITCH 自有 CASE/DEFAULT，默认分支是否允许删除必须由正式 TEST 模型确认；研究样本中可把 DEFAULT 作为固定槽位候选。
- WHEN 的“条件满足/超时”从用户任务和语义调查推导为候选；与正式业务执行模型核对之前，不声称真实引擎支持独立超时子树。
- LOOP 除次数，还可能有退出/异常条件；不应把所有内容压成单个“Value”字符串。
- TRY/CATCH/FINALLY 的可用性及语义须核对正式领域模型；本轮仅确立视觉结构识别需求。

### 4.3 叶步骤行
- 稳定的步骤序号/可理解的局部位置不依赖随机颜色。
- 一行主信息：**简明步骤类型或图标 + 用户可编辑名称**；一行次信息或次列：最重要的参数摘要（例如 `300 ms`、`Demo_Alive / 100 ms`）。
- 不能把“备注全文”默认铺在每行，避免 40 行时的垂直空间灾难；但长名可在 Hover/详情中完整获得。
- **状态层独立**：禁用（灰度/符号+文字）、问题（对象级问题标记）、断点（行边独立位置）、正在运行（独立 Run 视图），不互相覆盖。
- 当前选择用有足够对比的浅背景/细强调边与焦点轮廓表达；仅单击选中不写入实体设备。

### 4.4 Inspector（类型专用而非万能属性表）
- 固定顶部区：步骤名称与类型、所在用例/阶段/父分支、当前草稿与问题数。
- 高频字段：按步骤类型显示对应标签。例如等待→毫秒与条件；CAN 判定→DBC 信号、比较关系、期望值、超时；UDS→服务/数据及相关配置；输入动作→引用动作及保持时长。
- 复杂字段的可编辑区域要能被看到：表达式、DBC 资源搜索与选择器、输入组合等不能都塞到「操作对象」「操作值」「条件」三个通用文本框。
- 所有更改尽可能在当前面板连续完成，必要专业选择器可局部展开，不每次新建一个大弹窗。
- 输入状态由 FieldBuffer / ObjectDraft / DocumentTransaction 分层。单击另一个步骤时，不得悄悄丢失未合法完成的文本。

## 5. 操作合同：对象→命令→可见结果

| 操作 | 范围前置 | 具体交互候选 | 同屏反馈 / Undo |
|---|---|---|---|
| 选择阶段 | 鼠标点阶段主体 | 只变当前插入范围，展开状态单独变化 | 阶段选中，属性区明确显示「向某阶段添加」 |
| 选择步骤 | 点步骤行 | 当前 EditorSelection 改变；Inspector 类型同步 | 选中行与详情标题一致；不改变本次运行勾选 |
| 新建步骤 | 阶段/某节点的明确位置 | 添加主命令或类型搜索；默认同级「之后」，可切换「之前」 | 新节点自动进入结构，焦点落第一个有意义的参数 |
| 增加分支内步骤 | 父结构节点已选 | 指定 THEN/ELSE/CASE/超时等合法槽位 | 插入位置预览/新增行被选中，分支标题可见 |
| 复制步骤 | 选中合法对象 | 工具栏次命令、上下文、Ctrl+C/V | 新实体身份（正式 ID 规则待后端），子树结构保持，单次可撤销 |
| 同级移动 | 选中叶/整个结构 | 行内菜单/键盘或有可视落点拖动 | 改序后选中与滚动保留；单次 Undo |
| 跨分支移动 | 显式指定目标集合 | “移动到…”或有清楚目标槽位的拖放 | 目标父/阶段和位置可见，禁止隐式跨界 |
| 包裹连续步骤 | 同父同分支且合法连续 | 选择多个步骤→“用 IF/LOOP 包裹” | 插入容器并保持内部顺序；一次 Undo 全部恢复 |
| 删除步骤/子树 | 精确选中对象 | Delete / 对象菜单；危险性随引用影响而变 | 结构变化并可撤销；有引用时提示影响 |
| 启停步骤 | 选中步骤 | 专属 Enabled 状态控件，不用 RunSelection 勾选 | 行内状态与详情一致；不触发物理行为 |
| 设置断点 | 允许调试且有 StepId | 单独的断点操作与标记 | 与选中/禁用区分；没有真实运行不写 PASS |
| 定位错误 | Problems 含有效对象定位 | 点问题→展开祖先→滚到节点→聚焦错误字段 | 保留尚未提交的其他对象编辑缓冲 |
| 搜索步骤 | 当前测试用例 | 搜索类型/名称/参数摘要，可标记匹配 | 搜索不改变文档结构和 RunSelection |
| 撤销与重做 | 当前对象/文档事务有历史 | Ctrl+Z/Y 及稳定命令入口 | 恢复文档结构、选中和适用时焦点，**不**撤销实体执行 |

### 5.1 鼠标键盘优先级
- 单击普通行=选中；单击箭头=折叠/展开；双击名称=重命名（候选）或按明确字段编辑，不能随机打开另一窗口。
- 右键菜单绑定鼠标目标或保留合法多选；同样命令在可发现的主/次入口存在。
- Up/Down 移动 Tree 的焦点，Left/Right 控制层次，F2 重命名，Delete 删除，Ctrl+Z/Y 文档可撤销事务，Ctrl+F 搜索。
- **Ctrl+Z 的作用域必须明确**：输入框有正在编辑的文字时应先撤销该字段打字；结构/选择焦点时才执行文档级 Undo。不能一次 Ctrl+Z 同时改文字和删除/移动步骤。
- Ctrl+Space 不直接冻结为快速插入，须检测中文输入法冲突；插入快捷键应配置且 UI 中显示。
- 实际发送、单步运行或烧录不与普通输入框 Enter/Space 绑定。

## 6. 草稿与验证的状态机制（详细到可实现，但不代替 TEST 后端）

**字段输入**：Clean → Editing → PendingValidation → ValidDraft / InvalidDraft；在字段内容还未合法时仍能切换对象，保留原始文本并标记「待修正」。

**对象切换**：对象 A 有 `20x` 无效毫秒；用户单击 B 后 A 的字段值/问题保留在隔离草稿，B 的有效字段显示 B；返回 A 时光标仍可进入 `20x`，不是自动改 `20` 或清空。点击正式保存时，若后端不允许非法草稿则阻止保存正式资源，问题导航应指向 A/字段。

**结构事务**：插入、删除、移动、包裹和批量编辑应作为 DocumentTransaction，Undo 能恢复结构身份和顺序；在 UI 纯展示研究中可存可编辑草稿，但正式文件与运行快照边界不能假称已验证。

**校验**：Local Field Validation 与 Formal Resource Validation 分离。结构/引用问题应有「验证来源、对象、字段、严重级别、可修复动作」；UI 不能臆造真实引擎的执行合法性。

## 7. 初步视觉 token 候选（只用于下一轮 A/B 测量）

这些值是按 Fluent Windows 和 Carbon 专业密度抽出的**试验起点**，不是冻结值：

| 角色 | 候选 | 必须在真实任务中验证 |
|---|---|---|
| 主步骤名/参数输入 | 约 14 DIP 正文，清晰行高与中英文混排 | 40 步和 1366×768@150% 可读、不可因密度变成微字 |
| 辅助摘要 | 约 12～13 DIP，较正文弱但对比足够 | 不得承担唯一辨认步骤的信息 |
| 阶段/Inspector 子标题 | 约 14～16 DIP 半粗并用组间距建立层级 | 比普通步骤明显，不抢主编辑对象 |
| 阶段行与结构容器 | 首轮试验 36～44 DIP 高度范围 | 既能辨认容器，又不浪费一屏的步骤数量 |
| 普通步骤行 | 首轮试验 32～40 DIP 高度范围 | 阅读与双击/焦点命中稳定，足够显示短摘要 |
| 选择 | 浅色表面 + 边缘强调 + 清晰焦点 | 不与禁用/运行中/断点共用一种蓝 |
| 结构缩进 | 同级对齐、随深度增加的可追踪引导 | 3 层以上仍能看出祖先，宽度不过度损耗 |
| 专业参数字段 | 必需类型字段显式出现、次级帮助折叠 | 不用通用三个框代替所有类型 |
| 主要按钮 | 一个明确主操作，次动作不全部使用实心强调色 | 禁用、Hover、焦点对比与中文长度均可用 |

若任何候选尺寸不能满足具体任务或分辨率，优先重设布局与密度，而非牺牲文字可读性。

## 8. V02-01 A / B 如何接受同一套验证

使用 [40 步样本](TEST_TASK_AND_DENSE_CONTENT_FIXTURE_20261119.md) X01～X16，比较：

- 首眼识别：5 秒内能否找到当前用例、步骤、属性与常用添加入口（此处 5 秒只是测试任务设定，不是已通过的统计结论）。
- 最重要的信息是否有空间，且没有因字段文字变长使结构崩溃。
- 插入、改字段、移位、Undo 过程是否经过多余弹窗/隐藏工具。
- 20x 无效字段与 T09 资源缺失是否能清楚定位与修复。
- 分支深度 3+，折叠的父节点是否仍保留内部选中/问题上下文。
- 1920×1080 和 1366×768@150% 等任务中，是否有裁切、文字碰撞、控制溢出和操作不可达。

**暂时倾向**：宽屏高频步骤编辑以候选 A 进入下一轮可视化比较；候选 B 不能因项目经验被提前废弃。小屏可能需要“辅助导航暂收/详情停靠方式切换”，但这属于未验证的响应策略，不是已通过的 UI 最终规则。

## 9. 失败条件与下一步

必须打回设计（不进入 WPF）的情况：树结构看不出 THEN/ELSE；无法分辨阶段和叶节点；界面存在明示可点但不能执行的假命令；选中详情不一致；未完成输入被丢弃；上移/下移无对象作用域；当前 Run 状态误当编辑状态；窄窗使主要编辑区无法操作；所有按钮同色/等权重。

下一步是 **V02-03：以同一套 40 步样本生成可审查的视觉操作方案，实际验证 A/B 布局与状态表现**；之后再进行 Design System 组件规格落地，**不能将本轮“文字设计候选”伪装成视觉原型验收通过**。

本轮明确：不制作 HTML，不修改 WPF，不进行实体执行；只提交 Markdown 研究和设计合同。
