## A、B 选择不靠审美偏好

| 评价维度 | A 右侧持续参数 | B 底部参数 |
|---|---|---|
| 主结构实际可见空间（本轮画稿） | 约 1024 px × 835 px，宽屏右侧参数 506 px，左侧用例 256 px | 主表约 1542 px × 536 px；底部参数约 1542 px × 284 px |
| 当前编辑对象可见性 | T09 高亮与右侧「T09 · CAN 信号判定」并列 | T09 高亮与下方「T09 · CAN 信号判定」上下联动 |
| 不同步骤概要对照 | 中等：更依赖主字段与 Inspector | 强：宽表适合长名称、主要参数和状态并列 |
| 结构 40 步浏览 | 更多纵向可见行；编辑对象无需向下跳视线 | 主表高度减少，长树需要更多滚动 |
| 专业字段编辑 | 右侧窄一些：长表达式与复杂表格需要展开能力 | 底部宽：复合字段能多列排列 |
| IF / ELSE 层次与状态 | 阶段、容器、分支、叶节点颜色与缩进分离，支持问题摘要 | 同样结构语义，选中位置位于较短的主表区域 |
| 高频连续改参数 | 本轮偏向 A；需要实际操作测量 | 本轮偏向 B 的「结构检视」，但编辑频繁时要观察上下焦点跳转 |
| 小屏 150% | 不能照搬三常驻列；应按 C/D 的同一工作区双视图切换 | 同样不能压成很矮的主表；不假设 B 自然适配 |

**本轮推荐：** 将 A 作为日常「编辑测试程序」主要候选，将 B 保留为结构检视/长字段比较的备选。推荐是**设计推论**，不是用户批准、更不是经过统计效率证明。后续交互原型应验证是否值得支持属性停靠位置切换；不能为了「支持一切布局」而过度复杂。

### 视觉稿自己暴露的设计风险
1. A 的右侧 Inspector 在复杂表达式/DBC 位编辑时可能空间不足；要定义大字段扩展/停靠调整，不得再次弹多层模态窗。
2. B 的主表纵向空间明显更少；不能靠不断减小字体凑行数。宽表的优势只在「大量摘要检视」成立时才有价值。
3. C 采用高 DPI 下的同一工作区结构/详情切换候选；它需要可见的当前对象上下文、返回动作及状态保持，绝非重建两个独立数据对象。
4. 40 步样本覆盖三阶段、多分支、缺引用和数值非法；尚未覆盖所有类型完整专用字段、长字符串极限、拖拽动画、多选/范围选择与大规模 1000+ 步步骤树。
5. 静态 SVG 未证明所有文字在用户 Windows 字体配置下都不裁切。必须在可操作原型阶段用用户设备真实截图对比。
