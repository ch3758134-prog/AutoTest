# P-03｜统一视觉与命令组件

日期：2026-11-19；来源：AutoTest R01～R06、用户批准的 UX-PLAN v0.2；身份：UI/UX 研究、设计和纯 UI 实施。

## L0 场景与问题
全局样式、键鼠操作、控件密度和反馈缺乏统一规则时，各专业工具很容易重新变为杂乱的旧 WPF 风格。

## L1 端到端用户任务
研究长时桌面工作中的阅读密度、焦点、触控与鼠标、快捷键、DataGrid 直编、TabItem、上下文命令及禁用原因。

## L2 来源事实 / 研究依据
R01 P01～P12 与 R04 对象命令，R05 Windows DPI/虚拟化建议已归档；没有规范要求所有专业界面固定三栏。

注意：厂商公开资料证明其存在相应机制，不证明 AutoTest 应机械复制。原始资料见 R01～R06、SOURCE_REGISTER；本篇设计取舍属于 UX 候选。

## L3 对象、命令与交互设计
浅色中性底、蓝色强调、统一按钮与文本间距、表格虚拟化、直接字段编辑、常用命令就近显示。实体命令禁用原因明确，工具仍各自采用专业布局。

连续操作脚本：Ctrl+S 保存 UI 会话；Ctrl+O 打开；Ctrl+N 新建；测试步骤 Ctrl+Z/Y；Tab、双击、直接编辑和右键操作一致。

## L4 状态、异常与视觉责任
编辑状态不可伪装成执行完成，禁用控件应给出原因，涉及真实结果的区域显示暂无事实或 UNKNOWN。

所有编辑均作用于 UI 会话。任何离线/UNKNOWN 的实物状态不得在界面中呈现为通过。Windows 小屏、高 DPI、焦点/对话框属于最终跨批验收项。
