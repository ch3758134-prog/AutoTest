# W-08｜波形容差、重复性、测量不确定度与参考批准的工程标定方法

**2026-11-21 / Issue #71**。第二轮产品研究补充专题，`METHODOLOGY_PROPOSED / NO_CALIBRATION_DATA / FIELD_NOT_VERIFIED`。本报告不是要求 R1 首版建立统计分析平台，而是避免把工程师任意输入的 ±5%、默认 50ms 或一台 DUT 的曲线误称为有依据的生产验收标准。

## 1. 从质量测量的角度定义问题

波形系统面对三种波动，**不能混淆**：

1. **ECU/DUT 真正的产品差异**：不同合格产品的电机、算法、软件/硬件版本以及工况导致其报告波形不同。
2. **同一个 ECU 重复测试的正常差异**：接线、工位供电、KEY 动作触发、USB/CAN 观察时间、运行温度、工位循环过程带来的变动。
3. **测量系统造成的不确定性**：帧发布周期/丢失、主机时间抖动、DBC 量化、值失效、解码边界、数据处理/插值/窗口裁剪。

如果把这些不加区分地“拟合成黄金参考上下界”，可能导致：
- **假 FAIL**：正常 ECU 只因工位抖动或参考样本偏窄被拒绝；
- **假 PASS**：为了覆盖多个产品或工况随意放宽容差，使本该检测出的故障被吞掉；
- **无法证明却 PASS**：采样周期根本不支持需要检测的瞬态或响应时间，却把平滑插值当作高频测量；
- **版本漂移**：软件/DBC/测试动作改了，旧参考仍被无提示地拿来比较。

NIST/SEMATECH Engineering Statistics Handbook 的 Measurement Process Characterization 明确研究重复性、再现性、稳定性、校准与测量不确定度；其 Gauge R&R 章节解释了区分量测差异与产品差异的重要性；NIST 的 conformity decision rules 研究强调不确定度与合格判定规则的关联。引用：

- https://www.nist.gov/publications/nistsematech-engineering-statistics-handbook-chapter-2-measurement-process
- https://www.itl.nist.gov/div898/handbook/mpc/section4/mpc4.htm
- https://www.nist.gov/publications/assessment-conformity-decision-rules-and-risk-analysis
- https://www.ni.com/en/shop/services/hardware/calibration-services/calibration-services-guard-band-implementation.html

**不应断言** AutoTest 当前 CAN 波形是满足计量校准要求的外部测量仪器。这里只是借鉴严谨的计量判定思路，提高软件“给出 PASS 的证据”可靠性。

## 2. 首先应有独立的产品规范，而非先有“最好看的参考图”

对每个 WAVE 判定 Profile，优先让用户明确：
- **特性**：到底判 EPB 施加状态、释放状态、电机电流上报值、某个故障/诊断位，或变速动作；
- **可观察来源**：主控 ECU CAN/DBC 的实际被报告信号；原始 ID、扩展格式、DBC SHA、物理单位和枚举取值；
- **要求来源**：ECU 产品规格/客户测试要求/现有经过实测批准的测试计划；如果没有，标成`EngineeringProvisional`，不可自动变更为生产标准；
- **允许窗口**：在动作后的哪个时间区间满足条件，要求保持多久；若时间证据不足，显示`无法证明时间要求`；
- **对应工况**：ECU 型号/HW/SW、工位配置 TCF/TBC、IGN/按键动作、供电/负载设置、环境信息；
- **判定指标**：状态码、最大/最小、响应观测延时范围、超限持续时间、稳态 RMS/均值/波动等；何者是强制判定、何者仅用于显示。

随后使用合格 ECU 的真实波形确认规则的实用性和稳定性，而不是用同一个 ECU 的一次录波自动生成“验收范围”。

## 3. 参考与容差建立实验：可在首版 Windows 工位完成，不需要多工位 MES

建议一次 `ReferenceQualificationStudy`（实验设计由用户按真实 ECU 约束批准），不是代码内部硬编码样本数。

| 阶段 | 具体现场操作 | 记录什么 | 出口 |
| --- | --- | --- | --- |
| Step 1 规格/仪器前提 | 选择一个已知合格 EPB ECU、实际 DBC 信号和真实 KEY/IGN 动作；记录同一工程资源版本 | DUT/DBC/TEST/TCF/TBC/波特率/主控 FW 与测试环境 | 任何 DBC/来源未知即禁止形成生产参考 |
| Step 2 同台重复性 | **同一台合格 ECU** 在明确一致的工作条件下，多轮采集同一状态转移/数值变化；轮数是工程方案值 | 每轮 raw CAN、有效帧数、周期/Gap、时间轴、观测响应/稳态数值 | 估计本工位本次测试的正常波动、误判风险，不能直接解释成全型号分布 |
| Step 3 样品间差异 | 有可用样机时，重复采集不同已知合格 DUT，尽量覆盖真实硬件/软件/负载适用范围 | 区分合格产品差异 vs 采集系统差异 | 确定同一 Reference 是否适用多个 DUT，或应分变型 |
| Step 4 影响因素 | 在安全批准条件下逐步检验不同供电、线束、重复夹紧、工位正常负载/应用状态、USB/CPU 负载 | 采样抖动、判定窗口变化、USB/DBC 失效概率 | 判断是物理要求改变还是测量不确定性上升 |
| Step 5 负例灵敏度 | 使用安全、可恢复的真实异常场景或已知不符合的受控 DUT；算法可用模拟向量补足非硬件边界 | 实际 FAIL/INCONCLUSIVE 类型，不能把 Mock 当现场 FAIL | 检测是否过宽容差掩盖风险 |
| Step 6 阈值批准 | 负责人以实际规格为主、重复性/风险为约束，批准 Profile 的阈值及适用范围 | `ApprovedBy/At, ReferencePin, AlgorithmVersion, RiskNote, Thresholds` | 发布后只读/Revision，不自适应改宽 |
| Step 7 复核 | 使用未参与候选建立的运行记录/合格样件进行独立验证并重开报告核对 | 误拒/漏判/无法证明率按真实结果分类 | 超出批准误判预算则不能发布 |

可以只有一台可用 ECU 开始**工程调试与采集质量标定**；但不能仅凭一台合格 ECU 就声称已经证明了跨型号、跨生产批次的产品统计接受率。首版少量数据只能形成明确适用范围的实验性规则。

## 4. 推荐的容差设定策略（绝无未经批准的统一默认百分比）

### 4.1 离散状态

主要参数：
- 期待的初始态/目标态/非法态集合；
- 触发和预采样、响应时窗、保持时间；
- ECU 状态新帧允许的最大间隙/最大新鲜度，是否要求故障锁存；
- 设备当前可证明的主机观察时间精度分类。

**不要定义** “状态值和参考的相对误差 5%”——对状态枚举没有工程意义。`0→1` 响应可以 PASS，`0→2` 完全不等于 `中间值 1`；时间符合度必须独立判断。

### 4.2 ECU 上报数值

首版可以设：
- `MinValue / MaxValue`：来自正式产品规格；
- `WindowStart / WindowEnd` 与稳定/保持时间；
- `AllowedMissingSeconds / MaxGap / MaxAge`：来自实际采样能力和明确放行政策；
- `AbsoluteTolerance`，如有物理单位量化误差；`RelativeTolerance` 的作用与组合公式明确；
- `CriticalRegions`：对于不能容忍的一类超限，不允许用全局 PassRatio 99% 绕过；
- `Filter/Smoothing`：只有在明确算法规范中经过审核，才允许将滤波输出作为判定输入；原始波形/瞬时异常必须仍然可查。

**数值参数来自信号自身工程需求**：不借用所有 ECU 电流一律 ±5%，也不以一条 Golden 的最大值+固定百分比自动生成出厂合格线。

### 4.3 形态相似度

- 只在信号类别、动作/触发、负载/型号匹配时比较同样语义的波形；
- 允许诊断的最大 shift 与“响应时间合格”规则隔离；
- 可使用多次 approved good captures 的叠加观察变异性和做容差建议，但 R1 不应自动用这些数据形成严格生产 envelope；
- 差异要能够归类：提前/延迟/平台偏差/瞬时尖峰/缺失/异常停留/参考不适用；
- 定义“是否必须每个有效点合格”或“允许一定时间持续超差”，不能单纯按点数比例通过。

### 4.4 时间与计量不确定性

对于需要限时验证的观察，时间有**测量不确定区间**，合理的判定可能是：
- 明确在限值内 → PASS；
- 明确在限值外 → FAIL；
- 与限值相交或无法建立可信时间上界 → INCONCLUSIVE。

这与 NIST/NI 的 guard-banding 决策思想相符，但 AutoTest 的产品规则必须由需求和实验数据明确规定，**不能直接套一个计量实验室固定系数**。特别不能把主机观察延时当成 ECU 真实电气时间而给出虚假精度。

## 5. 给工程师展示“参数从哪来”，而不是填一长串小数

建议 Profile 右侧 Inspector 对每个关键容差设置以下来源：
- `产品规范`：明确规范编号、版本、批准人；
- `工程已批准经验值`：明确参考实验和实际条件；
- `临时调试值`：仅研发，不进入正式生产 PASS。

候选参考管理器提供辅助视图：同一信号多轮真实波形叠加、目标/观察时间范围、最早最晚变化段、波动/Gap 汇总、异常样本可跳到 raw CAN。**可以给建议**但不自动修改已发布生产阈值；发布需列出新旧范围/算法/适用型号与审批记录。

适用性在生产运行之前由计划冻结校验；若更换了 ECU 硬件版本、DBC 缩放/信号、固件策略、KEY 电阻网络/测试动作或台架适用工况，至少需要`NeedsReview`，不能静默沿用过去的容差，不能把所有历史成绩重新用新规则覆盖。

## 6. 参数敏感性与假 PASS/假 FAIL 检测的工程测试

完成实测后形成一个 `ThresholdReviewPackage`，至少包含：
1. 规格限值以及判定属性；
2. 实际连续多轮 capture 与 raw CAN Evidence SHA；
3. 每轮有效样本/异常 Gap/主机观察时延指标；
4. 在既定规则下 PASS/FAIL/INCONCLUSIVE 的次数；
5. 单个超差的最严重位置、时间与主观工况差异；
6. 容差向内/向外变化时的结果敏感度（仅研究视图，不能改变正式 verdict）；
7. 安全负例检验是否能被检测，而不是所有 Case 都通过；
8. 是否具备足够数据支持一个生产 Reference 和相应限值；若不足明确 `QualificationInsufficient`；
9. 审核人及内容 SHA，发布后仍可用旧版本复现。

如果为了保证好样机不误 FAIL 而不得不把容差放到丧失缺陷识别能力的程度，**正确结果不是继续扩大容差，而是声明当前采样源/方法不适合这个产品特性**，考虑另加独立高速测量硬件或改变可观察信号规格；本阶段不自动改固件。

## 7. 为什么这属于成熟产品标准，但不应阻碍 R1 首版

- **R1 P0 需要**：工程规格→波形用途→可观察性/质量→单条真实样本→明确参数来源→保守判定→正式记录；参数可以先由用户对真实 ECU 的工程要求审批，并清楚标识暂定范围。
- **R1 P0 不需要**：全自动 Gage R&R 平台、数百条 Reference 的机器学习拟合、批量生产 SPC 仪表板、自动生成自适应阈值。
- **R1 FIELD 必须**：以真实 ECU 执行正常/异常/缺帧与完整证据，不能把一张从 demo.dbc 或 Replay 得到的漂亮曲线当成有效的产品标定。

**本文件所有阈值、实验轮数均不作假定承诺**；只有真实客户规格和现场数据才能给出最终参数。状态保持 `NOT_CALIBRATED / FIELD_NOT_VERIFIED`，直到有真实记录。
