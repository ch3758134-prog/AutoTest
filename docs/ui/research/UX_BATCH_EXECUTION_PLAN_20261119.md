# AutoTest｜纯 UI 全产品分批研究、设计、实施计划 v1.0

**用户批准：2026-11-19**。本版替代此前“逐批等待用户批准/实测”的节奏。用户要求 **全部批次连续研究、设计、编码、留档，最终统一 Windows UX 验收**。不得将此批准解释为可直接合并 main 或接真实业务/设备。

## 角色与边界
- UI/UX AI 负责研究依据、设计取舍、跨产品一致性、纯 UI 实施、代码检查和逐批留档；各批不等待用户中途验收。
- 用户最终在 Windows 一次性验收完整纯 UI，之后再进入正式后端集成专项。
- Codex 负责本地 Windows Build/Run 与错误记录；未经执行不得宣称 PASS。
- 纯 UI 产品不依赖 PROJECT、TEST、DEVICE、UDS/Flash 等真实业务 DLL，不用旧 G4 UI 兼容层。
- R01～R06 为设计输入与假设，不是用户冻结页面；旧 UX-I01 接真后端合同因本次明确决策而 SUPERSEDED。

## 共通研究与设计深度（每批执行）
L0 用户/任务/环境；L1 连续工作流；L2 对象及信息结构；L3 鼠标/键盘/命令/状态/异常；L4 视觉与窗口/组件；L5 纯 UI 实现/任务验证。每批至少存档 RESEARCH、DESIGN、IMPLEMENTATION、VALIDATION、HANDOFF 结果，可合并成一份结构化批次档案但各栏必须独立。

## 顺序与依赖
- P-01 研究继承、覆盖/假设；P-02 应用/任务/窗口架构；P-03 设计系统及交互规则。
- A-01 Shell/启动/多文档/工具生命周期；A-02 工程资源与导航。
- B-01 测试项目；B-02 步骤编辑；B-03 流程控制与公共流程；B-04 资源/专业参数引用体验；B-05 运行与调试 UI。
- C-01 DBC；C-02 CAN；C-03 综合台架；C-04 输入配置；C-05 UDS；C-06 Flash；C-07 Wave。
- D-01 生产扫码；D-02 报告/历史；D-03 工位设备。
- E 全产品一致性、跨工具操作、异常/DPI/键盘及统一交付审查。

## 不等待用户的准出
每批自检 G-R 研究证据、G-D 操作及异常设计、G-C 代码映射、G-V 静态/实际检查、G-F GitHub 归档；结论 PASS/PASS_WITH_LIMITATIONS/CHANGES_REQUIRED/BLOCKED。**未做 Windows 操作** 的 G-V 必须标 NOT_RUN，不得为保证计划表全绿而捏造结果。发现阻断项可内部修正并重新归档；重大产品方向冲突才向用户集中请示。

## 总体验收门槛
完整而非禁用空壳的纯 UI：主应用、资源、TEST 项目/流程/参数、DBC、CAN、Bench、输入配置、UDS、Flash、Wave、SCAN、Record、Device、报告/错误状态与窗口体系可操作。每个界面使用可明确识别的 UI 工作会话数据，不伪造实体 ACK/PASS/报告事实。用户一次性进行 Windows 验收，不逐批等待。

## 版本、删除与权限
独立 feature 分支从最新 main 派生，在该分支直接删旧 Desktop 表现层，不将旧实现改头换面使用；正式后端各项目保留 main，不在本轮连接。ui/ide-design 记录连续设计与用户审批事实；feature 分支归档实际实施与验证日志；Draft PR 指向 main，未经用户批准不合并。
