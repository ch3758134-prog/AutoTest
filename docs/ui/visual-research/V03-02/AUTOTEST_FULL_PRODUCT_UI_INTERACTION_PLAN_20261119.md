## 0. 为什么现在必须改变任务分解

用户已在 Windows 操作验证 TEST 高保真预览的初步导航、步骤选择、阶段切换和问题定位，并表示“还可以，但略粗糙”；要求白色为主、取消不合适的紫色；指出缺主控连接状态。随后要求“微调，但完整规划，不止专业工具，还有文件和各种 UI 操作”。

经源码回读，`MainWindow.xaml` 中的顶栏包含新建、打开、保存、另存为、撤销、重做、添加、复制、剪切、粘贴、删除、上下移等，但这些目前大量调用 `PreviewCommand_Click`，只改状态栏，不完成文件编辑动作。独立 `TestHiFi` 工程是视觉预览而非正式应用；既没有工程文件生命周期，也无真正多文档管理。因此下一轮不能仅装修 CAN/DBC/UDS 工具页。

**要求：任务—对象—命令—状态—视觉—保存恢复同时定义。** 文档系统、主 Shell/导航、通用交互是基础能力；TEST 与专业工具共享基础能力，但具体页面结构根据任务独立设计。

## 2. 整款产品的信息架构（必须区分三个不同概念）

### 2.1 一级工作模式（用户想做哪一类工作）
1. **自动测试**（默认）：工程中的测试用例、公共流程编辑、运行准备、执行视图、当前测试结果。
2. **生产检测**：扫码、编号匹配、选择或自动匹配程序、执行状态、单件结果、统计。生产模式应降低不必要的工程编辑干扰。
3. **专业工具**：CAN、DBC、UDS、ECU 烧录、波形、手动台架、设备诊断。可脱离自动测试单独使用，也可从 TEST 步骤跳转到对应工具上下文。
4. **记录与报告**：运行记录、操作时间线、CAN/UDS/波形相关证据、筛选/导出、报告检索。

**工程及文件**不应成为与“自动测试”平行的一套重复大页面：通过“文件菜单 + 工程浏览器 + 文档标签 + 对象详情”贯穿各模式。设备连接在全局可见，设备诊断作为专业工作页。

### 2.2 工程浏览器（用户正在打开/管理什么）
一个工程针对一个 ECU 型号/硬件版本/配置组合；不在单一工程内部混放互不兼容的型号版本。

建议树：
- 工程根（名称、路径、修订/更改标记、当前硬件 Profile）
- 测试程序／测试用例（阶段、子步骤、可勾选运行子集）
- 公共流程（单一连续步骤树；固定引用修订）
- DBC／报文与信号资源（可打开编辑）
- 参考波形
- 输入配置（20 Key 命名、组合与 5 路模拟输出的 ECU 识别映射）
- 诊断与烧录配置（UDS 请求模板/会话参数、Flash 方案/文件引用；不要把烧录二进制当普通文本编辑）
- 生产配置（编号规则、扫码关联、程序匹配）
- 工程检查／问题

**需要同时区分**“工程已加载的资源文件”和“本机原始导入文件”；用户对资源的重命名、删除、复制、修改引用必须显式处理。图中只展示当前工程相关资源，不造没有业务需要的“资源库”大首页。

### 2.3 文档/工作页（用户现在正在编辑或操作什么）
- 中心多标签允许同时打开测试用例、公共流程、DBC、波形参考、CAN 工作台、UDS 工作台、Flash 工具、手动台架等。
- 左侧树是可折叠/可重开的一致导航，不因打开工具页被全部覆盖。
- 选中树节点不等于一定要新开文档；双击打开、单击预览是否采用需在操作实测决定，避免预览标签频繁替换刚编辑对象。
- 文档标签：名称、类型标识、* 未保存、问题提示、关闭、右键关闭其他/关闭右侧、固定标签、恢复最近关闭；切换文档恢复其自己的选中、滚动、过滤和详情上下文。
- 多种工作模式与工作页是**正交关系**：在“专业工具”打开 CAN 工作台，并不要求关闭 TEST 用例。
- 右侧属性/分析信息由当前中心文档控制；底部“问题、日志、波形、变量、执行时间线”等是上下文辅助工作区，不应在所有页面永久同时铺开。
- 默认不需要随意分离成大量独立弹窗；复杂资源选择/不可逆操作确认可用对话框，主专业工作应以同窗工作页完成。

## 3. 文件系统与完整对象生命周期（最重要的缺口）

| 任务 | 入口/用户操作 | 数据与状态必须保证 | 最低验收 |
|---|---|---|---|
| 启动 | 最近工程/打开工程/新建工程；上次会话可恢复 | 未选工程时不伪造正式文件或运行状态 | 首启无需猜下一步；能直接打开工程 |
| 新建工程 | 文件→新建工程（名称、路径、配置） | 初始化合法工程文件、目录、唯一 ID；不同硬件版本不混在一起 | 创建后有工程根、可新建用例 |
| 打开工程 | 文件菜单/最近工程/快捷入口 | 文件有效性、Schema/版本、资源路径、缺失依赖提示 | 打开/关闭/重新打开后内容一致 |
| 新建资源 | 工程树右键、+ 或文件菜单 | 明确对象类型和默认模板；新建即进入编辑区域 | 测试用例/公共流程/DBC 配置对象都能创建 |
| 导入外部文件 | 工程浏览器导入、文件选择器 | 区分复制进工程与外部链接、同名冲突、资源格式校验 | DBC/波形/配置/烧录文件后显示真实路径与身份 |
| 打开与编辑 | 树双击、搜索/最近打开、文档标签 | 激活正确编辑器；切换不丢未保存字段、选中步骤和滚动位置 | 打开 TEST→DBC→返回 TEST 状态保持 |
| 保存 | Ctrl+S/保存；保存全部；另存为 | 只保存目标文档或明确事务；更新磁盘原子写入、出错可恢复 | 改一字段→标签出现 *→保存消失→重开还原 |
| 重命名 | F2 / 右键 | 禁止冲突，文件与资源引用变更有确认/一致性报告 | 测试用例调用/DBC 引用不会悄然失效 |
| 复制/移动 | Ctrl+C/V、复制资源、拖拽（可选） | 新对象唯一身份，复制与引用区分，跨文件的目标位置明确 | 不生成重复稳定 ID，不把节点移错分支 |
| 删除 | Delete/右键 | 对可恢复删除支持撤销；关联引用提示；真正永久删除需明确确认 | 删除后可以找回或可知后果 |
| 撤销/重做 | Ctrl+Z/Y、顶部和右键 | **编辑事务所属文档**明确；文本输入与节点结构事务相互一致 | 改参数/插入/删除/移动均能正确撤销 |
| 关闭/切工程 | 文档 × / 文件→关闭/打开另一个工程/退出 | 未保存项清单：保存／不保存／取消；避免丢草稿 | 关闭多个有 * 文档逐个或批量处理 |
| 异常恢复 | 崩溃后重新启动、自动恢复快照 | 未保存恢复数据与正式工程分开；恢复后可审查差异 | 非正常退出不静默丢数据 |
| 资源校验 | 工程检查/文档问题/运行前预检 | 定位资源、引用版本、类型/范围、路径与配置，分错误/警告 | 从问题列表进入准确文件和字段 |
| 版本/迁移 | 打开旧文件/不兼容结构 | 不静默改旧版本；可备份/预览/迁移、拒绝不支持内容 | 文件损坏或不兼容时有可理解的处理路径 |
| 最近文件/打开 | 最近工程、快速打开、搜索 | 路径失效能清理或重新定位；不创建伪装文件 | 不重复大面积导航视图 |

R1 不一定要 Git 风格复杂版本系统，但资源修订、引用固定、必要变更提示属于真实 TEST 工程可用性底线。文件格式与域模型必须服从现有 PROJECT/TEST 合同，不能在 UI 专项偷偷引入第二套正式工程 Schema。

## 4. 全局 UI 操作合同（鼠标、键盘和命令都是同一动作）

### 4.1 命令作用域
- **全局**：打开/关闭工程、连接主控、全局搜索、偏好设置、显示/隐藏面板。
- **文档级**：保存当前、保存全部、关闭文档、撤销/重做、定位当前文件、检验当前文档。
- **对象级**：用例/资源新建、重命名、复制、删除、编辑属性。
- **步骤级**：插入前/后/明确分支、复制、连续选择、包裹为流程、移动至目标、禁用、断点、运行到此步（**仅真实引擎接入后**）。
- **工具级**：CAN 编辑多帧/发送、UDS 请求序列、Flash 配置、波形游标、输入动作等。
- 同一个命令在工具栏、右键和快捷键必须共用同一处理逻辑及可用性状态；**没接线不能伪装成正常按钮**。

### 4.2 建议默认快捷键与鼠标
- Ctrl+O 打开；Ctrl+S 保存当前；Ctrl+Shift+S 另存为；Ctrl+Shift+Alt+S 不建议硬编码“保存全部”，可在菜单直接提供并设置明确快捷键。
- Ctrl+W 关闭当前文档；Ctrl+Tab 切换文档；F2 重命名；Delete 删除；Ctrl+Z/Y 撤销/重做；Ctrl+C/X/V 复制/剪切/粘贴。
- Ctrl+F 搜索**当前工作对象**；Ctrl+P 快速打开工程文件；Ctrl+Shift+P 查找命令。快捷键冲突应检查并可在设置中查看（尤其中文输入法冲突）。
- 双击对象打开文档；右键菜单与鼠标所在对象/选中对象一致；拖拽前必须能判断合法落点。
- 双击步骤、单击步骤、右键步骤的语义分别由测试任务确认，**不要同时存在多个不明显的编辑入口**。
- 选择步骤 ≠ 本次运行勾选；选中/焦点/断点/无效/禁用/等待/真实 PASS 独立表达。
- 正在编辑字段时，不能因切换步骤把未完成字符串清空；输入校验即时、错误不破坏用户草稿。

### 4.3 用户反馈/错误/面板
- 破坏性行为确认、有用的取消、异步进度和取消、长任务 Busy 状态、文件读写失败可恢复。
- 提示优先级：字段内错误→当前文档问题→全局状态。不要每次点击都弹模态对话框。
- 消息分**提示、警告、错误、业务操作结果、运行证据**；不能把 UI 预览的“正常”冒充实际 ECU PASS。
- 工作区宽度/底部高度可调，保存布局、重置布局；保证任务栏不被覆盖；滚动/选择状态恢复。
- 性能：树对象多、DBC 大、CAN 高频日志场景需虚拟化、批量更新/限流；不能卡顿到连删除一个资源都要等待明显时间。
- 关键按钮有明确文字/tooltip/键盘焦点；状态色同时有图标/文字，不仅靠颜色。

## 6. 连接状态与真实测试状态的严格分离

- 全局右上**主控连接区**：仅一个清晰“连接／断开”主操作，旁有独立文本状态（未连接、连接中、已连接、通信异常、重连中、UNKNOWN）；状态不明确时不能随便显示“就绪”或绿色成功。
- 设备页显示主控身份、固件版本、请求 ACK/超时/错误、两路功能通道的连接/接收信息；**不以硬编码 CAN1/CAN2 代替 ECU/按键板的实际物理通道语义**。
- 软件工程是否打开、文件是否保存、工程预检是否通过、设备是否连接、当前测试是否运行、真实步骤 PASS/FAIL，**至少六种不同事实**不得混为同一绿色对勾。
- 在 UI-only 原型下可显示真实“未连接/未接线”状态，不允许 Fake 连接成功、模拟 ECU 通过、虚假 RUN 报告。
- 所有触发真实 IO/ECU 动作的按钮需在有后端合同时才能启用；无法执行必须明确说明原因。

## 7. V03-01 视觉保留与微调清单（限定在已认可的风格内）

保留：白色主调、轻浅灰分隔、低饱和蓝选中、步骤信息密度、右侧持续参数、可折叠问题、三阶段视图、文档身份。

微调：
1. **状态语义**：删除演示步骤“26 正常”等可能被误读为已执行的绿勾；替换为“字段校验/尚未运行”或明确示例的设计态，只有真实执行完成才显示 PASS/FAIL。
2. **流程结构**：THEN/ELSE/CASE 的饱和紫底改为白灰/深灰蓝结构标记，用缩进、边线和稳定容器区分，不靠高饱和色装饰。
3. **文本与图标**：统一 Lucide 风格/可用的 WPF 图标集合；控制字号最小值与关键行高，避免全局堆小灰字；优先使用中文简体专业词语。
4. **工具栏**：文件/编辑/流程/运行清晰分组；高频操作就近；缺实现的命令明确禁用而非假点击。
5. **右侧 Inspector**：步骤编号+类型+阶段+所在 IF 分支持续可见；CAN/UDS/等待/日志/波形/按键各自拥有类型化字段；资源选择回链。

7. **问题/日志工具窗**：问题数为零时收起或给有意义的空状态；需要时可显式展开；日志/变量/波形不和问题区无限叠加。
8. **连接显示**：全局明确未连接；成功/失败 UI 状态与连接状态分开。
9. **布局**：文档区优先；可调整工程树/Inspector/底部高度；1366×768@150% 必须不裁切/不挡任务栏；允许面板收合，不能通过缩字体凑。
10. **统一反馈**：保存成功/失败、引用更新、删除冲突、未保存、当前操作完成，都有清楚但不打扰的视觉反馈。
