# AutoTest｜一个型号一个工程、资源、TEST 目录树与模板
**2026-11-21｜USER_CONFIRMED；实现/实测状态见 06**

## 1. 工程定义
一个 ECU 工程绑定一个明确 ECU 型号；一个工程内一套当前生效 DBC、一套当前生效自动 TEST 体系、一套生产烧录配置和一份当前生效待烧录固件。不同型号使用不同工程。历史修订可以保留以便复现以前运行，但不在日常 UI 中强迫工程师同时选择多套“当前方案”。

**工程是资源组织空间，不是资源唯一拥有者。** DBC/波形/诊断/烧录专业工具独立运行，不必先创建工程；项目中的资源应可直接用工具打开，清楚指示“正在编辑工程资源”还是“独立文件”。导入文件应复制/纳入受控工程资源，不能让外部原路径移动后导致生产运行错误。

### 资源清单
| 分类 | 正常默认 | 进一步约束 |
|---|---|---|
| DBC | 该型号一套当前有效 | CAN 发送辅助、RX 解码、TEST 判定、WAVE 共用一致信号定义；编辑自动保存，失效引用有诊断 |
| TEST | 一个有序用例树 | 功能/故障等分类目录无执行能力；具体用例有步骤树 |
| 公共流程 | 独立复用步骤内容 | 与 TEST 同一 DSL 与执行器，不强迫所有用例先创建流程 |
| WAVE | 工程可保存参考与比较配置 | 真实采集/参考审查与判定准确度另验，不将模拟波形当真实参考 |
| 生产烧录 | 当前有效原生 Profile + 固件镜像/必要安全算法 | 取消正式外部 XML 导入依赖；XML 参数必须能原生编辑；实际路径/字段待技术审查 |
| SCAN/工位 | 该型号识别信息及必要工位配置 | 型号与工程匹配，不在扫码方案重复绑定 TEST/DBC/固件 |
| RECORD | 各次完整检测历史、报告与真实附件 | 同一个序列号可有多个检测尝试，历史不可覆盖 |

## 2. 测试树语义（目录与可执行单元严格区分）
```text
HydEPB（一个型号工程）
└── 自动测试（唯一）
    ├── 功能测试/（分类目录，无步骤）
    │   ├── 释放功能测试（用例，含 Prepare/Test/Cleanup）
    │   └── 夹紧功能测试（用例，含 Prepare/Test/Cleanup）
    ├── 故障测试/（分类目录，无步骤）
    │   └── 通信故障测试（用例，含 Prepare/Test/Cleanup）
    └── 公共流程（引用/复用资源，不参与自动生产用例计数）
```
- 树中的分类目录可嵌套、改名、拖动/排序，**自身不是测试用例**。只有具体测试用例才含 StepId、步骤、准备/测试/清理、断点等，并作为开发运行单元。
- 生产执行按工程测试树稳定的**有序深度展开顺序**遍历全部已启用的具体用例；不另有“出厂测试项目选哪几个用例”的常规配置。
- 开发中的单步骤、当前用例、勾选范围继续保留；Enabled=工程永久生效与 Selected=本次调试选择严格分开。可在目录中批量操作子用例，但不赋予目录自己的测试步骤。
- RUN 开始时冻结真实用例顺序、步骤参数、DBC/波形等引用和必要版本 SHA，不能因自动保存期间编辑而中途变更本次执行。
- 原有 `TestProjectDocument/TestDocument` 可用于实现，但 UI 中**不强制增加多层 TestProject/配置选择**。要先分析数据迁移、参考引用和旧用例兼容。

## 3. 用例编辑/流程控制
TEST 仍承担 CAN、KEY_SIM（20 Key 完整 mask + 保持时间）、IGN、等待、DBC 断言、UDS、WAVE、IF/ELSE、SWITCH、WHEN、循环、异常/变量与公共流程等目标。现有可编辑≠可运行；添加步骤、Inspector、预检、执行必须共用能力清单，不支持的类型显式阻断，不能假通过。

**失败处理在已有可编辑 TEST 流程中实现**：可执行诊断、等待、重试特定步骤、终止当前用例或允许继续后续用例；不是把任何非 PASS 在外层写死“停止全部”。历史 FAIL 必须进入累计检测结果，后续用例 PASS 不能覆盖。底层 STOP/Flash 故障/设备失联仍有不能由用户脚本绕过的安全边界。

## 4. 模板与自动保存
- 新建 ECU 工程自动填充通用基础设置、合理初始化与失败/收尾步骤，工程师按 ECU 修改即可。
- 模板内容复制进工程；修改工程不改模板，更新模板不会自动覆盖已经开发/实测的旧工程。模板几乎不改，管理入口低可见、可放高级设置。
- 所有常规资源和步骤属性修改**自动保存**，不出现“每次关闭未保存”提醒；编辑尚不合法时可恢复草稿，但不得自动成为可执行生产配置。
- 自动保存覆盖创建/编辑/移动/删除/批量操作、DBC/生产配置、恢复和工具窗口；需要原子提交、备份、版本一致性与失败可见。保存失败绝不静默关闭丢内容。
- 自动恢复上次工程，左侧工程树单击切换；添加步骤先出现在列表并选择，属性在右侧常驻，不反复开小窗。

## 5. 与记录及生产的关系
TEST 负责定义动作、观察源、判据及有意义的**关键测量数据提取**，把实际测量/步骤 Occurrence 交 RECORD；日志/报告由系统固定呈现。生产调用 TEST 的已启用树，不把扫码/夹具启动/生产必烧录当作每个用例中的普通步骤。
