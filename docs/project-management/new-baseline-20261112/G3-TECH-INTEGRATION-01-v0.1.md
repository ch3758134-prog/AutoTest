## 一、UI 专项分工正式隔离

- **独立 UI 对话**：只负责 AutoTest IDE 式正式 UI/UX 的研究、具体设计和后续经授权的 WPF 实施，直至项目负责人对视觉及操作实测满意；旧版 UI 研究单独暂停，待用户以后提供。没有 G4 授权前的设计成果不得自动当源码实施许可。
- **项目管理对话**：只提供稳定的行为/状态/资源/运行事件合同、设计审查、版本/仓库管理、集成和质量关口；不在 UI 专项之外并发改 XAML，也不以未获证的 UI 截图代替真实程序。
- **共同接口**：工程资产树与 Revision/SHA、TEST 文档/步骤能力、ProjectRun/PackageAttempt/StepOccurrence 实时事实、单一 USB/CAN 会话状态、Wave 实际数据与参考、Flash Lab 真实进度与授权状态。UI 为这些既有服务提供高效操作，不自创第二运行器或物理命令路径。

## 三、设计合并前解决的交叉冲突（按优先级）

1. **公共工位拥有权**：A2 单工位多包、F1 单独 EXE、手动台架都操作真实 USB/CAN；必须在 G3 指定唯一底层提供者与诊断/编程受控写入授权，不能在不同 UI 创建独立未协调会话。
2. **设备命令能力与现场事实**：主控固件包含 SET_ECU_PWR/IGN/KEYPWR/SOL；HOST 部分未接通，现场安装与安全信息仍待验证。先提供明确状态/授权合同，不承诺自动控制全部硬件。
3. **TEST 真实 Run 判定**：多包调度、波形分析、独立 Flash 以后进入 TEST，必须使用相同 verdict/证据身份体系；CanTool/波形的动作 ACK 或数据字符串不能直接当 DUT PASS。
4. **资源快照**：DBC/Controller/WaveProfile/Flash配置、固件镜像与 TEST 要使用同一个工程 Revision/SHA，运行中不能静默换资料。
5. **可测小增量**：UI 变化不等于设备实现；后端通过编译不等于 UI 可操作，真实 ECU 需要独立授权与证据。现场通过一项再扩大下一项。
