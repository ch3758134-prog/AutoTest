# AutoTest｜真实手动台架 UI/操作合同 V2（候选，待 Windows 实测）

- 设计目标：真实硬件通路验证，自动测试接线前使用。不再把单次 CAN 发送表单等同于 CAN 工作台。
- 作用范围：WPF 手动台架的导航、布局、编辑和会话状态；不擅改设备命令、授权和固件。
- 状态：UI 研究候选；未编译为 WPF，未验证实体硬件；不能作为设备能力 PASS。
- 实施参考：当前 `feature/g4-html-parity-20261115` 中 `ManualBenchWindow.xaml`、`ManualBenchViewModel.cs`、`HardwareConnectionService.cs`。

## 1. 固定布局

窗口浅色、默认最大化；左 CAN 发送（约 40%）、中工位操作（约 31%）、右 CAN 实时监控（约 29%）。三个区同时可见。统一顶栏展示 USB 连接、CAN0→KEY_SIM、CAN1→DUT 和实体输出授权状态。不要把实时监控置于底部，不要把发送编辑与日志混合。

## 2. 左侧 CAN 发送：多报文列表 + 专属编辑区

每条发送项拥有稳定会话 ID、可读名称、帧格式、ID、数据/DBC引用、信号物理值、发送模式（单次/周期）、周期ms、启用/停用、发送状态、计数/失败。列表可新增、复制、删除、排序，逐项勾选并停止；可以同时启用多条周期报文。勾选配置和实体发送状态严格区分，未授权不得启动。

选中一条报文时，在其下方专门 Inspector 编辑名称、DBC 报文、信号值、原始帧、周期和格式。列表摘要随修改实时同步。DBC 物理值合法性、资源修订和报文编码由现有业务服务负责，不在 View 中手拼 HEX。不可要求关闭列表、打开通用配置窗口再编辑。未接真实硬件时仍允许编辑待发送列表，但不虚构 TX。

周期发送由统一 CAN1 发送调度服务管理，不允许在 View 或每条 DataGridRow 中开启不受控无限 Task/Timer；明确总线拥塞、最小周期、队列拥塞、停止生效、退出和断连时停发、自动 TEST 获得工位所有权时停发或拒绝启动。周期授权按受控对象/范围/有效期设计，经设备专业审查；不能绕过 PhysicalCommandFence 或用自动 TEST 的授权偷放行。实际状态区分请求、已调度、USB ACK、停止、失败、UNKNOWN，不将 ACK 冒充 DUT 接收。

## 3. 中间工位操作：真实高频控制

顶部三条独立快速控制：IGN ON/OFF、夹具1压紧/释放、夹具2压紧/释放。两夹具分别是独立 GPIO；读取主控 GPIO 不代表夹具机械已到位。只提供真实授权后的物理操作，未连接时禁用输出且可查看草稿。

主区为**命名按键动作**，每个动作用显著可点击按钮呈现：左键执行（经过有效授权），右键编辑；也有可见编辑入口。动作不等于某个 Controller 状态；用户可创建、重命名、保存、复制、排序和删除。动作由任意长度序列构成：设置任意有效的 K01～K20 组合并保持指定时间；或只等待、保持当前 KEY 不变。20 路为电阻网络内部开关，最终形成五路模拟电压，不是 20 路 ECU 业务功能键或 DAC。mask=0 合法；不默认增加松开/恢复，也不预设任何 ECU 业务名。

动作编辑复用 TEST 编辑器已证明有效的“列表选中 → 专门参数区”交互。步骤列表显示序号、组合摘要、时间、当前选中、上下移动、复制/删除；选中设置组合段后显示 20 KEY 可点击格子和 ms 输入。保存到当前工程正式资源，有身份/Revision/SHA，重开不丢失，运行前检查适用性、版本、硬件冲突组合及互斥。当前 Controller 模型无法表达自由序列时，走最小受控模型扩展，而不是拼装旧 Pulse/Hold/Release 伪装。执行中显示段号、请求、USB/CAN ACK、超时/取消、UNKNOWN，不因序列结束自动断开 KEY；异常收尾按批准设备合同。

## 4. 右侧 CAN 实时监控

监控常驻右侧：CAN0、CAN1、全部过滤，按帧 ID/报文名筛选；默认按（通道、标准/扩展、ID）聚合刷新，包含最新时间、方向、ID、数据、次数、错误/丢帧，允许切换完整原始事件时间线。底部分离真实 USB、CAN、KEY、IGN、夹具操作事件。暂停显示仅暂停视图，不停止实际接收；清空显示不删除证据；日志可导出。未连接时保持真实空状态，不生成假报文。

## 5. 设备服务及状态原则

继续使用同一个 HardwareConnectionService/USB/CAN 事实源，自动测试与手动台架不得并发写实体。CAN 周期发送、KEY 序列、IGN、夹具各共享明确的工位实体授权；操作之前检查连接世代、资源快照、输出独占状态。请求、ACK、主控 GPIO 回读、ECU 实际识别、电气测量分别报告，严禁合并为单个“成功”。

## 6. 交付和验收

实施 G4 专项以正式 WPF View + VM + Application/Device 适配为目标，不仅实现 HTML 外观；先离线新增/编辑/保存多报文及命名 KEY 动作，再以真实设备独立验证 CAN1 单次与多条周期、CAN0 KEY 序列、IGN、两个独立夹具、右侧 CAN0/1 真实监控。测试断连、异常、自动 TEST 抢占工位和重连 UNKNOWN。未经 Windows Build/实体实测不能宣称完成。

用户当前优先目标：手动台架全面验证真实硬件通路，并与可勾选用例的自动测试同步推进；公共流程、全局配置工作区重构不能阻断这两条主线。
