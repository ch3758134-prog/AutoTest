# AutoTest R1｜浅蓝 IDE 原设计稿严格实现与 main 合并门禁

## 视觉权威

**唯一视觉依据**：2026-11-11 用户确认的浅蓝色九屏设计稿。图中的发动机 ECU、测试通过、CAN/UDS 数据、波形采样率是**设计稿示意**，绝不能用假的测试结果或虚拟物理数据填充正式产品。

正式 WPF 必须沿用设计稿的空间关系，不准再以“旧布局兼容”为理由保留重复菜单、空白操作栏、过宽参数表或占主工作区的大面积无用面板。

### 统一外壳

- 主框架：顶栏约 45 px、唯一全局任务栏约 60 px、左侧活动轨约 60 px、工程资源树约 280–300 px、中心文档/操作区自适应、底部状态栏约 30 px。
- 视觉：近白色底色 `#F4F8FD`、白色卡片、浅蓝选中行 `#E8F2FF`、灰蓝边界 `#D7E3F1`、深灰正文 `#243A52`。严禁以深蓝大块背景作为操作引导；不使用绿色作为成功/状态的默认强调色。
- 交互：中文操作语义、清晰大小写缩写（ECU、CAN、DBC、UDS、ISO-TP 等必要词除外）、鼠标左右键、滚动、步骤选择/上下移动、撤销/重做、键盘快捷键有对应实际功能。
- **窗口规则**：自动测试编辑和运行放主工作区；手动台架、DBC、UDS、烧录、波形、控制器/按键配置等使用自己的独立顶级窗口。独立窗口使用统一外壳、同一工程资源浏览器、同一物理连接状态；不能创建第二条 WinUSB 会话。

### 可复查的真实工程样例

- 使用 `AutoTest.Desktop.exe --ui-review`，或“更多 → 载入 UI 评审示例工程”。
- 实际 `samples/ui-review-epb/EPB-UI-review.autotest-project.json` 与真实 TEST/DBC 资源被复制进编译输出目录。
- 此工程只作 UI 验收与编辑，代码根据稳定 ProjectId 阻止任何物理测试，不准通过虚拟 CAN/模拟测量给出 PASS。
- 评审应展示完整分层步骤，选中参数化节点，在真实程序编辑器中保存/重开，不允许用静态截图假装工程功能。

### 准入 main 前必须完成的验证

1. **Windows Release Build PASS**：WPF 主项目及相关测试项目；UI 编译错误不能由本地 Codex 自主修复。
2. **自动化测试 PASS**：Desktop、Devices、Testing、Projects，并执行示例工程加载回归。
3. **实窗视觉对比**：最大化、100%/125%/150% DPI；逐页截图与用户已批准设计稿并排审查。主要比例、操作重心、中文文字和窗口边界不得明显偏离。
4. **交互测试**：工程打开/保存/重开、测试树选中/折叠/展开/右键、参数修改/撤销、DBC 导入、台架独立窗口、UDS/Flash/Wave 独立窗口关闭/重新打开，焦点与弹窗归属无误。
5. **真实设备安全**：连接自动发现、断连/超时、连接失败就地可见；不自动发 IGN、KEY_SIM、CAN、夹具或烧录操作。
6. **回归约束**：不修改现有持久化资源格式、测试判定真实来源、物理输出与授权门禁；不合并未经本地验证的 Draft PR。

> 本文是合并评估依据，不等于宣称已经编译成功、实机验收成功或与设计图 1:1 像素一致。必须拿 Windows 实际截图和日志才能给出 PASS。
