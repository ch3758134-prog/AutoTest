# 技术预研 → 实验验证 → 架构批准 → 纯编码 AI 准入｜V0.4

**状态：Draft PR #28 的工程管理工具候选。** 本页是管理平台的工作流设计与使用说明，不是对 AutoTest 具体架构、KEY_SIM 或任何硬件试验的批准。

## 核心原则

**系统需求明确 ≠ 技术实现可行 ≠ 架构设计已批准 ≠ 详细设计已充分 ≠ 实物验证完成。**

- 系统/软件架构负责人设计并比较候选方案；技术预研 AI 可以调研并提交候选实验，研究用的临时原型不等于正式产品源码。
- 真实实验的执行与安全许可由现场负责人与独立验证流程控制；本工具只记录计划、授权、结果、原始证据及审查，无任何 CAN、USB、固件烧录或其他硬件控制接口。
- **纯编码 AI 不进行技术选型、不新增产品需求、不设计系统/软件架构、不决定公共接口。** 这些要在设计阶段完成并经过相应审批；缺口作为独立问题向上反馈。
- 一项关键不确定性不应强制冻结整个产品。只阻断明确引用该研究的架构修订和对应的下游工作包；未受影响的开发继续。
- 既有测试失败、研究结论被推翻都可以重新研究、重新实测并生成新的设计修订。先前记录不删除。

## 真正可操作的管理对象

| 工程对象 | 用途 | 对后续工作的约束 |
|---|---|---|
| **Technical Investigation** | 某个尚不能通过设计推理确定的技术问题、来源需求与验证等级 | OPEN 时不允许把依赖该研究的架构批准 |
| **Candidate** | 一种实现技术路线，含方案描述、优缺点和未证实假设 | 不因为 AI 提出而成为架构事实 |
| **Experiment Plan** | 明确方法、输入、成功标准、环境、验证等级与必需性 | 未取得负责人明确授权不得登记实测结果 |
| **Evidence Record** | 真实执行者、时间、软件/固件/硬件配置、原始报告路径、SHA-256、观察值和结果 | 未经人工审查，PASS 也不能支持技术决策 |
| **Technology Decision** | 方案选择、被采用的已审查证据、适用条件、负责人、修订 | 决定版本固定后才可进入正式架构批准 |
| **Architecture / Software Detailed Design** | 设计引用的技术研究 ID + 决定修订 | 引用的研究重开或版本变更则架构/编码准入失败 |
| **Coding Work Package** | 有已批准详细设计、固定上游版本、Git 基线、文件范围及测试合同的纯实施任务 | 编码 AI 只修改授权源码并提交 PR/测试证据 |

## 研究等级按技术风险选择

- `ANALYSIS`：成熟技术/已有的可适用证据，完成分析记录和人工审查。
- `PROTOTYPE`：独立可复现实验程序、软件实测和可恢复的原始运行证据。
- `REAL`：真实目标环境或实物设备的实验记录，必须明确配置和实测判据。

不是每个模块都需要真实硬件实验：设备抽象、复杂时序、传输链、烧录及物理输出等关键未知应采用相应的实际环境；普通确定性软件逻辑可在已有验证基础上直接完成详细设计。**实验等级不等于设备安全许可**。

## 操作步骤（本地网页）

1. 在 **产品与系统 / 需求与架构** 中确认产品/系统目标，必要时审批需求修订。
2. 进入 **技术预研与实验**，新建具体问题，选择需求来源及最低验证等级。
3. 建立至少一个候选技术方案，记录取舍、代价和假设。
4. 为候选方案制定具有明确成功标准的实验；现场负责人评估并授权实验。
5. 实验在管理软件之外进行；回填真实环境、配置、源码/固件修订、原始证据 ID/路径、观察结果、PASS/FAIL/LIMITED/INCONCLUSIVE。
6. 人工审核记录与适用性。失败保留历史；改进后可再次记录并审核新一轮实测。
7. 只有每项必需实验的**当前有效审核结果 PASS**，且有符合最低研究等级的审核通过证据，才能批准技术路线。
8. 将研究决定绑定到相应架构/接口/详细设计对象，记录决定修订。**这不自动批准架构**：负责人还要独立审查架构、软件边界、接口和行为。
9. 编码前建立软件单元详细设计，完整记录功能算法、接口数据合同、状态、错误恢复、并发资源以及测试判据。
10. 创建编码工作包，建立并审核真实上下游设计依赖，固定所有输入修订，明确目标源码 40 位 Git SHA、允许修改文件和验收条件，执行实施准入校验。
11. 通过后生成 AI 实施上下文；新发现必须返回设计/研究，再形成新的有效版本。**编码 AI 不得自行研究选型或改变系统架构。**

## 具体阻断规则

- 预研尚无候选方案或没有实验，不能“通过”。
- 未授权实验不能登记结果；没有原始证据路径、环境和源码/配置修订，不能生成通过证据。
- 未审查的 PASS、已确认 FAIL、LIMITED、INCONCLUSIVE 均不能放行关键实验。
- 研究等级要求 REAL 时，单纯代码单测/原型结果不能代替真实实测。
- 研究已经决定后不可悄悄修改候选方案/证据；必须以原因重新开启，旧技术决定进入 SUPERSEDED。
- 架构/详细设计引用该研究时，必须锁定具体研究决定修订；研究重开将阻断新架构批准和受影响正式编码工作包，不抹去旧版本历史。
- 新建纯编码工作包采用 `execution_role=CODER`；需要已批准且具备六项软件单元详细设计合同的上游设计。实现 AI 不被授予研究/架构更改职责。
- **本工具仍依靠用户登记的真实证据**，尚不自动检验外部文件内容或 GitHub/CI 的真实性。记录“审核通过”不是自动现场认证。

## 跨软件系统与多设备

研究对象附属于项目和具体系统需求，不强制 ECU、CAN、AUTOSAR 或任何特定单片机。

一个产品可以包含不同的软件系统和构建/部署目标，如 PC Host、MCU 固件、工具链、独立诊断程序；技术研究与架构分别明确适用范围及证据配置。一个被验证的接口可作为多个组件的设计输入，但源码、模块责任和独立测试证据仍须分别管理。

## 离线使用与数据

```powershell
git fetch origin pull/28/head
git merge --ff-only FETCH_HEAD
py -3 -m unittest discover -s tools/lifecycle/tests -v
py -3 tools/lifecycle/server.py --repo . --port 8765
```

打开 `http://127.0.0.1:8765/`。默认数据文件：`%LOCALAPPDATA%\EngineeringWorkbench\workspace.sqlite3`。不需要登录、云服务、MySQL 或额外 Python 依赖。可以在“历史与配置”导出项目 JSON，现在已包含技术研究、候选方案、实验、证据和决定记录；但**外部原始日志文件不会自动打包，JSON 也尚不支持一键重新导入恢复**。正式备份仍需停服务后复制 SQLite 文件并单独备份原始证据。

## 本版本仍未提供

自动 GitHub PR / CI 同步；设备测试控制/原始证据数字签名校验；复杂系统结构图、完整产品配置基线；研究 AI 对实验程序的自动派工；计划/甘特图/里程碑持续推进。这些不能被当前研究闭环误称为已实现。
