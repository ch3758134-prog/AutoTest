# AutoTest UI｜交互设计与纯UI实施约束（实施工作合同）
本文件给下一接管AI使用，不得把它误认成用户批准的具体成品UI。
## 主空间
浅色标准 Windows WPF 主窗口：应用头、紧凑任务导航、资源/用例浏览、主任务工作面、状态和当前工作上下文。无工程仍能浏览和操作纯UI编辑场景；首次启动不强迫命名。专业工具受主窗口管理为可独立使用副窗口，避免用工具覆盖资源树造成空白。
## TEST
测试项目/用例在左侧可编辑列表，本次运行勾选独立于编辑选择；编辑器主区域是准备/测试/清理三阶段树，提供常用步骤插入、复制/删除/排序/撤销/重做；右侧只对相关步骤显示持续参数编辑。条件步骤的 THEN/ELSE、SWITCH、循环子步骤可见。运行工作区展示预检/运行/结果信息位置但不生成模拟结果；实体运行需要后续接线。
## 工具
DBC 双层对象编辑；CAN 左多条发送配置、中工位动作/快捷导航、右日志/观察；手动台架支持20电阻开关多选并保持，不将20开关直接视为20个ECU功能按钮；UDS请求序列、Flash阶段、Wave分析、生产扫码、记录/报告、设备诊断均提供不同专业布局；不允许静态占位弹窗冒充完整交互。
## 实施判定
每一批代码需用稳定的可编辑 UI 状态实现相应操作；允许本地 UI-only 草稿导入导出，不允许经业务层控制真实USB/CAN。按内容组织的文件分拆、可自检与可追溯日志；不再有旧 G4 View/ViewModel 兼容文件。
