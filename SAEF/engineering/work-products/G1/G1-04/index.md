# G1-04｜质量、可维护性与 UI 可用性要求（M2 候审）

## 一、明确的非功能方向

| 编号 | 质量维度 | 要求及理由 | 验收途径 | 数值状态 |
|---|---|---|---|---|
| Q-01 | 真实证据 | 不混淆静态源码、构建、单测、模拟、台架和系统验收状态 | SAEF/工作包状态核对 | 已明确原则 |
| Q-02 | 可恢复连接 | USB/CAN 断开、超时及重连应可观察，不静默假定动作执行成功 | B1/B2 异常注入 | 超时和重试阈值待实测 |
| Q-03 | 设备状态安全 | IGN/夹具等物理输出与控制请求/ACK/外部反馈分别表达 | B3 现场复验 | 禁止虚构到位 |
| Q-04 | 测试稳定性 | 编辑同一程序、保存重开、运行同一版本有可解释结果 | H3 重复回归 | 精确误差阈值待实验 |
| Q-05 | 数据追溯 | 测试记录区分 Run 数与不同 ECU 数，真实身份与程序资产有版本 | H4 样本与复测用例 | 已明确业务原则 |
| Q-06 | 离线与升级 | 首版工位无外网时仍能开展已配置测试，数据升级有清晰失败信息 | H3/H4 离线/格式测试 | 待定容量 |
| Q-07 | DUT 无关 | 平台公共核心不得依赖固定 ECU 信号/测试业务 | 非 EPB 假工程/资源替换测试 | 已明确原则 |
| Q-08 | 模块并行 | 经 G2/G3 统一接口后各工作包可独立构建/契约验证和组合回归 | 版本化 ICD + CI/本地测试 | 执行指标待实施 |
| Q-09 | UI 视觉 | 全局 Token/控件/文字层次/状态表达一致，重要信息易识别 | 组件画廊截图与高 DPI/中文回归 | 具体视觉值待 G2/G3 |
| Q-10 | UI 操作 | 编辑器、属性栏、运行控制、独立工具遵循同一行为模型，错误有明确反馈 | 任务走查/键鼠操作回归 | 任务量化指标待试用 |
| Q-11 | UI 可调整性 | 视觉资源/交互优化不应无故改动测试执行模型 | UI 与应用合同独立回归 | 以接口变更影响验证 |
| Q-12 | 固件可维护 | 每次 MCU 固件变更有编译目标、烧录映像身份、兼容矩阵与回归 | 固件 WP 的构建/板卡证据 | 当前固件未新复验 |

## 二、UI 是正式设计与验证对象

**视觉系统**：色彩、对比、字体和中文可读性、字号层级、间距、图标、圆角、线条、主题、交互状态、信息密度。需要设计 Token、WPF ResourceDictionary、共享控件模板、组件画廊和视觉回归证据，不仅是一张工作台截图。

**信息组织与操作**：项目浏览器、资源编辑、测试步骤树、预期/实际、运行状态、属性编辑、工具窗口、状态栏、Dock/Pane/Tab、键鼠、命令与撤销。研发/生产共用核心，但可经工作空间/权限设计形成不同操作路径；未实际走查前不得将 HTML 视觉原型当成最终 UI。

**实现边界**：G2 负责统一任务与状态、视觉模块、控件责任及依赖；G3 负责 WPF/XAML/Prism View/ViewModel、资源字典和组件模板的文件级合同；G4 先组件展示与工作台独立验证，再真实业务页面与现场使用验收。不能用“XAML 编译成功”证明交互和视觉满足要求。

## 三、指标制定方式与缺口

不得凭空规定 USB 延时、CAN 帧吞吐、DBC 处理时长、波形采样精度、平均生产节拍或 UI 响应毫秒数。G3 先指定代表性数据规模、设备版本和观测方法；G4 取得基线测量后提出阈值与风险；适用 G5 版本发布前形成经批准的量化准则。当前缺口已在 `D-01…D-16` 关闭矩阵中记录。
