# AutoTest R1｜面向使用者的完整操作路径：源码静态审查与整改

**分支：** `R1`（唯一实施分支）  
**审查与整改：** 2026-11-23  
**性质：** GitHub 源码静态回读及修订；**未运行 Windows 编译、CI、Keil、串口试扫、USB/CAN 实体联调或 ECU 烧录。**  
**Gate：** **BLOCKED_FOR_PRODUCTION**。不能把源码、配置冻结、产品界面或模拟测试当作 ECU 正式生产 PASS。

## 一、产品核心不变

- **一个 ECU 型号工程**拥有唯一正式 TEST 项目及有序**调用实例**，测试用例定义可独立编辑与公共流程复用。正式生产运行工程包含的**全部有序用例**，工程树或测试项目里的“勾选”只决定本次**开发调试**集合，不产生第二份生产方案。
- **检测准备**是工程的一级、可直接编辑对象：扫码映射、原生 FLASH（HEX + 受审安全文件 + 用户的 11 项 XML 参数）、夹具准备/收尾工艺、资源和运行前检查。不把它藏在工具菜单。
- **专业工具**独立于正式自动检测；可复用工程资源及真实设备服务，但不能默认给生产授权。
- 正式执行目标：**部署并锁定工程 → 扫码解析和身份匹配 → 实际夹具准备及工位状态 → 软件/实体 START 统一锁定 RunId → 每次必经工程级原生 FLASH → 全部有序 TEST → 同一 RunId 的持久 RECORD/证据 → 受控收尾**。复检不能绕过 FLASH，也不能重复计为新 DUT。
- 硬件基线：ECU CAN = MCU FlexCAN1 / J1 A12(H)、A1(L) / USB 通道1；KEY CAN = MCU FlexCAN0 / J1 B11(H)、B1(L) / USB 通道0。主控 IO ACK ≠ 夹具机械到位。

## 三、必须继续完成的 P0（不可用 UI 扮演已完成）

1. **物理 START 输入接口尚无可验证的主控硬件映射与订阅。** 没有证据不能制造“实体按键已触发”事件；不允许普通软件按钮充当未经验证的实体输入。
2. **正式生产执行适配器缺失。** `ProductionCommandHandler` 和 `ProductionWorkflow` 目前为后端合同；`AutomaticTestHomeViewModel` 尚未连接能安全调用一次原生 FLASH 和全量 TEST 的实体生产执行器。开发 `RealTestWorkbenchService` 每用例生成自己的开发 `RunId`，不能冒充统一生产 `RunId`。
3. **真正的生产记录提交与全生命周期证据还未接通。** `IVerifiedProductionCommitSink` 的最终核验与当前正式 UI 未形成闭环；扫码快照在预检中被保存，不等于已经持久入库。没有完整真实 FLASH 及 TEST/RECORD 证据不得输出生产 PASS。
4. **夹具机械真实状态与工位准备/收尾的动作合同**必须以实际 GPIO/现场设备能力为准；不能用 MCU 输出回读假装机械到位。FLASH 失败、STOP、复检必须有独立的硬件异常与 UNKNOWN/恢复路径。

## 四、P1 后续产品一致性

- `TestDocument` 仍以 `Prepare/Test/Cleanup` 三阶段持久化；编辑器已隐藏空阶段作为连续列表，但**未完成全域单连续步骤树**的正式格式与执行器迁移。不能简单删除以免原旧用例执行顺序/异常清理改变。
- 已存在未接线的 UDS 独立工具入口；不得把菜单禁用项冒充现成完整工作台。
- 主控固件旧 `CDD_KeySim` 使用 CAN ID `0x100`，与当前 KEY 物理协议 `0x730` 不一致。当前 BUS Proxy 透明转发并未调用该旧封装，故应冻结为遗留接口，不可在新的硬件动作路径启用。
- 串口规则仍限制 ASCII 文本、CR/LF 完帧和有限提取模式。任何其它扫码枪帧协议需在真实样本基础上扩展。
- WPF 生命周期、自动保存并发、CAN 总线确认、波形采样质量和参考判定、ECU 真实烧录后验必须在 Windows + 台架由操作员完成确认。

## 五、实测建议（仅建议操作；本次没有运行）

1. 从最新 `R1` 获取源码，本地 Windows Release 编译 Desktop、FlashLab，Keil 编译主控固件；修复所有实际编译错误，不以静态阅读代替构建。
2. 离线进入 HydEPB 工程；检查工程导航、搜索高亮、测试定义与有序实例、用例步骤树、右侧属性和配置页来回切换及自动保存。
3. 导入真实 HEX/SafetyFile、检查 11 项默认配置、镜像签名提示、冻结/发布指纹；在**独立专业工具**上做有证据的实体烧录，不用正式生产按钮提前执行。
4. 用真实扫码枪测试 CR/LF、字段映射、错误/截断帧、同编号复扫、切换/更新规则后的身份失效；检查字段和值可见。
5. 检验主控 0x42/0x43 设置/读回、KEY CAN 500k 不变，硬件 ACK 与实体电压/机械到位分别核验。
6. 关闭 FLASH 配置窗口、切换工程、主窗口退出，确保失败保存能阻止丢失草稿；测试所有独立工具窗口与 USB 会话释放。
7. 在 P0 全链实现前，生产“核对启动条件”必须拒绝实体运行，不能有假 RunId、假 FLASH、假 TEST PASS 或假报告。

**Gate 结论：** `NOT_READY_FOR_PRODUCTION`。工程开发、独立实测和源码/UI 交付可继续；正式生产检测须由 P0 整机执行链与真实验收证据解锁。
