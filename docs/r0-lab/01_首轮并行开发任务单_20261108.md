# AutoTest R0-LAB｜首轮专业可测版本：并行实施任务单 v0.1（候审）

基线 GitHub `main@f701902325994802b896dafecffb5cfe81679875`；须先读取 [00 专业实测开发与变更边界](00_专业实测开发与变更边界_20261108.md)。本文件定义下一轮开发对象、精确负责范围和验证证据，不授权跨模块私改，也不宣称当前 Windows 已通过新构建。

## 0. 共同交付流程

每个专业对话：**读 GitHub 当前 main → 对照现有源/测试/G3 → 提出专业 UI 的完整可测设计 → 用户按相关部分批准 → 生成私有范围内的精准源码与测试 → 本地 Codex 只机械应用 Build/Test → 由用户自行实测并在对应对话讨论 → 修改或提出跨层问题 → 回主对话登记差异**。

不允许把“设计说明或 Mock Demo 已完成”当作“用户可实测”。每个候选必须能清楚显示原始通信/数据、状态、失败原因、数据来源、版本及导出路径。若真实链路尚未接通，仍可以交付 Mock/Replay 功能，但状态标识必须为 `SOFTWARE_ONLY` 而非 `READY_FOR_PHYSICAL_LAB`。软件可持续开发，不等待人工实测结果。

每个专业首轮提交 ① UI 真实操作流程 ② 精确修改文件列表和差异 ③ 核心场景和失败场景 ④ 用户如何获得日志 ⑤ 专项自动测试 ⑥ 对 INTEGRATION 的明确 Port/Region/服务要求。不得让 Codex 自主研究修复。

**先做：** 现有诊断入口的设备身份枚举/连接/断开/重连/GET_VERSION/只读命令完整 UI；CAN RX Trace 必须显示原始帧、来源、角色、方向、主机时间与质量、世代、丢帧及异常；受控日志导出；连接失败时保留 Win32/USB 阶段与完整错误。重连后旧 Session 证据不得混进新会话。既有主控只读验证不得增加任何物理输出。

**尽早给 INTEGRATION：** 原生 Station/CAN RX 订阅和 Trace 服务生命周期；物理 UDS 只读请求所需的最小安全发送合同（设计与证明，当前不直接打开 Tx）。不碰 UDS/Flash 私有代码。

**先做：** 在专业 WPF 里完整提供服务模板/参数/寻址、请求与响应原始 Hex、NRC、ResponsePending/P2/P2*、会话可见、ISO-TP 帧级 Trace、复制/过滤/导出完整日志、单次取消和失败解释。先保障 Mock/Replay 可观察性。联合 DEVICE 准备 `R0-UDS-READ-01` 的真实只读功能：只在有独立受限 Tx 通路、身份确认、租约和日志保护时引入物理只读入口。需要主对话先审公共授权合同。

## 3. FLASH 专业｜先提供能看清每一步的 Dry-run，再进入真实刷写专项

**读取：** `src/AutoTest.Desktop/Tools/Flash/FlashToolViewModel.cs`、`FlashToolView.xaml`、`src/AutoTest.Specialists/Flash/FirmwareImageParser.cs`、`ProgrammingPreflight.cs`、`ProgrammingJobCoordinator.cs`、`MockProgrammingWorkflow.cs`、`ProgrammingEvidence.cs`、`ProgrammingStageHandlers.cs`、`FlashTransferScheduler.cs`、Flash tests。

**先做：** 镜像分段明细/哈希/目标核对/阻断原因，编程作业完整阶段和真实字节进度，Mock Bootloader 的正例/失败/NRC/取消/断线模拟，最后成功传输块、原始请求/响应关联和审计日志导出。UI 不允许仅一个进度条；明确 `Completed/Failed/Cancelled/Uncertain`。专业界面独立可查看，无需等最终 Shell。

**单独推进：** `R0-FLASH-PHYSICAL-PLAN`：用户反馈实际 Bootloader、镜像和目标 ECU 信息后，形成物理写入的地址/ECU 安全匹配、权限、校验和异常恢复方案。物理执行器必须通过主对话组织 UDS/DEVICE/FLASH 联合设计与受控验证，不能靠设置 `PhysicalProgrammingEnabled=true` 或删 Mock 判断实现。目标是**最终真实刷写成功并保留完整证据**，不是永远停留在 Dry-run。

**最小自动证据：** 错镜像/错 ECU/地址越界/段重叠/传输 NRC/取消/作业 Uncertain/审计完整性与敏感信息遮蔽。

## 9. 首轮回收与提交字段

每个专业第一次交回一个小而完整的 R0 候选，而不是笼统“本模块已完成”：`Specialist`、`CandidateId`、`GitBaseSha`、`ModifiedPaths`、`UIEntrypoint`、`HowToGetTrace`、`MockReplayCases`、`BuildTestEvidence`、`PhysicalStatus`（未测/待测/部分测/已复测）、`SharedChangeRequests`、`KnownGaps`。新源码进入 GitHub 前检查 main 的 HEAD 和已上传改动；共享层修改先交主对话裁决。未经用户单项批准的专业 UI 关键行为只属于候选，不宣称正式冻结。

## 10. 首个可测软件包放行规则

可以标 `READY_FOR_MOCK_REPLAY_REVIEW`：UI 可操作、Mock/Replay 自动测试通过、日志可导出、来源标签正确。
可以标 `READY_FOR_PHYSICAL_READONLY_LAB`：另须 DEVICE 的真实连接与只读 Tx/Rx 边界、原始 Trace、会话世代、失败保护和联合测试完成。
可以标 `READY_FOR_FLASH_PHYSICAL_LAB`：另须 ECU/镜像/地址/供电/授权/写后校验/中断恢复等专项设计与验证完成；**仅用户可进行现场验证，完成后由用户确认是否达成**。
不得把 Git Push、Build PASS、Mock 测试、WPF 页面显示当成真实硬件实测。
