# G1-05｜外部接口、连接与业务数据边界（M2 候审）

## 一、接口清单与事实等级

以下是**系统外部接口需求和当前约束**；它们不是最终针脚表或 G2 ICD。具体 USB 命令、GPIO 极性、CAN ID、扫码枪协议、WPF API 由 G0 证据和 G2/G3 设计确定。

| ID | 边界 | 系统需要交换/控制的对象 | 不能预设/待实测 | 来源 | 验证节点 |
|---|---|---|---|---|---|
| IF-01 | PC ↔ 主控 USB | 固件命令/响应、异常与设备身份 | 协议字段、超时和恢复由固件证据/复验确定 | G0-04/07 | B1 |
| IF-02 | 主控 ↔ DUT CAN | DUT 接口 CAN 收发/波特率配置 | 板卡/MCU 通道命名差异；实物接线需确认 | G0-02/07 | B2 |
| IF-03 | 主控 ↔ 按键板 CAN | 按键控制及按键板响应 | 现场使用帧 ID 和通道需要实测 | G0-03/05/07 | B2/B4 |
| IF-04 | 主控 IGN → ECU | 受控点火供电开关 | 初始状态及端子电气测量必须单独确认 | G0-02/04 | B3 |
| IF-05 | 主控 → 电磁阀/夹具 | 夹具动作输出 | 无机械到位传感器，气路/失电行为现场测量 | G0-02/07 | B0/B3 |
| IF-06 | 按键板 → DUT 输入 | 20 路按键、电阻网络信号 | 不视作任意模拟电压发生器 | G0-03/05 | B4 |
| IF-07 | 12V/24V 工位电源 → DUT/板卡 | 不同 ECU 型号的电源需求 | 实际分配/切换/保护待现场核对；不预设软件控制 | G0-01/07 | B0 |
| IF-08 | 扫码设备 → HOST | DUT 实物码字符串/事件 | 未知 HID/串口等物理传输方式，需扫码枪实物与样本 | G0-01/07 | H4 |
| IF-09 | HOST ↔ 测试工程/DBC | 文件读写、信号和资源引用 | 格式/版本/一致性与错误报告待 G2/G3 合同 | G0-06 | H2/H3 |
| IF-10 | HOST ↔ HEX/烧录资料 | 文件身份/地址/分块与实际诊断传输 | 参考程序未提供，本期不定义加密/Seed-Key细节 | 负责人后续资料 | H4 |
| IF-11 | HOST ↔ DUT 诊断 | UDS 与目标 ECU 的服务交互 | 具体服务/超时/负响应/ISO-TP 需要专项研究 | G0-06/研究 | 专项/H4 |
| IF-12 | HOST ↔ 本地记录/统计 | 编号/测试 Run/版本/步骤证据 | 每次运行独立，统计不同 DUT 数与次数 | G1-03 | H4 |

## 二、工程配置与 DUT 身份

工程配置至少需要能够关联 DUT 类型、设备端点、通信/DBC、测试程序、（必要时）烧录资产和结果记录；但该数据应怎样拆文件、编号是否包含型号、扫码后可否允许人工选择工程、同型号是否有多套测试程序，需要真实生产任务与 G2 数据架构研究。扫描输入只提供一个外部标识，必须经历规则检查和可解释的匹配结果，不能把输入事件直接视作允许烧录命令。

## 三、物理安全与接口准入

电磁阀无独立行程反馈，主控命令的成功与机械夹紧不是同一事实。DUT CAN 报文可帮助判断通信但不能泛化为夹具到位证据。对于 12V/24V ECU，必须先证实实际接线及供电选择，不以配置文件单字段当作自动切换能力。USB/CAN 接口必须明确物理板卡映射；旧 HOST 中出现的 `dut.power`、`keypad.power` 角色不是现役硬件功能证据。
