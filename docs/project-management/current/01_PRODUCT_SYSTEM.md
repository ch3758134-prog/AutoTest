# AutoTest｜产品体系、工具和资源的职责边界
**2026-11-21｜USER_CONFIRMED｜适用所有后续需求/UI/源码审查**

## 1. 产品定位
AutoTest 是 Windows 本地离线、WPF/Prism 的通用 ECU 开发调试、自动测试与出厂检测平台。HydEPB 为首例；单 PC/单工位/同时一台 ECU DUT。首先满足工程师能够开发、调试并可靠地执行 ECU 测试方案，同时支持批量出厂的少操作高节拍任务。报告及数据追溯属于正式产品能力，但全面验收仍有缺口。

### 三种工作体系不是父子关系
1. **专业工具**：手动台架、DBC、UDS、烧录、波形等。独立打开、独立完成工作；**无工程亦可使用**。资源按各工具实际需求使用。
2. **自动测试**：对特定 ECU 工程开发 TEST 树、步骤、判定、失败处理，执行单步/单用例/选定范围；不强制生产扫码或生产前置烧录。
3. **生产检测**：在同一软件的独立操作区，借助当前 ECU 工程和已有能力完成扫码、夹具、实体键、每次必烧录、全部自动测试、记录与报告；操作员常规不点击 PC。

**资源是独立概念**：DBC 是报文/信号资源，固件是镜像资源，波形参考/烧录参数/诊断序列是专业资源；自动测试与生产检测只是使用者。ECU 工程为某型号组织其当前生效的资源，并不意味着工具离开工程就不能使用资源。

## 2. 各能力必须保留的产品操作
| 工具/能力 | 无工程可用 | 有工程时 | 不应发生 |
|---|---|---|---|
| 手动台架 | CAN 单次/多个周期报文、完整 8B DATA、KEY_SIM 20 Key、IGN/夹具、CAN RX 日志（按设备能力） | 按需使用当前 DBC 辅助编辑/解码 | DBC 成为报文发送必要条件、手动操作必须从 TEST 启动 |
| DBC | 新建/打开/修改外部文件 | 编辑工程唯一有效 DBC，修改自动保存，失效引用诊断 | 独立工具修改临时文件却暗改生产工程 |
| UDS | 诊断会话/服务序列编辑、交互、NRC 与日志 | 可按需载入通信配置 | 工具必须等待生产编号才能服务 ECU |
| FLASH | 自行配置固件、算法、参数，独立实烧录/日志/进度 | 可主动选择工程资源，但工具设置与生产配置不强制同源 | 继续把导入 CanTool XML 当正式生产配置的唯一入口 |
| WAVE | 按真实可用的 CAN/DBC 信号实时观察多条曲线、分析与采集 | 可保存/使用工程参考波形，TEST 引用进行判定 | 将可视化曲线当成准确判定通过的物理证明 |

界面以现代浅色 Fluent 方向统一控件、信息密度、焦点/缩放与窗口；自动恢复上次工作环境。专业工具可在主窗拥有的独立窗口中使用，主窗退出时统一关闭，不留孤立进程；**窗口独立**与**硬件并发写入**是不同问题，后者由设备会话和真实安全事实单独约束。

## 3. 底层复用与职责
| 领域 | 单一事实来源 | 不要重复 |
|---|---|---|
| DEVICE/HW | 主控 USB、双 CAN、KEY/IGN/夹具、唯一真实设备会话 | 由工具/TEST/Production 各自重新实现实体控制 |
| DBC/CAN | 真实报文与信号定义及运行快照 | 各页面重写解析、或把发送 ACK 当 ECU 回复 |
| UDS/FLASH | 已验证 CanTool 参考 ISO-TP/诊断/Seed-Key/下载逻辑 | 独立工具、TEST、生产分别造协议栈 |
| TEST | 一套 StepNode/PlanCompiler/RealRunCoordinator 语义 | 生产另造测试脚本语言或模拟执行器 |
| RECORD | 同源原始数据、运行事实、测量、报告索引 | UI 拼日志文字当作正式 ECU PASS |
| PROJECT | 工程组织、资源身份、自动保存/恢复、执行快照 | 强迫工具依赖项目或为扫码反复选择生产用文件 |
| Production/SCAN | 工位业务状态、ECU 身份与跨工程查找、自动化顺序 | 重新定义 CAN/UDS/TEST 执行语义 |

## 4. 开发/生产边界
- 开发可以在无扫码/生产流程时单独 TEST 调试，正式生产则不因开发勾选状态改变出厂用例集合。
- 工具操作参数可以临时改变，只有用户明确编辑了工程资源才进入该工程；生产执行必须使用工程确定、开始前可核验的快照。
- 软件展示**命令已发送**、**主控已受理**、**ECU 已回应**、**测试判定 PASS**、**生产检测整体合格**为不同事实。不可相互替代。
- 不以“某项功能代码存在”宣称整个 AutoTest 可上市；Gate 见 [06](06_R1_GAP_AND_ACCEPTANCE.md)。

## 5. UI 两种工作区
**工程师工作区**：工程树、测试步骤树和常驻 Inspector，单击切换、直接编辑、添加步骤先出现再配置、调试与工具无缝切换；能稳定撤销/自动保存/恢复。CAN 数据第一、DBC 辅助。

**生产工作区**：扫码设备/型号/唯一编号、夹具/等待实体启动、烧录/功能测试阶段、醒目 PASS/FAIL、失败原因、当前数量概况与历史直达。正常不依赖鼠标操作；同型号连续扫描不弹窗；跨型号工程切换例外确认。这个工作区仍调用同一底层 TEST/FLASH/RECORD。

## 6. 专项对齐条件
所有专业研究需以这三个体系与通用资源边界为出发点。研究提案可以更成熟，但提出多余产品/配方层级须有明确真实业务需求与用户再次批准。产品不否定将来更多型号、工具与数据能力，但**首版不应为了假想复杂业务牺牲现场可用性**。
