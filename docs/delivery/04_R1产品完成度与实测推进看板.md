## 1. 总体目标和阶段冻结

产品终点为：一个通用 ECU、Windows 离线 R1 IDE，使用已设计的统一主工作台；首个真实 EPB 工件贯通 USB/CAN、UDS、烧录、DBC/波形采集与参考判定、生产扫码匹配、Test 自动执行、SQLite 记录和报告。**UDS 与 Flash 应保持各自独立可实测的专业工作台和物理准入；跑通后才成为同一个 R1 主工作台中的两个专业工具。** 不是一个共用 Mock 页签就证明二者完成。

当前已经确认的物理事实：用户在 2026-11-09 使用现有 DeviceLab 实测 WinUSB 连接成功、CAN1 DUT 接收连续报文，截图中显示 CAN1 已发布 2464 帧且丢帧/DecodeErrors 为 0。**记录为 USB/CAN RX 基础通路经用户实测**，不扩展为 CAN1 TX、ISO-TP、UDS 或 Flash 已 PASS；后续不要求用户重复同一个基础 USB/CAN RX 项目。

**正式业务先后顺序（用户纠正）：**
1. USB/CAN 收发基础（RX 已现场确认；诊断 TX 仍需受控实测）
2. UDS 独立真实只读及会话/诊断；Flash 独立专业流程，在支持的 Bootloader/镜像/安全条件核准后实测，不借 Mock 模型冒充
3. DBC 资源/在线解码 → 波形采集/参考/比较 → **波形判定产生可追溯的真实 Verdict**（DBC 和 Wave 离线功能可与 UDS/Flash 并行）
4. 生产扫码匹配：**必须在波形判定以后**，读取已冻结的设备身份/批次/配方/测试结果及波形 Verdict，再做匹配、复测或阻断；扫码枪键盘输入捕获可先做技术验证，但不得把它等同于正式匹配放行
5. TEST 执行器整合成熟专业动作/条件/判定后进行联合自动出厂测试（保留既有引擎，不重造第二套；以一套可复现完整程序验证）
6. RECORD/报告最后验收：从真实 RunId、StepFact、Verdict、BarcodeMatch、测试次数/不同 ECU 计数生成 SQLite 记录和报告。

**R1 UI 产品设计/视觉/操作与上面各物理专项并行持续实施**。R1 UI 的主工作区必须真正显示专业 View、使用统一工程/Station/Session/Trace、具备可靠导航/标签/布局/焦点/密度；不能以 13 导航项/Mock Tab 代替产品 UI 完成。用户集中实测仅在有可启动且具真实操作内容的候选时进行。

## 3. 下个验收节点及允许的依赖

### C1｜R1 工作台最小可运行
- Codex **仅**拉 PR #16 exact SHA，Build/Test/启动，软件窗口真正打开五个业务 View。失败只回原始错误，主对话归因并精准修复。无需用户重复 USB RX。
- UI 专业修复真实可用性：WaveWorkbenchView `MinWidth=990` 与主窗口中心可用宽度冲突、跨页导航/操作不能丢失输入、右侧 Inspector 与日志面板应可收起/缩放、焦点/键盘状态、比例与文字清晰；不重新研究整体风格。
- 此节点只代表 R1 视图装载、DBC/WAVE Replay/SCAN 输入的**软件验收**，UDS/Flash 明确 `Mock/Replay/Disabled`。

### C2｜UDS Physical 独立测试（可与 C1 并行）
- DEVICE 受控真实 CAN1 TX，UDS 真实 ISO-TP 收发；使用 ECU 已确认 ID/DID 的只读请求，响应、NRC、Timeout、日志均正确；经主对话授权后由用户现场实测。
- 不等待整个 R1 视觉完善，独立专业 UDS 测试可先运行。完成后接回唯一 R1 Host。

### C3｜Flash Physical 独立测试（依赖 C2）
- 主对话从 CanTool 只抽取配置资源与 Bootloader 流程，与真实 ECU 事实匹配；完成镜像/安全访问/传输/校验/掉电恢复预检；用户明确批准物理刷写步骤。
- 不因为 UDS 只读通过就直接允许 0x34/0x36；Flash 专业单独把可见阶段和异常处理做成可测试版，再集成 R1。

### C4｜DBC→WAVE→真实 Verdict（与 C2/C3 并行）
- 同一专业 CAN RX 和正式 DBC，参考保存/读取和差值/阈值判定可操作；输出与信号、时间窗口、缺样、预期/实际关联的 Verdict。
- 不用曲线窗口可打开或仅 Mock 比较冒充用户判定通过。

### C5｜WAVE Verdict→SCAN 匹配→TEST 正式运行
- 在既有工程/Controller 配置下，先取得 Wave Verdict，再执行扫码身份/产品/配方/复测规则匹配；扫码原始输入预先采集不代表正式业务匹配已执行。
- TEST 只按通过的真实专业动作组合自动流程，结束后记录完整 RunId/StepFact，避免重建第二套测试模型。

### C6｜RECORD/报告与最终 R1 操作验收
- 真实业务数据写 SQLite，报告准确呈现 DUT 身份、执行次数/不同 ECU、原始证据与最终判定；用户统一验收。
- G3/G4 档案/原理图与固件源码归档持续由主对话维护，但不能抢占 C1—C4 的实际开发和验证优先级。
