# AutoTest 产品定义与立项说明
**版本：V0.1｜正式批准**

## 一、产品定义

AutoTest 是一套面向不同型号 ECU 的可配置软硬件一体化自动测试系统。它依托真实台架提供外部刺激与响应采集，由上位机组织测试执行、数据分析与结果判定，并集成测试所需的专业工具。

## 二、立项目的

AutoTest 旨在改变原有 ECU 测试依赖分散的手动台架、专用 CAN 软件、诊断与烧录工具，以及人工观察和判断的工作方式。

将外部刺激、ECU 通信及广播解析、响应分析、程序化测试和结果记录组织成统一、可配置、可重复、可追溯的测试过程。

## 三、产品基本性质与范围

1. **软硬件一体化**：产品不仅包含上位机，还包含用于实现台架刺激、通信及响应采集的硬件、固件、工装与必要外设。ECU 是被测对象。
2. **自动测试是核心能力**：通过可配置的外部刺激和响应分析，实现测试过程的自动执行与结果判定。
3. **上位机是核心软件工作环境**：负责测试程序开发、执行、分析及专业工具集成，但不代表产品的全部。
4. **面向不同型号 ECU**：系统需要适应不同被测对象的测试条件、通信资料及测试资源，具体配置机制由后续设计确定。
5. **专业工具开放扩展**：CAN、UDS、烧录、DBC、波形等工具既可独立使用，也可参与自动测试。未来可以根据实际需要集成更多工具。
6. **以真实台架能力为基础**：尽可能模拟适用 ECU 测试所需的外部刺激，但实际覆盖范围和性能需通过后续调查及验证确定。
7. **支持识别与追溯能力的发展**：扫码枪等外设可以集成至系统，外部 ECU 编码方案可以与测试资源配置机制协同设计。

## 四、近期研发目标

优先建立一套能够在真实台架上运行的自动测试上位机，使工程师能够编辑并执行测试程序，完成实际刺激、响应采集、规则判定和运行记录的闭环。

在此基础上，根据实际测试工作不断完善不同 ECU 的资源配置、专业工具协同、扫码、烧录和生产追溯能力。

近期交付目标不构成整个产品能力的上限。

## 五、当前尚不确定的事项

具体使用场景、系统能力分解、软硬件职责、详细硬件接口、不同 ECU 的配置与匹配机制、测试操作流程及 UI 方案，均需要后续依据产品定义、实际工作和工程调查进一步研究。

当前不预先建立固定的使用场景分类，也不直接继承旧项目的技术方案作为新产品设计结论。
