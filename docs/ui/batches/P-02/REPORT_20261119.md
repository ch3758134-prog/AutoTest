# P-02｜应用 Shell 与任务/文档/工具关系

日期：2026-11-19；来源：AutoTest R01～R06、用户批准的 UX-PLAN v0.2；身份：UI/UX 研究、设计和纯 UI 实施。

## L0 场景与问题
此前把工程树、工具入口、文档和工位状态混成一个永久三栏工作台，导致用户不知道当前做什么。

## L1 端到端用户任务
分别研究首次启动、延续工程、开始测试编辑、打开第二个工具、关闭工具回到原任务与异常恢复。区分编辑中的对象与实体目标。

## L2 来源事实 / 研究依据
TIA Portal 区分任务导向和工程深度；Visual Studio 文档与工具窗口有不同生命周期，R02/R03 已给出处和限制。

注意：厂商公开资料证明其存在相应机制，不证明 AutoTest 应机械复制。原始资料见 R01～R06、SOURCE_REGISTER；本篇设计取舍属于 UX 候选。

## L3 对象、命令与交互设计
主窗口是持续工作环境；自动测试工作区占主任务，工程资源/扫码/历史在主导航；DBC/CAN/台架/UDS/Flash/Wave 等有受主窗口管理的副窗口，关闭副窗口不清空 UI 数据。

连续操作脚本：主任务间导航保留 UiSession 对象；相同专业工具重复打开时激活原窗口；主窗口关闭时关闭其拥有的副窗口。

## L4 状态、异常与视觉责任
无工程/空工程与加载失败不自动视为真实项目；窗口最大化使用原生 Windows 行为以避免遮住任务栏。

所有编辑均作用于 UI 会话。任何离线/UNKNOWN 的实物状态不得在界面中呈现为通过。Windows 小屏、高 DPI、焦点/对话框属于最终跨批验收项。
