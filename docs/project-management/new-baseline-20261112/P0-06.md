# AutoTest｜P0-06 质量、验证与评审策略

- **版本**：v0.1｜2026-11-12
- **状态**：候审；尚无 P0 Gate 批准
- **上游**：新基线 P0-01 v0.2、P0-02 v0.1、P0-03 v0.1
- **目的**：保证“已经设计”“源码存在”“用户界面可以打开”“真实 ECU 测试通过”不会被混为同一交付状态。

## 1. 质量目标

AutoTest 的首要质量目标是**在已知配置的真实 ECU 和真实测试硬件上，能够可靠复现测试操作、准确处理测量与判断、保存可追溯证据，并具有工程师实际可用的操作界面**。同时保持跨 ECU 配置、专业工具集成及持续扩展的可靠性。

质量活动围绕真实业务风险安排，不为填满固定表格而开展无效测试。项目负责人负责接受范围、资源和剩余风险；专业角色对技术内容负责；测试执行者提供真实记录；协调者核对一致性和未决问题。

## 2. 证据分级与不得跨级推断

| 层级 | 实际证明 | 明确不能证明 |
| --- | --- | --- |
| 代码/设计存在 | 找到对应文件、接口、版本 | 能运行、满足用户需求 |
| 源码审查 | 指定范围的逻辑、合同和风险经过阅读 | 编译或运行通过 |
| Build | 特定环境与 commit 编译成功 | UI 可用、真实 ECU 安全 |
| 单元/接口测试 | 指定输入输出与异常条件通过 | 真正的硬件刺激与响应 |
| 真实软件操作 | 在精确版本中完成打开、编辑、保存、重开等动作 | ECU 测试结果准确 |
| 台架/真实 ECU 验证 | 在记录的 DUT、设备、固件、工位及条件下完成指定用例 | 其他 ECU/场景自动通过 |
| 跨工具系统验证 | 真实硬件、测试编排、采集、判定、记录协调通过 | 未覆盖功能全部发布合格 |
| 正式验收 | 负责人依据证据接受确定范围和限制 | 尚未测试的功能被自动接受 |

除可充分说明不适用的项目外，**真实 ECU 自动测试闭环不得以 Mock、回放、UI 演示代替物理验证**。过去代码中曾有 `RunCoordinator` 的 MockStation 实现；是否被新接线取代，需在对应源码 HEAD 与台架结果上核查。

## 3. 必要质量活动

- **需求质量**：由真实使用场景出发，要求清晰、可实现、可验证，避免把 EPB 型号、现场通道或未批准的 UI 操作硬编码为通用平台规则。
- **设计质量**：检查跨硬件/设备驱动/工程配置/DBC/测试步骤/专业工具/记录的公共契约；资源生命周期、异常、超时、取消、重连和清理均有责任。
- **软件质量**：执行与风险相称的构建、单元/契约/集成测试，记录实际命令、输入 commit、结果和日志。是否运行 CI 按具体任务和项目要求决定，**不允许不运行却声称 CI 通过**。
- **交互质量**：在正式 WPF 窗口验证中文语义、鼠标和键盘、工程树/编辑器、长内容、DPI、操作反馈、错误恢复；不仅检查静态截图或 HTML 原型。
- **实体质量**：验证真实 USB/双 CAN、IGN、夹具、电阻网络按键模拟和其他已确认能力；按设备的实际可测方式核对操作请求、响应、超时与 ECU 行为，不能把控制器 ACK 简单当成物理结果。
- **结果质量**：测试程序的刺激、采样、时序、变量、判断、清理、RunId 和报告一一对应。新鲜/旧数据、缺报文、解码错误、断连等数据质量需明确处理。

## 4. 重点验证路径

首个近期系统级目标是：创建/打开真实工程 → 配置资源和信号 → 编辑、保存和重新打开测试程序 → 在真实 ECU 上运行 → 获取实际响应 → 判定与停止/清理 → 完整追踪运行结果。

专业工具要分别支持真实可操作的独立验证，还应验证参与自动化测试时与同一工程资源和设备事实一致。生产扫码/自动测试/烧录/报告属于整体产品范围，但应按真实风险和可验证条件逐步扩大覆盖。

## 5. 缺陷与质量问题的处理

发现缺陷时，先保存复现环境和原始数据，区分：产品要求问题、设计问题、实现问题、设备/固件问题、资源配置问题、测试办法问题及尚缺证据。将问题交给适合的责任岗位；修改后按实际影响进行回归。

若存在设备操作或刷写风险、不可恢复数据破坏、未知物理输出或错误放行的可能，**只停止受影响的现场工作或发布**；不应因此阻断无依赖的调查和设计。

## 6. 审查及里程碑决定

每一项成果有自己的审查与批准；阶段 Gate 或发布只有在其适用工作产品、真实配置和未决风险得到评价后才单独决定。负责人可以附限制批准，但必须写明阻断范围和后续证据。

项目质量审查的现实制约：AI 自审不是独立第三方质量审核，当前尚未证明存在外部认证/独立 QA 组织。高风险设计或实机动作按影响程度安排第二视角或真实专业人员评估。

## 7. 本项可批准范围与尚未取得的证据

本项只批准**质量与证据分级、必要验证活动、审查与风险处理原则**。不代表现有软件可编译、工具已完成联调、硬件全能力实测、任何 Gate PASS 或 R1 验收。

真实试验计划、参数、设备安全限制、环境数据、逐条验收用例由后续 G0/G1/G2/G3 及实际现场负责人确定，不能在 P0 从历史报告推断完成。
