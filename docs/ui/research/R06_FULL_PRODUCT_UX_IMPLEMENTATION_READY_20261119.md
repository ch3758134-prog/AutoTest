# R06｜AutoTest 全产品 UX v0.1：从研究到 WPF 实施的准出设计

日期：2026-11-19。身份：UI/UX 专项。状态：RESEARCH_COMPLETE / FIRST_WPF_IMPLEMENTATION_READY / DESIGN_CANDIDATE / USER_OPERATION_NOT_VERIFIED。
研究输入：R01～R05；PM-BUSINESS-DECISIONS-20261114 和更高优先的 PM-INPUT-SEMANTICS-20261114；main 正式 PROJECT/TEST 代码静态核查。
边界：只研究设计，不改 main，不自建 TEST/PROJECT/DEVICE/UDS 业务系统，也不声称实际 Windows 构建或硬件验证通过。

## 1. 全产品模型：一个应用、不同任务的工作环境

- 软件层 Application Shell：当前工程、全局设备状态、工具入口、窗口与后台任务/状态；不把各类对象的编辑命令堆到全局工具栏。
- 自动测试任务：运行当前任务、编辑测试资源、查看真实执行事实与历史证据。用户已经认可运行/编辑两种主任务，但这不要求每种工具也采用同样页签。
- 当前工程资源：工程、测试项目、用例、公共流程、DBC、输入配置、波形、固件与烧录配置、报告引用。树状资源组织不等于全部软件导航。
- 专业工具任务空间：综合手动台架、DBC、UDS、FlashLab、Wave、输入配置、设备诊断、报告；专业工具可用受主窗管理的原生窗口，各自根据专业对象采用合适的编辑形式。
- 生产操作：扫码、工位就绪、受控自动运行、结果与异常；与工程师调试共用真正运行后端，不造第二套执行器。

所有用户操作归入 R04 四种编辑模型 M1 密集表格、M2 持续对象详情、M3 结构/图形流程、M4 编辑与实体执行分离；具体工具按任务组合，不统一成左表中图右属性。

## 2. 主窗口六个可观察工作状态

| 状态 | 软件应该怎样表现 | 禁止行为 |
|---|---|---|
| WS0 无正式工程 | 完整软件可用，近期工程/打开/新建/探索真实编辑能力；适用独立工具可达 | 强制输入工程名才能看测试编辑器 |
| WS1 有工程但无资源 | 清楚说明下一步怎样创建测试项目、用例、导入配置；创建后直接进入编辑区 | 大片空白与所有按钮变灰 |
| WS2 正式工程开发 | 多文件、资源树、搜索、对象编辑、未保存标识、撤销、关联资源 | 选择对象即无意识切换运行目标 |
| WS3 测试准备/运行 | 本次勾选、工位真实状态、预检、步骤事实、停止和报告；Run 输入快照冻结 | 修改草稿改变已经运行的输入 |
| WS4 专业工具调试 | 工具拥有独立编辑/观察上下文，离线编辑与实体输出权限区分 | 打开第二工具抢占硬件、重置第一个工具 |
| WS5 异常/恢复 | 工程不可用、资源冲突、断线、任务失败时说明发生什么与恢复路径 | 静默替换旧工程、设备重连就显示成功 |

优先候选是“同一 Shell 的状态化入口”，不是每次打开独立欢迎页。只有上次工程无效/首次使用才显示开始入口；已有真实工程自动恢复上次测试工作。具体可用性需 Windows 操作验证。

## 3. 全产品工作区和主要操作完整覆盖表

| 工作域 | 核心对象 | 直接操作/编辑 | 主要反馈 | 接线特殊边界 |
|---|---|---|---|---|
| 工程/资源 | 项目、资源、修订、引用 | 搜索/预览/打开/新建/重命名/移动/复制/关联 | 保存、问题、外部冲突 | 正式 ProjectWorkspaceService 单一事实源 |
| 测试项目 | 有序测试用例 + 当次选择 | 添加、排序、勾选、预检、明确运行 | 真实用例进度与结果 | RunSelection ≠ Enabled；批量后端未接不冒充 |
| 测试用例 | Prepare/Test/Cleanup、StepNode | 按类型插入、连续编辑、流程槽/嵌套、复制、撤销、调试 | 依赖/字段错误、真实 RunFact | 唯一 TEST DSL、StepId、步骤真实结构 |
| 公共流程 | 固定修订步骤树 | 创建/插入/编辑/引用/显式版本更新 | 依赖与调用循环错误 | 不生成第二运行器 |
| 综合手动台架 | CAN 待发、工位外部输入/IGN/夹具、CAN 观察 | 直接选报文/改值/配置输入、显式发送、观察真实响应 | 请求、ACK、真实 CAN 和 UNKNOWN 分层 | 是综合刺激与观察，不是 KEY 优先或 EPB 专用 |
| DBC | 报文、信号、枚举、位布局 | 密集直接编辑与专属详情/位视图联动 | 解析、错误字段与正式保存 | 技术合法性完整校验 |
| UDS | 服务请求、可保存序列、会话响应 | 服务选择/参数化/序列增删、调试发送、回填 | NRC、实际响应、时间线 | 复用已存在 UDS/ISO-TP 服务 |
| FlashLab | 固件镜像、Profile、阶段 | 配置、预检、启动、停机/异常查看 | 字节、阶段、ACK、错误审计 | USB 所有权和不可逆行为合同 |
| Wave | 信号、曲线、参考、游标 | 选择信号、放缩/游标/采样、分析、保存参考 | 质量、来源、判定证据 | 曲线主导，不使用通用三栏属性表 |
| 输入配置 | 工程特定外部输入条件与真实硬件组合 | 定义、命名、组合、时序校验 | 合法映射与未知状态 | KEY_SIM 20 内部开关不是 20 个功能按钮 |
| 设备诊断 | 身份、通路、请求/ACK、故障 | 连接、断开、过滤/导出、错误定位 | 实体身份、Generation、UNKNOWN | 没有外部测量不宣称机械/电压已到位 |
| 生产扫码 | DUT 身份、工位条件、工序 | 扫码识别、自动预检与已授权执行、异常处置 | 当前结果、重复与审计 | 不要求每台手点 Run；不能跳过安全门禁 |
| 报告/历史 | Run、Step、附件、原始证据 | 编号/时间/状态查找、过滤、跳到对应步骤和波形 | 冻结的历史事实与报告 | 不受当前草稿改变 |

该表是目标 UI 的完整专业功能设计，不等于后端所有项目均已完成。未接线的实体操作要禁用并说明原因，绝不使用假 ACK、假成功、假日志。

## 4. 完整交互规范

1. 软件级：菜单与工具入口放全局；对象级：高频操作靠近当前对象，右键是补充不是唯一入口。
2. NavigationSelection、EditorSelection、RunSelection、StationTarget、TraceSelection 必须区分。单击选择不意味着执行设备动作或改变运行勾选。
3. 文档可预览/正式打开；再次打开同资源要激活原文档；页签、滚动与选择有状态并能恢复。
4. 高频字段使用 M1 直接可编辑表格，复杂参数使用 M2 专用持续可见详情，结构化对象采用 M3，真实执行采用 M4。禁止只读表格 + 多层编辑弹窗成为默认方式。
5. 典型键鼠：单击选择，F2 改名，Tab/Enter 连续编辑，Esc 取消当前输入，Ctrl+C/V 适用对象复制，Ctrl+Z/Y 撤销本地编辑，右键/Shift+F10 为同对象菜单；真实硬件执行不得默认绑定输入框 Enter。
6. FieldBuffer / ObjectDraft / DocumentTransaction / PersistedResource / ExecutionSnapshot 分层；临时无效输入保留但不能写入正式文件，也不能因未完成字段锁死所有导航。
7. 共享资源改动显式标注版本，不无提示修改另一个工具正在准备执行的输入；已启动 Run 仅使用冻结的输入快照。
8. “问题列表 → 受影响资源 → 精确对象/字段”导航闭环；失败后从历史 Run 返回编辑器时不能更改原历史证据。
9. 长时间作业在 TaskActivityCenter 标明实际阶段、错误、真实可用的暂停/停止能力；取消请求不冒充任务已取消。
10. 不把软件 UI 恢复、正式文件保存和真实实体输出恢复当作同一个命令。

## 5. WPF 组件与服务职责建议（不强制采用这些 C# 类型名）

| 组件 | 用户体验职责 | 禁止越界 |
|---|---|---|
| ApplicationShell | 原生窗口、全局当前工作、Owner、副窗口与关闭管理 | 不创建 DEVICE 第二套连接 |
| TaskWorkspaceHost | 运行、编辑等任务切换且共享当前用例 | 不修改 Run 快照 |
| DocumentHost | 预览页签、编辑页签、激活/脏状态/关闭/恢复 | 不绕过正式 PROJECT 文件保存 |
| ResourceExplorer | 正式工程树、搜索和资源管理 | 不擅自修改临时 Run 勾选 |
| ObjectSelectionService | UI 当前对象身份、关联导航 | 不把当前选择传播为实体输出 |
| ContextCommandService | 命令作用域、菜单/键盘映射、禁用原因 | 不自主获得硬件许可 |
| EditableTable | 行/单元格/批量编辑/焦点/检错 | 不跳过领域合法性 |
| ObjectInspectorHost | 类型特有的真实参数编辑 | 不写第二套 TEST/DBC 模型 |
| StructuredStepsEditor | StepNode 真实流程编辑 | 不重建 TEST DSL/Runner |
| ProblemNavigator | 定位错误的资源/步骤/字段 | 不伪造设备故障 |
| TaskActivityCenter | 背景任务、失败定位、进度与回到任务 | 不伪造真实烧录进度 |
| StationStatusPresenter | 独占所有权和实际事实层级 | 不绕过 DEVICE 权限 |
| SessionRecoveryService | UI 工作状态与适用草稿恢复 | 不恢复执行上次实体操作 |
| ProductVisualTokens | 统一 Fluent Light 文本/间距/状态/密度 | 不靠统一样式掩盖操作差异 |

WPF 技术方向：一个 Prism Shell/Region 生命周期；WPF-UI 4.3.0 Fluent Light 仅用于主题和可用通用控件；定制专业控件依据任务制作，不建第二套全局导航。保留 Windows 原生最大化、任务栏、多屏和高 DPI 适配。

## 6. 真实代码核查：无工程编辑可以做，但旧 VM 无法直接满足

从 main 中已核查：
- HOST/src/AutoTest.Testing/Authoring/TestDocument.cs：真正的 TestDocument.Create(name) 可直接创建具有 Prepare/Test/Cleanup 的正式领域文档；StepNode 稳定 Id/Slots。
- HOST/src/AutoTest.Testing/Authoring/StepEditTransaction.cs：Insert/Copy/Move/Delete/Undo/Redo 完整的正式事务。
- HOST/src/AutoTest.Desktop/Projects/TestEditorSession.cs：现存会话绑定 ProjectId、AssetId、Revision、FileHash，不能用于尚未归档的合法文档。
- HOST/src/AutoTest.Desktop/Testing/TestEditorViewModel.cs：现存 VM 与正式 TestEditorSession/ProjectWorkspaceService/Run 服务耦合；直接照搬旧界面会重新出现必须先建工程的问题。
- HOST/src/AutoTest.Desktop/Projects/ProjectWorkspaceService.cs：正式资源保存有校验、修订和指纹检查；必须保护，不得伪造项目身份绕开它。
- HOST/src/AutoTest.Desktop/Testing/StepUiCatalog.cs：已有不少正式编辑步骤，但若标记执行未接线则不可因新 UI 外观被宣布可真实执行。

因此 UX-I01 必须增加的是**展示层的 Unbound/Bound 编辑会话适配**，实际 TEST 数据永远用 TestDocument 和 StepEditTransaction。未归档会话不能冒充已登记的 PROJECT 资源；归档正式资源要调用/扩展经 PROJECT/TEST 审查的合法 API。

## 7. 建议实施批次与验收门槛

### UX-I01：首先实现能实际试用的全局入口与 TEST 真文档编辑
- 新特性分支从实施时最新 main 创建，研究文档继续只在 ui/ide-design。
- 正式 WPF Shell、WS0/1/2/5 状态、项目树和文档宿主、原生窗口与导航恢复。
- 不新建工程也能进入 TestDocument 正式模型、编辑三阶段步骤/复制/撤销/保存意图；硬件运行禁用。
- 工程已打开时能用正式资源打开/保存并恢复，错误与引用合法性可见。
- 无 fake 测试/设备响应。编译/启动由 Windows Codex 机械执行，用户实际操作 UX 反馈。

### UX-I02：把全产品专业交互实现为可实际操作的 WPF 工作区
- TEST 项目/用例/公共流程、DBC、手动台架、UDS、Wave、Flash、Input、Scan、Records、Device 都按上表各自模型完整设计、实现编辑、选择、状态与跨工具衔接。
- 保留实用的成熟产品交互机制，绝不强制所有工具三栏/只读表+弹窗。
- 真实未接的实体动作标记未接线而不伪造成功。用户在 Windows 完整操作每类工作区，按问题迭代。

### UX-I03：正式业务接线和真实台架验收
- 由 INTEGRATION/PROJECT/TEST/DEVICE 及专业工具根据职责审查接线，保护已验证的实际硬件和数据合同。
- 真 ECU/工位测试、结果/报告与生产流程等由用户现场按正式许可验证。
- 不因 UI 编译成功就标 RUN_FIELD_PASS。

## 8. 以任务为基础的 UX 第一批操作验收

| 编号 | 必须真实操作的任务 | 验收结果 |
|---|---|---|
| A01 | 无工程启动→打开真实 TEST 未归档编辑器 | 不强迫工程名称、无第二 DSL |
| A02 | 插入/复制/移动/撤销多层步骤→切换文件→回来 | 真 StepId 保持、操作恢复 |
| A03 | 创建正式工程→加入合法用例→保存重开 | PROJECT 文件/修订真实可读 |
| A04 | 恢复之前的工作→切运行/编辑 | 当前工程与用例一致，未自动执行 |
| A05 | 字段暂时不完整→切换对象→回来 | 草稿不丢、错误有定位、不能写非法正式值 |
| A06 | 工程移动/资源哈希冲突 | 原路径/真实原因/恢复路径，不能静默覆盖 |
| A07 | 打开两个专业工具并切回主窗口 | 保留选择/窗口位置、不重复 USB 所有权 |
| A08 | 1366x768 / 1920x1080，100/125/150% DPI，多屏移除 | 核心命令可达、任务栏不被遮挡、焦点正确 |
| A09 | 编译/启动后连续操作约百步结构编辑与日志检索 | 不因每次输入重建全部树导致明显卡滞 |
| A10 | 不具备设备或后端权限时点击执行相关区域 | 明确不可用原因、无虚假成功 |

R02 T01～T16、R04 O01～O12、R05 S01～S10 是后续完整产品的回归任务清单，不因第一批仅做入口就删除专业工具范围。

## 9. 研究准出审查

已具备：覆盖全产品的任务架构；跨对象交互合同；统一编辑与保存的层次；真实状态与硬件权限边界；正式领域模型接入锚点；可操作的 WPF 首轮任务与失败判据。

尚未具备：真实 Windows WPF 交互原型、用户操作验收、PROJ/TEST 临时内容归档正式 API 的全部实现、全产品真实后端接线。它们属于后续实现/集成，不构成继续无限研究的理由。

本轮结论：**研究充分到可以开始 UX-I01 代码，但具体 UI 不可直接标最终冻结，也不能在 main 开发。** 当前没有必须先请用户裁定的技术或业务选择；继续用实际操作反馈微调。
