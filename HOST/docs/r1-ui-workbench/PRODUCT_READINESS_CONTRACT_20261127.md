# AutoTest R1｜成熟产品重构：实现范围、设计合同与未完成门槛

日期：2026-11-27（UTC+8）；实施分支：`R1`。不修改 `main`，不建立第二套 TEST 执行器或额外生产配方。

## 目标

AutoTest 是可长期使用的 Windows 离线 ECU 工程开发、专业调试及出厂检测软件，不是开发功能演示程序。完成标准是操作链闭环而非按钮、VM、提交或评分。产品语言以“工程、测试项目、用例、报文、信号、参考波形、公共流程、烧录配置、检测记录”为对象，禁止把开发备注、异常调用栈、兼容实现和空泛校验术语作为常驻正文。

## 固定业务关系

- 一份 ECU 工程对应单一型号和唯一有序 TEST；跨用例 KEY_SIM、IGN、CAN 周期任务及变量按连续运行语义保持，直至显式改变或收尾。
- DBC 是可独立新建/打开/编辑/另存/重命名的标准文件工具；工程绑定一份有效 DBC，引用与文件名分离。
- 标准波形从真实多路同次采集建立，保留原始证据与时间质量；公共流程在 TEST 编辑环境创建并被 TEST 调用，不能当作普通 DBC 文件。
- FLASH 使用工程内部原生配置与 HEX，安全文件固定提供，正式检测每次 FLASH 都在唯一 TEST 前；不放回 TEST 步骤。
- 扫码保留完整原文并匹配整个工程；夹具/实体输入属于工位而非 ECU 资源；正式流程是扫码→工位条件→夹紧→START→FLASH→连续 TEST→RECORD→释放。
- 前台不设置额外的“发布/启用/二次选择测试方案”关卡；冻结、版本核验、烧录规划与互锁属于后台必要校验，不可删除或伪造。

## 正式产品验收表（非已完成清单）

1. **工程基本操作**：新建、打开、恢复、重命名、资源绑定，日常编辑自动保存，关闭重开一致；无需解释性弹窗。
2. **DBC 编辑闭环**：独立文件/工程引用、ID/名称/报文/信号/枚举编辑、Ctrl+Z/Ctrl+Y、批量编辑、保存回读、外部冲突与未知属性无损处理；目前尚有部分受保护操作，不能报完成。
3. **TEST 和公共流程**：同一类型步骤、双击/右键/键盘编辑、断点与单步/用例/范围、复制/引用、运行状态和证据一致；真实连续执行要通过主控/ECU 回归。
4. **波形**：多路实时查看、历史数据、建立标准、工程绑定、时间/采样质量及判定证据；多信号联合自动判定仍需设计、代码和验证。
5. **FLASH**：固件路径、原生配置、实际烧录计划、进度、CAN/UDS 原始证据和失败后未知状态；必须使用真 ECU 复核 HydEPB 特殊工艺。
6. **生产检测**：完整扫码显示、唯一工程命中、物理压紧和停止输入、每次重烧、连续 TEST、单台/批次记录、异常释放；工位接线和 WPF adapter 尚待真实联调。
7. **一致性与故障恢复**：关闭主窗统一收尾、工具窗焦点及生命周期、异步 UI 线程安全、异常日志和用户可执行恢复动作、1366×768/1920×1080 和 DPI 回归。

## 当前验证事实与下一步 Gate

本轮实际完成的是 GitHub `R1` 源码提交、提交 diff 回读、四个受改动的 XAML 界面标记栈/事件入口静态检查。**没有** Windows .NET/WPF 编译、自动化测试执行、可发布 EXE 或真实 USB/ECU/夹具验收证据。不得把源码检查写成 PASS。

下一次 Windows 本机工作只执行：拉取最新 R1 → Release 编译 → 启动 → 完整保存/撤销/DBC 原文保护回读 → 真实设备工位回归。若失败提供完整诊断日志，由 R1 代码实施过程修复；不让本机 Codex 擅自改业务源码。之后继续完成上述未闭环模块，而非为每个新增按钮单独宣布交付。
