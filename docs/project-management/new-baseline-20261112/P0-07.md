# AutoTest｜P0-07 工具、研发环境与可复现性管理

- **版本**：v0.1｜2026-11-12
- **状态**：候审；环境事实为本轮可核对范围，不代表本地设备已复验
- **上游**：新基线 P0-01 v0.2、P0-02 v0.1、P0-03 v0.1
- **目标**：使工程设计、源码、设备固件、运行证据及管理文档能够确定版本并复现。

## 1. 当前可以据实确认的技术背景

AutoTest 为离线 Windows ECU 软硬件测试系统；主机软件采用 C#、WPF、Prism。GitHub `main` 存在 `AutoTest.sln`、`src/AutoTest.Desktop/`、设备、工程、测试、专业工具和记录领域源码。仓库的 `global.json` 要求 .NET SDK `10.0.400`，并指定补丁滚动策略。

管理系统以同仓库 `tools/project-control-v2/` 的 Project Control 4.6.1 候选实现作为方法与工作台来源，**工具版本并非 AutoTest 产品版本**。目前不把旧 SAEF 本地目录或过时 Python/Keil/IDE 描述当成当前环境已经安装并验证的证据。

`main` 已有相关 WPF 与业务源码，但**当前具体 HEAD 上的 Windows 编译、完整业务操作以及实体 ECU 自动测试均需独立确认**。`local` 分支持续开发，其 HEAD 和可运行状态不能从此前一次调查永久固定。

## 2. 受控环境清单

建立并维护与实际可运行成果关联的环境清单，至少记录：

| 环境 | 应登记内容 | 当前证据与限制 |
| --- | --- | --- |
| HOST | Windows 版本/架构、.NET SDK、NuGet 依赖、Prism、构建配置、Git commit | `global.json` SDK 10.0.400 可直接核对；本机组合待验证 |
| 管理与交付 | GitHub 仓库、main commit、管理系统版本、受控批准记录 | 文档及源码在线可核；完整可信审批服务未部署证明 |
| 主控固件 | 工程、编译器、构建参数、映像、板卡型号及实装版本 | 历史工程有来源；现役烧录一致性待现场核对 |
| 按键板固件 | 工程、编译器、引脚/协议/电压通道相关版本、实际映像 | 具体版本待现场核对 |
| 工位/仪器 | USB/双 CAN、供电、IGN、夹具、按键网络、线束、扫码枪、DUT 型号 | 有历史运行线索；当前完整配置需 G0 复验 |
| 专业工具 | 所调用驱动、工具/库版本、通信配置、必要许可证与外部资料 | 逐工具在真实接入任务中补证 |

环境身份以实际读取和工具输出为准，不能从设计文档猜测 DLL、固件或实物状态。

## 3. 构建与验证动作必须有实际执行范围

常规的只读/低风险工程检查可采用 `git rev-parse HEAD`、`git status --short`、`dotnet --info` 等命令。正式构建命令由对应软件工作包核对解决方案和依赖后指定；典型 .NET Build/Test 只是可选执行方法，**运行之前不得写入 PASS**。

当前负责人要求减少不必要的远端 CI 和长期编译环节，应把研发文档检查与源码验证分开：纯 Markdown 政策归档无须假装完成 WPF 编译；代码实施必须按其真实风险和交付条件进行必要构建/测试，允许在负责人指定的本地 Windows 环境执行。

任何真实 USB/CAN 操作、IGN/电源/夹具/按键动作、UDS 或烧录都必须先核对台架状态和相应执行许可；不得因为软件启动就自动上电、动作或刷写。

## 4. 可复现交付的最低条件

- **管理文件**：能在 GitHub 读取确切文件、内容和批准边界；变更保留版本历史。
- **软件源码**：可指向准确的 commit、依赖与构建命令，并取得原始退出码和日志。
- **实际设备**：可识别板卡、固件、连接与供电配置；真实实验留出预期、实际、异常和操作人记录。
- **测试资源**：工程/DBC/测试程序/控制器配置/波形/HEX 等各自版本可追踪，与 RunId 的实际输入相连。
- **离线工作**：不依赖临时网页服务进行现场正常测试；第三方依赖/安装资源如为运行必要条件须有可用离线方案。

## 5. 环境变更和失效处理

SDK、编译器、设备固件、驱动、依赖、DBC 等变化时，先判断影响范围；仅对受到影响的构建、测试、实测和历史数据兼容性安排复核。遇到无法再现原始环境时，明确列出缺口和替代验证方案，不将旧报告改写为当前通过。

不在本项指定个人 Windows 目录为固定生产路径，不授权重装 SDK、不进行固件升级、不改变当前两板 PCB 或供电线路。

## 6. 接受边界

批准本项仅确立**环境识别、版本固定、离线约束、构建/验证证据和复现原则**；不代表已安装所有工具、真实硬件联通成功或任何代码已通过测试。详细环境清单在 G0 和具体实施工作包中逐步落实。
