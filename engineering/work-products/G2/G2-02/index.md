# G2-02｜系统职责、能力与公共入口（架构候审 v0.7）

## 架构不变量

**每个物理副作用只能由拥有对应设备能力的层实际执行；任何 UI、测试节点、独立专业工具都不能直接拥有 USB 句柄。**

| 能力 | 真实执行主体 | HOST 中唯一逻辑所有者 | 谁调用 | 关键验证 |
|---|---|---|---|---|
| 主控 USB | 主控固件+USB电路 | `A-SESSION` | Station / 诊断工具 | B1、断连/旧回应 |
| DUT/按键双 CAN | 主控物理通路+两固件 | `A-STATION / A-CAN` | CAN/DBC/UDS/波形/运行 | B2、通道角色 |
| IGN | MCU GPIO→高边电路→DUT | `A-STATION` | 设备诊断或测试步骤 | B0/B3，设备ACK≠电气证实 |
| 电磁阀/夹具 | 主控输出→气路/机构 | `A-STATION` | 诊断或测试步骤 | B0/B3，无到位反馈 |
| 按键模拟 | 主控 CAN→按键固件→电阻网络 | `A-STATION` | 手动工具/测试步骤 | B4，逐路电气证据 |
| 工程与 DBC | PC 文件与解码软件 | `B-PROJECT / B-DBC` | UI/编译器/专业工具 | 保存重开、样帧解码 |
| 测试程序 | PC 编辑文档、编译及运行 | `C-AUTHOR / C-RUNTIME` | UI、研发及生产作业 | Mock→H3 |
| 扫码与匹配 | PC USB 输入+本地规则 | `E-SCAN` | 生产协调 / 独立探针 | 真扫码/冲突负测 |
| UDS、波形、烧录 | PC 协议/算法通过 CAN 通路调用 ECU | `E-UDS/E-WAVE/E-FLASH` | 独立工具、测试步骤、生产协同 | 协议仿真与分阶段实机 |
| 历史/统计 | PC 本地持久化 | `R-RECORD` | 测试/生产/报告 UI | RunID、重复复测 |

## 调用方向

`View/ViewModel → ApplicationCommand → 领域服务 → Station/专业服务 → DeviceSession`。接收数据方向则是 `主控 USB → CAN Rx Hub → 订阅者（DBC、UDS、波形、日志、Run）`。记录服务通过结构化事实订阅或受控 API 接收数据，不反向操作 DUT。

## 两种操作入口而不是两套核心

研发工作台、设备诊断、CAN/UDS/烧录/波形工具和生产作业可以拥有不同窗口，但使用同一资源、设备与记录层。默认窗口与导航安排由真实 WPF 使用评估决定。**可以共享观测，但向 DUT 发送诊断/刷写命令必须根据资源仲裁。**

## G3 接收

每个模块唯一责任、输入/输出以及 `tables/ARCHITECTURE_MODULES.csv`；G3 可以决定程序集划分，不可以未经架构变更让业务 UI 直接操作低层协议字节。
