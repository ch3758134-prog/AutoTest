## L0 用户场景与设计问题
工程师编写 IF/ELSE、WHEN、SWITCH、LOOP、TRY/CATCH/FINALLY 和可复用公共流程，不能让嵌套步骤的编辑变成多层对话框。

## L1 成熟产品研究与既有证据
NI TestStand 支持不同步骤类型、序列调用和独立属性；R04 的结构化编辑模型要求分支清楚、移动与撤销可预测。https://www.ni.com/en/support/documentation/supplemental/06/a-guide-to-developing-effective--maintainable-teststand-sequence.html

上述只说明厂商存在相应机制，不证明该布局对 AutoTest 已经最佳。对应 R01~R06 研究/用户明确要求为直接设计输入。

## L2-L4 对象、操作、界面和状态设计
流程控制类型拥有明确的分支词汇：THEN/ELSE、CASE/DEFAULT、BODY、TRY/CATCH/FINALLY；子步骤单独插入并标记所属分支。公共流程用独立连续树编辑，不是一行纯文字引用。

**连续操作验收脚本：** 添加 IF → 编辑条件 → 选择 THEN 插入动作 → ELSE 插入等待 → 复制 IF 子树 → 创建公共流程 → 嵌套子步骤 → 在测试用例中选择公共流程。

**异常及可信状态：** 公共流程仅保存本地 UI 会话，不伪造版本固定、依赖图验证或实际调用执行。不存在公共流程不能假装已经引用成功。
