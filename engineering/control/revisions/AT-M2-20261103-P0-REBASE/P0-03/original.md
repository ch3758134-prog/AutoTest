# P0-03｜AutoTest 角色授权与质量独立性

> **工作产品**：SAEF v2.0 · `P0-03` · v001 · 候审  
> **合同目标**：明确审批者、设计者、执行者和证据职责。  
> **批准范围**：仅批准职责分配和授权边界；不批准具体技术方案、测试结果、P0 Gate 或任何编码/实物操作。实际状态只由 SAEF 工作产品登记表及负责人决定记录维护。

## 一、目的与适用范围

本文件针对 AutoTest 的**项目负责人 + ChatGPT 技术总控 + Codex 本地机械执行**的协作方式，明确谁提出工作成果、谁形成审查建议、谁实际执行、谁依据何种证据作出批准。适用于 P0—G5 的工程工作产品、变更、构建、验证和正式基线活动。

**质量独立性的实际含义**：本项目没有另设一个真实的独立 QA 部门。ChatGPT 的技术自审不属于独立第三方审核，Codex 的执行结果也不自动构成验收结论。本项目通过**独立保存的原始证据、可复核的检查结果和负责人独立批准决定**保持控制边界。高风险事项是否需要另外邀请真实专业人员复核，由对应风险评审决定；不能虚称已有独立审查。

## 二、责任与权限

| 职责主体 | 职责及可作决定 | 不拥有的权限 |
|---|---|---|
| **项目负责人（Authority）** | 确定产品范围与重要取舍；确认现场事实和可接受风险；**唯一批准**工作产品、Gate、重大变更、受控实施和有风险的现场操作；有权退回交付 | 不能用批准某份文档来替代尚未取得的构建、测试或实测证据 |
| **ChatGPT（Engineering Author / Technical Review）** | 项目推进计划、工程研究、方案设计、文档/源码和测试设计、交付包、技术自审、证据审查、提出批准建议与 Codex 精确指令；收到执行报告后判断是否符合交付合同 | 不能替负责人签署批准、伪造测试结果、自动提升 Gate，不能将自身技术自审标为独立第三方 QA |
| **Codex（Execution Operator）** | 在明确授权范围内原样应用文件、运行指定命令、执行批准的构建/检查、记录输出、生成只读网页、按单独授权进行本地 Git 归档，保留原始错误 | 不能自行设计、选型、修改方案、修复源码、扩大文件范围、编造审批记录、批准工作产品/Gate、擅自操作真实硬件 |
| **客观证据与检查机制（非人员角色）** | SAEF 文件哈希/状态检查、构建退出码、测试日志、实物测量、版本清单等为评审提供可复核依据 | 工具的 PASS 只证明其实际检查过的事项；不具备审批权，也不自动证明功能或质量达标 |

### 关键活动的责任归属

| 活动 | 编制 / 组织 / 操作 | 证据或审查 | 最终决定 |
|---|---|---|---|
| 需求、架构、技术合同及工作产品交付 | ChatGPT 编制、技术自审 | 引用原始依据、列出偏差与限制；自审不得冒充独立审查 | 项目负责人接受、退回或附限制批准 |
| 交付文件应用、归档、网页生成 | Codex 仅按 ChatGPT 编写且经批准的指令操作 | 哈希、命令输出、变更清单及归档回执 | 负责人授权；ChatGPT 对回传记录作技术核查 |
| 构建、单元/接口测试和分析 | ChatGPT 制订判据，Codex 运行明确获准的自动命令 | 真实退出码、日志、输入/预期/实际、适用配置 | 项目负责人依据证据批准对应工作产品或阶段；不能由操作人自批 |
| 实际工位、DUT、电源、气路等现场验证 | ChatGPT 制订验证要求；现场人员由负责人安排或授权 | 环境、版本、测量和原始观察由实际执行方记录；ChatGPT 可分析 | 项目负责人批准实际操作和验收结论 |
| ADR / 变更 / Gate / 发布 | ChatGPT 形成技术建议及影响分析 | 关联配置、差异、风险及验证证据 | **项目负责人唯一批准**；Codex 仅执行登记 |

> **边界说明**：同一人可以承担多种工程工作，但“形成建议”“执行检查”“取得证据”“作出批准”必须在记录中分别标识。审批者也必须明确实际证据是否足够，不得把自己对预期结果的判断写成已验证事实。

## 三、执行规则

1. **交付与审批分离**：ChatGPT 交付工作产品及技术自审报告 → 负责人明确批准/退回 → ChatGPT 发出对应的 Codex 执行指令 → Codex 回传原始结果 → ChatGPT 复核；工作产品接受不等于 Gate 通过。
2. **执行与技术决策分离**：Codex 只执行已明确的目标路径、命令、输入版本及停止条件；发现未授权差异、脚本失败、哈希不符或需要设计判断时停止，不作自主修复。
3. **审查与客观证据分离**：ChatGPT 可检查自己编制的文件，但审查报告必须注明“交付方技术自审”。`SAEF check PASS`、成功生成 HTML、编译成功、自动测试通过、真实台架通过和负责人批准是不同的事实，不得互相代替。
4. **现场授权独立**：只有负责人可以授权人员执行真实设备操作。文件批准、测试设计完成或软件可运行均不等于真实硬件操作获准；安全及技术前提由后续适用工作产品规定。
5. **已批准内容受控**：不能擅自覆盖已接受文档、冻结资产、决定记录或改变 Gate；实质性变更通过对应变更和影响评审进入批准流程。

## 四、记录与例外处理

每项活动至少保存能回答以下问题的原始记录（实际字段和路径由 P0-04、P0-05、P0-06 规范）：

| 对象 | 必要记录内容 | 保管责任 |
|---|---|---|
| 工作产品及其审查 | ID、文件版本/哈希、编制与技术自审结论、证据引用、负责人审批决定 | ChatGPT 编制；Codex 根据批准指令受控登记 |
| 执行活动 | 执行指令版本、输入配置、实际命令和退出码、修改清单、错误日志与备份记录 | Codex 保留原始输出；ChatGPT 复核 |
| 验证结论 | 测试对象及配置、预期/实际、证据来源、已通过/失败/未执行的明确区分 | 实际执行者取证；ChatGPT 分析；负责人接受相关结论 |
| 越权、缺证或异议 | 问题、影响范围、阻断动作、补证/变更责任、最终决定 | ChatGPT 汇总，负责人裁决；Codex 停止相关操作 |

**例外原则**：人员不足不构成“已有独立 QA”证明；缺少客观证据时，只能标记未验证或附具体限制，不能用 ChatGPT 自审、Codex 口头结果或负责人批准代替物理测试。必要的额外复核由负责人单独决定。
