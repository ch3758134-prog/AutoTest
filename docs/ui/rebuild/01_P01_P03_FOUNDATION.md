# P-01～P-03｜设计研究与产品共同基础
## P-01｜审查来源/用户意图
证据来源 R01～R06（在 ui/ide-design 分支）。复核得出的高优先事实：原版UI整体废弃；先交完整纯UI再接真实业务；研究/设计/编码分批留档但不让用户每轮验收；AutoTest为工业级离线 Windows 软件；自动测试是核心任务，生产扫码有不同工作重心，其他专业工具独立可达。
R01 六系统：工作空间、对象、命令、上下文、状态、恢复。R02~R05 是 UX 候选和一手厂商机制研究，不等于实际 Windows 用户已验。R06 目标覆盖工程、TEST、公共流程、DBC、CAN、手动台架、输入、UDS、Flash、波形、生产、设备、历史。R06 中以 HOST 服务接线推进的旧 UX-I01 技术合同已被本轮用户“先纯UI”决策替换。
## P-02｜产品交互组织
全局：一套 Shell、当前工作任务、原生文档、独立专业工具窗、全局工作状态。入口按会话状态，不强迫先创建工程。工程资源树只负责资源导航，不承担产品所有功能。
用户选择分类：导航选择、编辑选择、本次运行选择、工位目标、证据选择必须区分。此轮仅验证界面交互，工位/运行事实不实现。
自动测试：测试项目/用例/公共流程同一工作族，编辑、准备/运行观察在不同任务焦点，三阶段编辑、变量和分支可直达。
专业：DBC 密集表格与信号详情；CAN 可编辑多行发送清单并独立观察；手动台架综合激励与观察；UDS 请求序列与响应；Flash 专业流程；Wave 曲线/游标；生产扫码低交互负担；报告历史检索/追溯。
## P-03｜共性视觉与交互
浅色高信息密度，原生 Windows 最大化和任务栏；严守输入可读性，屏宽变小时以可滚动/可收起机制保障主操作。全局导航显式、工具副窗口 Owner 生命周期。
命令：单击选择、双击打开/聚焦，右键是补充，F2 重命名，Ctrl+S 存纯 UI 草稿，Ctrl+Z/Y 编辑撤销重做；设备物理执行按钮需禁用并注明原因，不在 UI 中用模拟数字制造成功。
视觉：中性灰白底 + 蓝色强调；主要编辑面充分利用屏幕，弱化无关装饰。每种工具独立布局但字体、控件、反馈一致。
## 排除边界
现阶段不实现真实工程/DBC/TEST持久化协议，不与后端同名对象/真实ID混用；允许设计态 UI 草稿、手动输入的步骤/配置，但必须全程标记“仅 UI 草稿”。
