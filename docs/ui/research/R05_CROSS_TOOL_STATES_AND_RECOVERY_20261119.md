# R05｜跨工作区协作、长任务、状态可信性与异常恢复研究

**日期：2026-11-19**。状态：RESEARCH_COMPLETE / RUNTIME_UX_CONTRACT_CANDIDATE / PHYSICAL_VERIFICATION_NOT_RUN。R05 承接 R02 五上下文、R04 对象命令规范；只设计 UI 合同，绝不扩权真实设备。已读 PM-BIZ-20261114-01 与 PM-INPUT-SEMANTICS-20261114（纠正“通用台架按键优先”错误）。

| Microsoft Windows 进度控件：可计量/不可计量区分，必要时文字说明、取消/停止含义明确 | E41 | 通用 Task Center 保存任务身份、状态、进度、错误、输出位置；不能凭空填百分比 |

## 2. 统一跨工具事件模型（展示端适配，不新建业务事件真相）

以以下映射为 UI 层事件类型示意，物理意义从 TEST/DEVICE/RECORD 实际合同读取：

| UI 事实事件 | 必备身份/关联 | 展示与行为 |
|---|---|---|
| ResourceSelected / EditorFocused | ProjectId, ResourceId, Revision, EditorId | 只变当前选择，不修改 Run/工位 |
| DraftChanged / ValidationResult | EditorId, ObjectId, FieldId, DraftRevision | 标记局部脏状态、错误计数；保持焦点和撤销能力 |
| ResourceSaved / ResourceChangedOutside | ResourceId, Revision, Fingerprint | 保存结果/外部变更提示，冲突时提供差异选择，不能无提示替换 |
| DeviceConnection / LeaseChanged | DeviceIdentity, BusRole, Owner, Generation | 区分未连接/可用/被占用/未知，写入命令按真实权限禁用 |
| OperatorCommandRequested / AckObserved | OperationId, RequestId, DeviceIdentity | 请求和设备 ACK 为两条事实；除非有依据，不宣称目标物理到位 |
| EcuResponseObserved / MeasurementObserved | CorrelationId, Timestamp, RawData, Source | 真实 ECU 总线或测量证据，与 USB ACK 和判定分离 |
| RunStarted / StepFact / RunEnded | RunId, OccurrenceId, StepId, SnapshotRevision | 只显示真实执行事件；来自后端的事实不能被 UI 伪造或回写 |
| ReportPublished | RunId, ReportId, ArtifactRevision | 记录可打开、可导出、不可被当前草稿静默篡改 |
| BackgroundTaskProgress / CancelOutcome | TaskId, Stage, Error, Percent(optional) | 只有可计算百分比才显示进度条百分比，取消请求不等于完成取消 |

仅用已有正式后台数据为 UI 字段赋值；字段未提供时显示“未知/未提供”，不要凭空设定 ID 或产生假事件。UI 层可定义仅用于视图的定位关联，不作为正式报告或设备执行事实源。

## 3. 全应用后台任务中心（候选）

**为什么需要**：长时间数据导入、DBC 校验、报告导出、日志查询、固件烧录等任务持续运行时，用户往往仍需操作其他无关编辑任务。明确区分：
- UI 可后台继续的纯计算/读取任务：进度条或阶段/旋转、任务中心可回到任务详情；关闭窗口时按任务生命周期处理。
- 必须独占硬件的实体动作：即使界面不阻塞，也要保留硬件租约、禁止并发写入、提供确认的停止/异常/恢复语义。
- 非中断操作/不可安全取消的阶段：明确写“当前阶段不可停止”及真实原因，不用假的取消按钮。
- 导入和报告任务的完成结果：提供可点击的目标资源/文件，错误提供具体问题及重试范围。

推荐状态 `Queued / Running / Waiting / CancelRequested / Completed / Failed / Cancelled` 只是 UI 任务状态分类。真正设备状态不得仅靠 `Cancelled` 推导物理安全。

窗口本身可有轻量进行中提醒；任务中心提供一条任务可定位的历史清单；不要把所有后台事件都塞到每个工作区底部。

## 4. 单真实工位的跨工具所有权（不重新定义专业许可）

| 场景 | 应有 UI 行为 | 禁止误导 |
|---|---|---|
| 编辑 TEST 文档、DBC、UDS 请求序列 | 即使 USB 未连接亦可进行离线编辑 | USB 断开=软件全部不可用 |
| 运行中打开手动台架 | 可查看允许范围的实时信息；写入工位的命令禁用并说明“自动测试占用” | 台架工具偷偷抢占工位 |
| FlashLab 准备/实体写入 | 硬件连接/总线所有权只由现役业务合同移交 | 通过开新窗口获得第二个物理会话 |
| 设备掉线/重连 | 明确 DeviceIdentity/Generation 变化，原操作未知时禁止假定已恢复 | 重连后直接把上次 output 识别为已到位 |
| UI 中止真实操作 | 立即显示“正在请求停止”；收到真实确认后再显示停止结果 | 用户点停止按钮=设备绝对已停止 |
| 扫码生产运行 | 工位资格+绑定/编号+预检+自动受控执行 | 不经授权把扫码输入当物理写入许可 |

状态面板不应把“操作已请求、USB 主控 ACK、ECU 报文响应、外部测量、判定通过”画成单个绿色成功。需要在不同视图中相互关联，但保持事实层级。

## 5. 资源变更与长期编辑中的跨窗口同步

- 同一份正式资源 **一份 canonical 版本**，跨编辑器引用同一个稳定身份；每个窗口可保留自己的临时输入与视图状态。
- 已保存的 DBC/配置更新：其他窗口标记“资源有新修订”并提供“查看差异/刷新/保持当前待发快照”策略。不要在用户正准备手动发送时即时无声修改 Data 和信号值。
- 内部未保存修改：其他工具不能当作正式资源已更新；可以明确可见“该资源仍在编辑”，但禁止把脏草稿视为正式可执行配置。
- 已启动 Run 的输入快照保持冻结；运行过程中后续编辑不修改当前 Run 的判定/通路/输入。
- 外部磁盘修改与内部版本冲突：展示冲突目标、原修订、当前草稿和可选处理，失败后保留两边信息。
- 同资源多窗口编辑是否共享一份可写草稿由 PROJECT 服务决定；UI 不应自行制造多个保存副本。

## 6. 失败处理与诊断导航

采用 `问题摘要 → 定位受影响对象 → 查看错误上下文/真实证据 → 修正/重试 → 返回原任务` 的闭环。

具体：
1. 错误位置：字段下方直接给出短说明；对象层错误以问题计数和可导航 Problems 列表呈现；真实设备错误附 Request/ACK/Timeout/Owner/Generation。
2. 每条问题应关联 `ObjectId/FieldId/RunId/StepId` 的适用身份，点击跳到对象并聚焦；不只弹全局 MessageBox。
3. 运行中错误可以打开日志/波形/报告，但不能用最新编辑资源覆盖已有 Run 快照。
4. 失败后可查看“发生了什么、影响了什么、我还能做什么”，同时保留报错原始码与可导出的诊断证据。
5. 未观察到真实结果时显示 `UNKNOWN` 或“暂无证据”，不转换成 PASS/FAIL。

## 7. UI 性能、Windows 可用性与无障碍：硬性设计验收候选

- 文字/行距/对比适于长时间看；不以大面积卡片牺牲数据密度。
- 1366×768 与 1920×1080、100%/125%/150% DPI 下主命令可操作，原生任务栏不被覆盖；多显示器移除后窗口回到可见工作区。
- 主窗、工具窗使用逻辑 Tab 焦点与标准快捷键，Shift+F10/右键一致；自定义控件提供可读名称和焦点状态。
- CAN 实时日志采用有界内存展示和后台/虚拟化滚动策略：暂停显示不等于关闭原始采集，数据丢失/过滤要显示统计而不伪装完整日志。
- WPF DataGrid 避免不受限的 StackPanel 外容器导致虚拟化失效；大日志/步骤切换要避免每次重建所有窗口树。
- UI 更新来自 Dispatcher/只读事件流；绝不在 UI 线程同步跑串口/USB I/O、报告生成或大型文件加载。
- 背景任务、滚动/过滤和拖拽不允许影响真实硬件计时语义；测试时必须有真实硬件独立事件时间戳。

## 8. R05 验收脚本（R06 组合场景需要逐项验证）

| ID | 操作 | 合格行为 | 重大失败 |
|---|---|---|---|
| S01 | 导入资源同时切换编辑器 | 长任务有状态且 UI 可继续正常编辑 | 导入卡死整个窗口 |
| S02 | 打开两个专业窗口引用同一资源 | 资源版本与未保存修改透明 | 未提示就改正在准备发送的数据 |
| S03 | 一次 TEST Run 占用工位时打开台架 | 可查看允许信息，实体写入禁用且解释 | 同时写硬件 |
| S04 | 硬件断连重连 | Identity/Generation/UNKNOWN 正确，原输出不默认已恢复 | 重连即显示物理到位 |
| S05 | 请求停止长实体任务 | 请求中、确认停止、失败/未知分开 | 点击即冒充已停止 |
| S06 | 找到一次失败的步骤与报告 | 从错误跳到原定义、Run 快照、证据；还能返回失败报告 | 当前编辑覆盖历史事实 |
| S07 | 关闭/恢复未保存工作 | 保留本地编辑草稿和真实已保存状态差异 | 恢复草稿假冒正式文件 |
| S08 | 改变窗口 DPI/显示器 | 主要命令、字段、模态窗仍可达 | 超出工作区无法操作 |
| S09 | 大量 CAN RX 行中搜索/滚动 | 有界、可筛选、流畅、无关运行不阻塞 | 大量行造成 UI 卡住、丢帧却不提示 |
| S10 | 报告异步生成 | 跟踪任务、成功可打开、失败有证据 | “生成中”直接变“已成功”而没有文件 |

## 9. 跨专业业务事实核查（不更改原合同）

已读取 PM-BUSINESS-DECISIONS-20261114 和更优先的 PM-INPUT-SEMANTICS-20261114：手动台架是**综合外部条件激励 + DUT 观察**，不是 KEY 优先工具；不硬编码 EPB 的驻车/释放；KEY_SIM 20 路为内部电阻网络；DUT 主电源当前不属于 HOST 控制；自动测试与人工台架不能同时写工位；扫码生产不能假装已经自动执行。本轮 UX 仅组织展示，具体设备许可与硬件安全仍归领域合同。
