## 一、先理解这次决定

用户已经决定现有 G4 因 UI 阻断而阶段性收口，保留已完成的真实功能和部分实测成果。**新的工作不是继续在 G4 分支上小修补丁**，而是专门把 AutoTest 整体 WPF UI 的交互和视觉设计完整实现；**用户在 Windows 上验收整体界面后，再定点接入既有后端**。

- `feature/g4-html-parity-20261115`（本次查到 `ce4dbd4401dac1a98ffa87885865d0b7c174df7f`）仅作为已有实用代码/操作与问题研究来源；**不是本分支父分支，也不准整体盲合并**。
- `ui/ide-design/docs/ui/AutoTest_UI.html`、2026-11-15 冻结自动测试 HTML 与 `docs/ui/UX_DECISIONS.md` 作为历史 UI 研究素材；新的**完整** UI 以用户最新审查和批准的设计修订为最终标准，**不得借“旧冻结 HTML”否决此次已明确授权的完整重设计**。
- 对照旧 WPF 实测调查（`LEGACY-WPF-FACT-INTAKE-20261117.md`）提炼高频编辑操作与数据保护，但不恢复已取消按键配置流程/旧执行器。
- 已批准的公共流程、直接 KEY、真主控 IO/USB 等**业务合同仍有效**。技术/硬件事实不由 UI 团队自行改变。

## 二、完整 UI 研究与实现范围

1. **全局 UI Shell / 现代 WPF 视觉系统**：浅色主题；顶端明确菜单/上下文操作，IDE 工程资源树 + 中间多文档页签/工作区 + 专业操作区域；工作区可恢复、分隔栏可拖动、窗口大小/DPI、滚动/焦点/快捷键、右键菜单、错误/空状态/保存反馈。窗口最大化不得覆盖 Windows 任务栏。
2. **自动 TEST 主线**：打开工程→测试项目→用例/公共流程→准备/测试/清理→添加/拖动/复制/移动/删除/重命名节点→步骤实际参数编辑→保存/关闭/重开；支持就地编辑 + 适用的锚定浮窗 + **测试编辑工作区常驻 Inspector**（不是对所有专业工具强加右侧全局属性区）；明确“编辑完成”“等待真实执行”两种状态。本次操作员临时选测与工程永久 Enabled 不混淆。
3. **手动台架**：三栏工作台方向：**左侧 CAN 发送及编辑**、**中间 20 KEY、IGN、两夹具与连续按键动作**、**右侧 CAN 实时监控/收发日志**。CAN 列表完整 HEX、ID、IDE、DLC、周期、选中状态和多报文管理；DBC 是修改信号的编辑工具，HEX 与信号值双向同步。点击主字段可以直接编辑或弹出就地定位快速浮层，右键打开完整属性；编辑不等于发送。**不把 LED1～LED6 操作硬塞回手动台架主区**；固件拥有该能力不意味着主工作台必须展示。
4. **工程/DBC/CAN 专业工具**：文件树名称和实际资源类型清晰；DBC 原名和中文显示别名分离、按中英文与 CAN ID 查找、信号物理值编辑；CAN 监控当前状态表与完整历史分开；工具窗口不应覆盖主导航树造成大面积无用空白。
5. **UDS/FLASH/WAVE/SCAN 界面体系**：专业工具使用独立的工作台/窗口空间与上下文，UDS/FLASH 承接各自专项已验证的真实操作方式；当前 UI 阶段只建立用户认可的外观、导航、输入/配置/审计交互宿主，**不得假造真实诊断响应、烧录 PASS、波形采样或生产扫码结果**。WAVE/SCAN 详细行为须在其完整专项研究/真实 TEST 集成合同满足后定稿。
6. **共享交互设计**：中文简明命名、真正可编辑的本地结构与持久化、撤销/重做、Tab/鼠标左右键一致性、多字段快速操作、验证错误可定位、关闭窗口前未保存提示、数据不被异常切换丢弃。对于 CAN 发送 GUI：**HEX 为主信息，DBC 信号是编辑/解释手段**。

## 三、“先完成 UI”不是假功能

- 本分支**不向真实 ECU/主控发送命令**，不劫持当前 G4 设备会话，不篡改既有硬件接口。
- 可在本地持久化 UI 工程/文档编辑结果，优先使用现有项目/TEST/DBC 真实模型与 Codec；不得为了容易画图重做第二套 TEST DSL、第二套工程资源格式或无归属的临时“假用例”格式。
- 编辑器真实功能可以验证：新增/改名/勾选/右键/拖拽/多选/复制/撤销/保存/重新打开；**运行、发送、读回、连接等暂不可用的实体动作必须显式禁用或标记未接线**，不能通过虚拟设备成功来应付验收。
- 当有必要通过真实界面展示运行结果区布局时，展示**空状态和接口定义**，不生成看似实测的伪造帧、ACK、波形或生产 PASS。
- 设计/视觉验收与真实设备验收严格分开，未接线不属于 UI 阶段缺陷，但不可在交付说明里称“完整 AutoTest 功能已工作”。

## 四、允许改动与边界

允许在该专项分支重构/替换 UI 私有文件、Shell、导航、View、ViewModel、Styles、Controls、Interaction、UI 适配层，不要为兼容旧 UI 保留无意义的弹层或多个入口。需要读取工程资源时应复用现有有效 Contracts/Codec，保持后端接口隔离。

**禁止**：改 MCU/KEY_SIM 固件、修改业务 CAN 通路、实现新的 USB/UDS/FLASH 后端、直接改共享业务域合同、随意删除已实测有价值的 TEST/DEVICE 源码、修改 `main`。跨专业 API 缺口只给出精确接口/事件/数据请求并由负责专业定点交付。

## 五、分批交付和验收

- **UI-00 设计源对齐**：读取最新用户 UI 研究与历史截图、已批准业务合同，列全页面/窗口/导航、组件、鼠标/键盘操作、数据及状态行为清单；形成可供用户审查的整体 WPF 设计说明（设计未获批准时不可声称“全界面定版”）。
- **UI-01 Shell+共享控件**：可启动 WPF；浅色、高 DPI、最大化正常；工程树与工作区、Tabs/分隔、独立工具窗口的视觉/操作原型可在 Windows 检查。
- **UI-02 自动测试+工程编辑**：WPF 真正可以编辑/保存/重开用例、步骤、公共流程及资源；Inspector、快速浮层和拖拽落点、右键交互可靠。
- **UI-03 手动台架+CAN/DBC**：CAN Data 显示和编辑、周期操作的目标状态编辑与保存、20 KEY 连续动作的编辑、CAN 监控布局及空状态；尚未接入实体发送时不得演示发送成功。
- **UI-04 其它工具+全局统一审查**：UDS/FLASH/WAVE/SCAN 的可用窗口宿主和已确认交互、统一菜单/样式/控件、无截断/溢出/复杂跳转、未连接明确反馈。
- **UI-ACCEPTANCE**：用户拿到真正 WPF EXE 操作全套界面并认可视觉、编辑、工作流；交付界面目录、源码 SHA、Windows 构建/启动日志、问题清单、已完成与未接线区别。
- **BACKEND-WIRING（后阶段）**：UI 经用户验收后才单独批准范围，按专业逐步接线、真实测试和审计。不要提前为了写界面重构现有后端。
