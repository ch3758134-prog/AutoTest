# AutoTest R0-LAB｜05 专业独立实测先行、正式集成后置（2026-11-09）

**优先级**：用户新确认的执行顺序。关联 `SAEF/engineering/decisions/ADR-20261109-SPECIALIST-LAB-FIRST-INTEGRATION-LATER.md`。本文件补充并纠正 `docs/r0-lab/00～03` 中可能被理解成“先统一接线，后专项实测”的流程描述。物理安全门禁和专业代码所有权不变。

## 给所有专业分支的共同指令

**每个分支自己开发完整的专业 UI 和可直接运行的专项实测入口，交用户在本地实际操作与反馈；本专业反复修正并获得用户专项验收后，才考虑接入正式统一 AutoTest 上位机。** 不得把完整 Shell、全局 Prism、唯一集成版 CAN Replay Publisher、正式 Records 端到端装配作为开始所有专业实测的先决条件。

### 专项交付的最低内容
- 自己拥有专业完整 WPF View、ViewModel、操作事件、业务逻辑；有明确可启动方式/独立诊断壳，不要求正式 HOST 多模块装配先成功。
- 能显示原始请求/响应/输入数据、当前资源与版本、开始和结束/耗时、错误阶段和错误码、实际结果与证据来源，并可复制、过滤、导出诊断包。不得只给几个按钮、Mock 演示或 ZIP 源码而宣称用户可实测。
- 有专业自带的最小数据适配装配：Mock / Replay / 受控 Physical，明确哪些可以独立测、哪些需要实际共享基础服务。不得在私有测试装配内另造第二套正式业务核心、第二套协议或绕过 DEVICE 门禁。
- Windows 本地机械 Build/Test/界面启动证据；对用户给出确切启动及操作方法。用户实测结果归原分支闭环，不要求先提交主对话才能修正。
- 交付一页**未来集成接口清单**：View/VM 创建、Port/Backend 契约、参数/错误/数据来源、项目/资源 Revision、Station Session/取消/断线、Trace/证据 ID、DI/导航注册位置。清单是未来集成依据，不代表现在要由 INTEGRATION 先实现全部接线。

### 当前专业的即时调整
- **DEVICE**：独立原始硬件调试 UI 继续实现，用户能单独验证 USB/CAN/受控 KeyMask、日志；它不是正式 BENCH 真实按键 UI。物理命令在各自授权 Gate 内执行。
- **BENCH/UI**：自己完成按 ECU/Profile/Controller 的动态真实按键界面与可运行专项壳；由 PROJECT 已有资产和 DEVICE 受限装配提供最小必要连接。不要因为正式 `ModuleToolsWindow` 当前为占位页而要求用户等待 INTEGRATION；界面不能绕过实际设备权限。
- **PROJECT/DBC**：独立编辑、加载、校验、保存/重开和实时/回放解码专业 UI，供用户独立实测。
- **WAVE**：先独立打开本地 CAN RX 档案，通过现有受控 Replay/DBC 后端提供曲线、原始帧、参考/比较和诊断导出；**正式 HOST 的 Replay Publisher 接线不应卡住独立 Replay 实测**。Live Physical 必须有真实已验证的数据源，否则单列待测。
- **UDS**：独立 Console 的 Mock/Replay/帧级日志/模板操作立即可测；真实只读诊断另从受控 DEVICE Tx/Rx 取得最小连接，在没有权限和真实链路前明确不能实测 Physical。
- **FLASH**：独立镜像/预检/Mock Job/UI/日志可先测；真实擦写仍要求独立的物理安全、ECU/Bootloader 与恢复证据，不因 UI 可运行而开放。
- **SCAN/PRODUCTION**：独立真实扫码枪输入、规则/配方/诊断 UI 可以先做现场验证；正式 TEST/RECORD 生产放行适配后置，Mock Runner 不算真实出厂合格。
- **TEST、RECORD**：专业编辑/执行模拟/记录查询/报告界面分别独立可测；最终完整 RunId/SQLite/Report 及跨模块一致性在后置 INTEGRATION 做联合验证。

### 何时交 INTEGRATION
专业的适用功能在 Windows 启动/操作、所需自动测试及相应真实用户反馈闭环完成，用户明确认可专项行为后，再交专业源码/测试、界面注册方式、未来集成接口清单及实测证据给 INTEGRATION。它仅负责统一宿主、DI/Prism、共享资源/Session 与跨模块适配和回归，不重新设计/编码专业业务 UI。
