# V02-01｜TEST 编辑器操作 × 视觉布局候选比较

日期：2026-11-19　状态：设计候选，未批准，未修改 WPF。
依据：[本批研究](RESEARCH_TEST_EDITOR_20261119.md)、R02/R04/R05、V01 原则。

## 同一套比较任务
- 工作区有 12 个测试用例，当前操作第 3 个；用例含准备、测试、清理与至少 20 个不同类型的步骤。
- 包括 IF/ELSE、循环、WHEN、CAN 判定、UDS、输入动作、公共流程引用、一个未完成的参数和一个定位错误。
- 完整操作：选用例 → 看懂三阶段 → 插入步骤 → 连续编辑 3 个类型不同的步骤 → DBC 引用 → 复制、移动、撤销 → 进入 ELSE 子分支 → 切换用例再回来。
- 所有示例参数仅用于 UI 研究；不推定真实 ECU 信号、时序或参数。

## 候选 A：中央步骤结构 + 右侧常驻属性
- 空间：全局导航可收起；用例导航用窄而足够扫视的区域；步骤树占主要宽度；右侧属性有可调整的最小可读宽度。
- 操作：单击选择步骤 → 右侧立即显示其类型、名称和专用参数；插入/复制/移动/撤销尽量就近且不等权重；右键与快捷键补充。
- 视觉：准备/测试/清理为阶段容器，IF/ELSE 为明确的分支结构；节点显示类型、名称、有效摘要、当前选择和问题状态。
- 优点假设：适合频繁在不同步骤间切换并连续改参数；当前步骤和参数可以同时存在于视野。
- 主要风险：1366×768、150% DPI 时横向竞争显著；用例导航可能必须折叠，属性应可调整宽度；不能把主要步骤区压成窄列。

## 候选 B：中央宽步骤表 + 底部参数工作台
- 空间：主编辑区承担更宽的步骤名称、摘要、期望和问题列；下方分隔区呈现选中步骤的专用参数。
- 操作：选择步骤 → 下方同屏展示参数；键盘在步骤间切换时同步参数工作台；支持下方详情收起/展开。
- 视觉：更适合横向对照大量步骤与参数摘要，不必用过窄的步骤列。
- 优点假设：适合批量审阅、顺序调整、对照长结构与复杂步骤摘要。
- 主要风险：高度被下方参数占用，20+ 步骤时一屏可见行数减少；复杂编辑仍可能需要扩展详情；上下移动视线距离较大。

## 研究比较：推论，非用户实测
| 判断维度 | A 右侧属性 | B 下方参数 |
|---|---|---|
| 连续修改多个步骤 | 候选较优；左右并列 | 候选较弱；上下跳转 |
| 宽步骤表格和摘要对照 | 横向受限 | 候选较优 |
| 小屏高 DPI | 横向压力，需要折叠/调整 | 纵向压力，需要折叠/调整 |
| IF/ELSE 多层结构 | 中间主区需要足够宽 | 中间主区横向更宽 |
| 属性复杂度 | 多组字段需要滚动/折叠 | 可多列，但占用大量高度 |
| 对用户当前截图缺陷的纠正 | 必须保障主编辑区域宽度 | 必须保障主编辑区域高度 |

## 初步建议（未冻结）
优先将 A 作为“连续编写/调试测试步骤”的研究候选，B 作为“长结构浏览与对照”的对照候选。不要以“右侧属性”或“底部工作台”预先锁死全产品布局。先在完整内容与两种屏幕规格下验证，再决定是否需要单一模式、可切换详情位置或其他方案。

## 两套方案共同不可缺少的约束
1. 步骤结构是当前 TEST 编辑任务的视觉中心，禁止中央大面积空白、步骤被压缩到边缘。
2. 选中对象、参数区标题、编辑字段和焦点要可见且联动；无选中时空态准确。
3. 阶段、步骤、子分支、禁用/错误、断点/运行状态必须有不同语义，而非同色小字。
4. 新增是常用主命令；复制/移动/撤销等靠近对象或可预测的次级命令；不能堆一排同权重蓝色按钮。
5. 不同步骤按其类型显示专业参数；无效字段保留草稿，但不能假称正式已保存或硬件已执行。
6. 窄窗口/DPI 下允许辅助导航与详情变化，但不应牺牲主要对象和核心命令。
7. 左键、右键、键盘、菜单的对象与作用域必须一致。
