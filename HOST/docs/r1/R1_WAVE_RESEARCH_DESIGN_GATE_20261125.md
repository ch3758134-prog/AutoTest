## 0. 任务边界

仅现有 R1 分支。先回读 WaveCaptureService、WaveTimeQuality、WaveComparator、ConfiguredWavePort、WaveWorkbenchViewModel、WaveWorkbenchWindow、WaveChartAnalysis 和回归测试，然后对设计独立评分，**设计达 9 分后才实施源码**。不改 main、不新分支、不运行 CI、不在此机器编译、不把源码检查当真机验收。与正式生产夹具/USB 相关的已知未接线条件保持阻断。

## 1. 实际源码盘点与当前评分

- **采集**：来自唯一共享 LiveDbcSignalService，DBC SignalRef 与版本绑定；支持同时观察多个信号，同次采集、60 分钟上限、真实来源时间戳、原始证据 ID、流溢出/断续/混合时钟识别。采集较完整，**7.6/10**。
- **实时/历史波形交互**：多信号 lane、同一时间轴、参考叠加、游标、窗口滑动/缩放、极值保持的显示降采样；真实参考保存需人工确认，显示数据不参与判定。但数据质量和比较模式未让用户明确识别，**7.0/10**。
- **参考与 TEST 绑定**：不可变参考和资产 SHA、DBC 修订匹配、测试前冻结，TEST WaveStart/WaveStop/Compare 分离，避免 UI 操作暗中判定，**8.0/10**。
- **数据质量**：Gap、溢出、时间不单调、时钟源改变、非可信输入拒绝；精密计时可要求硬件同步。但是当前 HostArrival 不能证明 ECU 实际信号电气时序，**7.2/10**。
- **判定核心**：当前比较器只用线性插值，在 DBC 枚举/状态信号跳变间生成原本不存在的中间值；覆盖率/通过率按参考“点数”统计，可能漏检两点之间短促的错误状态；超差时长按整段参考采样间隔累加，边缘有偏差；缺乏明确的连续/离散判据模式，**4.9/10**。
- **独立生产交付**：WAVE 专业模块已有能力，但尚无真机噪声、真实 CAN 间隔、错误帧/波形稳定性验收，也没有正式生产 Inspection 证据准出，**4.8/10**。

**本轮修改前静态综合：6.5/10**（工程研究判断，不是产品可用性测试）。

## 2. 目标模型：一个测量链，两种严格比较语义

### 输入/来源
所有波形都是 **DBC 信号时间序列**，不是模拟示波器采样。采样时刻来自实际接收到的 CAN 帧和解码事件，不得插入假的 65ms 数据点；IEC/示波器式微秒/纳秒性能无法由目前的主控 USB HostArrival 证明。参考须人工确认、版本冻结、保留完整原始样本与证据；界面折线、平滑和极值保存仅为展示。

### 两种明示比较类型

1. **连续数值（Linear）**：适用于电流、电压等随时间连续变化的 DBC 量。参考采样时间轴上做有界线性插值、绝对/相对容差、有限时间对齐和有效覆盖判定。延续旧已发布工程默认行为（不悄悄改变既有判据）。
2. **离散状态（StepHold）**：适用于 `KeyStat`、`Car_State`、枚举位状态、故障状态等。相邻样本之间采用左保持，**绝不产生插值中间值**；比较窗口内取参考和实测状态切换时间的并集，对每个实际观测到的状态片段积分错误持续时间，不能只在参考采样点对齐时判断。明确报告不满足窗口、无观测支持的时间区间和错误时长。严禁默默依据 DBC 信号中文名推断类型。

数据质量的拒绝必须先于比较。越界区间不允许借插值填补，Gap/Overflow/DBCrevision/连接世代变化必须 fail-closed，质量不足返回 **Inconclusive**，信号身份或配置错误返回 Error，而实际观测数值不符才返回 Fail。最大对齐量由已发布配置明确规定，不得通过过宽的时间平移掩盖错误切换。

### UI 与工程配置

- WAVE 工具“参考与比较参数”明确提供 `连续数值 / 离散状态`，在结果里展示当前比较语义；工具的分析不自动编辑 TEST 判定。
- **正式 TEST 使用 WaveSettingsDocument.Comparison 的同一个版本冻结字段**。旧配置没有新字段时保持 `Linear`；需要离散判定的工程师必须明确选择 `StepHold`，保存新资源修订并重新确认绑定，绝不自动把旧配置变成新版本。
- 波形不重新创造采集/数据库格式；比较算法结果继续使用已有 WaveEvidenceDocument，增加的比较模式包含在序列化的完整比较配置中，可重复打开/审计。参考存储中的 SignalRef、Unit 和 DBC SHA 不改。
- 多信号显示仍可在共享 CAN 输入多 lane 查看；离散阶梯仅表示显示模式，**显示样式不隐含判定算法**。

## 4. 精确验收样例（实施前冻结）

- 连续量同源且窗口/质量合格，等值曲线 PASS；错幅值 FAIL；错 DBC 修订 ERROR。
- 离散参考 0→1，实际 0→1：只有在配置允许的时间误差/超差时长内才能 PASS，任何两点间虚构的 0.5 均禁止。
- 离散参考保持 0，实际采样包含短暂 0→1→0：即使所有参考样本时刻实测均为 0，也必须从状态切换并集检测到这次错误；不准 false PASS。
- 离散实际缺少跳变事件、间隔过长、Gap 标记、输入溢出、连接世代变更，必须 INCONCLUSIVE，不得因为左保持自动补齐。
- 最大时间平移受阈值约束，超过量时 FAIL/INCONCLUSIVE 取决于观测覆盖度，不许随机择优。
- 源是 HostArrival 且要求硬件高精度时必须 INCONCLUSIVE；显示阶梯/平滑不能替代正式比较模式。
- 改配置/参考后 TEST 使用冻结版本；旧工程未设置模式时默认 Linear；新版 StepHold 序列化后重读一致。

## 5. 参考与范围限制

NI TestStand 强调测量与分析解耦、严格管理硬件会话；ASAM MDF 把时间通道、原始数据和元数据视为独立可追溯内容。这里只借用设计原则，不声称 AutoTest 已支持 MDF 文件格式。资料：
- https://www.ni.com/en/support/documentation/supplemental/06/a-guide-to-developing-effective--maintainable-teststand-sequence.html
- https://www.ni.com/en/support/documentation/supplemental/08/improving-teststand-system-performance.html
- https://www.asam.net/standards/detail/mdf/

**明确不承诺**：没有独立硬件同步时间戳时的毫秒以下精度、与示波器模拟电压波形同等的高频采样、正式生产 PASS 现场验收。系统当前测量的是 CAN DBC 信号波形，不是五路物理电压信号直接采样。


## 6. 实施后勘误：Linear 模式兼容与旧判定数值并非等价

最初方案提出“不改变旧 Linear 判定”，但实施时发现旧算法只在参考采样时间检查，确实可能对两参考样本间已实测的尖峰误报 PASS。最终实施了针对这个问题的防漏判修复：Linear 名称/阈值/参考绑定保持不变，**数值判定算法已变为双向真实观测节点比较，并使用时间加权与保守超差**。因此这不是旧结果的数值完全兼容；部分已存旧波形的 PASS/FAIL 会改变，必须进行受控重新验证和再批准。当前未完成判定算法版本锁定，正式出厂生产 WAVE 准出继续阻断，不得把原研究评分 9.3 视为已通过实测。完整实施和静态复评见 `R1_CLAMP_WAVE_IMPLEMENTATION_REVIEW_20261125.md`。
