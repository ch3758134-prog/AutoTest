# AutoTest R1｜主控实体 KEY1～KEY3 真实输入监视交接

**协作基线**：固件 `Main_Control`；上位机 `R1`。源码已修改，**未完成 Keil、WPF 编译或真实物理按钮验证**。

## 1. 冻结的硬件身份

| 物理输入 | MCU | TestCtr V1.5 J1 |
|---|---|---|
| KEY1 | PTC7 / U7 Pin79 | C17 |
| KEY2 | PTC6 / U7 Pin78 | C18 |
| KEY3 | PTC5 / U7 Pin77 | C16 |

这些是主控板三个自复位按钮的**输入**。与按键模拟板 KEY_SIM K1～K20（通过 KEY CAN 发送并模拟 ECU 电阻网络）严格区分。未建立 KEY1/2/3 → 启动、停止或夹具动作的任何映射。

## 2. 真实链路

外部电路 → PTC7/6/5 → PORTC 双边沿 IRQ → 中断记标记/MCU DWT Tick → 主循环逐路20ms稳定电平确认 → USB `0x44` 异步事件 → 已有 WinUSB 帧解码/分发 → HardwareConnectionService → 手动台架实时3路显示与事件日志。

- `0x44`：仅 MCU→主机，SEQ=0、STATUS=0，5字节 `[key,level,stable_levels,sequence_lo,sequence_hi]`。
- `0x45`：主机只读空请求，正常应答3字节 `[stable_levels,sequence_lo,sequence_hi]`。主机物理写拦截器仅为该空请求授予只读权限。
- `stable_levels` 的 bit0/1/2 分别对应 KEY1/KEY2/KEY3。序号是 MCU 上电以来16bit稳定变化计数，回绕；USB事件队列存在丢失可能，序号跳跃必须显示告警。
- R1 从现有唯一 WinUSB 会话消费事件，不能绕开物理写隔离，不能另开 USB 接收器或模拟 ACK。
- 连接后查询一次 `0x45` 作为**初始稳定电平基线**。由于用户尚未提供有效高低电平，界面仅展示“初始状态/状态变化”和“疑似按下/疑似松开”，不得将其当作真实按压极性结论。
- 断开与新连接重新置为“未知”，重新查询；不允许用旧状态自动推断松开。
- 旧固件对 `0x45` 返回 ERR_CMD 应明确显示“不支持，请更新固件”，不能合成 KEY 输入事件。

## 3. 现场验证步骤

1. 主控板升级 `Main_Control` 后连接 Windows 上位机，打开 R1 手动台架。
2. 确认“实体按键输入（主控板）”的三个卡片均成功读到电平0/1，状态不再为“未知”。
3. 先观察静止电平，并按住一个实体按钮超过20ms：确认出现一条对应 KEY 的电平变化和事件日志。
4. 持续按住，确认没有不停重复的稳定事件；松开后确认产生对应 KEY 的相反电平变化。
5. 依次单独验证三只实体按钮，记录实物标识→KEY1/2/3；检查同时按下、快速重复、复位、USB断开/重连。
6. 若在按下时电平和初始电平相同，先排查是否在按住时采集了初始基线；完成实测再决定正式按下极性和业务映射。

**验收界限**：界面显示的事件必须由真实固件经 USB 上报，模拟的协议单测不构成硬件验收。首次测试前不要把按钮绑定到正式产线启动/停止逻辑。
