# UDS Lab｜连续交互与受限实体诊断授权提案

状态：\`UDS_PROPOSED / DEVICE_PM_REVIEW_REQUIRED / NOT_PHYSICALLY_ENABLED\`  
范围：AutoTest 独立 \`AutoTest.UdsLab\`；不涉及 FLASH、KEY_SIM、主控固件或 G4 TEST 运行器。

## 1. 用户目标及现有现实

用户主要操作自行创建的诊断操作（读取 DID、DTC、会话、例程等）。UDS SID 是协议能力而非主操作对象。连续交互包括：①持续使用同一 ECU 诊断上下文执行多项操作，②单击顺序执行已选只读操作，③对明确选定的只读数据定期重复读取。

当前 \`WinUsbByteLink.AuthorizeOneCanTransmission\` + \`PhysicalCommandFence\` **每 15 字节 CAN TX USB payload 仅接受一次精确人工输入授权**。CAN 租约仅仲裁总线，不授予实体操作权限。ISO-TP 的请求分帧、流控帧同样需要 CAN TX；逐帧人工确认会损害时序甚至使多帧读失败。UI 不能自动生成并代填现有令牌，也不得以“连接 USB”取代 ECU 诊断会话建立。

## 2. 本次 UDS-L1.2 已完成、并可运行的范围（仍待 Windows 和实机验证）

- 服务选择 + 参数化编辑 + 自动 UDS PDU 组帧，保留自由 HEX 编辑，提供常用子功能中文预设。
- 用户自定义操作/分组，最多 100 项的手动交互清单。支持“下一项”和明确点击后的一轮**有限次**顺序执行。每次等待最终真实 ECU UDS 响应，遇否定响应/预期不符/超时/取消立即停止。
- 单个 DID 的 \`0x22\` 受控重复读取：周期 1000..60000ms，最多 30 次/90 秒，以实际响应结束后间隔计时；**不排队重叠请求**。旧操作清单/周期存储于工作台 JSON，保持 L1 文件格式兼容。
- 记录每次响应、NRC、耗时、原始 USB/CAN 追踪，取消会使受污染 ISO-TP 会话失效，需要重新连接；展示真实租约有效期、ECU 会话“未知”。
- 基础 \`0x19/02\` DTC 列表解析：DTC 24 位编码 + 状态掩码；无 OEM DTC 描述时不自行给故障命名。

**不是**自动 ISO-TP 会话授权，也不是 ECU 诊断会话切换。当前仍要求每一物理 CAN 帧人工确认，因此真实连续读取可能操作繁重或超过 ISO-TP 时限。未能完成 Windows Build/ECU 现场验证前不得标为 FIELD_PASS。

## 3. DEVICE/项目管理待审的最小授权合同

### 3.1 单项只读诊断授权（候选）

用户在 UDS Lab 中明确确认一次**精确的**已解析诊断操作意图，授权对象必须绑定：

- 主控板身份、\`UsbSessionService.Generation\`、CAN 总线 \`BusRole.DutCan\`、物理端口映射以及事务独占 CAN 租约。
- 精确请求/响应 CAN ID、11/29 bit 帧格式、ISO-TP 寻址模式（当前 Normal），请求 UDS PDU 的实际字节与指纹；绝不只按 SID 允许任意 PDU。
- 允许 SID 白名单初始仅 \`0x22\` 单 DID 和经过明确审核的 \`0x19\` 读取子功能；\`0x23\` 内存读取、\`0x2A\` 周期状态订阅均不应作为自动授权默认。
- 单个 UDS exchange 的最大允许物理发送帧数、总长度、绝对截止时间、ResponsePending 上限与流控状态，不因 NRC 0x78 无限续期。
- 操作独立相关 ID、当前状态；无其它总线写入者，停止/取消/断连/错误/到期后自动撤销。

需要上层 UDS 事务与下层 \`PhysicalCommandFence\` 联动，能够证明所写 CAN 数据确实属于**此唯一已授权 UDS PDU**的 SF/FF/CF 帧或为**该请求、该响应 ID**所需的 ISO-TP FC 帧。帧序号、长度、流控和接收端来源均必须验证；仅比对 \`data[1] == SID\` 不能阻止拼接危险请求。

不得在 UDS Lab 自动构造 \`AUTHORIZE CAN TX ...\` 字符串以绕过逐帧人机确认。须由 DEVICE 按硬件合同增加专用、可撤销且审计化的 operation-scope 授权能力。签名/确认内容包含绑定参数及失效条件，只有真实用户在明确的界面中主动批准。

### 3.2 受控连续重复读取（候选）

初期只允许用户选择一个已审核的固定 \`0x22\` DID；显式“开始”后根据周期调度，最多 30 次/90 秒/同一个有效租约。请求按实际发送及最终 ECU 响应串行完成，连续错误或负响应立即停止，用户随时停止。增加 DEVICE 范围授权后，最多允许受限的重复次数和时间；**不得默默自动扩大授权范围**。

### 3.3 诊断会话变更（单独审批）

\`0x10\` 和 \`0x3E\` 是状态相关服务，不能误用当前只读授权。若审批通过，另需精确批准会话子功能（默认/扩展）、当前 ECU/Profile、设备/会话代次、TesterPresent 调度条件与停止撤销机制。ECU 返回 \`0x50\` 才视为“最近确认切换”；USB 连接、发送 ACK、以及超时均不等于会话确认。S3 时长未由 ECU 配置与证据确定时只能显示“未知/可能已失效”，不能宣称保持会话。

所有 \`0x11\` 复位、\`0x14\` 清故障、\`0x27\` 安全访问、\`0x2E\` 写入、\`0x2F\` I/O 控制、\`0x31\` 例程、\`0x34/0x36/0x37\` FLASH 服务继续保持实体阻断。FLASH 继续使用其已验证的独立 OEM 编程业务，不纳入诊断自动授权。

## 4. 审查与验收门槛

DEVICE 与项目管理须批准精确代码变更与物理副作用边界后才能改 \`src/AutoTest.Devices/Usb/PhysicalCommandFence.cs\` 和共享授权 API。

最低真实设备验证：未授权零帧发送；精确请求受限授权；正常 SF 和多帧 FF/CF/FC；NRC 0x78 等待与最终响应；错误 ID/乱序/丢帧/USB 断连；撤销后不可再发送；租约到期不可发送；多操作不交叉；禁止写入/复位/烧录；所有效果未知有证据、不记为 PASS。

UDS 专项仅推进本分支及本专业 UI/诊断业务。Codex 本地只做 Windows Build/启动/收集证据，用户真实 ECU 操作与验收；未经授权不得直接修改 DEVICE 安全门禁或 main。
