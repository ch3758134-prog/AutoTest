**专业分支对话是实现责任人**：读取主对话已批准的设计/精确任务，负责在自身文件范围内编写和提交代码、WPF 专业 UI、自动测试、诊断与实际软件缺陷修正，输出 PR。**不得自行重做系统设计、发明或冻结公共接口、重新划定专业责任、决定整体 UI 或擅改物理门禁。** 发现设计缺口时提交最小决策请求（涉及文件、实际事实、期待行为、候选方案及影响），由主对话决定。专业内已有明确合同的局部实现细节可以自行完成，但不能改变合同语义。

**本地 Codex**：只拉主对话指定 Git 提交，Release Build/Test、启动 WPF/诊断程序并留原始错误证据供用户操作实测，不负责 Git 审查、方案选择、修源码、推送或合并。

## 3. 固件管理路线（本轮不修改固件）

目标 Git 目录（正式固件源码入库之前，均为**规划，不伪造已提交**）：

```text
firmware/
  main-controller/   # EPB_Test_Keil / Project 当前实测固件
  key-simulator/     # KEY_SIM / WS/EPB_EOL 当前实测固件
```

未来每份固件必须记录原始 ZIP SHA-256、项目确切编译入口、工具链/构建目标、有效硬件版本、现场签发版及 Git 对应快照；原始字节和代码受独立变更门禁，禁止在仅开发上位机的本阶段修改或重新刷写固件。源项目附带多个候选工程和生成目录时，只能依据已确认的**现役编译工程**选择，不能把同名目录随意替换。

本仓库目前只含对固件输入的**受控描述和历史资料**，没有承诺已经把二套原始固件 ZIP/源工程上传到 Git；任何“本地删除后仍可完整恢复固件源码”的结论，必须以远端实际存在的文件及 SHA 校验为准。
