# G4｜正式 Controller/KEY_SIM 配置页重构记录

**交付范围：** 仅 `AutoTest.Desktop` 的 Controller 配置前端与纯 UI 投影。不变更 `EcuControlProfile`、`ControllerState`、`HardwareKeyPolicy`、`ControllerEditSession`、USB/CAN/KEY_SIM 固件协议或 TEST 步骤业务模型。

## 修正缘由

通用 `ConfigurationWorkbenchView` 原先把 ECU 功能按键、具体状态、20 Key 电阻开关、目标/识别电压、动作时序共 20+ 配置字段混为逐行文本表单。大量参数需要通过“选择电阻组合”弹窗编辑，五路电压被拆为十五个不连续输入框，当前功能与状态缺乏操作上下文。

## 新交互

1. 工程资产仍在左侧正式项目树；打开 Controller 后左侧子树显示功能和状态，状态有缩进，选择后在中部直接编辑。
2. 配置总览只承担 ECU 身份、KEY_SIM 硬件型号、硬件可用掩码和冲突规则。可用 Key 必须由工程师核实，不从模板假定已通过现场验证。
3. ECU 功能节点用名称及展示属性定义操作；新增功能键仍按正式 `ControllerEditSession.AddController / AddState` 构造，创建的是待保存草稿，不代表物理动作。
4. 单个状态页面直接显示 20 个 Key 开关，可并选、可清空。每个选择写入原有 `Fields["mask"].Value`，而 `ApplyFields()` 仍通过正式 `ControllerState.KeyMask` 校验和保存。未配置硬件可用 Key 时只允许离线编辑；已配置时不允许新选禁止使用的开关。
5. 五路模拟输出作为五行电压编辑表：目标值 / 识别下限 / 识别上限。行编辑直接绑定原有 `ConfigurationField` 对象，`ApplyFields()` 仍创建正式 `VoltageWindow`。没有复制另一个持久化结构。
6. 动作方式使用“短按/瞬时、保持/锁存、弹回指定状态、互斥操作”中文展示，但存储的仍是原 `ControlInteraction` 枚举标识；弹回目标从当前控制器的真实状态列表中选，而不是手工输入 GUID。
7. 时序集中为按下前延迟、短按默认保持、释放后间隔。失效输入仍由正式 `Validate` 拦截。
8. Controller 专业页面隐藏重复“应用参数”按钮，点击“保存配置”自动执行原正式 `ApplyFields()` 和版本化保存；其他工程配置页面仍使用原编辑器。

## 安全与未完成

- 20 Key 是组成五路模拟电压的电阻开关，不是 20 路独立 ECU 数字输入。按下 UI 开关只改变本地配置；**绝不发送 CAN、IGN 或夹具命令**。
- 所有电压为要求/识别区间，并非真实测量值，不承诺 ECU 已识别。实际电压由独立台架验证。
- 本批未增加“按键物理名称”、硬件引脚映射或电压采样输入字段；这属于后续正式产品配置合同研究，不应随便塞入字符串字段。
- 新建尚未确认的硬件可用 Key 策略时，选择器从**全部不选**开始，不再默认把 20 个电阻开关全部标记为已验证可用。状态编辑遇到硬件禁止同时闭合的 Key 组合，会拒绝改写当前草稿。
- 当正式文档自身已经有完整编辑器（如 Controller、DBC）时，IDE Shell 不再留空白的“对象信息”右侧栏；真正提供 InspectorHost 的 TEST/项目编辑器仍保留右栏。
- UI 代码虽已提交，但 **Windows Build、运行截图、真实工程保存/重开回归还未验证**。不得声明 G4 配置页已完成用户验收。

## 集中 Windows 检查

- 打开既有真实 Controller 文件，确认原功能、状态、KeyMask、五路电压无损显示。
- 新增 ECU 功能，选择“按下”，组合选 Key01+Key03，配置 CH1 目标/上下限及保持时间；保存并重新打开，确认值、状态 ID、Revision 正确。
- 未配置和已配置 HardwareKeyPolicy 两种场景，检查不可用 Key 不能作为新组合写入。
- 切换状态时编辑校验失败要阻止切换并显示错误，不可静默丢失草稿。
- SpringReturn 从真实状态名称选择弹回目标，Exclusive 明确要求互斥组；不出现必须输入 GUID 的入口。
- 测试 1366×768 与 1920×1080 的左侧功能列表、20 Key 矩阵、五路电压表和滚动行为。
- 一起验证现有扫码、波形、TCF/TBC、烧录配置视图未被影响。
