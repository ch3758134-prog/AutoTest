# AutoTest｜独立 UI 产品设计重启与交付规划 v1.0

日期：2026-11-21
分支：`ui/research-product-ux-reset-20261121`
来源基线：已获用户认可的 `ui/ux01-02-shell-files-20261120` 浅色视觉方向
阶段：研究与设计规划，**本提交不构成 UI 实现、构建或验收通过**

## 一、纠偏决定

1. R1 是**业务能力、硬件边界、操作需求的参考资料**，不是 UI 视觉和交互模板。不得复制 R1 现有 `TestEditorView` 作为新 UI 成果。
2. UI-01/02 中用户认可的是浅色界面与基本导航的**起点**，不是所有页面已经冻结或功能已可用。
3. UI 研究以独立产品信息架构与任务流程为主线：先设计工作方式，再确定页面布局，再编写 WPF，最后接正式域能力。
4. 正式程序只保留一套 PROJECT/TEST/DEVICE/RECORD 领域模型与执行器。研究工程中的 `UiTestProgram` / `UiWorkspaceFiles` **不得进入正式领域层**。
5. 任何未连接的动作必须明确不可执行或显示真实阻断原因；不得生成虚拟 CAN、USB ACK、UDS 响应、波形或 PASS/FAIL。
6. 已有 `ui/r1-inline-test-acceptance-20261121` / Draft PR #73 仅可借鉴正式验收项目创建方法，不作为 UI 集成合格证据；保持待审，不直接合并 `R1` 或 `main`。

## 二、不可更改的产品边界

- 产品：Windows、WPF/Prism、离线、通用 ECU 测试与开发工具，生产检测首要但不牺牲研发编辑效率。
- 单机单工位；主控 USB → ECU CAN / KEY CAN → 20 Key 电阻网络的 5 路模拟电压输出；硬件通道、USB 指令与安全边界以正式 DEVICE/FW 合同为准。
- 单一主程序、启动恢复上次工程并直接进入测试主工作区，编辑可以自动保存且保证意外切换时不丢草稿。
- 自动测试：**主窗口内嵌文档工作区**，不是独立窗；左侧工程/用例导航，中部步骤树及执行视图，右侧常驻参数，底部观察/日志。
- 工具：统称“**工具**”，独立的 **DBC、UDS、ECU 烧录、波形分析、手动台架** 五种由主窗口 Owner 绑定的 WPF 子窗口；关闭主程序全部关闭，同进程非独立 EXE。
- **不做独立 CAN 工具工作台**；CAN 发送/监视属于手动台架与测试编辑/运行能力。
- UI 颜色与组件：白底/浅色 Fluent 方向，现代、信息密度合理，不使用大片深蓝底、老式控件或不可读灰字。

## 三、正式研究产出（在写 WPF 前）

### D0｜资料和需求抽取（输入归类，不以旧代码决定 UI）
- 用户明确要求清单与操作场景、历史实测反例、否决点。
- 独立梳理资产/工程/测试/运行/扫码/生产/工具的真实操作，逐项标注后端现有、待接、硬件依赖。
- 成熟产品对照矩阵：NI TestStand（步骤+参数+调试）、tracetronic ecu.test（包/项目/配置/执行）、Visual Studio（文档与工具窗/布局记忆）、CANdb++（DBC对象编辑）、NI DIAdem（曲线/游标/分析）；只提炼交互原则，不照抄外观。
- 产物：`01_需求与任务清单.md`、`02_竞品交互决策矩阵.md`、`03_反模式与禁止事项.md`。

### D1｜产品信息架构
- 明确工程、文件资源、测试项目、用例、公共流程、工具、记录与生产操作的导航层级。
- 定义主窗口导航、文档标签、焦点与选择上下文、工具窗口所有权、状态栏、搜索、错误提示、会话恢复规则。
- 标注每项命令的触发位置、对象归属、生命周期和用户反馈。
- 产物：界面地图、窗口清单、状态转换图、数据/命令归属表。

### D2｜全局设计系统及交互规范
- Fluent 浅色颜色令牌/字体/间距/按钮/输入/表格/树/菜单/状态/空态/错误态。
- 分辨率与最小宽度响应，停靠与折叠；禁止工具窗口重复绘制主工程树。
- 统一右键、快捷键、拖动、撤销/重做、保存、未保存告警、导航和回退语义。
- 产物：设计令牌、通用组件、所有状态规格、不可变视觉基线。

### D3｜全部工作流 UI 设计（**全部设计完成后才实施 WPF**）
1. 工程与文件：新建/打开/恢复/自动保存/重命名/移动/版本引用/撤销/删除/资源关联。
2. 工具：先 UI-05，包括 DBC 从零建报文/信号与批量表编辑；UDS 连续服务序列与响应解析；Flash 三文件与真实阶段；波形参考/实测叠加与游标/质量/判定；手动台架 Key 组合、IGN/夹具、CAN 发送与右侧日志。
3. 自动测试编辑 UI-04：用例/准备测试清理/公共流程、步骤选择器/新增后立即编辑、右侧参数、CAN 原始数据优先 + DBC 辅助、流程控制、断点/禁用/状态、步骤内资源引用。
4. 运行与调试 UI-06：步骤/用例/勾选范围运行、预检、单步/跳过/运行到此处、异常/停止/清理、变量/日志/波形/记录/报告关联；与编辑共享当前用例而非独立测试弹窗。
5. 生产/扫码/记录 UI-07：扫码只是 DUT 编号入口，独立配置匹配与重复判定，不阻碍研发调试；测试记录与复测正确统计。
- 产物：各工作流屏幕与交互原型、正常/空态/错误/运行中完整状态、键盘/鼠标操作路径、文案与验收脚本。
- 不允许某工具仅交付“导入文件”空页或把通用三栏模板复制给所有工具。

## 四、实施与集成顺序

### E0：设计审查关口
- D0–D3 形成整体可操作高保真原型，使用同一真实工程语义贯通“工程→编辑→工具→运行→报告”。
- 用户评审**整体体验**；未通过，不在 R1 XAML 上继续堆补丁。

### E1：UI-01/02/03｜主壳与工程管理
- 以认可的浅色外壳为基础建新 UI 层、真实会话、工程树、文档标签、操作入口。
- 通过正式 PROJECT 后端适配；不双写工作区清单。

### E2：UI-05｜五种工具独立工作窗
- WPF Owner 绑定窗口，同进程、多窗口生命周期一致。
- DBC/UDS/FLASH/WAVE/BENCH 界面由任务特点设计，各自接入已有后端；未连接能力显式禁用。
- 不提供独立 CAN 工具，CAN 功能收归手动台架/TEST/观察面板。

### E3：UI-04｜正式 TEST 编辑器
- 以新的设计实现视图和组件，后端用 `TestDocument` / `StepEditTransaction` / 正式存储。
- 禁止沿用 R1 旧 `TestEditorView` 视觉作为交付，亦禁止引入 `UiTestProgram` 第二模型。

### E4：UI-06｜运行与调试
- 与 E3 共享选择与执行上下文；调用真实 R1 执行链，不额外造执行器。
- 严格前置条件、运行边界、真实设备/证据/结果反馈，不用 Mock。

### E5：UI-07｜生产/扫码与记录 + 横向回归
- 输入编号与配置绑定、运行范围、生产统计、历史结果、报告。
- 统一关闭、恢复、布局、配置、权限及异常回归。

## 五、验收工作流而非页面数量

验收工程必须用正式 PROJECT/TEST 资源创建，具有非虚假的报文/信号编辑样本、流程控制样本与 **明确禁用、未绑定实体设备的动作**；不捏造 ECU 期望数据。
- 操作链 A：打开工程→选用例→增加 CAN 步骤→直接改 8/64 字节→可选 DBC 辅助→保存→重开→内容一致。
- B：创建公共流程→引用→编辑/撤销→固定修订变化提示→预检。
- C：运行单步/用例/勾选范围→真实预检与阻断→运行日志/步骤状态/证据的正确关联（需接硬件时据实说明）。
- D：DBC 从零创建报文→批量改信号→引用到测试步骤；直接编辑而不是只导入。
- E：UDS 连续服务序列，保存配置，打开后继续编辑；不显示假响应。
- F：波形真实参考/测量数据叠加、放缩与游标、容差/覆盖率等判定配置；数据不足时清晰呈现“无法判定”而非 PASS。
- G：手动台架 20 Key + 保持时间、IGN、夹具、多个 CAN 周期发送与右侧日志；窗口关闭和异常停止安全。
- H：主程序关掉时工具窗口全部关闭、工程与文档状态可恢复。
- I：扫码只作为编号输入/匹配，不因缺少扫码配置卡住开发调试。

## 六、交付协议与门禁

- UI 研究独立分支归档 D0–D3；Codex **只负责本地 Windows 拉取构建启动与反馈**，不决定 UI、架构或产品需求。
- 正式后端保持单一真实能力实现；专业工具/TEST/PROJECT 各模块的接口改动由对应责任人复审。
- 每轮交付 GitHub commit/PR 与简短 Codex 身份、仓库、分支、HEAD、工作区、项目路径；不提供冗长重复命令。
- Gate-Design：全局设计、任务链、状态与窗口层级完整，且用户认可。
- Gate-UI：交互稿与实际 WPF 对齐，不得退回 R1 布局；各项功能真实保存。
- Gate-Integration：全部操作只走正式后端、资源版本一致、所有外设路径不会假成功。
- Gate-Acceptance：Windows build、启动、验收工程和关键任务链实测完成，才能请求合并主交付分支。
