# AutoTest R0-LAB｜05 分支独立实测与集成后验收的分类执行规则（修订 v0.2）

**现行权威**：`SAEF/engineering/decisions/ADR-20261109-SPECIALIST-LAB-FIRST-INTEGRATION-LATER.md`（修订 v0.2）。先前将所有分支一律要求开发独立可现场实测 EXE 的表述已经失效；其他 R0-LAB 可观察性、错误诊断、物理授权及代码责任规定继续有效。

## A 类：可独立实测的专业

DEVICE、WAVE、UDS/Flash、PROJECT/DBC、BENCH 的独立可验证能力，及 SCAN 的扫码枪/规则等：各自交付可直接使用的专业 WPF/调试入口、必要的受控数据源和设备接口、完整 Trace/错误/导出、Windows Build/Test，然后由用户在对应专业对话实测和复测。确认专业操作成熟后才纳入统一 AutoTest。

- 真实设备能力有独立 Gate，软件 Mock/Replay PASS 不等于 Physical。
- DEVICE 底层 KeyMask 原始测试 UI 不等于 BENCH 的真实 ECU 按键操作 UI。
- 复杂跨专业能力用最小受控依赖先验证真正独立部分，不把“全平台集成”当作入口。

## B 类：集成后由用户统一实测

- **R1 总体 UI**：现在启动完整产品级 R1 IDE/Shell/导航/多文档、全局交互及视觉设计实现；无需制作额外独立完整验证软件给用户先测；自动化/构建/组件冒烟先行，最终在集成后的统一 WPF HOST 中由用户验收。
- **TEST**：继续完成正式 TestProgram 编辑、控制流、执行引擎、调试/运行展示、Mock 契约和自动测试；不额外开发独立给用户现场测的测试软件；与真实设备/资源/RunId 的完整操作在集成后验收。
- **RECORD/报告**：继续完成真实 SQLite/审计/报告/查询/统计和自己的页面/VM及自动测试；无需单独给用户做“报告实测软件”；以集成后的 RunId/StepFact/真实生产数据做正式验收。
- **SCAN 正式闭环**：扫码本身可以独立测，生产运行、去重/复测与 TEST/RECORD/报告全链联动要集成后测。
- **INTEGRATION**：等专业可用能力与 R1 UI/TEST/RECORD 达到组件候选状态再逐项合入；负责一套正式 Shell、唯一共享 Session、跨层资源和数据接线。不要改写成熟的专业页面或伪造已验证状态。

## 所有分支必须提前交付的接口信息

1. 自己的 View/VM/Service 入口与源代码所有者；
2. 专业功能所需的 Project/Profile/Resource Revision、Station/Session/Mode；
3. 请求、取消、错误、状态、日志/原始 Trace、证据 Ref、实际数据来源；
4. 专项独立调试时的受控 Port/Backend，正式统一 HOST 接线需要什么；
5. 构建测试与真实用户/现场验收的独立状态，不可冒充。

## v0.3｜集中实测不是研发串行门槛（用户已确认）

**全分支持续并行开发，不等 DEVICE，也不互相等待。** DEVICE 当前实测/排障，只阻断确实依赖该真实硬件状态的物理用例。其他专业继续 UI、后台、回放/Mock、日志、自动测试和候选版本；用户另行集中安排实测时间。

分支交付候选后若用户还没测，状态为 `USER_LAB_PENDING`；只暂停此项的最终现场确认，不停止同专业下一项不依赖的开发。R1 UI、TEST、RECORD/报告现在持续开发，正式用户验收在整体集成后。INTEGRATION 可现在提前准备接口，不要求任何分支等总 Shell 完成才能开发自己已有的功能。公共合同缺口做最小问题单，不许私改共享层；独立 worktree/专业分支保护并行改动。

用户集中实测时，按候选版本、启动方式、验证目标、需要设备/样本、操作步骤、原始日志/导出路径和仍未确认的事实整理测试清单，供用户**自主选择测试顺序和时间**。不得把候选 ZIP/PR、Mock 测试通过与用户实测 PASS 混为一谈。
