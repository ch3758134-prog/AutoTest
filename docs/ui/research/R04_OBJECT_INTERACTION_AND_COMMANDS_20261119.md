## 1. 研究范围与证据说明

研究对象：Visual Studio 的 Preview tab/搜索/错误定位、NI TestStand 步骤设置、Ignition Designer 的属性与上下文命令、Fusion 的参数表/特征编辑、ecu.test 的步骤编辑/Problems 导航，以及微软 Windows 命令和 WPF 数据校验。以下 E26～E39 均是厂商机制的可验证事实；交互规范属于综合设计推论，不是厂商或 ISO 强制标准。文献考察并非同软件实机 A/B 效率实验。

### 经核实的产品机制

| 厂商操作机制 | 一手来源 | 得到的 UX 判断 |
|---|---|---|

## 2. 关键结论：编辑对象不是“打开一个属性窗口”

成熟编辑器应让用户围绕一个稳定对象循环：

`定位 → 选择 → 识别可编辑内容 → 改动 → 查看局部反馈/关联变化 → 继续同类操作 → 提交/保存/撤销`。

“当前对象”可来自工程资源树、表格行、流程节点、图形信号、日志事件、搜索结果或历史运行结果。所有选择最终指向**同一个对象身份**，不能每个控件再创建一份可变的副本。

用户改变选中对象，原则上不应默认触发“执行实体动作”“保存整个工程”“切换全局 Run 目标”或“丢弃之前未完成的局部输入”。

## 3. 四种专业交互模型：统一规则，按对象适用

### M1 密集表格直接编辑

适用：报文/信号参数、配置清单、数据表、发送列表、变量表、日志筛选定义等。单击选中行，直接点击/键盘进入可编辑单元格；Tab/Shift+Tab 连续移动；Enter 提交单元格，Esc 取消当前输入。选中行与详情联动。支持多行复制/粘贴、排序/搜索/过滤（具体合法性由领域层约束）。不允许通过排序误更改正式执行顺序。

**禁止**：表格纯只读，却要求对每一个字段右键“完整属性…”弹新窗口。

### M2 持续对象详情编辑

适用：一个有多个相互依赖字段的对象。中间对象列表/画布选择，旁边或下方持续呈现**真正可编辑**的完整或高频配置；在对象间切换时需要明确指示当前被修改的对象、待保存状态和校验问题。高频字段既可以从 M1 直接改，也能在 M2 调整，但二者必须共享同一个正式数据源/事务。

**禁止**：右边所谓“属性”只显示概况，真正编辑藏在另一个“高级设置”模态窗口。

### M3 层次/图形/流程编辑

适用：流程/步骤树、公共流程、时间线、波形参考、位图等。主要操作与空间对象绑定：鼠标定位、插入、移动、折叠、复制，直接看到结果。复杂参数进入与当前选择绑定的详细区。对拖放给明确落点；超出有效层级必须拒绝并解释原因。撤销必须保留对象身份及引用一致性。

**禁止**：流程看似可展开，但操作必须先找工具栏按钮、新建后又找右侧隐藏属性，且上下文不一致。

### M4 编辑—执行分离的实时操作

适用：真实 CAN/UDS/Flash/IGN/夹具/KEY 等。用户先组合、编辑、保存待发送/待运行设置，合法且授权后由**独立主命令**发送或执行，右边/下方展示真实请求、设备应答、ECU 响应、停止/错误和日志。编辑改变不自动发往 ECU；所有可暂停/停止/取消状态由专业合同提供。

**禁止**：勾选报文等同发送，改字段自动发物理输出，USB ACK 直接标“ECU PASS”，离线工具展示假成功。

## 4. 全产品对象命令合同 v0.1

UI 命令必须声明以下字段（具体领域服务独立负责行为）：

`CommandId / Label / TargetKind / SelectionScope / Preconditions / InputDraft / SideEffect(LOCAL_EDIT|PERSIST|HARDWARE|REPORT) / UndoContract / ProgressContract / ErrorTarget / EvidenceLink`

通用行为：
- 单击 = 选择/设置焦点，不执行有副作用的操作。
- 双击 = 正式打开/详情/特定字段编辑，优先遵循具体对象类型习惯；所有按钮/提示文案与之匹配。
- F2 = 当前可改名对象重命名，Esc 取消字段本轮编辑。
- Ctrl+C/V/X = 适用时复制/粘贴/剪切；结构复制需稳定 Id 生成、引用规则和顺序一致性。
- Ctrl+Z/Y = 本地编辑事务撤销/重做；不回滚实体物理输出，不把永久 RunRecord 当编辑草稿。
- Delete = 作用于当前明确选中对象，有引用影响、不可逆风险才询问或阻断；不能静默误删项目。
- 右键菜单 = 对应对象的补充命令；主操作必须始终有可发现入口。
- Ctrl+F/Ctrl+Shift+F = 当前资源或全局资源查找（具体功能和快捷键冲突经应用层注册），结果可点击定位。
- Enter/Space/Shift+F10 = 遵守 WPF 常见控件键盘习惯，保证有焦点提示；焦点在输入框时不可触发全局实体发送快捷键。
- 危险的设备写入、烧录、生产操作：必须是显式命令，UI 不能通过普通双击/Enter 意外执行。

常用命令的可用性需要解释为什么禁用，不能只显示灰色不可点击；快捷提示应说明当前位置、目标与效果。

## 5. 选择模型：与“执行选择”绝不能混淆

| 选择类型 | 表达 | 用户意图 |
|---|---|---|
| NavigationSelection | 当前导航树选中一个资源 | 在哪儿/找什么 |
| EditorSelection | 当前文档选中若干对象 | 想编辑/操作哪些对象 |
| RunSelection | 当前测试项目中选择执行哪些用例 | 这次 Run 范围 |
| StationTarget | 当前实体通信目标/通路 | 哪个真实工位/设备 |
| TraceSelection | 选中历史消息、波形片段、报告证据 | 想观察哪条事实 |

同一个项目树行上“蓝色选中”“勾选本次 Run”“用例默认 Enabled”是三种不同状态。应该使用不同视觉表达和清楚文案，绝不能隐式互相修改。

## 6. 校验、草稿、提交与跨对象切换

提出一个可实施但尚需领域审查的五层状态：
1. `FieldEditBuffer`：正在输入的文本（允许半成品）；进入到下一对象时保留原始缓冲。
2. `ObjectDraft`：一个对象整体的临时参数；可以被原始数据类型和技术合同验证。
3. `DocumentTransaction`：一次结构化可撤销编辑，绑定正式对象身份与版本。
4. `PersistedResource`：保存至 PROJECT 文件/DBC 资源，格式与引用合法。
5. `ExecutionSnapshot`：TEST/DEVICE 固定本次运行数据，后续编辑不改变历史事实。

边界：
- 输入字段中可以出现暂时不完整的数字，但技术校验必须拒绝非合法提交；带错误的编辑对象不能保存进正式文件。
- 用户切换对象时，不得自动丢失 FieldEditBuffer，也不应因为数据尚未合法就把整个文档导航锁死；可以每个对象保存隔离草稿并显示问题计数。
- 同一个值表格/Inspector/图表只允许 **一个数据模型、一个状态源**，重复展示不是重复业务对象。
- 用户可以明确“撤销该对象草稿/放弃此次更改”，不能把“选择其他对象”当作丢弃操作。
- 保存时执行完整验证、引用完整性、外部修改冲突检测；出错聚焦关联对象和对应字段，不只是弹出全局错误码。
- 真实领域支持程度须从 TEST/PROJECT 接口确定；不能因为设计说明有草稿层就自行造第二套存盘格式。

## 7. 全产品对象类型到编辑模型的初步映射（不是窗口定稿）

| 领域 | 主要对象与操作 | 首选模型 | 仍需要的专业能力 |
|---|---|---|---|
| PROJECT | 工程、测试项目、资源、修订、引用 | M1 + M2 | 浏览/搜索/打开/重命名/移动/引用跟踪/版本 |
| TEST | 用例、结构化步骤、公共流程 | M3 + M2 | 步骤库/插入/嵌套/IF/SWITCH/变量/局部运行 |
| BENCH | 发送配置、输入动作、工位状态、CAN Trace | M1 + M2 + M4 | 多行快速修改、发送/停止、真实响应 |
| DBC | 报文/信号、位布局、枚举、属性 | M1 + M2 + M3 | 完整合法性、位图/数据表双向定位 |
| UDS | 诊断服务/请求序列/会话日志 | M1 + M2 + M4 | 服务模板、参数编辑、执行序列、响应关联 |
| FLASH | 配置、镜像、阶段、日志 | M2 + M4 | 完整预检、进度、异常与不可逆动作审计 |
| WAVE | 曲线、信号、参考、游标、质量 | M3 + M2 | 大图直接操作、同步时轴、参考/容差 |
| SCAN | 条码、匹配结果、受控生产 Run | M4 | 无键盘导航负担、异常处理、禁止重复计数 |
| RECORD | 历史 Run、步骤证据、报告 | M1 + M2 | 时间/编号/结果检索、历史冻结关联 |
| DEVICE | 设备身份、通路、错误、许可 | M2 + M4 | 请求/ACK/ECU/物理事实分层 |

不同对象之间共享键鼠语义和状态合同，而非强制相同三栏或通用属性表。

## 8. 可操作任务验收（R04 输出，供 R06）

| ID | 用户实际任务 | 应验证 | 失败例 |
|---|---|---|---|
| O01 | 单击工程树中的资源并直接预览 | 未永久打开大量页签，焦点可预测 | 单击即创建文件/执行 |
| O02 | 选择数据表一行编辑多个字段 | 不需要反复打开弹窗，Tab/Enter/Esc 工作 | 每字段“属性…” |
| O03 | 同一对象在表格与详情区修改 | 值一致、验证一致、撤销一致 | 两份草稿相互覆盖 |
| O04 | 编辑中半成品字段，切另一行再返回 | 输入不丢、定位原字段、正式保存被合法校验保护 | 无效值锁死页面 |
| O05 | 复制移动流程子树并撤销 | Id/引用合法、结构顺序不乱 | 粘贴失败后损坏文档 |
| O06 | 搜索一项问题并跳转到字段 | 错误定位、能马上修改 | 只有不可操作的红色弹窗 |
| O07 | 修改待发送报文但不发送 | 实体无输出；草稿值变化可见 | 修改文本导致 ECU 动作 |
| O08 | 执行一次真实授权发送/运行 | 请求/ACK/响应/结论分层真实反馈 | 成功按钮即显示 PASS |
| O09 | 打开两个不同专业工具编辑关联资源 | 共享版本/冲突透明，不强制另存副本 | 不同窗数据无规则分叉 |
| O10 | 用户按 Ctrl+Z 撤销一次字段修改 | 恢复本地数据而不回滚实体 | 撤销后错误修改工位 |
| O11 | 大量对象搜索/过滤、连续编辑 | 列表滚动和选中状态稳定 | 每次修改重新构建所有树导致卡顿 |
