# V02-02｜TEST 步骤结构、命令与视觉的一体化深度研究

日期：2026-11-19｜阶段：V02 第二批｜状态：RESEARCH_RECORDED / DESIGN_CANDIDATE / NOT_USER_ACCEPTED / NO_WPF_CHANGE

## 0. 本批独立研究问题

继 V02-01「两种空间方向」之后，本批不再只比较右属性和下属性，而是解决它们共同的底层问题：**用户怎样从一组复杂步骤中辨认结构、定位可操作对象、实施正确范围内的命令、连续编辑具体参数，并通过视觉确认操作结果？**

研究对象：阶段容器、普通步骤、复合流程节点、分支槽、当前选择、编辑焦点、禁用、未保存、字段错误、断点、运行指针、当次运行选择、文档状态。

设计目标：在相同样本和相同任务下，操作行为与视觉呈现双向解释，不先把它们实现为 TreeViewItem 或一排按钮。此前真实 Windows 截图说明这两者曾同时失败，但本轮不把任何具体源码归因为已确定根因。

### 1.1 对成熟软件机制的负面证据

成熟软件也可能选择模态参数窗、隐藏高级选项或自定义步骤设置，这并不自动不合理；其适用条件可能是首次插入的复杂前置条件、上下文强约束或一次性的高风险配置。AutoTest 反复进行的普通步骤编辑，默认应优先连续可见，但**不能禁止任何必要模态场景**。用户既往反感的是「经常编辑还必须重复打开弹窗」，而不是所有情况下都禁止弹层。

### 1.2 本项目已批准边界与仅属研究推论

项目事实：准备/测试/清理三阶段；包括 IF/ELSE、SWITCH、WHEN、循环、异常、变量、公共流程；DBC 用于方便 CAN 发送和信号配置；可勾选本次运行用例；用户期望鼠标左右键、高频编辑、同区步骤属性。

研究推论：根据任务与屏幕尺寸将步骤树与属性区组合；不同结构节点采用不同视觉行样式；采用行内摘要并保持属性编辑联动；默认禁止跨分支隐式移动。

未冻结：具体节点行高、字重、图标、左右/上下布局、所有键盘热键、批量选择默认行为、复杂条件编辑器的最终形式。

## 2. 结构对象应如何被识别

| 节点类别 | 本质 | 用户主要操作 | 视觉必须表达 | 不得混同 |
|---|---|---|---|---|
| 阶段 Prepare/Test/Cleanup | 三个固定阶段容器 | 选中插入目标、展开/折叠、跳转 | 独立组标题、边界、统计与可插入提示 | 与普通步骤同层的小号文本 |
| 普通步骤 | 有身份/类型/参数的最小动作 | 选择、改名、参数、复制、移动、禁用 | 类型标记、名称、最有意义的单行参数摘要 | 与执行完成的状态 |
| 流程容器 IF/SWITCH/LOOP/WHEN/TRY | 拥有条件和有序子节点 | 设条件、添分支、展开、移动整个子树 | 容器头、子区域、关联层次、分支指示 | 当作一个不能容纳子节点的普通行 |
| 分支槽 THEN/ELSE/CASE/DEFAULT/超时/CATCH | 父流程内部的步骤集合 | 在槽内插入/移动、选择分支 | 与所属父容器关联的缩进/竖向引导/分支标题 | 拥有独立的实体执行语义 |
| 调用公共流程 | 引用另一个资源及修订 | 选资源、跳转定义、编辑引用 | 引用名称/状态及进入/定位提示 | 复制粘贴公共流程正文 |
| 问题或引用指示 | 局部诊断与元数据 | 定位/修复/跳转 | 与节点或字段同屏的警告/说明 | 作为额外“步骤”掺进树里 |
| 运行指针 / 断点 | 当前执行定位与调试策略 | 观察/调试 | 与选中态不同的独立标识 | 把蓝色选中当作已执行 |

## 3. 视觉层级不是只改文字大小

### 3.1 建议层级（待具体视觉版验证）
- **H0 文档/用例上下文**：能识别当前工作的是哪个测试资源、是否有未保存/问题；不与产品 Logo 抢视觉注意。
- **H1 阶段条**：准备/测试/清理，显示名称、步骤数、折叠状态、适用插入目标；与普通行有稳定分组间隔。
- **H2 流程容器**：IF / LOOP / SWITCH 等有容器标题和子树边界；展开箭头独立命中区域。
- **H3 分支标题**：THEN、ELSE、CASE 与超时分支独立可见，不能仅靠某一行前缀“〔ELSE〕”。
- **H4 普通步骤行**：名称与类型的主从关系、序号、核心参数摘要与可编辑状态；禁用、错误、断点独立标识。
- **H5 类型化详情**：标题说明当前对象身份与类型，字段按含义成组，错误就在对应字段旁边，专业资源选择不要求记十六进制。
- **H6 全局与对象命令**：创建/保存/检查属于文档或结构；移动/复制属于选中步骤；实际运行是不同任务，不与普通编辑按钮混排。

### 3.2 原型文字排版候选（不是像素冻结）
- 主编辑数据行以正文可读字级为基准，不把关键的步骤名称降到 Caption。
- 辅助摘要可以比名称弱，但保留必要对比；不要每行重复过长的「当前 UI 只是草稿」告示。
- 行内属性“等待 300 ms”“等待 BrakeStatus.Ready=1（2 s）”用于扫描而非替代完整详情。
- 类型标记在全文一致；颜色优先用于状态，避免所有 20 种步骤类型被染成 20 种颜色。
- 中文、英文变量、DBC 标识、十六进制值应实际验证断行/裁切、等宽数值和字体回退。

## 4. 结构层级与交互边界的硬要求

### 4.1 选择 vs 展开 vs 插入 vs 执行
- 点整行的**选择区** → 编辑对象；不触发硬件、不改变 RunSelection。
- 点箭头的**折叠区** → 展开/折叠，不改变现有编辑对象；子节点被收起时可在父节点显示“内部有当前选中步骤”的提示。
- 在阶段标题上使用“添加步骤” → 目标为该阶段的合法末尾（或显式指定位置）。
- 在选中普通步骤时“插入同级” → 预览插入后的顺序位置；“插入子步骤”只能对允许子节点的流程/结构容器启用。
- 双击普通步骤名称 → 进入对应字段快速编辑（候选）；双击引用 → 定位定义动作应与编辑名称动作区分。
- UI 中显示的“运行中/通过/失败”只能来自真实 RunFacts；纯 UI 研究不为截图合成实际 PASS。

### 4.2 结构移动的三种不同语义
1. **同级重排**：在同一个集合内移动，操作可撤销。
2. **跨分支/跨阶段重归属**：与同级移动不同，必须明确目标容器和插入位置，并展示操作预览，且接受领域合法性校验。
3. **包裹多个步骤**：选择同一合法连续区间→将其置于 IF/LOOP 等容器内，必须为**一次可撤销事务**；不可无提示改变父子层级。

错误操作提示应包含起点与目标（如「不能将 ELSE 子步骤移至 IF 之外；请选择“移动到…”」），而不是通用“移动失败”。

### 4.3 结构中可出现的选择对象
- 结构树中允许当前编辑选择与多选结构选择；二者需要明确焦点和命令作用域。
- 当前用例选择与树内选择、生产 RunSelection 必须互不影响。
- 同一个子树有错误时，折叠父节点仍显示“内部问题数量”；定位问题时自动展开祖先并滚动至目标。

## 5. 高频命令：用操作语义决定可见性

| 优先级 | 命令 | 视觉与位置 | 键鼠候选/作用域 |
|---|---|---|---|
| 主命令 | 添加步骤 | 树工作区命令条，焦点附近；在空文档直接可见 | 主按钮 + 类型搜索，目标位置可明确查看 |
| 主命令 | 修改步骤参数 | 随当前选择出现的持续编辑区（不需第二次开窗） | 单击选择后立即编辑，Tab 切字段 |
| 常用次命令 | 复制/删除/启停/移动 | 选中对象的局部工具栏、对象菜单，不铺设多行同色按钮 | Ctrl+C/V、Delete、上下文菜单与相应快捷键 |
| 历史编辑 | 撤销/重做 | 文档级固定位置；禁用原因可见 | Ctrl+Z/Y，注意当前文本字段 Undo 与文档 Undo 的优先级 |
| 上下文命令 | 插入到前/后/某个分支、包裹、移动到 | 类型选择器、右键、可视插入引导 | 当前节点+目标集合+落点明确；仅显示合法操作 |
| 文档命令 | 保存、校验、查找、问题定位 | 文档/问题区，不能与步骤级移动合并 | Ctrl+S、Ctrl+F、点击错误跳到字段 |
| 高风险真实命令 | 启动测试/单步真实运行/烧录 | 独立运行任务区与实体状态 | 与纯结构编辑区和输入字段键盘事件分隔 |

**快捷键特别说明：** ecu.test 的 Ctrl+Space 为事实，但中文 Windows 输入法可能使用该组合；AutoTest 的“快速插入”应该优先研究 Insert、明确按钮或可配置快捷键，不未经验证照搬。以内容可发现性为第一入口，键盘加速第二。

## 6. 三种错误场景如何同时处理操作和视觉

- **缺少 DBC 引用**：步骤行有“引用缺失”标签及错误标志；详情字段旁显示所需资源，选择器提供“查看/创建 DBC 资源”入口；Problems 跳转至本步骤并聚焦字段。不能只弹一个错误框。
- **时间输入到一半**：用户键入 `20x` 时，该字段是无效的编辑缓冲，必须显式保持，切别的步骤后再返回仍可修复；不在后台无声替换成 20 或清空。
- **禁用分支内有错误**：禁用与错误两个状态都可同时存在。是否阻断正式保存由领域校验规则决定；UI 不凭颜色推定已不影响运行。

## 7. 用何种内容验证 V02-01 两种布局

延续 A：中央步骤结构+右常驻属性；B：宽步骤表+下方参数。
- 相同 12 用例、至少 30 个步骤、嵌套深度 3+、问题/半成品/引用缺失状态。
- A 与 B 都必须显示：当前用例身份、阶段、步骤名与摘要、流程容器、分支、当前选择、详情、常用命令、Problems 定位。
- A 的横向不足与 B 的纵向不足必须实际测量，而非“我觉得很宽敞”。
- 如果空间不足，应研究导航暂收、属性可切换停靠位、阅读/编辑任务视图等行为，而非将关键文字缩到不可读。
- 尤其注意 1366×768、150% 的 WPF 可用逻辑布局空间小于 1366×768 的 DIP 数量，不能固定最小窗宽 1024 DIP 然后声称适配。

## 8. 结论与未解决问题

**支持的设计结论**：结构容器、分支槽、叶步骤与其参数必须具有可观察、可操作、不同层级的语义；插入和移动有清楚的目标；选择与焦点、禁用、断点和真实执行必须独立；高频属性编辑与当前选中项直接联动。上述与 R04 的编辑模型 M2/M3、V01 的视觉层级 P01/P02/P03/P04/P09 相互支持。

**尚未解决、不能报已完成**：
1. 右侧属性 vs 下方参数，具体屏幕验证仍未进行。
2. 数字化字体/行高/分支引导/焦点配色与图标，还需在真实内容版中定稿。
3. 全量 TEST 步骤 Schema、StepId、分支允许条件、错误模型须由后续正式 TEST 合同确认；当前只是纯 UI 的交互研究。
4. 用户尚未体验本文形成的任何实际 UI，故不能写“用户认可”。
5. 本批只做研究，不改 WPF、不生成 HTML。

**本批交付结构**：本研究 + 完整样本任务 + 交互状态设计 + 审查矩阵分别归档，并在 V02-02 README 中互相引用。
