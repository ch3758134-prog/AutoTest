# G4 网页多对话并行开发：主对话总控合同（v0.2 批准方案执行细化）

**本文件是组织和派工合同，不是 G4 源码授权。** 只有完成首个公共工程初始化与可编译合同基线后，主对话才能为各方向签发填写完整的工作包。

## 一、职责边界（不向用户转嫁开发统筹）

- **主 ChatGPT 对话（系统设计与集成总控）**：管理所有分支派工、基线和 CT/DTO 定义，研究/审查源码，决定迁移与修复，生成完整功能/测试源码交付，维护冲突清单和集成顺序、复核每个真实测试结果。用户无需自己决定谁改哪个文件。
- **专题 ChatGPT 对话（各工作包的代码作者）**：仅在精确授权文件范围内，依据同一源码基线和合同版次交付完整代码、测试代码、Fixture 和 hash；不允许重划全局架构，不擅改共享公共文件。
- **本地 Codex（机械执行者）**：按经主对话签发的不可模糊操作单，核验 hash，复制/编译/跑测试/本地 Git 记录，任何冲突失败停止，完整回传，不自主修复或选型。
- **项目负责人（用户）**：决定是否授权工作包和 Gate、把完整包在本地交给 Codex、运行软件及实物、提供现场事实和验收反馈；不负责融合架构或手动修复源码。

## 二、唯一入口与技术所有权

`INTEGRATION` 唯一管理 `.sln`、`.csproj`、集中 NuGet 版本、`Core/Contracts`、公共 DTO、Composition/DI、Prism Shell 装配、测试基础设施和跨模块集成测试。其它方向只能提出变更申请，不得并行写入公共文件。

`PROJECT` 工程资源/DBC；`TEST` 编辑、Plan、运行；`UI` 样式、工作台、View/ViewModel；`DEVICE` USB/双CAN/Station；`RECORD` 记录/证据；`SCAN` 扫码；`UDS` 诊断；`WAVE` 波形；`FLASH` CAN烧录；`PRODUCTION` 生产编排。十一方向不意味着同时启动十一对话；依赖已满足的方向才可放行。

文件级独占由 [`COMPLETE_FILE_OWNERSHIP_PROPOSAL`](matrices/COMPLETE_FILE_OWNERSHIP_PROPOSAL.md) 约束，新增源码仍须在任务授权清单注册唯一写入者。

## 三、迭代波次与释放依赖

| 波次 | 工作方向 | 并行前置 | 当轮应交付的可见结果 |
|---|---|---|---|
| V0（唯一写入者） | INTEGRATION | 负责人允许初始化 | 新 HOST 工程、可编译 DTO/CT、Mock、WPF 主窗口、测试框架、首次源码 Git 基线 |
| V1（首批并行） | PROJECT、TEST、UI、DEVICE（纯协议/Mock）；INTEGRATION 汇总 | V0 通过真实 Windows 构建、Mock 与 UI 启动 | 工程/DBC、测试编辑执行、WPF 操作的 Mock 全链路；共享合同由 INTEGRATION 维护 |
| V2 | DEVICE + INTEGRATION | B0 安全核查、已完成 USB/Can Mock | 真实 USB PING、双 CAN 收发与 Trace；不擅发 IGN/夹具命令 |
| V3 | DEVICE、TEST、RECORD + INTEGRATION | 物理专项放行、B0/B2 前置 | Station/按键/运行/历史真实闭环；无传感器则输出 UNKNOWN |
| V4 | SCAN、UDS、WAVE + INTEGRATION | Mock/非破坏前置 | 真实扫码、诊断、波形；UDS无破坏性服务优先 |
| V5 | FLASH、PRODUCTION、RECORD + INTEGRATION | Bootloader模拟与恢复策略验证 | Flash Mock、生产检测流程与统计，真 ECU Flash 另外授权 |

各方向可以先在网页对话准备独立的理论与代码方案，但**未经 V0 公共合同实际构建基线，不得生成声称可直接合并的正式工作包**。

## 四、主对话持续管理的五个账本

1. **工作包台账**：编号、方向、准入依赖、工作范围、授权、分支对话交付编号、目标测试 ID、责任人和状态。
2. **源代码基线台账**：每轮唯一 `BASE_COMMIT`、`CONTRACT_REVISION`、共享 DTO/公共类型 SHA、NuGet SDK 身份及下轮发放基线。
3. **文件独占台账**：每个可写文件的唯一方向、创建/覆盖类型、精确旧/新 SHA；跨方向变更只能 INTEGRATION 统一发布。
4. **验证与缺陷台账**：每项测试目标 `NOT_RUN` / MOCK / BUILD / BENCH 证据层级，命令、退出码、固定输入、日志/截图、缺陷处理和回归情况。
5. **集成回执台账**：交付 ZIP 身份、应用顺序、冲突检测、真实 Git HEAD、集成报告与最终是否验收。

以上账本由主对话生成、维护和更新版本，不能要求用户手工补齐工程决定。

## 五、每个正式分支交接单必须有的字段

- `WPB-G4-...` 唯一标识、批准范围/禁止行为、G3 SAEF HEAD、最新源码 `BASE_COMMIT`、接口 `CONTRACT_REVISION`。
- 具体代码/测试 `NEW/REPLACE/DELETE` 文件列表，旧哈希、新哈希，唯一写入责任、使用的现成源码/迁移决定、禁止覆盖文件。
- 相关 G3 合同编号、类/方法/错误与取消语义、Mock 输入/断言、对应测试 ID、最小可复现命令。
- 交付完整源码 ZIP、对应单元测试/Fixture，说明哪些验证真的运行过；不准用 `PASS` 取代 `NOT_RUN`。
- 如果缺公共类型或真实硬件安全证据：立即 STOP，在主对话提出 CR/阻断清单，不得另起同名接口或猜现场参数。

## 六、执行闭环

`主对话冻结任务→开发对话产出源码与测试→主对话检查接口/路径/质量→Codex预检SHA→本地应用→恢复/构建/测试→用户WPF/台架验收→主对话分析缺陷并发修订包→回归验证→受控Git提交→新基线分发`。

如果发现多份交付同时改写同一路径，主对话重新协调唯一写入者和集成波次；Codex必须停止，不得合并内容猜测意图。

## 七、所有分支始终受 G3 的安全限制约束

USB ACK 不能等同真实动作；无夹具到位传感器则不得声明到位；IGN 上电初态须先现场核查；扫码枪 USB 直连 Windows；无有效硬件状态不得放行具有物理副作用的命令；真 Flash、固件升级另获专项授权。
