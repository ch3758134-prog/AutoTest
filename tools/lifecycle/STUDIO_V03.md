# Engineering Workbench V0.3｜Windows 本地启动与使用

> **状态：功能候选 / Draft PR #28，不是已正式验收的企业 ALM 产品。** 本版本从 AutoTest 专项 KEY_SIM 演示升级为通用单人工程生命周期管理应用。用户已经否定 V0.2 的界面组织；V0.3 不继承那套四页调试工作流。

## 启动

在已有 PR #28 专用 Git worktree（例如 `AutoTest-Lifecycle`）中运行：

```powershell
git fetch origin pull/28/head
git merge --ff-only FETCH_HEAD
py -3 -m unittest discover -s tools/lifecycle/tests -v
py -3 tools/lifecycle/server.py --repo . --port 8765
```

打开 **http://127.0.0.1:8765/**。如果端口已经被旧进程占用，先在旧 PowerShell 窗口按 `Ctrl+C` 结束服务，再启动新版。Chrome 可按 `Ctrl+F5` 强制刷新。

Python 3.10+ 标准库即可，无需 XAMPP、MariaDB、npm、NuGet、pip、联网或任何云账号。

- 首次进入没有假数据或强制演示项目：先点击 **创建工程项目**，填写产品名称、背景/使用场景、版本与型号。
- 创建后在 **产品与系统** 建立产品背景、能力与系统组成；在 **需求与架构** 建立需求、总体架构、接口和详细设计；每个对象可编辑正文、设置父级、查看上游/下游与历史版本。
- **决策与变更** 中增加发现/变更，再关联影响对象。关系默认 `CANDIDATE`，需要人工确认；对于每个受影响目标要选择“需要修订/无需改动/继续研究”，然后才允许关闭变更。
- **实施与验证** 新建实施工作包，并与上游已批准需求/设计建立 `实施依赖` 关系，审查确认关系。在工作包填写目标源码的 40 位 Git SHA、可修改文件、验收条件；点击“固定当前关联输入修订”，检查准入、批准当前修订，然后才可以生成 AI 实施上下文。
- **历史与配置** 查看操作记录，导出项目 JSON（含对象、历史、关系、事件）。
- **资料与归档** 可以预览并选择 **从当前仓库导入 SAEF 档案**。导入前必须先建项目。该功能只从 `--repo` 指定工作树读取登记文档，作为 `reference` 型对象复制到本地工作区；原始 SAEF 不被修改。源文件登记批准状态与本地新对象 `DRAFT` 严格分离。导入前后都可以重新进入本页面，但已导入的相同路径会跳过，尚不实现历史数据双向同步。

## 新版与旧版的关系

- **新默认入口**：`tools/lifecycle/server.py` 启动通用可编辑 Studio（单机，无登录）。
- **旧的 KEY_SIM 静态演示**：需要时用 `py -3 tools/lifecycle/server.py --legacy --repo . --port 8766` 查看；原有示例图不会默认加载进新的工程对象。
- 当前管理数据默认写入 **`%LOCALAPPDATA%\EngineeringWorkbench\workspace.sqlite3`**（Windows）；可用 `--data D:\EngineeringData\workbench.sqlite3` 明确指定。**不是**写到 AutoTest 产品源码/SAEF 文件内。
- 数据库每次变更为 SQLite 事务，历史修订及操作者决策依据保留在专门表中；但产品级备份恢复导入尚未实现。建议定期关闭服务并备份整个 `workspace.sqlite3` 文件，也可导出 JSON 快照。
- GitHub/PR、真实编译、真实硬件/用户验收都未自动同步进新系统；`source_sha` 是人为提供的目标基线字段，不意味着软件已验证远端 Git 存在对应 SHA。
- 管理系统不自动修改 AutoTest Git main、设备固件或正式 SAEF Gate；不发 CAN/IGN/按键/Flash 命令。
