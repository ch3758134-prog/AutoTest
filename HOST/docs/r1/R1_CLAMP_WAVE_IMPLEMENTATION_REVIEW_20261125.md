# AutoTest R1｜统一夹具压紧/释放 + WAVE 9 分设计研究后实施记录

状态：**仅 R1 源码已提交、静态检查待 Windows/硬件验收**。未修改 main、未新建分支、未运行 CI、未进行 Windows build、单元测试或 ECU 实测。

## 一、夹具：由一套物理夹具的压紧/释放语义驱动真实测试

**原问题：** 主页面显示两路 GPIO、先后顺序、3000ms 和大量 USB 术语，用户不知道只是“夹具压紧/释放”。控制器确有两路输出，但不能把物理 GPIO 数量当业务夹具数量。

**新逻辑：**
- `ProductionPreparationWindow.Guided.cs` 默认只有一个“自动控制夹具”开关与“检测前压紧 → 自动烧录和完整 TEST → 正常完成后释放”业务预览。该窗口**不下发物理动作**，双路顺序/低电平有效不在主界面。
- `ProductionFixtureConfiguration` 扩展 `AutoClampEnabled`（业务启停）、`Clamp1PressHigh / Clamp2PressHigh`（实体安装时验证的电平极性）、`SettleDelayMs`（明确的稳定等待 0～30000ms）。保留 `UseClamp1/2` 与 `FirstClamp` 作为**高级硬件路由**。已有配置中省略新字段时取默认高电平压紧、0ms稳定延时；需现场校核，不能称已验收。
- 停用 `AutoClampEnabled` 绝不丢弃曾配置的输出1/2和极性，恢复后仍使用同一路；首次开启且没有线路映射时默认输出1，需按真实接线确认。禁用期间不产生任何 GPIO 输出命令。
- `StationFixtureExecutionPlan.From` 同时冻结动作顺序、电平转换、USB 回读超时和独立稳定时间；单路自动压紧/释放，双路仍可在高级安装配置指定动作顺序、释放反序。
- `AutomaticTestHomeViewModel.Run.cs` 的工程整组实测在 FLASH 前调用计划的物理 GPIO 高低电平，读取真实 MCU 0x19，保存操作意图与 GPIO 回读，再按专门设置的延时等待。正常完成、记录落盘、无活动 TEST/FLASH 授权后才尝试释放，且异常时不擅自复位气缸。记录同时显示**逻辑动作**与**电气电平**，避免低电平压紧时的日志语义倒置。
- 高级工位设置可以配置两路实际 PTB1/J1-B5、PTC2/J1-B4 的 HIGH 压紧极性和稳定延时；机械到位、START、互锁仍不能通过填写字符串或 MCU GPIO 状态假装已接线。
- 物理动作权限沿用已提交的 project-scope 指纹/USB连接世代/one-shot 精确指令授权，没有退回手动台架许可。

**夹具静态复评：** 操作可理解性 **9.2/10**；数据模型与执行连贯性 **8.6/10**；总静态 **8.7/10**。物理阀方向、稳定等待、机械传感器、异常后受控恢复均**未实测**，不得称为现场合格。

## 二、WAVE：先审查/评分，设计到 9 分再写代码

详细的**事前**调查和设计评分见 `R1_WAVE_RESEARCH_DESIGN_GATE_20261125.md`：
- 旧能力静态评分 **6.5/10**：共享 CAN/DBC 信号源、成组采集、多曲线、参考冻结、证据质量方面有基础；算法只按参考时间节点线性插值，离散状态会出现虚构中间值，且可能漏检实际采到的短暂异常；连续尖峰也可能在参考采样节点外被忽略。
- 修改前研究合同/方案评分 **9.3/10**，先提交设计落档，**之后**才实施 WAVE 比较器和 UI。它是“方案达到 9 分”而非“未经实测的产品已达到 9 分”。

**已实施：**
1. `WaveComparisonConfig` 增加明示的 `WaveInterpolationMode.Linear / StepHold`。默认 `Linear`，不按信号中文名、值表或画图样式偷偷决定比较规则，非法枚举拒绝。
2. `WaveComparator`：`StepHold` 采用真实参考与实测状态时间节点并集，在节点之间保持状态并**按实际区间长度**计算覆盖率、偏差和超差时长；状态若刚好在末样本切换但没有之后的观测区间，返回 `INCONCLUSIVE / UNCONFIRMED_TERMINAL_STATE` 而非假 PASS。
3. `WaveComparator`：连续数值仍使用线性插值，但不再只在参考采样点比较；改为使用实际/参考观测节点并集、同时检查实际尖峰，以**保守整区间超差**避免短时间真实采集异常隐形；RMSE与覆盖/通过比例按真实支持时间加权。采用有序双流**线性复杂度合并**，避免每个时间平移候选重复排序大量原始采样点。
4. `ConfigurationWorkbenchViewModel`：正式 TEST 的 WAVE 配置增添中文“连续数值（线性插值）/ 离散状态（阶梯保持）”选择，属于已保存的比较配置；更改后仍需保存新工程资源修订并重新确认引用。
5. `WaveWorkbenchWindow`、`WaveWorkbenchViewModel.Workspace.cs`：独立 WAVE 工具里的“参考与比较参数”增加相同模式选择，结果明确展示本次比较采用的方式；离线比较**不替用户改正式 TEST 判定配置**。
6. 测试源码覆盖：正常离散状态、两参考点之间实测的短脉冲、跳变时间偏差、未证实末端跳变、非法模式、连续量实测尖峰、旧配置默认模式、明确保存后的新模式，以及夹具启停时保留物理路由。

**重要受控兼容性提示：** 旧 WAVE 配置**仍选 Linear**，其阈值与模式不被改写；但为了消除旧算法的漏检问题，**新比较器更严格地评估实际观察到的尖峰并按时间计算覆盖/超差，部分旧数据的 PASS/FAIL 可能改变**。这是一项安全相关算法修复，不应宣称“完全数值等价”。上线前必须回归历史合格与已知失败 ECU 波形，用受控修订重新批准判定标准。当前尚未实现独立的算法版本锁定机制，正式生产 WAVE 判定准出仍为 **NO-GO**。

**WAVE 独立复评：** 源/DBC/证据能力 **7.7/10**，算法防漏判设计与源码 **8.8/10**，UI与配置一致性 **8.5/10**，数据质量限制 **8.1/10**，历史规则兼容和验收 **7.5/10**。当前**源码静态综合 8.4/10**；整体设计仍为**9.3/10**；真机可靠性**未评**。不能用研究分数替代 Windows / ECU 实测分数。

## 三、验收顺序与禁止行为

1. 本地 Codex **只拉取现有 R1、编译、启动**；ChatGPT 不替用户运行本机编译/CI。若编译出现报错以原始文件/行号修复，不能用“静态通过”冒充构建 PASS。
2. 手动台架先物理确认电磁阀方向。正式使用前配置高级硬件输出通道、极性与稳定延时，再在主界面打开“自动控制夹具”、保存并**重新发布**工位。
3. 用户以真实扫码进入**工程整组验证**，确认装夹 0x18/0x19、设置稳定等待、完整 FLASH、连续 TEST、受控收尾，外部夹具观察为准；断电/超时/故障时状态 UNKNOWN，禁止虚假 PASS。
4. WAVE 以实际 65ms CAN 信号、连续量电流等分别采集**多条同时查看**，显式保存标准参考，连续/离散分别对正确样本、已知错误样本、短跳变、Gap、USB重连、DBC SHA 修改与主机到达时间源做判定。测试线性与阶梯比较都必须有严格记录证据。
5. 正式生产的可信实体 START、机械到位/互锁及 InspectionAttempt 仍未接通；**绝不取消现有准入阻断**。GPIO / USB ACK 只是 MCU 电平读回，不是机械安全证明。HostArrival 时间戳不能实现硬件级精密时序。


## 四、后续 R1 独立复审与针对性修复（持续整改）

本轮未扩大到 main/固件，未执行 CI、编译或真机操作。继承同一 R1 的正式代码。

### 已纠正的实际断点

1. **跨时钟来源不可直接判定**：`WaveComparator` 在两份源各自通过质量检查后，还必须校验 `TimeSource/TimeQuality` 属于同一时钟域；例如 HostArrival 与 Replay/DeviceSample 不能因为数值相同而返回 PASS。保留 `RequireSynchronizedHardwareTime` 更严格的工艺设置。
2. **波形算法版本的批准证据**：`WaveSettingsDocument` 新增 `ApprovedAlgorithmRevision=2` 和 `ReviewedCriteriaSha256`。指纹覆盖 DBC 身份、修订/SHA、CAN ID/信号/单位、命名参考及完整比较参数。旧文件或版本变更文件依然能打开、查看、编辑，**不再能被误当作已批准的自动 TEST 判据**；阈值、模式、DBC 或命名参考发生变化将自动使旧批准指纹失效。
3. **WAVE 配置 UI 显示批准状态**，保存新修订时必须显式确认已复核当前阈值/算法/参考；不是单凭“导入成功”批准。批量自动测试严禁仅靠步骤自由输入的参考名与容差绕开这一层。
4. **TEST 作者与执行器合同同步**：`WaveCompare / WaveAnalyze` 必须选择真实的 `WaveProfile` 映射；`StepDescriptorCatalog`、`StepTreeValidator`、TEST 步骤 Inspector 和 `RealRunCoordinator` 已同步。旧式步骤可以在编辑器中看到并迁移，不得参与严格运行或以隐式缺省转成 PASS。
5. **不可判定不得变成有效变量**：在真实 `ConfiguredWavePort` 中，只有确实得到 Pass/Fail 的判定可用；Inconclusive 保留证据但不作为有效测量变量。运行步骤报告 `NoData`，而不是误作 Completed 或正常断言。
6. **波形资源先于不可逆操作核验**：`RealTestWorkbenchService.VerifyProjectWaveProfilesBeforeHardwareAsync` 只读检查全部有序 TEST 的有效结构、映射、WAVE 审批与标准参考，`AutomaticTestHomeViewModel` 在夹具、IGN、FLASH 之前调用。避免擦写 ECU 后才发现 WAVE 引用失效。
7. **阈值质量兜底**：`MaximumGapFactor` 的 NaN、无穷及过大值拒绝；时长阈值限制为硬性采集范围，避免借极端参数绕过缺帧判断。

### 夹具额外修复

- 新建工位草稿默认 **AutoClampEnabled=false**；已安装通道仍可保留，在主界面一键启用/停用。
- 工位发布和实际装夹计划分别阻止“自动夹具已启用但没有配置任何 MCU 输出”的状态；不能一边显示自动装夹一边静默烧录 TEST。
- 工程师点击真实物理操作确认后，第二次回读工位发布版本；如果等待确认期间重新发布了输出路由、极性或工艺参数，取消执行并要求重新扫码/确认。
- 以上只验证输出请求和 MCU GPIO，实际机械压紧/释放、独立到位与 START 输入仍未现场验收。

### 必须告知 Windows/现场验收者的更改

- 旧 WAVE 资源**不会自动升级算法批准**。请在配置工作台选择真实 WAVE 配置，核对标准参考、DBC、连续/离散模式和时间质量，在“确认已复核本次波形判据”选择“是”，保存新 WAVE 资源修订，随后在 TEST 编辑器明确更新此资源引用和工程发布。未完成时应在烧录之前阻断，而不是迁就旧配置运行。
- 旧 WaveAnalyze/WaveCompare 步骤若仅有参考名称与临时容差，必须明确改成受版本管理的 `WaveProfile` 映射；不会把旧判据当作安全合格。
- 测量误差 / 实际状态异常是 **Fail**；缺帧、跨时钟来源、流溢出和不充分覆盖是 **Inconclusive/NoData**；引用与参数不合法是 **Error/InvalidData**。三种含义不可混淆。
- 编译、测试执行、真实波形计时及机械动作方向仍未验证；**当前不是正式出厂检测的准入证明**。
