## 模块职责与依赖

按键板的主要软件职责是接收 CAN 指令、解析掩码并更新用于控制开关的 GPIO；不负责 DAC 波形输出、不负责自动测试 PASS/FAIL 判定，也不管理 DUT 供电。

## 驱动到物理器件的调用链

`WS/EPB_EOL/Sources/APP/main.c` 初始化 GPIO/CAN → `Drv_CAN_ReceiveFrame` → `KeySim_ProcessFrame` → `KeySim_WriteMask` → `KEYn_ON/OFF` → P2 的控制引脚 → P3 的 DG411 控制端 → 物理开关/电阻网络 → DUT 输入。**从“GPIO 置零”到“DUT 端电压是多少”中间有真实模拟电路，不能跳过。**

## 协议/状态/异常

- 目标 CAN ID `0x730`，DLC=8、数据帧；`DATA[0]=0x01` 时以 Data[1..3] 的低 20 位设置 mask，保留位必须为 0。
- `DATA[0]=0x80` 且其余字节为 0 时执行全部释放；非法命令返回失败值，当前主循环未见逐条 ACK 上报。
- `KEYn_ON` 宏通常写 GPIO 0、`KEYn_OFF` 写 GPIO 1；具体模拟开关真值表须匹配所装 DG411 的精确型号/供电。顺序更新 20 路，不应擅自认定物理原子切换。
- **KEY16 差异**：当前 `Driver_Gpio.h` 用 `PTED_PTED2`，原理图 P2 `K16_CTL` 标为 `PTB3_9P`。保持问题登记，不能擅自更改已冻结固件。

## 现有测试证据与约束

从代码可定位全部 20 路掩码驱动；**这不是已测完 20 路真实按钮响应、5 路电压或所有组合**。需留存真实板卡、固件映像、CAN 发送日志、实物端电压、DUT 响应和仪器配置。已有整机功能通过是负责人历史描述，不伪造本次逐路实测。
