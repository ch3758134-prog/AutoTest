# Project Control｜新建项目与已有资产项目接管协议

## A. 共同的第一步：识别目标，而不是先生成代码

输入：用户上传的管理系统文件夹 + 用户提供的目标 GitHub 仓库地址。管理系统包与被管理仓库必须明确区分。

检查目标仓库可访问性、账号/组织、默认分支、HEAD、目录、现有 `.project-control`、可见分支/PR/Issue、CI 与已有工程文件。访问失败时明确未核实事项。仓库可能包含 README、源码、设计、数据、固件、CAD/EDA 等多种资产；不因没有源码就称为空项目。

**禁止**：直接 clone 大量临时副本来调查；擅自 push/merge/reset；从仓库名称猜产品定义；使用管理系统源码的原始 AutoTest 项目状态污染目标项目。

## B. 全新项目 NEW

判定前提：没有可用的现成工程基线；“空仓库”与“新项目”并非同义，例如用户可能打算迁入外部资产。

管理 AI 可以先建立中立的初始化候选，项目名可以暂用仓库名但标识为临时；继续与用户讨论：
- 产品/研究对象及立项目的、当前范围边界；
- 实际资产与约束、可靠信息来源和待调查事项；
- 最早可以交付/验证什么，如何组织项目阶段和工作。

只在用户明确批准后确立正式产品/项目身份。初始化脚手架和候选计划不是 P0 批准，不自动进入 G1、G4 或实施。

在目标仓库的候选分支保留早期讨论/研究可追溯线索；首次正式 Codex 编码前必须形成足够具体的有效设计输入与执行授权。

## C. 已有资产接管 ADOPT

优先调查而非重建：Git 树、分支、版本、标签、既有设计、需求、测试、CI、Issue、PR、发布记录、硬件和外部资料线索。

形成 **资产清单 + 有来源的当前状态 + 版本关系 + 已知缺口**。现有代码、文档和 CI PASS 都不能自动升格为正式批准产品定义或阶段 Gate；同样不能因为未找到批准文件就宣布历史工作无效。

区分：
- `OBSERVED`：Git 直接可核实的资产或提交；
- `CLAIMED`：历史文本/人员声明，需再核对；
- `APPROVED`：能够确认正式授权范围及责任人的基线；
- `UNKNOWN`：暂时无法证明，不虚构状态。

项目负责人应决定是否接纳历史基线、是否重新开展某一阶段研究、是否将既有实现接入新管理流程。只有实际受影响的工作需要复核，不全项目重置。

**接管**不等于复制全部旧代码至管理文件夹、替换现有目录、改默认分支或建立一个“干净的新仓库”。

## D. 最小目标仓库文件合同

初始化在目标仓库创建下列轻量文件（不要求复制整个 Python Web 工作台）：

```text
PROJECT_START_HERE.md
.project-control/
  README.md
  project.json
  assets.json
  decisions.json
  tasks.json
  resolve.py
```

- `PROJECT_START_HERE.md`：此目标项目的 ChatGPT/Codex 入口；
- `project.json`：项目身份、来源 URL、初始化/管理状态；
- `assets.json`：资产来源及置信度登记，NEW 可为空，ADOPT 必须记录真实发现；
- `decisions.json`：正式决策历史，默认空；
- `tasks.json`：任务合同与执行状态，默认空、没有 READY；
- `README.md`：读取顺序及各状态解释。

不要把管理工具内部 `workspace/autotest.json` 或 `sources/autotest_engineering.json` 放进其他项目。

## E. 管理 AI—GitHub—Codex 的最低闭环

- 任务合同存在目标仓库，绑定目标仓库、原始提交/分支、任务 ID、责任角色、有效输入、允许文件范围、验收条件及操作限制；
- 研究/设计任务与正式编码任务的准入条件不同；设计尚未批准不能假装编码已授权；
- 管理 AI 在目标仓库写入候选任务并取得必要审批后，给用户一段**短启动指令**，而不是把实施细节粘贴给 Codex；
- Codex 在用户指定的本地空目录检查真实 Git origin 与目标提交，执行真实任务并保留日志及工作区去向；
- 只有实际 commit/push 之后才能说项目已同步 GitHub；完成任务不代表产品验收；
- 临时查看/测试工作区必须登记、可回收、不能直接乱丢；正式开发工作区保留到移交审查。

## F. 文件安全

任何现有 `PROJECT_START_HERE.md` 或 `.project-control/` 内容先核对来源、版本和职责。初始化程序默认只读预览，`--apply` 必须是已获授权的明确操作。碰到同名文件或仓库身份不匹配，拒绝覆盖。不能根据远端文本授予 Windows 路径访问权限。

## G. 管理系统的自身演进

当前 `tools/project-control-v2/server.py` 等程序仍有 AutoTest 固定示例绑定。只有真实完成通用项目数据加载、项目选择、权限、迁移、UI 验收及新旧项目端到端验证，才能标为“完全通用产品”。本初始化协议不构成这种完成证明。
