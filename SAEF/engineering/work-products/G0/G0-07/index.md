# G0-07 · 跨层物理接口、硬件能力及需求符合性

> SAEF v2.0 / G0-07。**M2 内容候审；本地 G0 仍为 NOT_STARTED，B0～B6 新复验未执行。**本文件仅记录来源可核的板级/代码事实、负责人报告的历史行为和待现场验证事项，三者不能等同。

> **G0 能力判定的主索引**：从实际物理能力出发，与历史 G1 原文要求做核对；本阶段只认定“图纸支持、条件支持、缺口或未验证”，不重新批准 G1/G2，也不形成新的实现方案。

## 接口适用场景和边界

读取顺序：**需求/外部使用场景 → DUT 实际输入和主控/按键板板外接口 → PCB/芯片资源 → 板级能力与限制 → 现役 FW 使用 → HOST 现状 → 实测证据**。这不是“从 HOST 命令找哪里能接线”的逆向设计流程；逆向调用链仅供调试。

纸面能力的综合判定枚举：

- `DESIGN_SUPPORTS`：原理图存在相应网络及器件；**只到电路设计级**。
- `DESIGN_SUPPORTS_WITH_CONDITIONS`：有能力，但前提包括外部供电、电阻/DUT 输入阻抗、线束或安全条件。
- `DESIGN_GAP_FOR_FEEDBACK`：要求某物理反馈而本次图纸未给出独立可证路径；仅说“无证据”，不能以未见证据推断绝不存在。
- `IMPLEMENTATION_UNVERIFIED`：未取得现役固件构建/当前 HOST 或实测证据。
- `CURRENT_BOUNDARY_ALIGNS`：明确约束“此电源不受控”，不视为需要软件补救的硬件故障。

## 参与者与所有权

PCB 与外围决定物理资源/电气限制；MCU 固件决定本次配置中如何使用资源；Windows HOST 只能调度已暴露且已验证的软件能力；外部 DUT、台架电源及机械机构具有独立状态。任何返回值都必须注明证据语义。

## 外部工位设备与身份识别接口（新增）

`IF-STATION-SCAN-01`：自动测试使用的外部扫码枪读取当前 DUT 的唯一编号，是**工位识别数据输入**，不是对 DUT 施加的电气激励；扫码枪不是主控/按键 PCB 的内建能力。当前确认的是使用目的和读取结果，不代表已确认品牌、接口、驱动、编码格式或软件集成完成。

| 分层 | 已知事实或缺口 | 可用于 G1 的结论 |
|---|---|---|
| 工位使用目标 | 扫描当前 DUT 的码，获得 DUT 唯一编号（负责人确认） | 将识别/追溯作为自动测试工作流程的需求输入 |
| 扫码枪实物 | 型号、标识、接线、接口与电源未知 | 无法宣布使用 USB HID、串口、键盘模拟或专用 SDK |
| 数据内容 | 唯一编号用途明确；编码规则、长度、合法性与重复冲突未核 | 不能把读到字符串直接等同已认证 DUT 身份 |
| 软件与记录 | 历史 HOST 未形成扫码链路的完整静态证据 | 是否自动定位配置、何时绑定测试记录等留待 G1/G2 与当前源码审查 |

扫码接口是**工位信息输入**，不是主控 PCB 的额外 GPIO/CAN 通道，也不是 DUT 电气刺激。它不计入下面 11 项板级硬件能力/约束矩阵。

### 每项能力必须分栏的六个状态

| 维度 | 允许写的证据 | 不能被替代 |
|---|---|---|
| 芯片具备 | 厂商型号、手册版本和参数条件 | 不代表已接出 |
| PCB 已设计 | 原理图页、位号、网络、连接器 | 不代表已装配 |
| 实物已装配 | BOM、PCB 修订、照片、线束 | 不代表固件已实现 |
| 固件已使用 | 实际 Target、源文件、宏/寄存器和烧录映像 | 不代表 DUT 已响应 |
| 现场已验证 | 输入、预期、实际、测量、版本、原始日志 | 不代表其他配置也通过 |
| 需求符合性 | 已批准要求 + 以上匹配证据 + 限制 | 不可用同一句“支持”跳过所有层次 |

### 物理外部信号示例（不得颠倒证据方向）

1. **按键模拟**：DUT 输入要求（如 PARK/RELE/MODE）← 板外接线 ← 电阻网络 + DG411 开关 ← MCU GPIO 控制资源。板级能力先成立；CAN 0x730/20 位 mask 是固件控制方式，放在后面。
2. **IGN**：ECU 端需要的 IGN 电气状态 ← J1/线束 ← BTS724G 高边 ← MCU 电气控制。当前代码的 `PTC10` 只是控制来源；GPIO 读回 ≠ ECU 端实测。
3. **CAN**：DUT/按键总线需求 ← CANH/L、终端、收发器与电源 ← MCU CAN 资源。固件 0x40/0x41 和 HOST API 是数据交互，不等于物理收发器的总线能力已验证。

## 字段/编码/时序

以下是**软件当前实现事实的附属索引**，不是硬件能力定义：主控 USB `A5/SEQ/CMD/LEN/CRC16/5A`；CAN 透传 `0x40/0x41`、15 字节帧信息；按键板 `0x730`、20 位 mask。当前没有足够现场时基/数据质量信息，不能填写系统级性能符合性。模拟网络的电压阈值必须来自原图、器件和 DUT 电气要求及测量，而不是 USB payload 解释。

## 错误/超时/重试/幂等

固件处理状态、PC 超时及 CAN 总线错误是软件协议现状与未来设计事项，不能代替物理反馈。尤其 `IGN/SOL` 的命令 ACK 与“外部真实端电压/机构到位”属于不同状态。取消、重复指令与机械失电后果应在后续 G2/G3 以已验证硬件条件为基础设计。

## 版本兼容与测试

硬件能力矩阵应先给后续 G1/G2/G3 明确的**限制与待验证项目**：输入供电非软件可控；按键板是电阻网络非任意电压源；五路网络实际电压未测；高边关断高阻；工装机械状态缺独立反馈；USB/CAN 高负荷数据质量没有实测基准；历史固件版本身份不能靠 ZIP 哈希推定。验证路径参见 G0-08，正式性能指标在对应验证阶段决定。

## 上游下游追踪

上游：两份 PCB PDF 原件、两套固件 ZIP、用户确认的产品使用与供电边界；需求索引来自 `AutoTest_Engineering_Master_v2.1.html#requirements` 的历史文本，**不是本次重新批准**。下游：G1 判断能力是否覆盖真实目标；G2 决定跨系统职责；G3 依据经过核实的能力、时序、电气和状态约束进行接口及逐文件设计。对缺口单独建立风险/变更，不默默重定义硬件。


## 产品边界校正与 G1 输入（v004）

1. **系统领域**：已获批的 P0-01 v006 将 AutoTest 定位为 ECU 测试台架，主控 PCB、按键 PCB、两套固件和 HOST 是系统内部设计对象，DUT 在系统边界外。G0 记录这些设计元素的实际能力，不把现役 CAN/按键方案升格为所有未来 DUT 的强制协议。
2. **HOST 扩展性**：P0 确认 HOST 通用测试核心不绑定 EPB 或任何具体 DUT，但“软件应如何分层、接口如何定义”必须由 G2 审核历史 `src` 后决定。G0 不拿 `Capability/Binding` 代替需求，也不先行批准 G2。
3. **需求符合性口径**：上表 `SYS-*` 等是**历史 G1 索引**，不是 G1 的现行已批准验收要求；新的 G1 要按 DUT 外部条件、台架交互、可观测结果、功能/质量目标重新建立正式追踪。
4. **软件现状隔离**：`src(20261030-022559).zip` 可证明曾存在某些 HOST 抽象和角色，但 `dut.power`、`keypad.power` 不能自动证明现役硬件有相应电气能力；详见 G0-06。


## J1 外部能力检索入口（v005）

主控 J1 的 64 个图纸触点已在 G0-02 建立网络标签索引，源数据 `data/J1_64pin_drawing_index.csv`。该索引可以支持 G1 从某个外部网络定位到硬件能力，例如 CAN1/CAN2、HOUT、SOL、SPEED、KEY、KLINE 等；但**不能未经实物核对作为线束制造或上电接线指令**。系统能力的可用性依赖具体资源、固件映射与现场条件；详见 G0-02/03 和 G0-08。

## 最新跨层能力语义约束
12V/24V 台架电源是实际外部测试条件，不是 `dut.power` 的软件实现证据。夹具位置无独立反馈，来自 DUT 的 CAN 报文只能在指定条件下作为间接观察。两套固件及未来 HOST 可以通过批准的版本升级增加能力，但不能越过 PCB 电气限制。新 HOST 的设备端点及编码建议应先经 B0～B4 检验再冻结。

## M2 设备能力及扫码接口的交接边界

**扫码枪是一项独立外部输入接口。** G0 应登记设备型号/接口/供电/PC 端输入方式与样本证据，尚未取得则写 `UNKNOWN`。G1 可定义 HOST 必须读取和关联编号；G2 才决策解析/匹配/预检/运行身份锁定的数据和状态模型，不能在 G0 直接指定 USB-HID 或串口协议。

固件及 HOST 后续扩展均需按设备能力与真实观测分级：请求发送、主控回应、总线回应、外部物理测量、测试程序判定五者不互相替代。
