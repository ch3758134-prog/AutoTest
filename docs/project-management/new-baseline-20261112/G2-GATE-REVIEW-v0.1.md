## 1. 为什么现在必须集中做 G2 审查

用户已澄清：此前的连续 UI / 业务研发与实测，是重要的**研发经验和可继承源码**，不是让 G2 按旧对话逐句冻结界面要求，更不是已完成新基线 G2～G4 的批准。历史 `local` 已有大量 Windows WPF、工程/DBC、TEST、设备和波形实现，可作为现行设计输入；但这些代码不能因“存在”直接跳过架构/详细设计审查，或宣称 V1 可交付。

项目需要有三个不混淆的事实：

1. **阶段批准**：G2 决定系统架构和公共边界，G3 决定精确可实施工作包，G4 才是受控编码/联调/实测/集成阶段。旧代码可以通过现状调查、允许的维护与观察继续保留；不能把它归属为新基线 G4 验收通过。
2. **开发与实测迭代**：对一个已获授权的 G4 工作包，可连续多轮 UI、交互、业务逻辑和真实硬件实测，发现问题就按影响范围修订；不是一轮设计后永不改动。
3. **代码集成**：`local` 是当前 HOST 在研来源，`main` 是正式管理/集成中心；仅指定提交和用户明确接受的功能范围经差异、构建、依赖及回退审查后才能进入 `main`。不得整支无差别合并。

**与先前错误部署的区别：** 2026-11-14 建立的 FLASH-LAB Issue #44、`feature/flash-lab-20261114` 只是待执行任务和保留的分支起点，不是已经获准启动 G4；当前不得交给新对话不经 G2/G3 审查直接写实体刷写代码。Issue #25 的 CanTool 研究可用于 G2/G3，无需重做。

## 2. G2 审查的系统边界（与 G1 保持一致）

```text
工程师／生产操作员／扫码枪
     │
     ▼
Windows AutoTest HOST：工程与资源 / 测试项目与程序编辑 / 运行与调试 / 证据与历史 / 专项工具
     │  单一实际连接会话；USB/WinUSB
     ▼
主控板固件
     ├── CAN0 → KEY_SIM：20 个电阻网络开关组合 → DUT 五路模拟输入条件
     ├── CAN1 ↔ DUT：原始 CAN、DBC 信号、UDS 及经授权的 ECU 编程
     ├── IGN 控制输出
     └── SOL 电磁阀控制输出 → 工装
```

**架构决定 A-01：** 软件能力分为“用户可编辑的测试定义”“运行时真实执行”“可观测证据”和“现场硬件实际能力”。平台不产生固定 ECU 合格阈值，不把 MCU ACK 解释成机械到位、ECU 接受或独立测得的物理量。未测的实体能力保持未知。不同型号 ECU 使用各自工程、DBC、配置与测试程序。

## 4. 用户工作流与 UI/UX 属于架构，不是 G4 末期美化

**架构决定 A-03：** Windows 工作台将“工程师能连续完成业务任务”作为完整功能要求，与后台设备/TEST/资源协作同时设计。用户操作链是：打开工程→资源与依赖→打开包或测试项目→直接创建和编辑动作/流程参数→保存/修订确认→运行前检查→实时步骤/设备与 CAN 事实→结果及证据→返回失败步骤修改重试。自动测试优先；专业工具以明确工作入口独立使用。

UI 架构必须可表示：`Workspace/DocumentState`（当前工程及编辑草稿）、`PlanSelection`（本次选中包，不等同持久 Enabled）、`RunPresentationState`（预检、运行、等待、停止、完成、失败以及当前包/步）、`StationPresentationState`（真实设备已知/未知状态）和 `EvidenceNavigation`（从结果回到资源与步骤）。这些是**逻辑职责**，不要求 G4 一次重写全部 ViewModel。

已有 `local@a9a26ebf` 将步骤编辑从旧弹窗迁移到 `TestStepInspector`，添加未应用草稿保护、KEY_SIM 20 开关直接选择、右键等。此前 `local@d57aff53` 旧弹窗与新 Inspector 的重复顶层类型问题，已在后续提交删除旧文件；**不能继续把已修复的静态问题作为待派发任务。** 但嵌入式 UI 的 Build、Windows 鼠标操作、DPI、保存重开与现场认可仍无本稿证据，不得写“已验收”。

**交互边界：** 编辑不触发设备写入；缺失资源/不支持步骤必须明确阻断并帮助定位；运行启动后的步骤不能被新的编辑草稿静默替换；右键/快捷键/焦点/错误提示是 G3 的可操作行为；用户现场评价可驱动同一获准工作包的 G4 多轮修改。浅色、中文、默认最大化、工程树等已验证方向优先继承，但本次不冻结特定像素和最终窗口排布。

## 5. TEST 项目与步骤的运行架构

**架构决定 A-04：** 项目级调度不能简单 `foreach` 调用旧 `ExecuteAsync(TestDocument)`。现有运行器在单包完成后可能执行动作清理、释放 KEY 保持及授权，且每包有独立 RunId。G2 决定以下职责层级：

- **已编辑的 `TestProjectDocument`**：持久资源中的包序、Enabled、固定 Revision/SHA，同一包重复引用以 `ItemId` 区分。
- **当次选择与准备计划**：界面选择本次要运行的包，冻结 TestProject、每个包和其他依赖的指纹，全部预检先于第一条实体写命令；已保存 Enabled 不必每次跟随临时勾选改变。
- **唯一 ProjectRun**：一次项目级 RunID，包含每个 PackageAttempt 的身份、顺序、状态和结果；同包重复引用/重跑不混淆。
- **真实执行内核**：保留 `RealRunCoordinator` 的现有步骤语义，通过明确作用域、事件输出和工位级生命周期支撑组合运行；不能假设已有 SWITCH/WHEN/TryCatch/Subroutine 等均可执行。
- **结果和证据**：保留 StepId + 实际 occurrence（循环/子包）以及真实时间、预期、观测、质量、异常与错误；项目级 PASS 不可掩盖 ERROR/INCONCLUSIVE/UNKNOWN。

**尚待详细设计：** 包级变量和保持状态、每包清理/项目末端清理的责任、默认失败继续策略、运行到/跳过涉及真实物理动作时的许可、界面事件节流、保存证据失败时如何表达。本稿不自动选定具体物理复位动作。

## 6. 硬件、通信与异常责任

**架构决定 A-05：** 真实设备连接事实集中管理，自动测试、独立工具和手动台架不得在同一 USB 主控/CAN1 上并行进行冲突写入。单工位一个运行所有权，可区分只读观察与独占写入。所有授权需要精确对象与生命周期，连接 epoch 变化使旧授权失效。主控 ACK / CAN RX / ECU 响应 / 实体回读按证据等级分离。

IGN、按键与夹具的测试步骤必须可由用户编排；当前 SOL 的完整 TEST Mapping/端口实现不足，G3 应依据真实主控命令、工装及现场能力核对后设计，不以“主控有命令字”冒充工装到位。USB 断连、超时、停机、取消后的恢复与输出状态若未知，必须显示未知，执行器不得据此默认无条件 IGN OFF、松夹具或清零所有按键。DUT 主电源由外部设备控制，不新增假控制步骤。

## 7. 标准波形与比较架构

**架构决定 A-06：** 标准波形取得与自动波形判定是 A 编辑—运行链必需能力，完整独立高级波形分析窗口可在 X 后续扩展。当前可先复用现有采集和命名参考服务，不要求单独开发整套分析软件。

轻量工作流：在工程或步骤界面选择真实 DBC 信号→实际采集→检查来源、时基、丢包、采样与适用工况→工程师明确保存为标准并固定引用修订→测试运行按选择的标准采集实际曲线→判定/解释差异。`WaveAnalyze` 当前会写变量而不是直接产生整个 Run 的 PASS/FAIL；G3 应定义工程师如何通过显式判据使比较影响 Run 结果，不能凭变量存在默认为测试通过。实际判定容差、对齐和多通道需求以现场重复验证决定。

## 8. FLASH-LAB 的准确阶段定位

**架构决定 A-07：** F 是已批准业务交付规划中的并行工作线，但“可以并行”不是“自动获准 G4 写代码”。

- **已有 G2 输入**：Issue #25 对原 CanTool、实际配置 XML、烧录状态机、Seed/Key DLL 静态结构与风险的研究。已知 `SafetyFile.dll` 为 .NET 托管库且没有原生 `ZLGKey` 导出；`sa_demo.dll` 的导出/演示算法不等于 ECU 已兼容。不能重做此项调查，也不能把研究判作实测成功。
- **当前真实代码缺口**：`ProgrammingProfile.Validate()` 仍有 `MockOnly` 约束、`UdsClient.RequestAsync()` 拒绝非只读危险级别服务。独立 WPF EXE 尚不存在；不能宣称现有 Flash 后端可以直接实体刷写。
- **G3-F1 可先设计的内容**：只读独立 WPF 工具的真实 USB/CAN1/ISO-TP/UDS 连接、配置导入、固件离线校验、错误/阶段日志和退出；必要的服务复用与设备独占，明确不启动 0x27/31/34/36/37 等写入过程。
- **F2 的不同门槛**：任何真实 ECU 擦除/下载/安全访问代码和实体操作需先核对目标 ECU、镜像、DLL ABI/合法性、OEM 擦除/校验、CAN 速率及供电/恢复条件，再经专项详细设计与现场操作授权；不得自动放开现有只读/MockOnly 门禁或复制原 CanTool 静默算法回退。
- **交接状态纠偏**：Issue #44 和 `feature/flash-lab-20261114` 保留为任务及准确起点，当前标记 `PLANNED / WAITING_FOR_G2_G3`，**没有 G4 实施许可，不应让另一对话直接按旧任务指令提交代码**。

## 9. 扫码、报告、独立工具与交付版本

**架构决定 A-08：** 扫码在 V1 需要绑定实际 DUT 身份、工程与测试计划，不得覆盖运行中 DUT；完成 RUN/Flash/波形后与同一个可追溯事实关联。扫码本身不等于启动执行。V1 保留原始运行、步骤、设备、波形与判定证据，V2 再依据现场实际需求完善正式报告、历史查询和生产统计；重复扫描/复测不重复计算新增出厂数。专用 CAN、UDS、波形高级分析等工具按实际优先级扩展，必须复用项目与物理会话事实源。

## 12. G2 Gate 候选结论与授权边界

### 12.1 本次提出的结论

建议 **`PASS_WITH_LIMITATIONS`（候选，不生效）**，其理由是：系统责任、已有代码可继承性、用户主业务链、共同事实源、项目级运行身份与物理独占、UI 交互作为系统架构、标准波形和独立烧录的阶段边界已能支持下一步**分工作包 G3 详细设计**，且上列未决事项可附明确阻断条件继续研究。用户可退回本稿或改为不通过；本稿本身不批准自己。
