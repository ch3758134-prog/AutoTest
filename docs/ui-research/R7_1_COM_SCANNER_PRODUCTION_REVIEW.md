# AutoTest R7.1｜生产检测工作区与 COM 串口扫码系统重设计

## 结论

R7 原来的“扫码与工位”是设备维护面，不是合格的生产操作面。原版在同一导航中混入 HID Keyboard / COM / HID POS 等不适用选项，还把本地文本输入直接标记为已识别编号。它不能作为生产 UI 设计基线。

已确认扫描枪输入为 **USB 串口 COM**。产品 UI 只保留这种通信方式。USB 代表物理连接，Windows 通过 COM/CDC 虚拟串口接收；扫描枪具体 COM 号、波特率、数据位、校验、停止位、结束符需和实物一致，当前没有实测默认值。

## 正常生产界面应满足的问题

1. 当前工位是否准备好？
2. 正在处理哪一台 ECU（型号、唯一编号）？
3. 当前阶段：扫码、夹具、实体启动、前置 Flash、全部 Enabled 自动测试、归档？
4. 接下来生产操作员应该做什么？
5. 检测失败时原因是什么？有无真实执行证据，是否需要人工处理？
6. 上一台结果是什么？新扫码不应把旧结果悄悄抹掉。

操作员正常流程：放入 DUT → 扫码枪通过 COM 上报完整帧 → 条码规则/唯一编号/型号/本机工程查找 → 当前工程同型号直接沿用，异型号受控确认切换 → 控制夹具压紧请求 → 若设备确有可验证到位证据则等待该证据，否则不能冒充已确认压紧 → 等待实体 START → 每次完整生产都先烧录 → 烧录有效完成才运行该工程中全部 Enabled 用例 → 保存完整运行证据和单台结果 → 按定义收尾并保持结果等待下一台。

此生产流程依赖硬件和设备服务。实际启动/停止键 USB 事件及压紧位置反馈仍待实物核验，不能在浏览器界面提供“模拟成功”和“空进度条自动前进”。

## 工具/设置分工

- **生产操作**：只看当前编号、当前进度、下一动作、故障原因、上一台结果；不要求操作者每台点击电脑“确认/开始”；不会让工人编辑端口或测试范围。
- **型号工程配置**：由工程师维护一份当前固件、一份原生 Flash Profile、一个型号和一棵有序测试树；生产按全部 Enabled 运行，不使用旧的多层 Recipe/NoFlash。
- **设备设置/诊断**：单独维护 COM 端口、波特率、8N1（如实物适用）、分帧结束符、重连策略和原始 RX 日志；独立查看主控 USB、ECU CAN、KEY CAN、夹具及实体按钮状态。
- **历史与记录**：扫码事件≠检测尝试；同编号可复检，按真实 RunId/InspectionId 区分；生产结果来自 FlashAttempt+CaseAttempt+RECORD，不得仅靠人工扫码写 PASS。

## R7.1 HTML 已改

1. 删除 HID Keyboard/HID POS 选择，扫码接口固定 COM。
2. “生产操作”重设计为单工位操作员主屏：大号当前状态、ECU 编号、操作指引、6 阶段连续流程、真实执行状态、工位阻断和上一台结果。
3. “设备设置”分离到维护入口：真实串口参数配置和原始编号文本解析检查；参数格式检查不冒充实体连接。
4. 人工输入文本仅在维护界面测试候选条码解析，**不会更新生产 scanState**，也不会触发夹具或烧录。
5. 保留工程师工作区、记录页、五种独立工具的原有交互和业务边界。
6. 升级原型时清空此前仅人工验证过的“已识别”生产状态，防止错误恢复虚假扫描。

## 正式 WPF 接线清单（不在 HTML 内伪造）

- SerialPort.GetPortNames 或对应 Windows PnP 枚举；显示当前可用 COM 设备，并在端口断开/重新枚举时给出明确状态。
- 真实 SerialPort 打开/关闭、串口参数保存、掉线重连；以结束符、长度或超时明确分帧，处理一帧拆包、多帧粘连、乱码、不完整帧。
- 串口 RX 原始文本保留时间戳；仅完整有效帧产生 ScannerRead 事件。不要把人工输入框的文本事件当成真实 ScannerRead。
- 同一个 ScannerRead 多次触发时区分重复事件与新的检测尝试；忙时拒绝扫描并记录原因，不自动排队。
- 解析只按发布的条码方案识别型号与唯一编号，跨工程先索引再受控切换；未知/歧义值阻断而不是用字符串 includes 误判。
- 生产状态机由真实 DEVICE、FLASH、TEST、RECORD 驱动；用事件和证据更新进度、阶段、失败原因及报告。
- 把工程调试、串口维护和生产正常操作从角色权限、默认入口及日志上分离；R7.1 HTML 不对正式权限作未批准决定。

## 浏览器回归

- 生产主屏没有生产人工输入或“开始测试”按钮。
- 只有 COM 串口，无 HID/POS 选择。
- 未配置 COM 参数时检查报告明确未就绪；参数格式通过也不显示设备已连接。
- 维护界面合法编号文本可以做“候选规则解析”；型号不匹配被拒绝；两者都不改变生产状态。
- 生产页面持续停留“等待扫码”，Flash/TEST/归档全部未开始；无 JavaScript 运行异常。

**Gate**：本轮是产品设计修订与浏览器操作验证，不是 Windows 串口联调或真实工位生产通过。
