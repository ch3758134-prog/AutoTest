# AutoTest｜P0-08 风险、问题、决策与变更管理

- **版本**：v0.1｜2026-11-12
- **状态**：候审；本文件中的初始风险仅为管理 AI 提议，尚非已正式闭环的风险台账
- **上游**：新基线 P0-01 v0.2、P0-02 v0.1、P0-03 v0.1
- **目的**：在持续实测、专业工具扩展和多方向研发中，及时发现变化、限定影响、落实责任，而不是以重新开始全项目代替问题处理。

## 1. 管理对象

| 类型 | 适用条件 | 最低记录 | 关闭依据 |
| --- | --- | --- | --- |
| 风险（RISK） | 可能发生的质量、进度或安全损失 | 原因、影响、可能性判断、责任、应对、复核触发 | 风险已消除、已获接受或有可核对的降低措施 |
| 问题（ISSUE） | 已观察到的缺陷、冲突、阻塞或证据缺口 | 事实、来源版本、复现或调查路径、影响、责任和处理状态 | 对应修复或补证结果已复核 |
| 决策（ADR/DECISION） | 关键的范围、流程、接口、设计或交付取舍 | 背景、备选方案、理由、批准对象、影响及替代关系 | 决定按批准范围生效且实施/验证关系明确 |
| 变更（CHANGE） | 需要修改已批准工作产品或实际基线 | 旧版/新版、原因、依赖与影响、风险、验证和回退建议 | 新版批准、实施与必要回归分别完成 |

**提出/审查/批准/执行/验证**是不同事件。管理 AI 可以提出风险和影响评估，但不得自行把未批准的变更登记为正式已接受决定。

## 2. 变更影响判断

每次新发现或用户反馈先分类：

- **新事实**：如新的 CAN 原始帧、电压测量、现场接线或故障日志。
- **需求变化**：对期望用户行为、支持对象或合格判据提出新决定。
- **设计问题**：现有模型或接口无法合理支持已确认要求。
- **实施缺陷**：代码或资源不符合当前有效合同。
- **验证问题**：条件、用例、证据或真实观察不足以支持结论。

针对被影响对象沿链路判断：产品目标与用户场景 → 需求 → 硬件/软件与工具责任 → 公共接口 → 具体代码、固件及工程数据 → 测试与报告 → 发布/用户操作。对无影响的环节说明理由，不强制每次全项目重审。

## 3. 处理原则与权限

1. 优先保存原始事实、旧版本和问题复现，不用新实现覆盖无法确认的历史。
2. 对局部无依赖事项允许继续调查或独立研发；涉及不可逆刷写、电源/机械输出、错误生产判定时应停止受影响的现场操作，直到取得许可和充分证据。
3. 重要产品范围、公共契约、被批准需求、正式基线和工程安全条件变更，必须由项目负责人决定相应批准范围。
4. 未确认的研究结论保持候选；因用户反馈产生新的设计方向，先评估与此前批准的工作是否冲突，再进行局部修订。
5. 对已经批准的管理文档，只有经过负责人审查的新版本才能再次写入 `main`；不得修改旧提交来消除不一致。

| ID | 风险或问题 | 当前依据 | 责任与下一核对动作 |

| P0-R04 | GitHub 的宽写权限可能绕过审批工作流程 | 读取当前 main 没有分支保护与 Ruleset | 管理角色提出最小权限和可信发布方案供负责人取舍；不得声称当前强制控制已完成 |
| P0-R05 | 硬件、两套固件、工位与真实 ECU 当前实装身份尚未统一证明 | 历史工程文件≠现役实物 | G0 依据现实设备与安全授权完成身份、连接和证据调查 |
| P0-R06 | 专业工具扩展与自动测试执行间的共享资源和错误处理可能发生冲突 | 产品定义要求工具独立与集成；跨工具契约尚待 G2 | 专业需求/系统架构阶段评估唯一设备会话、资源仲裁、可测性 |
| P0-R07 | 未经实测的 UI/扫码/波形/烧录能力可能被误报为正式交付 | 既有研发历程中多次发生 UI 和真实使用脱节 | 引入按实际操作、台架、跨模块分别验证的交付证据 |

责任是后续**调查与组织责任**，不是给 Codex 发布实施指令。风险排序应在取得进一步证据后结合影响与紧迫性决定，不凭本表编造定量概率。

## 5. 例行复查和升级触发

在负责人批准重要交付、接口更改、专业分支交接、重大缺陷、实机失败、外部依赖变化或发布候选形成时复查相关风险与变更。报告应首先说明对项目目标的实际影响、已经做出的判断及下一项行动，而不是只列风险数量。

对于超出已有批准范围、无法判断安全性或恢复可能性的事项，停止**受影响的执行动作**并提交明确的决定请求；不要把其他无依赖工作全部堵住。

## 6. 本项审批边界

批准 P0-08 代表同意**风险、问题、重要决策与变更的记录、影响分析、职责及处置方式**，并接受首批线索为待调查候选。它不代表这些风险已解决、发布权限已受到强制控制、真实硬件已验收、或 P0 Gate 自动通过。
