# AutoTest｜全新纯 UI 连续研发总计划 v0.2
日期：2026-11-19｜状态：用户授权连续推进至全部代码完成，最后统一验收。
## 准确工作边界
这不是旧 G4 UI 改造。本阶段不连接 HOST 的 TEST/PROJECT/DEVICE/FLASH/WAVE 等业务服务，不产生 ECU 实测结果。旧 Desktop 的窗口/VM/样式/编辑器移除后以纯 UI 产品重建。物理控制和正式运行均不能被界面草稿冒充。
设计研究依据：既有 R01～R06；它们是研究候选，不是全部 UI 已经过用户验收。当前用户批准本规划工作方法，不等于批准具体页面和体验。
## 连续批次
P-01 产品与来源事实；P-02 任务、信息、窗口架构；P-03 共性视觉/命令/状态。
A-01 Shell、空工程入口和会话；A-02 资源与工程工作区。
B-01 测试项目；B-02 三阶段步骤编辑；B-03 分支/循环/公共流程；B-04 资源映射和参数；B-05 运行与调试交互。
C-01 DBC；C-02 CAN；C-03 综合台架；C-04 输入配置；C-05 UDS；C-06 Flash；C-07 Wave。
D-01 生产扫码；D-02 记录报告；D-03 设备管理。
E-01 窗口/导航/状态/性能统一回归。
## 每批合同（R/D/C/V/F）
R 研究：场景、对象、成熟方案、反例、证据/假设；D 设计：工作流、状态、命令、视觉、空/错误状态；C 实现：本批真实纯 UI 可操作源码；V 检查：静态检查、用户任务脚本、Windows 编译状态；F 归档：提交SHA、变更、未验缺口、下一批依赖。每批不单独等待用户验收，最终完整UI由用户统一实测。每批验证结果只能在已执行时声称通过。
## 验收禁区
不延续旧 UI；不假造硬件消息、PASS、ACK、RunRecord；不要求用户逐步批准页面；不将用户认可流程误当设计已冻结；不将可点击但无行为的按钮标作完成。
## 工作纪律
GitHub feature 分支交付，main 未批准不写入。窗口环境纯 UI，草稿存储与真实业务文件彻底分离。部署、Windows/WPF 构建需要本地 Codex 验证；若当前环境没有 dotnet，则记录 NOT_RUN，不伪称PASS。
