# Codex｜远程任务发现与本地空目录执行协议（候选 V1）

目标：用户主动打开 Codex，指定一个空目录，Codex 通过已绑定的 GitHub 管理仓库发现自己应执行的任务，核对后直接准备本地源码并工作。

## 关键区别

- **空目录**：本地实施位置，不是项目或仓库的身份凭证。
- **仓库关联**：需要已知或一次性绑定 GitHub 的仓库 URL。不可从任意空目录自动推断远端。
- **任务登记**：[`dispatch.json`](dispatch.json) 是 Codex 任务发现入口。正式计划和阶段审批分别存放；不能因为一个规划任务存在就开展代码实现。
- **任务来源**：单一任务明确绑定项目、来源仓库/分支、最低祖先 SHA、设计/研究输入、允许文件范围、输出和禁令。
- **工作区**：用户指定空目录后只在其中克隆一份相应源码；不要把其他 PR 的检出版本混在同一目录。
- **执行**：`resolve.py` 只负责本地读取/核验任务以及记录执行基线，**绝不自动执行需求不明的编码、Git push 或删除**。

## 常规自助流程

1. 通过 GitHub 连接或已安装的全局仓库入口读取根目录 `CODEX_START_HERE.md`，定位任务登记。
2. 选择任务：明确任务 ID 优先；否则只在**恰有一个**就绪且授权为 Codex 本地实施的任务时继续。
3. 对该任务做代码与设计准入判断。登记里所有 `inputs` 都必须读取；如果未批准的工程输入被当成正式实施依据，应停下来提出问题。
4. 核查用户给定空目录真实为空，既有目录、链接或不可读目录不得覆盖。绝对不要自行删除别处以腾出目录。
5. 按记录的准确 GitHub 仓库和分支执行受控 `git clone --branch <source_ref> <repo_url> .`，而不是从网页拷文件、随便选最新 PR。
6. 校验 `git remote get-url origin`、`git rev-parse HEAD`、`git merge-base --is-ancestor <minimum_sha> HEAD`；调用 `resolve.py select` 和 `claim`。如果环境已是已有工作区，不可当作全新空目录重置。
7. 创建任务独立本地分支，按 `allowed_paths` 修改本地文件。任何超范围修改、方案未明或缺少授权，向工程协调报告，不自行扩权。
8. 本地测试，先核对更改范围再提交；结束时运行 `verify-scope`，报告确切 SHA、证据、工作区实际位置和保留/回收状态。
9. 按 `restrictions` 决定是否允许 push；默认禁止。不能自行发布 Gate、合并 PR、终止旧进程或回收未知目录。
