# AutoTest R1｜首次交付候选 UI 全面审查与现场实测准入

> 时间：2026-11-11。适用范围：正式 Windows WPF AutoTest Desktop 和从主界面实际可打开的专业工具。本文件用于研发与交付复核；**不是**程序运行时的产品定义或硬件能力承诺。实机验收依据必须来自实际 ECU、主控板和按键板。

## 1. 产品定位及审查结论

本候选定位为**真实用户可以直接开始现场操作、采集问题并持续完善的首次交付候选**，不是演示软件、模块测试板或 Mock 设备界面。不得将编译通过和人工确认框出现等同于真实 ECU 动作或测试 PASS。

本次审查覆盖：
1. 实际可达的 Main Shell / 工程树 / 自动测试 / TEST 程序编辑
2. 独立手动台架、CAN1 发送、CAN1 ECU 广播接收、工程按键动作与 20 Key 步骤编辑
3. 主控连接/WinUSB/双路 CAN 只读诊断
4. DBC 编辑、CAN 烧录、UDS 诊断、波形采集判定、控制器按键电压、扫码与生产、记录与审计
5. 对象左右键行为、焦点、滚动、空状态、执行/取消、主控 ACK 与 ECU 实际反馈边界
6. 用户语言、工程存档及 Windows 编译/模型测试/启动

**审查原则**：业务含义与执行门禁不能因更换控件受到改变；优先减少理解和操作成本，避免向普通用户展示内部阶段号、LAB 测试术语或未解释的状态码。

## 3. 首次现场实际操作路径

### A. 首次启动与工程准备
- 打开 AutoTest，确认主界面是工程与 TEST 结构，不出现旧模块页堆叠。
- 新建/打开工程并保存。导入当前 ECU 的 DBC 并加入工程资源，必要时配置 Controller。
- 通过工具导航打开“主控板连接”。核查接线、供电和 IGN 初态，选择真实主控板，连接 WinUSB。
- **不能**由软件 GPIO 回读推断实际电压、夹具已经到位、ECU 已经上电。

### B. 手动台架（优先实测）
- CAN1 发送：选择 DBC 报文或新建原始报文，编辑 ID、DATA 和周期；勾选欲周期发送的行，点击发送；可停止发送或单发选中行。
- 中栏按键：新建任意命名的动作按钮，右键进入编辑，用 K01～K20 设置每一步完整开关状态和保持时间；保存配置，或明确授权实际试运行。
- IGN 与夹具独立操作；发送与实际机械反馈区分。
- 右栏接收：默认按 CAN ID 更新，必要时切换原始接收流水。以实际被测 ECU CAN1 广播判断响应。
- 按键板 20 开关合成 **5 路模拟电压**，不是 20 路独立电压通道。主控 ACK 不证明 ECU 已识别目标按键。
- 未保存工程可进行临时 CAN 与按键动作试发，**保存配置**需先保存工程；切换工程后不可沿用之前工程的数据状态。

### C. 由手动研究进入 TEST 程序
- 在 TEST 编辑器以中文类型添加测试用例、结构步骤、变量、条件、等待和控制器状态，右键可以操作所指步骤。
- 配置真实控制器状态及完整清理逻辑，保存测试程序到工程并保存工程文件。
- 自动测试页先预检，再在设备可用和有实际步骤许可时执行；结果由真实观测与执行事实组成，不由界面模拟一个 PASS。

### D. 其他专业工具
- UDS 仅以当前真实适配器支持的可执行诊断服务开展实测；其他服务不因界面可编辑就认为允许物理发送。
- CAN 烧录要使用 ECU 匹配的配置、固件、Seed/Key 算法库与安全授权。配置解析、主控 ACK、擦写阶段响应和 ECU 实际成功必须分别判断。
- 波形捕获/参考/比较、扫码生产、报告与审计必须由真实数据闭环逐项验收。

## 4. 可验证的结论和绝不能提前宣布的结论

| 检查类别 | 可用证据 | 结论边界 |
| --- | --- | --- |
| 代码结构与界面对象 | GitHub 精确提交、WPF 源码差异、审查约束 | 可以确认已按规则修改；不能代替打开窗口视觉检查 |
| Windows Release | Actions 编译、发布与 WPF 启动检查 | 可以确认可编译/启动的候选，不证明每个窗口无遮挡 |
| Desktop/Devices 模型测试 | 自动化测试记录 | 可以确认模拟端口的编辑/约束逻辑和设备命令栅栏；不是实际 ECU 电气通过 |
| 现场鼠标与窗口检查 | 本地运行截图、逐工具交互记录 | 必须覆盖右键目标、停/启按钮、弹窗归属、大小和 DPI 下的可用性 |
| ECU 真实实测 | 设备会话、CAN 原始帧、现场波形、烧录/诊断数据 | 只有实机日志和独立实际观测才能对外宣布相应能力已验收 |

### 尚待现场证据的项目

- 真实 USB 主控连接/断开/重连和多设备选择
- ECU CAN1 实际广播解码、CAN1 多帧发送在物理总线的实际效果及 Windows 定时偏差
- KEY_SIM 20 开关组合与五路真实电压、ECU 按键识别结果、夹具及 IGN 真实反馈
- UDS 实际请求与 ECU 响应；完整烧录流程、真实 Seed/Key 与断电/失败恢复
- 多窗口在使用设备的目标分辨率、缩放比例、外接屏幕下的操作验证
- 工程旁附属 `.bench-actions.json` 与 `.bench-can.json` 配置文件在备份、迁移、交付归档时的随行问题（当前并未改为工程内嵌资产）

**审查结论**：按首次**现场实测完善**候选交付软件；未经实机、窗口截图和项目迁移验证，不能标记为最终验收通过，也不能生成“所有功能实测合格”的结论。
