## 一、问题到底在哪

1. 上轮大架构已收敛为单 ECU 工程、唯一有序 TEST、独立资源编辑、生产扫码匹配完整工程、真实 FLASH→TEST→RECORD，但详细设计仍从已有 `StepNode`/XAML/工具弹窗长出来。拥有“步骤选择器”和“检测工程”窗口，不等于用户能不费解地操作。
2. 当前存在**三个相互不完全等价的步骤目录**：`StepDescriptorCatalog.Builtins()`（结构/可执行标志）、`StepUiCatalog.Choices`（展示及 Runnable）、`TestStepInspector.Options`（用户动作/作用目标），`StepActionPaletteCatalog` 再根据可见项选分类。现有筛选修复只消除了空白类别；**没有解决用户感知动作、结构节点、条件字段、执行器、报告相互不一致的问题**。
3. 当前 `TestDocument` 固定 Prepare/Test/Cleanup，`TestEditorViewModel.RefreshTree` 每次重建三类阶段。用户已经要求这些不是不可取消的固定编辑负担；运行器内部的设备资源收尾也不能与用户的 Cleanup 误认成同一事务。
4. `CanStopPeriodic` 现只有全部停止，无法在插入动作处明确停止一条正在跨用例发送的物理 CAN 任务。
5. `TestStepInspector` 仍把大量步骤参数从原始字符串字典汇总成 `ParameterFields` 文本框；只有 CAN/KEY/部分信号有专用面板。用户面对“variable/equals/target”等术语，不是自然地配置 ECU 条件。
6. `TestEditorView.xaml` 中步骤选择器用 `Popup StaysOpen=False`，列表条目仅 `FontSize=12`、插入位置提示 `FontSize=11`；复杂 CAN 编辑区域左右 `MinWidth=335 + 12 + 330=677 DIP`，而 Shell 属性栏通常约 350–440 DIP，不能简单缩小窗口来解决。
7. `ProductionProjectLibraryWindow` 是独立的大弹窗：顶部查询、默认空的本机列表、下部型号标记和试扫、隐藏的“跨电脑导入导出”、整体滚动。用户没有保存到**生产副本库**时看不到原先工程，而界面没有把“工程开发中真实存在的 ECU 工程”和“工位内部的生产快照”解释成一种自然连续的操作。这正是截图“我这里没有工程”的主要可见产品原因；仅凭截图不能证明该工程文件是否真实存在。
8. 工程首页和资源页是静态概要卡片；步骤工作区、工程库、各专业工具采用不同的命名/保存/编辑浮层/空状态/状态栏，不存在统一的用户交互语言。
9. `PublicFlowEditorView` 已可编辑步骤，`TestStepInspector` 可引用公共流程，`PlanCompiler`/`RealRunCoordinator` 无 `CallPublicFlow` 完整执行。仅在添加面板隐藏它不算需求完成。
10. `ProductionInspectionArchive` 存单台父记录；`RecordHistoryWindow` 主要查询项目中的 SQLite 子用例记录，用户一次生产的完整结果不形成同一查询/报告体验。

### 两张现场截图的直接评审

**截图 A｜“添加测试步骤”**：类别只是一排抽象标签，没有把“CAN 操作”“等待信号”“测试判定”“IF 分支”等不同目的按概念清楚区分；2 列同质灰按钮缺乏强弱层次；当前插入位置写成“测试 / 测试 (0)”之类技术路径；缺功能说明/示例/插入结果预览；输入区域和字体偏小。**不是再加几种步骤按钮可以解决。**

**截图 B｜“检测工程”**：标题未说明现在在“工程开发/生产检测”的哪个任务中；工程清单为空还被迫展示巨大的固定 DataGrid；关联和试扫位于底部，要滚动；“跨电脑工程包”这种少见操作比“使用已保存 ECU 工程”更显眼；常见动作没有一条无歧义的主路径。**不能通过多加提示文字让旧窗继续成立。**

## 二、统一的用户任务与对象归属

| 用户任务 | 看到的真实对象 | 在界面上完成的结果 | 内部实现允许存在、但不得向用户强迫学习 |
|---|---|---|---|
| 新建 ECU 工程 | 工程名称/当前型号、唯一 TEST、资源入口 | 创建后直接打开首个用例并能编辑 | manifest、resource ID/hash、revision |
| 编辑 TEST | 完整用例/有序项目/步骤/分支 | 修改后自动保存，立刻可继续编辑/调试 | StepNode、Mapping、事务/编译缓存 |
| 调试 TEST | 当前选择的步骤/用例/范围及 CAN 实时证据 | 单步、用例、选中范围、整项目 | 实体授权/USB lease 由真实动作服务拥有 |
| DBC | 独立 `.dbc` 文件、工程关联的唯一 DBC | 新建/导入/编辑/另存/导出/绑定 | parser、指纹、底层源文件保护 |
| 波形 | 多路信号、同次采集、标准、比较方案 | 采集/建立标准→在 TEST 选择→有真实判定和证据 | 采样缓冲、时间质量/算法快照 |
| 公共流程 | 可复用的真实步骤树 | 编写→在任意用例调用→参数和返回值→运行证据 | 稳定资源 ID/版本/调用闭包 |
| FLASH | 工程内原生烧录参数+固件 | 配好真实文件和 ECU 参数，正式检测每次自动前置烧录 | job freeze、HEX 安全文件、诊断底层接口 |
| 工位调试 | USB/CAN/夹具/IGN/KEY_SIM/扫码枪 | 验证实物控制和观测，不改变工程 DSL | 设备独占和实时会话管理 |
| 正式检测 | 完整扫码号和一个匹配工程 | START→夹具→ECU CAN→FLASH→连续 TEST→报告/释放 | 工位内部只读版本快照，不是第二个业务配方 |
| 检测记录 | 一台 ECU 的一次完整检测 | 复检历史/单台报告/批次统计/步骤证据 | 归档/索引/报告渲染和各级外键 |

普通操作面不再并列出现：`工程检查`、`生产准备`、`检测工程库`、`发布`、`保存工位部署`、`启用测试方案`、`可信准入` 等重复中间层。“真实硬件当前不具备某条件”只在明确执行动作附近显示原因，不变成另一套人工许可系统。

## 三、必须从领域到 UI 只定义一次的 Step Action Contract

目标为一份机器可读取的**动作/控制节点定义**（Testing.Authoring 内部，不需要新的用户 DSL、第二执行器或额外插件平台），每个语义声明：

`ActionKey / NodeType / Version / DisplayName / Category / AllowedInsertionSlots / TypedInputs / Outputs / ConditionSource / EditorKind / Defaults / SynchronousFieldValidation / CrossStepValidation / RuntimeHandler / ExecutionStatusAndEvidence / Reversibility / ResourceEffect`。

UI 只是这些定义的投影，不能再在 `TestStepInspector.Options`、`StepUiCatalog`、`StepDescriptorCatalog` 分别靠字符串猜功能。运行器与静态分析用相同 AST 字段/类型；未实现的类型不能出现在“可新建的正式步骤”列表中。**编辑已有文档不等于可以在正常工作流中继续创建不可运行的节点。**

所有输入分为：
- **即时可判定错误**（范围、数据长度、重复 CASE、非法比较操作、无界循环、非法 DBC 定义）→ 字段原位提示；用户草稿保留，不将坏定义写入正式工程。
- **工程关联错误**（资源缺失、引用版本变化、无来源变量、循环引用）→ 当前步骤和相关资源位置显示；可直接跳去修复对象。
- **运行事实**（真实 USB 断线、CAN 超时、ECU 无响应、FLASH 失败、记录写盘失败）→ 仅运行时报告；不能把“没有实物连接”作为日常编辑的阻断理由。

运行状态必须区分：`NotRun / Running / Completed / DUT Pass / DUT Fail / NoData / TimedOut / Interrupted / ExecutionError / CleanupUnknown / Skipped`。Control/Write 的 Completed 不可机械地升级为 DUT Pass；“IF TRUE”“USB ACK”“发送任务启动”尤其不是功能检测通过。

## 四、TEST 全部语义逐项裁决（包括当前缺项）

**标记**：已接线＝源码至少存在结构、编译和真实 Runtime 路径；不代表实机验证。未接线＝新增路径不能宣传为可运行。缺失＝当前 DSL 无对应节点/参数。以下“目标”是这次 UI/运行重构设计，需以端到端实现作为完成判据。

| 用户动作/节点 | 当前 R1 事实 | 目标语义和编辑方式 | UI 决策 |
|---|---|---|---|
| 发送 CAN | `Write` 已接真实端口 | ID、帧格式、DLC、完整原始字节；单发/周期；周期保留到明确停止/截止/运行作用域结束 | 专用 CAN 双区域编辑，数据在左，DBC 辅助在右 |
| 周期 CAN 管理 | `CanStopPeriodic` 仅全部停止 | 停止选定任务/ID、全部停止、同 ID 更新、跨用例持有，状态可观察 | 主表/步骤插入显示明确“停止某报文”与“停止全部” |
| KEY_SIM | `Write` 已有按键通道 | 20 Key 组合、设置并保持、显式全部断开、保持/等待；保持时间到期**不自动释放最后组合** | 一组可点击 Key，最终组合预览，不用“旧版短按后释放”作默认 |
| IGN | `Write` | ON/OFF 明确，主控读回与 ECU 响应分别说明 | 两态动作按钮，保留结果与读回 |
| 读取 CAN 信号 | `Read` | 从 DBC 选择、Latest/Next、新鲜度、超时、输出变量；不自动判定 | 信号选择器+示例值+输出名 |
| 等待信号 | `WaitUntil` | 实时新鲜观测，条件满足/超时/无有效数据区别明确 | 统一条件构造器；不属于“普通固定延时” |
| CAN 信号判定 | `AssertSignal` | 有效数据/期望/时间窗/失败判据和证据，支持真正的 ECU PASS/FAIL | 与等待信号共用条件组件，显示“产生检测结论” |
| 固定等待 | `Wait` | 纯时间，不隐式修改 CAN/KEY/IGN | 一行可直接改毫秒，不需要复杂弹窗 |
| IF / ELSE | `If` 已接线，主要引用既有变量 | 允许直接选择已定义变量**或**DBC 信号条件；TRUE/FALSE/UNKNOWN；UNKNOWN 不走 ELSE | 创建即显示 THEN/ELSE 两个可插入分支，条件一行可读 |
| ELSE IF | 当前无独立模型 | 按顺序的多个条件分支，最后可选 ELSE；不许把多重 IF 的 UI 复杂度强迫给用户 | 在 IF 内“＋ 否则如果”，不是主步骤类型 |
| SWITCH / CASE | `Switch/Case` 已接线 | 唯一命中、最多合法 CASE、可选 default、禁止 fall-through；无数据不选 default | 插入 SWITCH 自动给“＋ 添加匹配项”与“默认分支” |
| 固定次数循环 | `Loop` 已接线 | 有界 N 次、每次迭代真实证据、取消/异常终止 | “重复 N 次”行内可改，直接显示循环体 |
| 条件循环 | 当前缺失 | 必须有最大次数/总时限、条件数据有效性；不能无限运行 | 作为循环模式而非制造新的无界脚本步 |
| BREAK / CONTINUE | 当前缺失 | 仅最近一层合法循环，明确退出/跳过本次迭代 | 仅在循环体中出现上下文命令，不占全局常用列表 |
| WHEN（等待条件再执行） | `When` 尚未接线 | 新有效观测、持续稳定时间/次数、超时后如何处理；满足后执行子步骤 | 只有接通 Runtime 后才作为“等待条件后执行”呈现 |
| TRY / CATCH / FINALLY | `TryCatch` 尚未接线 | 只接可恢复领域错误；绝不吞 USB 不可确认/外部 STOP 并伪造 PASS；Finally 在合法退出时尝试 | 三分支可视化，类型化错误选择，不暴露底层异常类 |
| Retry | 当前缺失 | 动作/等待的**显式策略**，仅幂等/可重试的动作可配置；保留每次 Attempt | 在动作高级选项设置，不能把副作用整个用例盲目重放 |
| Timeout | 部分动作字段具备 | 动作/等待/调用的限定时间及真实取消语义，不能自动得 DUT FAIL | 只在相关步骤显示，不另放空泛“超时步骤” |
| 步骤分组 | `Sequence` 已接线 | 有序可折叠容器，不单独产生 DUT PASS | 在步骤树提供“组合为分组/取消分组” |
| 公共流程调用 | `CallPublicFlow` 可编辑、不能运行 | 选已有流程、明确输入输出、本次调用ID/固定引用版本、无递归、真实执行及记录 | 在插入“复用流程”分类显示，支持双击跳转 |
| 内部子程序 | `Subroutine/CallSubroutine` 尚未接线 | 复用优先使用公共流程，确有局部功能时再作为命名作用域；不与公共流程重复造平台 | R1 主菜单不同时提供两种含义难辨的“子程序” |
| 设置/计算变量 | `SetVariable/Calculate` 已接线 | 类型/作用域/单位/来源、明确数值计算及空值，不允许瞎猜全局名 | 变量选择和计算式编辑，输入/输出来源可追踪 |
| 比较/期望判定 | `Expect` 已接线 | 数据值≠执行状态≠ ECU 判定，引用实际观测须有证据血缘 | 专用断言表单（左值/运算/右值/容差与质量） |
| 波形采集与分析 | `WaveStart/Stop/Analyze/Compare` 存在真实路径 | 多路同次采样、时基/丢帧质量、已确认标准、比较结果与证据闭环 | 工程内选择波形标准/判据，不编辑原始文件路径 |
| UDS 服务 | `UdsRequest` 仍未接 TEST Runtime | 与独立 UDS 工具共享已经验证的诊断服务合同（首个版本按实测服务范围逐步开放） | 未支持前不要出现“可运行 UDS 步骤” |
| FLASH | 已被用户决定为**正式测试前置** | 不作为 TEST 步骤，不允许通过 TEST 禁用前置烧录 | 从 TEST 步骤菜单永久剔除 |
| 并行与任意 GOTO | `Parallel` 非可执行 | 单工位共享 USB/ECU 资源，R1 不设任意并行和 GOTO | 不展示，不新增第二引擎 |

### 关键语义定义（所有条件共用）

统一条件编辑模型：**来源**（当前 DBC 信号/有类型变量/真实步骤输出）→ **比较**（==、!=、>、>=、<、<=、区间/状态条件按实际类型）→ **目标值**（常量/另一个有来源值）→ **数据有效性**（时间新鲜度、采样质量）→ **最大等待时间**（仅适用的等待与判定节点）。

条件求值至少 `True / False / Unknown / Error` 四种，Unknown 绝不被当成 False 或“默认分支”。`IF` 用条件选择路径，本身不构成测试 PASS；`WAIT` 是等待时间，`WHEN/WaitUntil` 等待真实条件，`AssertSignal` 是具有预期和时限的 ECU 判定，**用户必须看得出这几者区别**。

变量默认用例局部，不允许靠同名字符串跨独立调用任意读写；已经确认需要跨用例共享的项目状态使用明确的项目作用域/显式输出绑定，并与当前已实现的连续运行变量行为统一。`CALL` 的输入/返回映射必须可审计。循环每次 Iteration 与调用每次 Occurrence 均有独立记录路径。

### 本次对“流程控制”界面重新分组（展示优先，不等于马上全可运行）

- **条件分支**：如果…否则如果…否则；按值分支（SWITCH/CASE）。
- **循环和中断**：重复 N 次；有上限条件循环；在循环内“结束循环/跳过本次”。
- **等待与超时**：等待时间；等待信号；等待条件后执行；超时作为局部高级参数。
- **容器与复用**：步骤分组；调用公共流程。
- **异常恢复**：尝试/按可恢复错误处理/最后执行；可重试策略作为动作高级属性。

主选择器默认优先**实际可执行**的小集合；尚未接通 Runtime 的目标能力只能进入设计/开发待实现列表，不能作为正式测试可添加按钮。CASE、ELSE IF、BREAK/CONTINUE、FINALLY 等依上下文产生或定位，不应在全局“添加测试步骤”中占据和 CAN 同级的大方块。

## 五、统一 TEST 编辑器：具体外观与鼠标操作合同

### 5.1 主界面布局

`主窗口：顶部当前 ECU 工程 + 保存状态 / 左侧唯一有序 TEST 用例树 / 中央真实步骤树（最大面积） / 右侧按需编辑面板 / 最右侧可折叠 CAN 实时观察`。不需要“工程检查+参数面板+底部日志”三套长期占空间。

- TEST 项目序列在左侧；单击用例打开/切换且不生成预览垃圾标签；双击或 F2 修改名字，选中用例显示当前测试步骤。
- 中央步骤列表常驻。列：序号/缩进层级、步骤与关键参数摘要、是否本次调试选中、断点、实时状态、耗时/失败原因。子树可展开；搜索仅高亮和滚动，不丢失展开或选择。
- “准备、测试、清理”不是每个用例默认必须出现的三条巨大固定行。普通用例默认一条连续可编辑测试步骤列表；若需要显式准备与清理，可从**用例阶段**显示/添加并折叠。**项目级准备/收尾** 属于唯一 TEST 项目的显式有序步骤作用域，不允许夹具扫码与前置 FLASH 误入此树。
- 工位设备释放与项目资源清理由执行器单独拥有，不等于某用户选择隐藏的 `Cleanup` 节点。
- 顶部主操作：`＋步骤`、`运行当前步骤`、`运行本用例`、`运行到此`、`停止`。整项目/勾选范围在项目视图，调试入口不挤满用例工具条。
- 选中当前行总能看出插入点：鼠标悬停行间有细 `＋`，分支空槽显示“＋ 添加本分支第一步”，菜单只含合法动作。可 Ctrl+Space 全局搜索，Enter 选择、Esc 取消。
- 新增步骤**先在当前位置显示临时编辑行**，随后打开与该动作匹配的编辑区域；草稿不参与正式运行或自动保存；完成才提交，取消后行和临时资源引用消失。后续普通字段有效修改自动保存，无日常人工确认门槛。
- 复杂编辑器不会因点击其它区域自动消失；显式完成/取消，始终允许原位修正非法输入；离开有编辑草稿时说明具体未完内容而不是弹泛化错误。
- 波形、DBC、公共流程可在选择器中按工程资源选择；缺资源时就地提供“去工具建立/绑定”而不丢失当前步骤草稿。

### 5.2 步骤插入器，不再使用现在的统一灰按钮网格

主窗口内从当前 `＋` 打开轻量命令面板：顶部是**插入位置**（例如“静态驻车 / 循环第 2 步之后”），中间搜索与“常用｜CAN/工位｜读取｜判定｜流程｜波形｜复用”类别；每项有 1 行可识别标题 + 最多一行实际作用解释；右侧或下方出现样式一致的插入预览（例如“CAN1 · 0x123 · 单次 · DATA 00 ...”）。窗口较窄时不强制两列。

关键：用户点“IF”后**先看到 IF 条件+ THEN/ELSE 的步骤树与两个独立插入入口**，不是跳去一堆 property 字符串；点“循环”后先看到“重复 [2] 次”和可插入的循环体；点“CAN”后直接进入真正完整字节面板。

### 5.3 六类专用步骤编辑组件（共享外框/撤销/错误呈现）

1. `CanFrameEditor`：CAN1 通道、ID、标准/扩展、DLC、逐字节 HEX、发送方式（单发/周期/持续/指定时长）、实时预览；DBC 报文/信号辅助与原始字节同步，拒绝越界而不改坏帧。使用可分离的宽工作面板，低宽度单列，绝不放在 350 DIP 侧栏里硬塞 677 DIP 双列。
2. `KeyActionEditor`：20 个真实 Key 可点选、组合预览、保持时间和后续状态。操作语义只有设置保持/显式释放/纯等待（纯等待属于 Wait），不能用“保持时间到期自动释放”误导用户。手动台架和 TEST 共用此输入语义。
3. `SignalConditionEditor`：搜索 DBC 信号或 typed 变量→比较符→目标→新鲜度/等待时限→输出变量/是否形成测试判定。IF、WHEN、WaitUntil、AssertSignal 采用同一条件来源，不通过四套字符串字段区别。
4. `FlowStructureEditor`：直接编辑多分支、CASE 值、循环次数和中断上下文。每一分支可插入、复制、整体折叠、显示不可达/无数据路径；条件无需另一个悬浮对话框层层套娃。
5. `WaveJudgeEditor`：多路信号、命名标准、采集范围、同步/覆盖/对齐、误差、最终判定与证据质量，可跳到真实波形工具；分析数据与 TEST Verdict 明确分离。
6. `PublicFlowCallEditor`：流程选择、输入/输出映射、当前调用来源、修订差异、跳转到公共流程、影响范围及状态，不要求手输 AssetId/SHA。

小步骤 `Wait/SetVariable/Calculate/IGN` 优先行内编辑或紧凑卡片，避免每次弹大窗。UDS TEST 动作真实接入时也应有独立 typed 服务编辑卡片，与 UDS 专业工具共享服务目录。

### 5.4 自动保存、切换、撤销与异常

- 所有修改复用同一编辑事务：新建、改值、拖放排序、复制、删除/取消、资源绑定，均有可撤销的用户意图。
- 自动保存只提交**合法完成的对象**，与运行中冻结的执行快照互不干扰；不能因为草稿有未填字段而使已存在的合法工程突然无法保存其他对象。
- 本地关闭窗口/切换工程，已合法编辑自动保存；未完成草稿留下明确原位状态，允许继续/放弃，不反复弹通用保存确认。
- 结构性错误反馈定位到步骤行、字段/分支；真实硬件异常定位到相应设备/步骤和证据，不说“工程操作未完成”而不指出对象。

## 六、检测工程库：重建截图 B 的对象与操作

### 6.1 用户应该看到的

“工程”只有一个认知对象：**已保存 ECU 工程**。后台为了防止编辑中途改变正在生产的固件/TEST，可以内部复制一个不可变执行快照，但这只是实现，不产生“测试工程”“生产工程”“发布包”“检测工程库”四个需要用户自己区分的对象。

- **常用路径**：新建/打开 ECU 工程 → 编辑 TEST/DBC/波形/FLASH → 切换生产检测 → 系统使用这个完整已保存工程的有效快照 → 扫码原文直接显示 → 命中固定标记 → 开始检测。若缺 HEX 或没有真实判定，打开工程和编辑不受阻，但正式启动处明确缺哪项资源。
- **首次没有工程**：不是一张 226px 高空表格+远处的关联栏，而是中央简洁空状态：`打开 ECU 工程` / `导入工程`；导入可以选择当前受支持的工程清单/工程目录（具体可支持文件形式要与唯一工程协议一致），不要把跨电脑归档格式当普通工程的唯一入口。
- **切换型号**：一个可搜索的型号/工程列表，当前项可见 DBC、TEST 数、固件与固定识别标记。选中后旁侧直接设置/试扫；冲突在同一项解释，普通操作不滚到窗底才能发现。
- `*.atpkg` 等跨电脑传送如仍保留，应放在“更多/工程移交”且只对需要者可见；这不是同电脑生产前要手动导出的“发布”步骤。
- 工程和标记保存后，下次扫码直接匹配整个工程；不要再为生产端单独选择用例、DBC 或烧录参数。
- 在生产状态优先显示完整扫描原文与“选中了哪个工程、为什么失败”，不能静默置空。

### 6.2 对当前窗口的直接处理裁决

`ProductionProjectLibraryWindow.xaml` 的大型嵌套 `ScrollViewer + StackPanel + 固定高度 DataGrid + 多个说明卡片` 不宜作为正式操作入口保留。**整体替换为工程选择/绑定/试扫同屏工作区**；只有跨电脑归档保留高级工具入口。移除“空列表还强制显示大白表”“关键关联藏在滚动底部”的交互方式。

## 八、统一 WPF 视觉与控制部件参数（验收用，不是当前已实现）

### 8.1 页面层级与阅读

- 主题固定浅色：主背景 `#F7F9FC`，编辑工作面 `#FFFFFF`，一级文本 `#243548`，二级文字 `#526579`，边框 `#DCE4ED`。主交互蓝色、执行中信息蓝、成功绿、失败红、未知琥珀。色彩只辅助，不作为唯一状态编码。
- 普通正文不低于 **14 DIP**；输入字段/表格主数据 **14–15 DIP**；主要页标题 **20–24 DIP**；卡片/区域标题 **16–18 DIP**；只有非必要元信息可用 12–13 DIP，不能用灰淡 11 DIP 承载关键操作与插入位置。状态信息要同时有文字、必要时图标。
- 正文与背景目标对比不低于 WCAG AA 常规文本 **4.5:1**；实际 WPF 截图测量确认，不仅看 XAML 颜色。禁用态可以弱化但不可让用户无法理解为何不可用。
- 基本输入框/按钮高度 **34–40 DIP**；长表步骤行 **36–42 DIP**（现阶段 35 左右目标）；表头约 40–44 DIP；触发器和拖动命中区实测。禁止仅靠占用大块空白营造现代感。
- 空状态**立即告诉用户能做的下一件事**；正常有数据时不放冗长的设计原则/内部术语/“请先……”说明。

### 8.2 宽度/DPI 与浮层

- 必测 `1366×768 @100/125/150%`、`1920×1080 @100/150%`。测试以物理可见区域和 WPF 逻辑像素双重核对。
- 根据内容动态布局：主步骤列表优先宽；CAN 双区在 ≥约 820 DIP 的编辑工作面才并排，不满足则垂直堆叠/可移动独立编辑窗。任何 350 DIP 侧栏都不能被带有 677 DIP 硬最小宽度的复杂面板撑爆。
- 临时步骤选择器可以 `Esc` 退出；**正式参数编辑、资源编辑、有效草稿**必须显式完成/取消，不允许一次空白点击把未应用数据丢掉。
- 每个弹窗/浮窗负责唯一任务；主窗菜单不会打开一串互相嵌套的“设置→绑定→工程→资源”窗口；关闭主窗时所有 owned tool windows 正确清理。
- 鼠标单击/双击/F2/Enter/Esc/Ctrl+Space/Ctrl+Z、焦点/输入法、高 DPI、键盘 Tab 顺序必须跨工具一致。每个按钮有实际动作，关键入口不能只出现在右键菜单。

## 十、设计验收关口：按真实任务走，不以截图或自评分替代

| 场景 | 通过条件 |
|---|---|
| 从无工程到首个 TEST | 新建→直接可编辑首用例→插入 CAN、KEY、IGN、Wait、IF、循环→连续修改→自动保存→退出重开精确还原 |
| 插入所有合法步骤 | 每个类别项都能创建一个合法、可持续编辑的节点；CASE/ELSEIF/BREAK 等上下文操作仅在合法位置出现；禁用项和无效字段有就地解释 |
| 复杂流/变量 | THEN/ELSEIF/ELSE、SWITCH、循环、WHEN、可恢复错误、公共流程，三值/四值条件与每次 StepOccurrence 对应，不出现 fake PASS |
| DBC 真实文件 | 新建/导入合法 DBC、批量改信号、保存、重新打开、绑定工程、在 TEST 使用；编辑出错不破坏文件，不靠旧格式兼容 |
| 波形与公共流程复用 | 工作台建立真实标准/流程→在 TEST 选择→直接编辑/跳转→调试运行→证据可追溯 |
| 整组物理状态 | 65ms 周期 CAN 跨用例不中断、按键最后组合保持、IGN 及变量作用域一致；用第二设备观测 CAN |
| 工程选择与扫码 | 从新建或导入工程到扫码命中**无人工发布向导**；显示真实完整扫码内容；所有关联在一个页面完成，不无故显示空库 |
| 正式检测 | START→夹具→预期 ECU CAN 确认→每次原生 FLASH→有序 TEST→一台父 Inspection→单台报告→释放；真实硬件故障与 UNKNOWN 不伪造 |
| 历史和复检 | 同一编号可查每次生产、完整 FLASH/用例/步骤、报表与批量统计；一次生产只算一台 |
| 桌面交互 | 1366×768/150% 所有关键字段可见，键鼠/弹窗/自动保存/关闭恢复，普通错误不弹通用阻断窗口 |

**当前判定**：仅形成设计裁决并审计真实源码；不得标记这些场景为“通过”。从这份合同实施时，应按“统一 Step Schema 与 Runtime → 重做 TEST 中央编辑 → 资源独立编辑/绑定 → 工程选择/扫码 → 生产与报告 → 专业工具统一 UI → Windows/真机验收”纵向执行，不能分头只把控件换皮。
