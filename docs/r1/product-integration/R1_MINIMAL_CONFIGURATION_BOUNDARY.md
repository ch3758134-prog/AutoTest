# AutoTest R1｜配置模型减法与固定工位边界

**范围**：固定硬件的 Windows ECU 测试系统；不同 ECU 使用不同检测工程。  
**状态**：R1 简化基线（先清理冗余配置，不在本次增加另一套 UI/DSL）。  
**安全**：对既有工程资产采用保留与兼容读取策略，不物理删除、不修改原有 JSON、不在清理中发起 USB/CAN/夹具动作。

## 一、唯一需要编辑的业务对象

**ECU 检测工程**本身就是检测内容的定义，包含：

- 工程名称及必要的 ECU 型号标识（仅供引用和匹配，非独立被测系统建模）；
- TEST 用例与执行顺序；每个用例是正式 TEST 步骤/流程树；
- 已引用的 DBC、波形参考、固件及其他必要资产；
- 当前 ECU 的原生烧录工艺及其真实固件/安全算法资源；
- 当前 ECU 实际需要的工位准备、收尾动作；
- 如需要，工位扫码得到的唯一编号及与当前工程的匹配规则。

**固定工位设备**由软件管理，安装/更换硬件时维护一次：主控 USB、ECU CAN/KEY CAN 固定硬件角色、扫码枪实体设备与串口、夹具和 IGN、实体 START。ECU CAN 运行波特率可由当前 ECU 检测工程决定，不需要为不同 ECU 克隆一套工位描述。

**本次检测事实**由执行器/RECORD 产生：DUT 唯一编号、FLASH、TEST 运行和步骤发生次数、判定与证据、报告及复检。不属于工程编辑资源。

## 二、明确删除的正常配置概念

- **TCF**：额外的“被测系统描述”不是正式检测必要条件；不再创建、不再作为编辑入口，也不需要先选择才能使用 DBC 或测试步骤。
- **TBC**：固定硬件工位不需要由每个 ECU 工程重复描述；不再创建、不再出现为必选配置。
- **独立扫码/烧录配方**：不作为新工程创建流程；旧扫码配方对 TEST/DBC/固件的重复引用不得成为正式生产的第二来源。烧录使用工程原生 Profile。
- **再次注册 ECU 系统对象**：取消额外概念；当前工程足以表达要检测什么。保留必要型号标识，避免破坏现有真实烧录与型号匹配合同。

**注意**：此处的“取消”指取消 *新建与正常业务链路*，不是立即删除所有历史类型、源文件、Codec 或兼容测试。待项目数据迁移与回归证据齐全，再物理移除已证明无调用者的旧实现。

## 三、这轮源码已执行的最小变更

1. `ProjectWorkspaceService.CreateConfigurationAsync` 拒绝新建 TCF/TBC，返回 `LEGACY_CONFIGURATION_RETIRED`；原 `ProjectConfigurationCodec.Decode/Encode` 保留，可打开历史资产。
2. 工程「检测准备」不再创建/自动载入 TCF、TBC 两个编辑器；扫码、原生烧录、工位真实操作、夹具工艺编辑和工程检查仍然存在，原功能入口不重造。
3. 工程树不再展示 TCF/TBC/旧扫码/旧烧录为可创建类别。若工程清单确实包含旧类型，集中放到“兼容保留的旧配置”分组，不删除底层文件。
4. 移除 shell 内 TCF/TBC 创建、打开、选中入口；「首个配置」入口回到实际工程准备，而不是默认创建空 TCF。
5. 工程概览资源计数只统计已登记的 DBC、固件、波形/波形配置、夹具工艺；不冒称它包括原生 Flash 发布或本机扫码设备。
6. 保留已有旧 Codec、历史配置编辑器与旧工程检查以防止破坏源资产；**它们不是新产品必须完成的配置环节**。

## 四、尚未删除的技术债及后续准出

- `ProjectWorkspaceService` 中早期 TCF/TBC 的选中上下文与旧编辑器仍存在，仅为兼容留存；删除前必须审查所有调用者和历史工程。
- `ProjectConfigurationCodec` 仍可编解码旧扫码/旧烧录配置，旧集成测试可以运行；它们不应继续成为生产决策来源。
- 主工程中的完整检测配置与真实执行（扫码 → 准备 → START → 原生 FLASH → TEST → RECORD → 收尾）仍未完成整机集成，**本轮减法不代表生产功能完成**。
- 只有完成这一轮配置模型收敛、资源关联核对与真实执行闭环后，再设计面向操作人员的 UI。不得先造一个新的 TCF/TBC 等价配置模型。

## 五、本轮验证要求

- 保留旧工程所有资产、SHA 与引用，不做自动迁移和隐式删除；
- 新建工程不提供 TCF/TBC，且工作台不再因二者缺失显示阻断；
- 旧工程依然可读取 TCF/TBC JSON，实际 TEST、DBC、Flash、工位服务不能因减法丢失；
- Windows WPF 重新编译并检查：工程创建 → TEST 编辑 → 工程配置 → 扫码与烧录/夹具已有入口 → 保存退出与重开；
- 源码静态结构检查不能替代 Windows 编译或现场 ECU 验收。

**当前验证状态**：代码已经写入 R1，已做基础结构/XAML 配对审查。Windows 构建、原工位运行、USB/CAN/ECU 实测均未在本次完成。
