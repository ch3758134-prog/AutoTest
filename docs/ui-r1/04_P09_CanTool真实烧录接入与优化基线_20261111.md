# R1 P09 CAN Flash｜真实 CanTool 接入与后续优化基线

状态：**源码接入候选 / NOT PHYSICALLY VALIDATED**。没有真实 ECU 证据时，不得宣布物理烧录 PASS、R1 完成或生产放行。

## 正式产品与独立工具

- 正式产品入口：R1 `AutoTest.Desktop` → P09 `FlashToolView`，位于主 Shell 中，不再单独打开第二个 USB/主控进程。
- 真实硬件会话：**唯一 R1 Station** `DeviceLabEmbeddedView.Controller`，通过 `AttachPhysicalLink` 以惰性 provider 注入 P09。
- 独立排障：`tools/AutoTest.FlashDiag` 继续保持单独 EXE，用于烧录专项定位；同一块 WinUSB 主控不能同时由两个进程连接。
- **唯一烧录流程实现**：`src/AutoTest.Flash/CanToolFlashEngine.cs`。R1 和独立 Lab 编译引用这一共享程序集，禁止复制出第二套真实 UDS/ISO-TP/Erase/Download 引擎。
- 物理层：`HardwareBenchController.CanToolFlash.cs` 与 `HardwareBenchController.ReadOnlyUds.cs` 通过现有 WinUSB/CAN1、同一 CanFrameHub、同一 CAN1 租约、独占作业 Permit 执行；断开/设备掉线撤销当前 Permit。独立 Lab 继续使用同一硬件层类。

## P09 操作流

1. R1 Station 实际连接主控，验证 `GET_VERSION`；P09 不创建第二个设备实例。
2. 导入真实 `Configuration.xml`，保留 APP/Boot 请求及响应 CAN ID、地址、字段来源与 XML SHA。
3. 选择 HEX/S19/BIN，并解析镜像、地址段、固件 SHA。对齐 block 与 Flash 范围需校验。
4. 可选先进行 **真实 CAN1 Boot/APP 的 10 03 探测**；此操作会改变 ECU 诊断会话，但不解锁、不擦除、不下载。
5. 选择真实原生 `ZLGKey` DLL；人工确认 ECU 接线/供电、CAN1 **实际**比特率、擦写风险；生成绑定 XML SHA、镜像 SHA、CAN ID 与 USB Generation 的授权短语。
6. 人工逐字输入并最终确认后，才由同一个 CanTool 引擎执行 Boot/APP→Security→Erase→34/36/37→Verify→Reset。所有写入经租约、有效会话、限时/限帧 Permit 和底层 CAN1 输出门禁。
7. 显示实际阶段、确认字节与 NRC，并可导出 P09 本页事件；底层会话另记录 WinUSB/CAN 原始 JSONL。
8. 取消/断连/ACK 不明确标为不确定状态，禁止默认重试。关闭 R1 时若 P09 正在烧录，先请求取消并等待作业退出，不直接销毁设备会话。

## 注意

当前接入是现役 CanTool 协议研究的实际实现候选，不代表上述 OEM 参数适合任何任意 ECU。Flash XML 的 `BaudRate` 只是期望值，不能自动修改主控 CAN1 速率。R1 与 Lab 共享流程代码，但分别拥有自身 WPF 操作界面及 USB 会话生命周期。

后续优化优先修改共享引擎与正式 P09 交互，独立 Lab 保留最小、可重复的对照实测工具。
