## 总览及功能电路分解

| 页 | 电路领域 | 对软件能力的工程含义 |
|---|---|---|
| P1 | J1 外部端口与隔离/保护及电气网络 | 哪些端点可真正接出，是上位机能力边界的第一层 |
| P2 | DAC / 运放 / 模拟输出 | 纸面有模拟激励能力，软件能否利用需驱动与电气验证 |
| P3 | MK20 MCU、引脚、电源/时钟 | MCU 外设只有被正确接到外围/接口才形成板级功能 |
| P4 | USB、双 CAN 物理层、电源 | PC 通路/两个外部 CAN 通路以及板内供电边界 |
| P5 | 高边/低边输出与检测网络 | 对工装和 DUT 的物理控制边界、失电与负载条件 |

**器件查阅入口（参考，不取代 PCB 型号核验）**：NXP K20 `https://www.nxp.com/products/K20_100`；ADI ADuM4160 `https://www.analog.com/en/products/adum4160.html`；NXP TJA1042 `https://www.nxp.com/products/TJA1042`；Infineon BTS724G `https://www.infineon.com/part/BTS724G`；TI TLV4172 `https://www.ti.com/product/TLV4172`。NXP、ADI 等产品页面只能说明器件类别资源与额定条件，不代表我已取得当前实装批次/PCB 的器件完整 datasheet 及验证数据。

**主控 MCU 事实卡（器件级与板级分开）**：U7 标注 `MK20DN512VLL10`；NXP Kinetis K20 家族 MCU（Cortex-M4、常见额定上限 100 MHz、型号中的 Flash 容量为 512 KB；最终参数以准确 MPN 手册与该板的时钟/供电配置为准）。主图 P3 可见 MCU 的 USB0_D+/D−、TXCAN1/RXCAN1、TXCAN2/RXCAN2、SPI、ADC、GPIO 等符号，P3 右侧有按接口分组的原始信号说明，**但不意味着所有通道都可由外部连接器使用**。对实际引出能力应同时核对 P1/P4/P5 的网络与实装板。

**CAN 命名特别注意**：主图 P4 标题写作 `CAN1`（U9 ADM3054）与 `CAN2`（U10 TJA1042），主图 P3 使用 `TXCAN1/RXCAN1`、`TXCAN2/RXCAN2` 等网络名；历史 MCU 固件的 `CAN0/CAN1` 是**外设/软件编号**。在形成跨专业接口表之前应以网络名逐段对应，不能简单把“图纸 CAN1”当作“固件 CAN1”。

| `CAP-M-DIGITAL` | MCU GPIO 接驱动输出/相关端口 | 合理电平、驱动电压、负载与保护 | `DRAWING_SUPPORTS` | 未枚举逐端点电压能力，不宣称所有 GPIO 可用 |

## 电源时钟复位与保护

供电的阅读顺序应为：**外部供电 → 板级电源轨 → MCU/隔离/收发器/模拟与输出负载域 → 上电复位行为**。P4 存在 LMR14203、TLV70233 等电源器件及防护，P3 提供 MCU 相关时钟与复位符号；目前未取得输入最低/最高电压、各电源轨实测值、功率预算和负载边界。不得把芯片参数书上的“支持”直接套成这块 PCB 的已验证指标。

## 信号/引脚/网络/外部接口

| 设计入口 | 上下游物理对象 | 当前可确认层级 | 需要补的事实 |
|---|---|---|---|
| J1（P1） | 外部 DUT、工装、主板 CAN 和数字/模拟输出 | 图纸连接器与网络存在 | 图纸级 64 针网络表已补齐；现场线束与 DUT 端子对应、负载仍待核 |
| U7（P3） | USB、CAN、GPIO 等 MCU 管脚 | PDF 管脚/网络可读 | 实际复用配置、外设资源约束 |
| U9/U10/U18（P4） | 总线物理层及 USB 隔离 | 设计芯片与电源网络可见 | 逐通道 TXD/RXD 对应、隔离跨域约束 |
| U22/U5/U23、JU1/JU2（P5） | 高/低边到外部 HOUT/控制网络 | 设计驱动级存在 | 负载安全电流、默认电平、实际引脚连通性 |

**关于 IGN**：从现有记录可追到源码的 `PTC10` 映射，以及历史图纸解释 `U22 IN3/OUT3 → HOUT5 → J1-C6`。但“当前实物实际 DUT IGN 电压”必须以现场线束/电压证据关闭。`BTS724G` 关断时的高阻状态不得画成主动下拉。`PTC10` 属于“固件如何使用”的事实，**不能替代本节的电路能力分析**。

## 软件控制关联

此节严格**后置**：当前主控工程具有 `EAL_GPIO`、`EAL_CAN`、`ASW_BusProxy`、`ASW_PwrCtrl` 等实现，分别使用部分 GPIO、双 CAN 与 USB。是否覆盖 P2 模拟输出、P5 所有通道和主板 J1 全量功能，不因驱动/函数存在就判断为完整。精确源码文件、差异、运行状态见 G0-04。**任何后续 HOST 方案都应从本节前面的物理能力及约束出发。**

## 物理约束与证据

1. `HW-MAIN-01`：原理图 vs 实物装配、替代料/飞线、板号；关闭证据：实物照片 + BOM/装配记录。
2. `HW-MAIN-02`：J1 逐针与线束、IGN、SOL、CAN、模拟输出；关闭证据：对点连通/现场接线表。
3. `HW-MAIN-03`：IGN/高边负载与失电态；关闭证据：批准的安全操作条件下端电压与状态日志；未核实前不做危险上电操作。
4. `HW-MAIN-04`：模拟输出幅度/输出阻抗与变化率；关闭证据：实际波形和负载条件；**不能因 P2 设计存在认定 HOST 已具备任意激励输出能力**。
5. `HW-MAIN-05`：电源/隔离/CAN 物理层实际配置；关闭证据：原件、实装型号、测量与现场连接。

本文件只接收事实，不提出新 PCB 方案；严重且软件无法弥补的硬件缺口应通过后续正式问题/变更决定是否修改硬件。

## 最新物理供电与外设范围备注
12V/24V 是台架所具备的供电种类，**尚不能据此推断主控 MCU 能控制两路电源的通断或自动选择电压**。现役控制范围优先复验 CAN、IGN、夹具电磁阀和按键板；灯、蜂鸣器等是未来候选硬件，本期不纳入现役能力验收。原连接器索引属于图纸级，实物线束与额定电压仍需现场核对。

## M2 后续复验与变更边界

本原理图只能支持板级设计事实，不能单独证明现场装配/烧录映像和实际 DUT 操作。B0 在获准现场环境核实线束、供电、电源保护、板卡版本和失电状态；B3/B4 将实际命令响应与电气/机械观察分开记录。任何 PCB 修改须另行评估硬件缺口、修改影响与回归，而非默认 G0 已批准改板。
