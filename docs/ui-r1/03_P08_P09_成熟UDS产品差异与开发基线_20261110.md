# AutoTest R1 | P08 UDS Console / P09 CAN Flash 产品工程基线

原型：`docs/ui-r1/reference/AutoTest_UI_Interactive_Prototype_V0.1.html`。正式 R1 WPF 使用主产品 `AutoTest.Desktop`，不使用当前 FieldStudio 的简化页面。

## 成熟产品审查

- Softing DTS.monaco：诊断服务目录、参数编辑、ODX 数据驱动、符号响应、原始/符号 Trace、诊断序列、Quicktest 与 Flash 作业。https://automotive.softing.com/products/softing-dts/softing-dtsmonaco.html
- Intrepid Vehicle Spy 3：可创建诊断 Job、编辑/保存、执行/取消、结果、Signals 和消息历史、ODX。https://docs.intrepidcs.com/vspy-3-documentation/vehicle-spy-main-menus/main-menu-spy-networks/diagnostics/diagnostics-view
- Vector CANape：支持 UDS/KWP2000、ODX/CDD、诊断控制台、DTC/环境数据、Trace 与诊断编程。https://www.vector.com/en/products/products-a-z/software/canape/

## 硬性边界

1. FieldStudio 仅供实际 USB / CAN1 / UDS / Flash 硬件联调，当前 0x19/0x22 物理只读门禁不向正式 Mock Shell 自动迁移。
2. 正式 `AutoTest.Desktop` R1 使用单一 Shell、Prism Regions；P08 / P09 作为中央 Document View，不创建第二正式 USB Session 或 CAN Hub。
3. 视觉必须继承 HTML 深色 IDE：38+30+48 标题/菜单/命令区域、50px Rail、255px Explorer、中央多文档、286px Inspector、190px Trace、25px 状态栏；支持高 DPI、默认最大化。
4. UDS 后端差距：现有通用 ISO-TP Classic Normal 和服务目录、Mock/Replay、NRC 0x78 已有；真实物理仅 0x19/0x22，服务参数化与 ODX/PDX、持久诊断 Job、全面 NRC 与时序、P2/S3、会话状态、诊断结果输出、物理 programming Tx 尚未完全实现，不能宣称成熟完整。
5. Flash：参考 CanTool 提供 APP/Boot 双端点、0x10/0x27/0x31/0x34/0x36/0x37/0x11 的代码行为，但其物理 ECU 配置兼容、Seed/Key DLL ABI、校验、擦写恢复均有未验证项，真实写入保持 LOCKED。

## 可视化产品交付验证

代码候选必须由 GitHub Windows CI 实际编译。正式产品 UDS Service/Builder/Response/Trace 不得是空 UI；真实物理请求必须等主控服务绑定及现场验收。不得用 Mock 成功冒充 ECU 实测。每一版记录具体可操作视图、服务源、Build/Test/屏幕截图和未完成项。
