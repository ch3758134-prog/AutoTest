## G0-02｜HOST 当前研发状态

**已确认的源码情况**

`main` 有工程管理、DBC、测试程序编辑及 USB/CAN、扫码等实现入口。`local` 另外包含真实测试执行、硬件动作控制和工程配置编辑等在研实现。

这些是源码事实，不等同于实际用户操作已经通过。

**已确认的遗留问题**

- 历次 UI 研究失败及早期项目管理混乱造成了废弃代码与分支。
- `main` 和 `local` 均残留旧 `MockStation` 运行代码。
- 负责人已明确废弃 Mock 运行路线。
- 历史代码不得因为存在于仓库中就自动成为需要保留或集成的功能。

**当前处理**

不再为了 G0 完成全面代码清理。另一个对话继续进行技术研究与研发；本对话在取得其成果、版本及证据后负责管理审查和集成决策。

**结论：**HOST 属于持续研发状态，暂不认定为稳定或已验收。后续针对具体功能完成必要的代码整理与验证。

## G0-03｜硬件与固件现状

已确认的主要工程事实：

- Windows HOST 通过 USB 与主控板通信。
- 现有软件通道约定：CAN0 连接按键板，CAN1 连接 DUT。
- 按键板使用 20 个内部模拟开关，通过电阻网络形成五路面向 DUT 的模拟输入条件。
- 按键板源码中存在 CAN ID `0x730` 的掩码控制。
- 主控板已有 USB/CAN、IGN、夹具及其他输出相关的电路和源码。

**尚需在相应研发或实测时核实：**实际板卡修订、在机固件版本、接口接线、模拟电压及物理动作结果。

这些缺口不意味着已有硬件设计或固件代码失效。

**结论：**继承现有硬件资料和两套固件工程。未来可以根据需求修改主控及按键固件；具体修改或烧录前再核对所涉及的实际硬件与版本。

## G0 Gate｜阶段准出

**建议结论：PASS_WITH_LIMITATIONS**

G0 的现状调查和接管工作已经能够支持继续开展需求研究。剩余问题放入对应的后续研发活动，不再无限延长基线调查。

| 限制 | 后续处理 |
|---|---|
| L1：HOST 不稳定，存在废弃 UI/Mock 代码 | 在具体模块整理、集成和验证时处理 |
| L2：实际硬件状态和固件映像尚未全部确认 | 在相关固件操作、烧录及实机验证前核实 |
| L3：历史方案和并行研发成果未全部完成适用性审查 | 在需求、设计或集成采用时逐项核实 |
| L4：项目管理系统的技术执行控制尚未完整验收 | 在实际任务派发和正式放行时核对版本、权限及批准证据 |

上述限制不覆盖或撤销 P0 原有的六项限制。

### 准出后的工作

进入 **G1 需求研究**，重点组织两条完整用户工作流程：

1. 工程管理 → DBC → 测试程序编写与调试。
2. 设备连接 → 扫码 → 真实激励 → 自动测试 → 判定 → 日志和报告。

同时研究专业工具、手动台架、UDS、烧录及波形能力如何独立使用或参与测试程序。

以上为 G1 的研究入口，具体需求和设计仍需形成独立成果供负责人审查。
