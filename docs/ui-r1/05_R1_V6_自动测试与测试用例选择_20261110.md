# AutoTest R1｜V6 浅色运行工作台及测试用例选择

**状态：候选源码已实施；Windows Build/Test/Publish 与真实 WPF 启动/现场执行分开验收。**
基础分支：`feature/r1-html-product-ui-20261110`；本工作分支：`feature/r1-v6-selective-testcases-20261110`。不直接修改 main。

## 1. 正式术语与原则

- **TEST 程序**：完整的版本化工程资产。拥有 Prepare / Test / Cleanup 三个阶段。
- **测试用例 TestCase**：TEST 阶段下可选择执行的顶层容器；一个用例包含任意数量的操作、观察、断言和控制流步骤。TEST 内可有多个 TestCase。
- **测试步骤 Step**：如 CAN 发送、UDS、波形比较、IGN 等原子/复合动作。不能逐条勾选任意底层动作当作普通运行用例，因为这样可能破坏安全初始化和条件逻辑。
- **常规扫码运行**：USB COM 仅采集 DUT 编号，依发布的唯一编号规则匹配完整 TEST。不会读取工程师在调试视图里勾选的 TestCase。
- **局部工程测试**：工程师选择一个或多个 TestCase，再调用同一个已有 TEST 编译/执行器；不用复制出一套 TEST 引擎或改变原 TEST 文件。

参考：ecu.test 官方 Selective Testing（可勾选一组测试用例）；NI TestStand Run Selected Steps 的 Setup/Cleanup 规则。

## 2. 源码落实

- `src/AutoTest.Testing/Lab/LabSelectiveExecution.cs`：发现顶层 TestCase、兼容旧式平铺 TEST、检查选择范围、生成不可变选中运行计划。
- `LabPlanCompiler`：接受并验证顶层 TestCase（只能出现在 Test 阶段）。
- `LabRunCoordinator`：按原有执行语义展开 TestCase.body，**Prepare/Cleanup 不因为只选一个用例而跳过**。
- `LabTestWorkspaceViewModel`：对 UI 提供 TestCases 勾选项、全选/清空、RunSelectedPhysicalCommand；完整运行/扫码仍走原入口。
- `R1ProjectRunView.xaml`：浅色 TEST 运行视图；运行范围复选框、步骤结构和最大面积的真实 StepFact（预期/实际/质量/判定/来源/原始证据）。
- `MainWindow.xaml(.cs)`：默认运行视图，收起工程 Explorer/Inspector/空日志；切换工程开发则恢复 IDE 布局，工位扫码状态放在外层工具条。
- `LabProductionToolView.xaml`：扫码配置与编号规则仍为外部工位工具，不嵌入 TEST 文档。

## 3. 执行安全

1. 空选择、未知用例 ID、任何整个 TEST 编译错误均拒绝局部运行。
2. 先编译完整工程程序，再基于其内存副本过滤 TEST 阶段的未选用例，生成本次运行专属 `Plan.Digest`。原 TEST 不修改。
3. 准备与清理阶段、顶层子程序声明保留；所选用例缺少引用时拒绝执行。
4. 原设备授权与工位同一 CAN/USB 会话、互斥执行仍生效。局部运行不是绕过物理动作准入的后门。
5. 本次证据文件区分 `FULL_PROGRAM` 和 `SELECTED_TEST_CASES`，保留源 TEST SHA 与已选用例 ID；未选用例不计为已测试通过。
6. 旧 TEST 没有 TestCase 节点时，全部未分组 TEST 步骤被显示为一个兼容用例（使用程序 ID 作为稳定选择键），无需迁移历史文件。

## 4. 重要限制

当前 R1 **并未具备所有目标专业 Step 的实机执行能力**。独立 CAN/UDS/Flash/Wave 专业工具可以存在，但只有已经接入正式 TEST runtime、通过有效授权且满足物理安全条件的步骤才允许执行。CI 编译通过不等于实际 ECU 测试通过；不能以一次选中用例 PASS 作为整份 TEST 或出厂 PASS。

R1 V6 视觉基线目前以运行工作台、TEST 编辑和扫码配置为主，其他专业工具的浅色一致性及独立浮动 IDE 文档仍需继续专项验收，不宣称 V6 全产品视觉已完成。
