# A-02｜工程资源管理工作空间

日期：2026-11-19；来源：AutoTest R01～R06、用户批准的 UX-PLAN v0.2；身份：UI/UX 研究、设计和纯 UI 实施。

## L0 场景与问题
传统的“空白资源树 + 一堆禁用按钮”既不可探索，也不支持连续资源编辑和搜索。

## L1 端到端用户任务
新建资源、填写名称/类型/路径、查找、按类过滤、复制、删除、连续修改多行。

## L2 来源事实 / 研究依据
R02/R04 以工程资源为用户对象，要求单击选择、双击/直接修改、搜索/过滤和有明确作用域的命令。

注意：厂商公开资料证明其存在相应机制，不证明 AutoTest 应机械复制。原始资料见 R01～R06、SOURCE_REGISTER；本篇设计取舍属于 UX 候选。

## L3 对象、命令与交互设计
类别浏览与当前资源表分离。资源列表采用可编辑数据表、内联搜索与复制/删除；工程资源在纯 UI 阶段仅为工作会话对象。

连续操作脚本：新建空资源→直接在表格修改→筛选定位→复制或删除→保存 UI 会话→重新打开。

## L4 状态、异常与视觉责任
未绑定正式 PROJECT，不假装资源已完成版本化持久化，不能把文件路径文本当作已导入的资源。

所有编辑均作用于 UI 会话。任何离线/UNKNOWN 的实物状态不得在界面中呈现为通过。Windows 小屏、高 DPI、焦点/对话框属于最终跨批验收项。
