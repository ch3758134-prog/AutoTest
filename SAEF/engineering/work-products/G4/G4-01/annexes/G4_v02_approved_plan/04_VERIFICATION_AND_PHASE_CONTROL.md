# G4 迭代验收与测试责任

- **G4**：由专题对话编写功能源码和单测、Fake/Mock及负面测试；INTEGRATION 编写公共契约和跨模块/最小闭环测试；Codex 机械构建/执行；负责人 Windows 操作和现场测试，原始日志由主对话判读。G4-01～G4-07 必须根据真实证据累积。
- **G5**：在 G4 形成的受控可复现版本基础上，开展正式完整系统和物理台架/性能可靠性验证，不等于第一次摸硬件。
- **V0 可交付条件**：Windows 实际 SDK 还原结果、完整 Build PASS、测试命令与真实通过条数、Prism WPF 窗口可启动、FakeStation/Mock 运行日志及首次源码 Git；没有来源日志不写 PASS。
- **V1 条件**：保存/重开工程、DBC 解析、编辑步骤、Mock 执行、运行结果/记录/UI；提供完整输入和自动测试结果。
- **V2 条件**：B0 安全、设备身份/版本、USB PING、CAN真实收发与回放/Trace，保留原始报文。任何真实 IGN/夹具/按键输出另行批准。
- **V3 条件**：专项输出允许后，按键/Station/ECU自动测试闭环，保留 ACK 与事实分离及未知结果。
- **V4 条件**：扫码枪 Windows输入、UDS 非破坏服务、波形真实电流/回放比较证据。
- **V5 条件**：Mock Bootloader/失败注入、资源选择与生产流程、记录/统计；真实烧录必须有目标配置、恢复路径和专项许可。
- **退出方式**：每轮由主对话整理成功/失败/未运行证据和开放项，用户确认；G4 Gate 的批准必须在正式 G4 工作产品建立后单独审查。

具体101项测试原 ID、承担者和候选类/方法见 [`G4_TEST_EXECUTION_101`](matrices/G4_TEST_EXECUTION_101.md)，27个现场/WPF过程见 `procedures/`。
