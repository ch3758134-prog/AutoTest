# AutoTest · UI-01 + UI-02 工作区与文件操作验证版

本分支：`ui/ux01-02-shell-files-20261120`，继承用户已经初步认可的白色 TEST 高保真预览，**不会修改正式 `main`**。

**重要边界：** 这是一套独立的 WPF UI / 文件交互版本。工程清单使用 `.autotest-ui-workspace.json`，**不等同于正式 AutoTest PROJECT / TEST Schema**；不使用真实 DEVICE、USB、CAN、UDS、Flash 后端，不执行 ECU、不生成真实 PASS/FAIL。可以在 UI 工作区中导入真实 `.testjson`、`.dbc` 等资源并作为文件查看和保存，但不能因为文件可以编辑就宣称解析或业务合同已经兼容。未来合入正式工程前需要适配已有 PROJECT/TEST 后端。

## 启动

Windows，.NET 10 SDK，在仓库根目录：

```powershell
dotnet build UI/AutoTest.TestHiFi/AutoTest.TestHiFi.csproj -c Debug
dotnet run --project UI/AutoTest.TestHiFi/AutoTest.TestHiFi.csproj
```

文件系统生命周期专项检查（无 WPF，完全在临时目录运行，不修改用户工程）：

```powershell
dotnet run --project UI/AutoTest.TestHiFi.FileTests/AutoTest.TestHiFi.FileTests.csproj
```

**该分支目前只有 GitHub 源码回读 / 静态检查，没有 Windows Build、真实运行、文件 IO 冒烟测试完成证据。**

## UI-01

- 主导航：自动测试、工程与文件、资源管理、生产与记录、专业工具。
- TEST 原有步骤列表保持已加载状态，打开工具/文件页后切回，当前用例、阶段、选中步骤与搜索不会强制重置。
- 在专业工具按钮中选择 CAN、DBC、手动台架、UDS、Flash、波形、设备诊断；当前只有导航入口和明确未接线的说明。不能触发物理设备。
- 顶部主控板始终明确显示**未连接**，设备诊断独立查看；不把 UI 启动状态当作真实 USB 在线。
- 流程 THEN/ELSE/CASE 紫底改为灰蓝分支标记；视觉示例正常行不再显示假运行成功的绿勾。
- 非 CAN 判定步骤选择后，右侧不会继续用 CAN 判断字段冒充参数，显示该步骤的摘要与类型提示；完整可编辑类型化 Inspector 留待 UI-03。
- 流程节点双击展开折叠；支持展开/折叠全部、问题错误/警告筛选、问题定位。
- Ctrl+Q / Ctrl+P：快速搜索测试用例、已打开工程文件、可用文件命令和工具工作页。
- 窄屏时可以在步骤结构与右侧参数间切换，面板大小与问题展开状态存入会话；仅限本版交互预览，仍需用户原生 DPI 截图确认。

## UI-02

- 文件菜单 + 工程树右键 + 资源详情操作，保留同一文件身份。
- 新建 UI 工作区：用户选父目录和名称，建立实际工程目录及分类子目录、写入 `.autotest-ui-workspace.json`。
- 打开本 UI 生成的工作区；最近工程列表最多 8 项，明确区分“下次恢复会话”和“主动关闭工程”。
- 新建资源、从磁盘复制导入真实文件（不覆盖已有同名文件）；分类为测试程序、公共流程、DBC、参考波形、输入、诊断、烧录等。
- 多文档标签可切换、关闭；使用中央文本编辑器修改真实文件，修改中显示 `*`。
- Ctrl+S 保存当前，Ctrl+Shift+S 保存全部，Ctrl+W 关闭文件；实际磁盘写入并更新 UI 工作区修订；另存为可写外部副本，不修改原工程引用。
- Ctrl+Z / Ctrl+Y 作用于当前文本编辑器；切换文档时清空旧文本框 Undo 栈，避免跨文档撤销。
- F2 重命名文件；复制创建新资源 ID；移动资源分类；删除进入工程内 `.ui-trash` 回收目录，可恢复最近删除。重命名/移动/删除均警示**不会自动修复其他资源引用**。
- 关闭/切换工程/退出时枚举未保存文件，支持保存全部、放弃或取消；应用重启询问恢复上次打开的工作区与文件标签。
- 保存以临时文件后移动覆盖，UTF-8（含 BOM）与 UTF-16（含 BOM）编码按原格式保持；遇到无法无损解码的旧 ANSI/GBK 文件会拒绝文本编辑，避免错误覆盖。二进制文件不会使用文本编辑器。
- 正式 `project.autotest-project.json` 的完整业务操作、引用图谱、旧工程格式迁移、Step DSL 可编辑和真实设备接线不属于本批，不得用 UI 工作区清单冒充。

## 用户验收路线

1. 打开时观察 TEST TC-003 的完整步骤；选 T16 CAN 与 T18 ELSE，右侧内容应不同。确认灰蓝流程标签，没有紫色，也没有虚假硬件在线与绿勾 PASS。
2. 选中 T16 → 专业工具 → CAN 工作台 → 工程与文件 → TEST 返回；确认原步骤、阶段和搜索上下文保留。
3. 文件 → 新建工程，选择一个空位置，输入名称；工程树应出现分类。新建测试程序 `A`，修改文本，检查标签 `*`；Ctrl+S 保存；关闭重开应还原磁盘内容。
4. 再创建测试程序 `B`，交替编辑两个文件；关闭未保存文档、关闭工程和退出时检验保存/放弃/取消三种分支。
5. F2 重命名、复制、分类移动、移入回收区、恢复最近删除；每次用资源树和磁盘路径验证一致性。
6. 导入真实 UTF-8 DBC 文件，双击打开后修改并保存，确认文件实际落盘；旧 ANSI DBC 应拒绝有损编辑，不准产生乱码覆盖。
7. Ctrl+Q 搜索某个本地工程文件与 CAN 工作台；Ctrl+P 快速打开；切回 TEST，确认无重建。
8. 窗口缩小，测试“查看步骤参数 / 返回步骤结构”；调整分隔条与问题列表，关闭并重启，检查布局恢复。
9. 运行文件专项检查 `FileTests`；如果出现 CS、XAML、IO 异常，交回完整错误日志，代码在 GitHub 分支直接修复。

## 交付纪律

本分支只包含 UI/文件交互示范与静态安全限制；不能以此宣布正式 AutoTest 工程管理或 TEST 执行完成。项目正式接线必须以当前真实 PROJECT / TEST / DEVICE 合同为准，保留用户现场既有工程文件与硬件通路事实。
