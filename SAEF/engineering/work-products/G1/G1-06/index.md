# G1-06｜异常保护、停止与恢复原则（M2 候审）

## 一、系统级不可混淆的四个状态

1. **命令已发送**：HOST 发出请求，仅能证明软件发起操作。
2. **设备已回应**：主控/按键或 DUT 返回 ACK/帧，仍不能单独证明外部负载的电气和机械状态。
3. **物理已观测**：经独立电压、电流、夹具机械观察或经认可的测量证据确认。
4. **测试已判定**：在已批准测试程序的预期条件、实际值和证据范围内计算结果，可能仍有未观测物理对象。

四个状态必须能在测试证据和 UI 中区分，不可默认为等价。

## 二、异常和最低应对

| 异常 | 应做 | 禁止的错误行为 | 关闭证据 |
|---|---|---|---|
| USB 拔插/超时 | 保留原始时间/错误，令相关操作进入 UNKNOWN/FAILED；明确重连条件 | 静默当命令成功 | B1 故障注入 |
| CAN 缺帧/通道错 | 报告通道、配置和超时，阻止不可靠判定 | 自动把两路 CAN 当同一总线 | B2/B5 |
| IGN 输出未知 | 停止依赖该输出状态的自动步骤，要求现场核实 | 假定复位、忽略上电初始态 | B0/B3 |
| 夹具无法验证到位 | 把机械状态标为 UNKNOWN，只报告已发的阀命令及观察 | 把 ACK 或 ECU CAN 当夹紧证明 | B3/B5 |
| 按键输出未释放 | 进入受控清理/现场人工确认，并保留证据 | 假定全部开关已释放 | B4 |
| ECU 额定电压不符 | 阻止高风险测试启动，提示核对线束/电源/DUT | 自动猜测或切换电源 | B0/H4 |
| 扫码空码/歧义/冲突 | 阻止错误 DUT 关联或烧录，记录诊断 | 自动沿用上次 DUT 或资源 | H4 |
| 烧录丢包/失败/断线 | 标记此次烧录 FAILED/UNKNOWN，按专项恢复合同处理 | 静默重试不可逆动作或宣称成功 | 烧录专项 |
| 测试暂停/跳过 | 对可中断与不可中断步骤分别实施受控行为 | 中断中途物理动作而不清理 | H3 |
| 数据文件损坏/版本不符 | 保留原件，显示不可用/需要迁移，停止危险运行 | 静默覆盖旧文件或丢历史 | H2/H4 |

## 三、状态与恢复的设计责任

G2 必须给出设备健康、测试 Run、生产 Session、烧录 Job、编辑会话状态的责任所有者和转换事件；G3 才详细定义超时、取消、重试、清理、回滚、人工确认和日志格式。未验证的机械反馈与烧录恢复不可用“默认安全”的假设取代试验合同。

## 四、适用范围和迭代

当前禁止未获授权的设备实测和固件烧录。异常策略中尚无依据的部分应作为 `TO_VALIDATE` 关联试验与关闭时机。后续证据若要求修改固件/主控 USB 协议、G1 要求或公共运行状态，按受控 CHG 修改受影响文件并做回归，不必重启整套 P0～G5 文档审批。
