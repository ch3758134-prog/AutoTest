# B-01｜测试项目、用例组织与本次运行选择

日期：2026-11-19；阶段：纯 UI 研究设计实施；状态：IMPLEMENTED_CANDIDATE / WINDOWS_NOT_RUN / USER_FINAL_UX_PENDING。

## L0 用户场景与设计问题
用户在一个测试工作区中连续创建测试用例、重命名、复制、删除并选择本次运行范围。默认 Enabled 与当次运行勾选是两个不同的概念。

## L1 成熟产品研究与既有证据
NI TestStand 的 Sequence Editor/Operator Interface 服务于不同任务，R02/R04 要求 RunSelection 不等同文档结构。https://www.ni.com/en/support/documentation/supplemental/08/teststand-user-interface-development-best-practices.html

上述只说明厂商存在相应机制，不证明该布局对 AutoTest 已经最佳。对应 R01~R06 研究/用户明确要求为直接设计输入。

## L2-L4 对象、操作、界面和状态设计
测试用例列表紧邻结构编辑器；创建后直接选中。编辑页签与运行页签共享同一 UI 会话。运行页选择框只影响演示会话的 RunSelected，不伪装为正式 TEST Enabled。

**连续操作验收脚本：** 新建测试用例 → 修改名称 → 复制用例 → 查看步骤 → 转到当次运行页选择两个用例 → 返回继续编辑。

**异常及可信状态：** 删除空用例后可重新创建；不存在真实执行记录；真实 Run 不应从纯 UI 的勾选直接启动。

## L5 代码映射、版本与限制
TestWorkspace.cs：BuildEditor / BuildRun / DuplicateCase / DeleteCase；UiSession.cs：UiTestCase。

实施分支：feature/ui-full-rebuild-20261119；核心实现提交 5f39eb9c、49e413be、7d2e73d1、a5d3d79e、11cd7046，均非用户 UX 最终批准。

**限制：** 当前 UI 未做多个正式 TestProject 资源之间的管理；正式 Project/Cases 版本、引用与执行独立适配。
