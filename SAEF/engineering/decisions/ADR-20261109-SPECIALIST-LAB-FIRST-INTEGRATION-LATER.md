# ADR-20261109｜AutoTest 专业独立实测先行，统一上位机集成后置

- 日期：2026-11-09（以用户会话时区日期为准）
- 类型：用户确认的开发/实测/集成顺序与 UI 所有权设计决策
- 状态：USER_CONFIRMED / RECORDED。只是归档开发边界，不代表各模块已编译或已通过实测。
- 来源：用户对此前 R0-LAB 与 INTEGRATION 建议的明确纠正：“实测是各分支自己做界面我来实测，实测没问题后再考虑接入统一的上位机。”
- 关联：`docs/r0-lab/05_专项独立实测优先于统一集成_20261109.md`、`03_专业分支实测反馈与自主优化补充协议_20261108.md`
- 效力：凡此前描述“必须先由 INTEGRATION 完成正式 Shell/共享 Publisher/导航接线才可以开始专项实测”的流程要求，本 ADR 在**专项可独立运行和独立安全验证可行**的范围内优先。不得删除既有已批准 G3/G4 记录、绕过物理权限或冒称 Gate 已更新。

## 1. 正式工作顺序

1. 各专业分支独立负责完整功能及其**可直接运行、可独立操作的 WPF/诊断工具界面**（包括必要的专用启动/测试入口、专业业务逻辑、最小数据源/适配器、原始 Trace、日志导出和专项自动测试）。
2. Windows 本地 Codex 仅机械应用/编译/测试/启动并回报原始日志，不得自主定位、修改或修复任何编译错误；专业对话对其责任范围内的缺陷设计和补丁负责。
3. 用户逐个使用专项界面进行真实操作/实测并在原专业对话提供截图、原始日志和经验反馈。专业对话完成“现象→证据→原因→本专业修改→自动回归→新版本→用户复测”，直到用户确认该专业在实际适用场景达到验收要求。
4. **只有专项已确认达到对应的独立验收条件后，才将其作为成熟候选交给 INTEGRATION 统一接入 AutoTest 正式 Shell、导航、共用工程上下文、Session 和记录系统。** 某些设备相关能力需要多专业交互才能真实验证时，由专业负责人组织**最小、临时、受控的接口适配/测试夹具**，不得把正式 Shell/全局集成作为唯一入口，也不得据此擅改其他专业的私有代码。
5. 统一集成后的系统回归和交互一致性验收是另一阶段；在此之前专项独立通过 ≠ 已集成到主 HOST。

## 2. UI 和代码所有权

- 专业 WPF View、ViewModel、交互、可读/原始诊断、专业校验、独立测试入口**由该专业分支自己完成和迭代**；主 UI/INTEGRATION 不重做专业 UI。
- INTEGRATION 在后置阶段只接 Shell/Prism Region/导航、DI 注册、共享 Session/Services、项目引用、跨专业适配和联调测试，不得推翻已验收专业交互，也不能用空白占位页代替专业成果。
- DEVICE 可以保有**硬件原始调试 GUI**（USB/CAN/KeyMask/五路人工测量/物理授权调试）并由用户实测；正式真实按键的**业务台架 UI**属于 BENCH/UI，按 ECU Controller/Profile 动态生成真实键而非 20 Key。PROJECT 负责映射，TEST 使用同一动作能力；不能将 DEVICE 原始调试页冒充正式业务台架。
- 各专业可自行实现**专业私有适配、Mock/Replay 或仅为专项测试存在的最小测试装配**，不得私改共享 Contracts、CAN Hub、设备核心、UDS/ISO-TP、共同 Prism 及其他专业私有文件；如确需共享接口变化，提交明确的最小依赖申请，主对话指派唯一修改责任人。

## 3. 接口连接的要求——提前确定边界，但不前置正式集成

专业交付必须列出：自身 View/VM 可直接启动的方式；数据依赖/服务 Port、参数、返回和错误；Mock/Replay/Physical 来源；需要外部资源 Profile/Revision/Station 的字段；订阅与释放、线程调度、取消/断连、日志/TraceRef、失败/未观察语义；供将来 DI/Prism 接线的最小 API；已有 Mock/Replay 临时装配如何在正式接线时替换。

- **运行分离**：专业独立调试环境不得生成第二套正式业务资源与虚假的物理状态；独立测试入口的启动、配置和证据必须可复现。
- **Session 单一性**：独立实测单个专业时可由诊断装配拥有一次真实 USB 会话，但不得同时和另一个专业/正式 HOST 并发打开相同物理控制板；后置统一集成由 INTEGRATION 注入唯一共享会话。
- **物理输出**：任何独立 UI 都不能绕过 DEVICE 受控物理门禁。B0/B1/B2 只读与 B3 真实按键激励、真实 UDS 只读 Tx、真实 Flash 的权限和验证条件分别保持。界面独立不等于自动获准发送 CAN/改 IGN/动作夹具/擦写。
- **判定分层**：软件可运行、Mock/Replay 通过、现场实体受限测试通过、专业业务场景通过、正式 HOST 集成通过是不同独立状态。无需硬件的 WAVE Replay 和 Flash Dry-run 可先完成独立软件实测，但不能误报完成 Physical 功能。
- **依赖处理**：若专项需要 CAN RX/DBC/项目数据、或只读 UDS Tx 等实际硬件服务，可从现有 DEVICE/PROJECT 的**受控可复用功能**创建最小独立装配；真正缺少的共用能力交唯一责任人实现小接口，不要求整个平台先完成。

## 4. 项目阶段状态

`SPECIALIST_UI_READY` → `LOCAL_BUILD_TEST_PASS` → `READY_FOR_USER_SPECIALIST_LAB` → `USER_OBSERVED` → `SPECIALIST_REVISED/RETESTED` → `SPECIALIST_ACCEPTED` → `HOST_INTEGRATION_CANDIDATE` → `HOST_INTEGRATED` → `SYSTEM_ACCEPTED`。

真实硬件相关功能仍另列物理准入、观测与实际完成状态；前述状态不是单一路径上所有模块一齐等待，每个专业可并行推进。

## 5. 既有交付修正要求

当前 WAVE/SCAN ZIP、UDS/Flash 分支、BENCH PR 及 DEVICE 后续开发均需要按此 ADR 核对各自可独立启动/操作/日志及本地 Build/Test 证据；**不得用“缺少正式 INTEGRATION 接线”为理由停止专项独立 UI 和可先行实测的功能**。无法独立验证的跨层能力应精确列出唯一必需依赖，不能假称可以单独完成。

本 ADR 是现阶段受控设计输入。待 SAEF 原生工程检查与现有 G3/G4 工作产品影响评审完成后，按受控流程补充其关联和 Gate 状态，不伪造检查结果。
