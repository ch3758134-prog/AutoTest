# C-02｜CAN 多报文发送与接收观察

日期：2026-11-19；角色：UI/UX 全产品研究、设计、纯 UI 实施；状态：DESIGN_CANDIDATE / UI_CODE_COMMITTED / NOT_WIN_VERIFIED。

## L0 专业任务与问题
用户需要同时配置多个报文，能够直接编辑 CAN ID/数据/周期、选择启停；接收日志应与发送编辑形成持续工作关系。

## L1 成熟产品研究及本项目事实
Vector CANalyzer 的交互生成器提供报文与信号发送的专业任务机制；R05 要求有界日志与明确请求/结果层级。https://www.vector.com/int/en/products/products-a-z/software/canalyzer/

限度说明：以上资料提供成熟工具的机制与本项目用户明确的硬件语义，不是对各厂商最新版的完整上机测试。不能把参考资料的存在当作本界面用户效率已被证实。

## L2 对象、信息与映射
核心编辑对象和关联约束由本批任务决定。当前 UI 仅保存显式命名的编辑草稿、选择状态与用户配置，不编造正式项目修订、DBC codec、UDS/ISO-TP 传输事实或物理电压。

## L3-L4 专业界面与操作方案
左侧发送列表、右侧观察、中央快捷外部输入；从共享 DBC 选择报文加入待发队列，支持复制/删除、勾选 UI 计划及设置周期草稿。真实发帧和停止独立显示禁用原因。

**完整用户任务脚本：** 新增报文→修改 ID 与数据→从 DBC 选择一条→设置周期草稿→勾选多行→查看接收区域但不生成假帧。

**状态/异常/可信性：** 原始 RX / DBC 解码为空直到真实接收，UI 不制造时间戳、丢失统计或设备 ACK；总线角色用 DUT / 按键板命名而非含混 CAN1/2。
