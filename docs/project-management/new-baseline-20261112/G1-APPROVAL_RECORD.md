## 获批的重点事实与范围

- AutoTest 为通用 ECU 测试能力平台；具体 ECU 的测试步骤、观测、期望值与 PASS/FAIL 判据由测试工程师在测试程序中定义；平台必须正确执行用户判据和保留数据质量、执行与记录证据，而不是自行规定 EPB 的产品出厂合格标准。
- 当前 DUT 主电源由独立外部电源设备直接供电、控制；HOST、主控板和按键板不控制该主电源，现阶段不提供 DUT 主电源软件控制步骤。
- IGN、夹具电磁阀、按键网络是平台需要组织的真实控制能力；夹具压紧/松开必须可手动操作，也必须能够作为测试程序步骤编排，以服务连续扫码与真实自动测试。
- 停止/异常恢复行为采用可配置方向，借鉴 ecu.test 的执行机制；不预设所有异常都强制关闭 IGN、释放夹具或清零按键。具体物理安全状态以对应台架实测和经审查的策略为准。
- 真实 ECU 观测、ECU 内部采样量和独立物理测量分层记录；通信 ACK 或软件判定不得冒充未验证的实体结果。
- 承认 `main` 与 `local` 独立研发状态，当前 HOST 代码存在与获批需求的实施差距；源码存在或 Mock 清理不等于 Windows 编译、实机或生产流程已验收。

## 限制与后续关闭责任

- **G1-L01｜UI：** 工作空间与交互仍需专项设计、用户实测，不冻结旧失败方案。
- **G1-L02｜硬件：** USB/CAN/IGN/夹具/按键能力依真实工位证据逐项验收；DUT 外部独立电源不属 HOST 控制能力。
- **G1-L03｜专业工具：** UDS/烧录/波形具体 ECU 参数、恢复规则与测试证据尚需专项研究及验证。
- **G1-L04｜生产：** 扫码、连续检测、数据统计与复测逻辑需真实 DUT/工位样本验证。
- **G1-L05｜HOST：** `main` 不宣称稳定；`local` 不因本批准而自动整支合入 `main`；真实功能按精确版本分别验证。
- **G1-L06｜判定与证据：** 平台按用户编辑的规则计算和记录，不能代替特定 ECU 产品规范；不得将内部报告量冒充独立物理测量，也不自动要求增建硬件。
