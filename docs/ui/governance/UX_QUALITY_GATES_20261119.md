# AutoTest｜纯 UI 实施质量门禁 v0.2

## 门禁判定
- G-R：研究对象、用户任务、原始来源与设计推论分别记录；引用 R01～R06，注明无厂商全部实机体验。
- G-D：每批记录对象、工作流、界面、命令、交互、正常/错误/空态与状态隔离；任何虚构硬件成功状态为 BLOCKER。
- G-C：代码必须在 UI 独立工程中实现，不依赖旧 G4 UI 或任何业务运行程序集；对每批行为提供具体路径和命令；删除旧 UI 不能无故删除非 UI 的后端。
- G-V：Windows .NET 10 Restore/Build、程序启动、无工程开始、工具窗口管理、Ctrl+S/O/N、TEST 步骤插入编辑/撤销、公共流程、DBC/CAN 引用、20 Key 动作、UDS 序列、Flash 文件选择、波形游标、生产扫码输入、历史/设备空态、多 DPI/任务栏，逐项记录实际结果。
- G-F：研究、设计、实现、验证、缺口、提交 SHA 与交接说明完整；工作完成声明必须与证据一致。

## 最终统一用户验收场景
A01 无工程开始、编辑；A02 创建测试用例→三阶段→连续改步骤；A03 IF/ELSE→子步骤→公共流程；A04 DBC 新增报文/信号、修改中文别名、TEST 选择引用；A05 CAN 多报文列表/周期配置；A06 综合台架 20 Key 组合/保持时间/动作；A07 UDS 服务模板→连续请求编辑；A08 Flash 选择文件、配置与阶段查看（未真实运行）；A09 Wave 信号配置/双游标；A10 扫码输入/本地重复；A11 历史、设备状态不伪造；A12 工具切换和关闭、保存恢复 UI 会话；A13 1366×768/150% DPI 和 1920×1080 多屏；A14 键盘焦点及鼠标右键等专家操作。

## 不得混淆
静态代码检查 ≠ Windows Build PASS；Build PASS ≠ UX PASS；UI 演示状态 ≠ ECU 真实反馈；用户总体验未开始 ≠ 正式产品冻结。现有状态如不满足验收，保持 CHANGES_REQUIRED 或 NOT_RUN 并继续修复。
