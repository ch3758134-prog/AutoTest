## 2026-11-16 实测反馈

用户反馈：实际 WPF 的工程树、插入步骤弹窗及 CAN 发送属性明显偏离冻结 HTML。
已核实原因：
- 正式步骤菜单曾按 `Runnable` 的技术状态分成“测试步骤/待接入的步骤”，
  冻结 HTML 则按用户任务类别（CAN 与数据、工位操作、UDS 服务、波形分析、流程与计算）分组。
- CAN 发送属性曾让每路信号占用三至四行，导致同一属性栏难以连续编辑；发送周期未出现。
- 将正式 TEST 接到预览视图时曾另造简化的工程树；后续已统一列表来源，
  但测试项目 PACKAGE 归属、其他真实页签内容仍未完成。

## 本批代码整改（尚待 Windows 验收）

1. `PreviewPalettePresentation` 仅定义展示分类与图标，正式步骤合同依然来自 `StepUiCatalog`。
   弹窗恢复冻结 HTML 的五组与紧凑左右两列，保留搜索、关闭、点击即选中并在右侧编辑。
2. `CASE` 仅在 SWITCH `cases` 分支位置提供；键盘 Enter 与鼠标列表遵循相同限制，
   不会在根阶段插入非法 CASE。
3. `AtPreviewCanSignalTemplate` 压缩为“信号名/单位与物理值”同行；
   物理范围通过悬停提示显示，非法值时才呈现错误信息。
   输入有效非空值可直接勾选该信号，不强迫工程师先点复选框。
4. CAN 属性恢复发送周期：`0` 为单次，非负整数为周期毫秒数；
   数值无效禁止正式 TEST 保存；步骤行同步显示报文、已选信号数及周期。
5. 正式 DBC 的资产 ID、修订、SHA 和原始编码 CAN ID 继续与 TEST 保存，
   禁止沿用失效的文件映射，不使用演示报文伪装真实导入。

## 验收时需覆盖

- 导入包含十余条报文的 DBC；展开查看报文和信号，按报文名称与 ID 辨认。
- 在 CAN 发送步骤直接选择报文，输入多路信号物理值，分别检查 0/100ms 周期。
- 错误值、非法周期、已过期的 DBC 资源引用必须报错，不可静默保存。
- 步骤弹窗在空搜索、过滤搜索、键盘 Enter、关闭/再次打开时布局及插入位置正确。
- 切换测试用例、撤销/重做后，右侧所编辑的步骤必须保持一致。
