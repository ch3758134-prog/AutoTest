## 1. “严格实现、不许偏差”的可测试解释

- WPF 必须遵守冻结 HTML **自动测试**部分的最终（含 CSS 层叠覆盖）可见结构、字号/字体、颜色层级、间距、尺寸/可调整区、上下文菜单、键盘与鼠标行为、信息密度、禁用与错误状态。**不允许只参考大致布局，换回旧 TreeView、右侧另开弹窗或替换为别的表单。**
- 对同一个输入、同样屏幕尺寸和相同操作序列，WPF 应呈现与 HTML 对应的对象、焦点、数值、排序、展开、保存、验证、日志和状态。尚未接通的真实后端由明确“不支持/待联机/被预检阻断”显示代替，不得假造 HTML 演练结果或悄悄隐藏正式 G1 要求的步骤。
- HTML 的 CSS/DOM/JS 是**设计判据**，但正式实现必须使用现有 .NET WPF/Prism 及真实业务模型；不得用 WebView2 把 HTML 演示直接包进 EXE 冒充真实 WPF 编辑器。原生技术选型必须达到可观察的等效行为和视觉效果。
- WPF 的文本度量、ClearType 和浏览器排版存在客观差异。准出必须运行实测截图对照，任何肉眼可辨的非预期差异标记 `UI-DIFF` 并修复或经用户明确接受；不得预先宣称“100%逐像素”等效。**不能把实施难度当成自行更换设计的理由。**
- UI 研究分支可继续改 DBC、UDS、波形、手动台架等；只有用户要求变更自动测试设计基准并给出新精确 SHA 时，才版本化修订本合同及冻结快照，旧快照仍在 Git 保留。

## 2. 已从冻结 HTML 直接读取的布局和样式依据

| HTML 最终规则/对象 | 应保持的观感与操作 | WPF 落地建议（非替代布局许可） |
|---|---|---|
| `header` | 顶部单行 38px、浅色、紧凑项目/菜单/工具入口 | `MainWindow.xaml` 顶部固定高度 Grid，菜单/命令统一 Bind |
| `#sidebar`、`--tree` | 工程树起始宽度约 270px，可在约 220～500px 范围拖动，工程/测试项目/用例层次清楚 | Dock/GridSplitter + 轻量分层 ItemsControl/TreeView 模板，但不能回旧“所有资源一列无分组” |
| `#main`、`.tab` | 中部多文档/工作区，页签紧凑，编辑焦点优先 | 复用项目页签寿命管理，视图内容新建、不是保留旧布局 |
| `#inspector`、`--inspector` | 右侧默认约 320px（255～510px），选中步骤直接显示完整上下文和可编辑属性，可隐藏/拖动 | 绑定到稳定 `SelectedStep`、可草稿编辑，页面内部不另弹 `StepParametersDialog` 承担高频参数 |
| `#bottom`、`--bottom` | 底部默认约 180px（最小 110px，可收起/拖动），为运行时间线/CAN 事件/变量/问题/设备状态 | 共享 Run 事件源与设备状态，不能生成前端虚拟 CAN/Run 记录 |
| `.status` | 最下 23px 状态条，显示项目/连接/编辑提示 | 真实连接事实与状态分层显示 |
| `.steprow,.stepcolumns` 的**最终 CSS 覆盖** | 高密度行，最新最小行高 **35px**；列最终为 `36px / minmax(185px,29%) / minmax(220px,1fr) / 126px / 72px` | 使用保留层级缩进的虚拟化行列表/TreeGrid 效果，**不要只读旧样式的 31px 规则**；列宽按窗口约束适配 |
| `--bg/#eef2f8`、`--paper/#fff`、`--line/#dbe3ed`、`--blue/#2368bd` | 浅色、低噪、紧凑；主字号 12px，步骤最终信息列 12px | 令牌写入 WPF ResourceDictionaries，可由主题统一驱动但不得自行换色/字号 |
| `.steprow.active`、`.step-match` | 选中蓝色底和左缘，搜索高亮，断点、禁用、执行状态位置固定 | 触发器/VisualState + 差异对照；禁用/失败不能仅靠颜色区分 |
| 调整/隐藏/缩放/滚动 | 树/Inspector/底部面板的比例，键盘焦点及行可视性 | `GridSplitter`、保存窗口布局偏好；高 DPI 下保持编辑目标及不丢字段 |

**重要：** HTML style 中存在后续覆盖，G4 应以浏览器计算后的最终样式与用户实际截图为准，而不是原 CSS 第一次出现的定义。浏览器 100% 缩放与 WPF DPI 需要按可比条件测量，不简单把 CSS px 假设为任意 Windows 物理像素。

## 3. 主工作区按 HTML 冻结的行为清单

| 编号 | 用户可操作任务 | HTML 实际表现 | WPF 必须具备的行为 |
|---|---|---|---|
| U-01 | 新建/打开工程 | 工程概览及顶部资源入口 | 真实创建/打开/最近工程，未连接也能编辑，保存/损坏/未保存防护 |
| U-02 | 工程树 | “自动测试”下项目展开用例；DBC、输入配置、波形参考、UDS 在资源组 | 真正的项目/Package 引用、可收起与打开，资源 ID/版本和冲突提示 |
| U-03 | 测试项目 | 有序用例表，列有本次勾选/顺序/名称/工程默认/步数/调整 | 复用 `TestProjectDocument`，增删引用、排序、保存、无重复污染；默认与本次选测严格分开 |
| U-04 | 测试项目选择 | “全选/清空/检查所选”；左树和编辑页同步勾选 | `RunSelection` 非资源修改，初值根据保存 `Enabled`，勾选并不会修改正式生产方案 |
| U-05 | 测试用例阶段 | 准备/测试/清理分组，展开/折叠和阶段末尾添加 | 保留 `TestPhase` 三阶段及其可编辑子步骤，持久与展开状态分离 |
| U-06 | 高密度步骤行 | 序号、步骤名及类型、参数摘要、资源、状态同屏 | 虚拟化行、不重复冗长卡片，完整错误/断点/运行状态与 StepId/Occurrence 对应 |
| U-07 | 嵌套流程 | IF/ELSE、SWITCH/CASE、WHEN、循环、异常等可展开、插入子分支 | `StepNode.Slots` 正式树、不只是视觉缩进；移动跨层/循环校验保持引用与 ID |
| U-08 | 步骤新增 | 选类型后立即选中新步骤、右侧属性可编辑 | 单个 `StepEditTransaction` 草稿、添加/映射一笔事务；不要求先新建对象再找编辑位置 |
| U-09 | 右侧属性 | 选中即显示当前步骤参数，CAN 选择 DBC 并改物理信号 | 输入验证、单位/范围/有符号/大小端/复用校验；无 DBC 提示导入；不能 `Number(v)||0` 静默写零 |
| U-10 | 高频直接编辑 | 等待、IGN、夹具、循环等可双击摘要修改 | 行内即时草稿和 Inspector 同步，未保存与资源失效能定位 |
| U-11 | 步骤键鼠 | F2、F9、Ctrl+Space、Ctrl+F、Ctrl+Z/Y、Delete、右键、拖动、上下移动 | 同焦点语义；在文本输入框中 Delete 不删步骤，Undo 不回滚已经真实发送的物理动作 |
| U-12 | 标签页 | 工程概览/项目/用例/配置切换，多编辑工作对象 | 不因打开同一资源重复建立 VM，页签关闭前保护草稿，切换不丢编辑状态 |
| U-13 | 调试/观测 | 时间线、CAN、变量、问题、设备状态在底区，实时步骤定位 | 绑定真实 `ProjectRunEvent`、CAN Hub、质量/错误、物理 Unknown，不用演示随机数据 |
| U-14 | 检查与运行 | 对本次选择做预检；HTML 只逐步高亮并标 `NOT EVALUATED` | 正式 WPF 仅在资源、权限与真实设备预检通过后调用项目 Run；不移植 HTML timer 来冒充测试 |
| U-15 | 扫码生产 | HTML 有生产工作区原型 | 生产扫码自动匹配/预检/按批准工序启动；独立于临时勾选，不要求每件再手点开始 |
| U-16 | 工具入口 | 可从工程和步骤打开专业工具 | DBC/UDS/WAVE/Flash/手动台架可独立工作，共享真实资源及设备会话；其完整视觉仍由后续专项验收 |

## 4. 可执行的 HTML ↔ WPF 映射

| HTML 函数/状态 | WPF 正式承载点 | 禁止做的事 |
|---|---|---|
| `renderSidebar/renderTabs/renderCenter` | `MainWindow` + 新的 Shell/资源树/文档导航 VM | 复制演示 JSON 或重用旧高层导航布局 |
| `renderProject/projectSelectionLine/currentItems` | `TestProjectWorkbenchViewModel` 适配 + `RunSelection` 内存状态 | 将一次性选择直接持久化为 Enabled；当前 HTML 默认全选 bug 原样移植 |
| `renderCase/phaseHtml/rowsHtml/stepSummary/stepRef` | 新步骤树行投影（保留 `StepNode` 树）+ `TestEditorViewModel` | 把 TEST 格式变成 HTML `cases[]`，把 IF 纯文本直接交给未实现的旧执行器 |
| `renderInspector/updateField` | 重做 `TestStepInspector` 可编辑控件与验证适配 | 将原型字符串/无效值转换为真实硬件命令或静默写零 |
| `validateCase` | `StepTreeValidator` + `PlanCompiler` + 资源/设备/运行前检查 | 把“没有字段缺失”显示成“测试成功” |
| `runUiPreview` | **不进入正式生产代码**；用真实 `ProjectRunCoordinator` 事件呈现 | 使用 `setInterval`、虚拟结果、按时间填色模拟完整真机测试 |
| `renderProduction` | SCAN→Run→Record 同一项目业务服务与事实源 | 依靠 UI 模拟日志/历史 Mock 判定生产 PASS |
| `renderTool` | 专业工具窗口容器 + 同一工程/设备依赖注入 | “打开工具”暗中复制第二份真实硬件连接/会话 |

## 5. 用户已认可范围与未验收范围

- **自动测试 UI 已认可的方向**：U-01～U-14 对应的工程/项目/步骤/Inspector/流程编辑操作与可观察视觉，可作为 G4 WPF 实现基准。
- **仍需实现/实证的能力**：步骤解释器完整度、项目聚合真实运行、生产扫码、异常恢复、物理设备连通、UDS/波形/刷写与报告。HTML 展示能力不能当功能完成证据。
- **仍归 UI 专项继续研究**：DBC/UDS/WAVE/Flash/手动台架专业窗口的具体视觉与操作，不因本次冻结 HTML 全文而宣布所有专业 UI 已通过。手动台架按最新用户习惯左 CAN 观察/中实际外部激励和 IGN/夹具/右 CAN 发送，但不把该页默认 EPB/按键化。
- 用户日后可在相同 HTML 工作文件迭代新版本；对已接受自动测试 UI 的实质变更须有新版本对照/验收。

## 6. 严格视觉/交互验收办法

**V-UI-01 冻结来源**：从归档 HTML 而非 UI 专项移动的 HEAD 建立基准截图，记录 HTML SHA、浏览器版本、窗口尺寸、缩放和工程样本 SHA。  
**V-UI-02 对照环境**：Windows 11、100%/125%/150% DPI，默认最大化；至少 1366×768、1920×1080、2560×1440 三种任务窗口；高分辨率不应凭空把步骤信息挤小。  
**V-UI-03 对照操作**：空工程/样例工程、项目 0/1/10/30 用例、准备/测试/清理、深层 IF/SWITCH/WHEN、不同长度资源名和多个 DBC 信号；逐操作截图和视频/记录，含滚动、文本焦点、右键、拖动、撤销。  
**V-UI-04 差异记录**：为每一处非预期差异记 `UI-DIFF-ID / HTML截图及SHA / WPF截图及SHA / 操作步骤 / 偏差 / 原因 / 修订提交 / 用户验收`。未批准偏差不得自动关闭。  
**V-UI-05 数据实证**：同操作后工程资源的 Revision/SHA、StepId、映射、测试用例顺序、选择范围、断点和保存重开必须保持语义一致；不要求将 demo 数据存成真实资源。  
**V-UI-06 响应/性能**：滚动、窗口调整、30 个用例/上百步骤的真实编辑不得因 UI 全量重建反复卡死；长期运行 CAN 数据不能不受限制地向 UI Collection 添加。  
**V-UI-07 实体级别分离**：视图静态/窗口手动实测不等于设备可用；CAN、IGN、夹具、UDS、Wave、扫码分别按真实许可和证据层级独立验收。  
**V-UI-08 准出**：本节每项均有结果，用户实际 Windows 使用确认，无未经批准的 UI-DIFF，才能认定该 WPF 切片严格匹配归档 HTML。

## 7. 明确交给 G4 的结果

不是让 Codex“参考这个页面重新设计 UI”。G4 UI 文件责任和交付检查必须引用**本合同 + 固定 HTML SHA**；实施者逐项实现 U-01～U-16、V-UI-01～08，对未实现项给编译/运行/硬件阻断及版本化差异，不做私自降级。项目管理对领域/设备事实负责；用户对视觉和操作是否严格一致负责。

**G3-01 候审结论：** 技术上可用原生 WPF 严格对照这版自动测试 HTML 组织界面；当前旧 WPF Shell/TEST 界面不符合基准，**必须重建对应 View 与表现层投影**，但不能因此删除测试、工程、CAN、设备与记录的真实业务核心。
