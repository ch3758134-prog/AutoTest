# G1-07｜需求可验证性、台架复验与版本验收（M2 候审）

## 一、验证级别与证据

| 等级 | 实际证据 | 绝不能冒充 |
|---|---|---|
| 静态审查 | 原理图、参与编译源码、设计与接口检查 | 真实板卡/ECU 工作 |
| 代码构建 | 工具版本、源码 SHA/HEAD、构建日志与目标文件 | 功能正确或真实硬件成功 |
| 单元/契约 | 编解码、资源、程序编译、运行状态、持久化、UI 命令的自动测试 | 实机、生产合格 |
| 模拟/虚拟设备 | 注入异常帧、USB 断连模拟、扫码文本与生产数据模拟 | 真实扫码枪/烧录/机械动作 |
| 板卡与 ECU 实测 | 现场配置、DUT、固件版本、实际命令、CAN 日志与电气/机械记录 | 系统全面发布 |
| 系统/使用验收 | 真实研发或生产任务，异常与回归，负责人批准 | 未来全部功能完成 |

## 二、分批验证合同

| 批次 | 必要目标 | 典型能力 | 执行前置条件 | 输出证据 |
|---|---|---|---|---|
| B0 | 现场安全和版本身份 | 电源/线束/板卡/固件/夹具失电行为 | 现场负责人确认设备状态 | 实测记录和风险/阻断清单 |
| B1 | 稳定 USB 会话 | 枚举、命令/响应、断开、重连 | B0 满足适用安全前置 | 带时间戳请求/响应/异常日志 |
| B2 | 两路 CAN 物理映射 | 实际 DUT/按键路由、帧观察/错误 | B0/B1、接线确认 | 两路独立实际帧/波特率/映射证据 |
| B3 | IGN/夹具 | 默认态、命令、电压/机械变化 | 现场安全许可、气路确认 | ACK、电气测量、机械观察分别记录 |
| B4 | 按键板 | 20 路按键与 5 路电阻网络的实际响应 | 两固件版本/接线确认 | 逐路控制与电气观测、KEY16 核对 |
| B5 | 真实 DUT 交互 | 输入操作后 ECU 实际 CAN 行为 | DUT 型号/电源/线束确认 | 实际 ECU 报文、步骤观测和限制 |
| B6 | 组合/异常回归 | 断连、恢复、冲突、清理与身份一致性 | B1～B5 关键链路通过 | 可复现回归集和未解决 ISS |
| H3 | 研发自动测试闭环 | 工程→DBC→程序编辑→真实运行→记录 | 设备能力复验及 G2/G3 合同 | 真正的 ECU Run + 编辑/执行/记录证据 |
| H4 | 出厂生产闭环 | 扫码→匹配→CAN 烧录→测试→统计 | 扫码样本、烧录代码、正式流程与授权 | 不同 ECU/复测/失败/统计真实记录 |

32 项 B0～B6 候审用例详见 `data/B0_B6_32_CASES.csv`，**现为 NOT_RUN**。任何设备高风险操作的具体步骤、量测方法和安全许可应在 G3 实施合同与现场授权中逐项明确。

## 三、逐需求可验收性

46 条 G1 候审要求的来源、成熟度、验证办法与架构去向见 `data/requirements_reclassified.csv`。核查时至少具备：需求 ID → 工作包 ID → 版本化合同/源码 commit → 实际验证 ID → 原始证据 → 关闭意见。`CANDIDATE` 不因为有验证方法就自动变成已批准要求。

## 四、UI 的分级验收

1. **视觉资源层**：WPF 组件画廊验证 Typography/Colors/Metrics/Icon/Styles、浅深主题、状态、多 DPI、中文长文本、禁用/错误情形。
2. **工作台交互层**：实际可用的工程树、资源编辑、步骤、属性、撤销、快捷键、Dock/Pane/多窗口、运行状态；状态改变须对应真实应用命令与数据。
3. **实机业务层**：研发人员完成 H3 操作，生产人员完成 H4 任务（条件具备后）；原始结果应来自实际 DUT/设备，不接受仅凭可点击 HTML 原型作为验收。

## 五、结果记录格式与判断

每次验证至少记录：配置/板卡/固件/HOST 版本、DUT 型号/编号（适用时）、测试人员/环境、前置条件、实际动作、原始报文或测量、预期/实际、通过/失败/受限、关联 ISS 与 Git/文件证据。不能仅根据统计数值推定没有漏测；出厂目标集和实测 DUT 集的比对规则待 H4 明确。
