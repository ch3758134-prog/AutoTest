# AutoTest R1｜完整认知重建与破坏性重构实施基准

日期：2026-11-27  
实施分支：**R1**（唯一活跃分支，不修改 main）  
状态：**设计合同已收敛；R1 源码已有实际提交；Windows 编译及真实 ECU/工位验收尚未完成。**

> AutoTest 不是通用 IDE、资源关系配置平台，也不是独立的 TEST 编辑器加上外围脚本。
> 它是完整的 ECU 测试软件：TEST 用例是工程开发中的主要编辑对象；DBC、WAVE、FLASH、UDS、CAN、手动台架是软件内置的完整专业能力；生产按唯一工程完成一次扫码到报告的真实检测。内部可以有修订、SHA、资源身份和安全门控，但不能要求用户替系统管理它们。

## 1. 使用者能够认识并操作的对象

| 用户概念 | 用户的直接行为 | 持久内容 | 软件责任 |
| --- | --- | --- | --- |
| ECU 测试工程 | 新建、打开、直接重命名、自动保存、更新到生产 | 唯一 TEST 程序和资源定义 | 文件管理、引用有效性、资源复制、生产稳定快照 |
| TEST | 增删用例、排序、编写/调试步骤、查看运行证据 | 有序 TEST 用例及步骤 | 唯一 TEST 解释/执行器；跨用例保持 CAN、KEY_SIM、IGN 与变量 |
| DBC | 独立新建/打开/编辑；工程选一份生效 DBC | DBC 报文、信号、注释及编码 | 维护合法性及 TEST 引用；禁止不安全源文件重写 |
| 波形 | 多路观察、采集标准、建立判据、比较实测 | 可以有多份参考与规则 | 时间质量、DBC 信号依赖、算法判定及证据 |
| FLASH | 选 HEX、编辑 APP/Boot CAN ID/地址/波特率、独立烧录调试 | 唯一生效 HEX + 一套原生参数 | 固定安全文件、镜像检查、真正的 UDS 烧录流程 |
| 公共流程 | 可选创建、编辑、在多个用例中调用 | 工程内可复用 TEST 定义 | 引用完整性；不创建第二套测试 DSL |
| UDS/CAN/手动台架 | 独立连接、诊断、观察和控制真实设备 | 工具设置和可保存诊断序列 | 物理会话所有权；不会自动成为正式生产 PASS |
| 生产检测 | 扫完整编号、启动、观察 FLASH/TEST/结果 | 单台 DUT 检测记录 | 标记→唯一稳定工程、夹具、START/STOP、每次必经 FLASH、TEST、RECORD、释放 |

**定义与呈现原则：**
- 软件“工具”不是工程需要绑定的文档。
- 工程的一份生效 DBC 是具体 DBC 数据，不是 DBC 编辑器/文件选择器。
- FLASH 不需要另绑定“工艺文档”；烧录参数存在工程固定位置，工程选择唯一 HEX。
- 安全文件固定为用户确认的原始 4,096 字节 `SafetyFile.dll`，SHA256：`EE2C4A2791B88DCE19DB29F308752C8F79BC0654463D43E6880F65C6FDEA3833`。由 AutoTest 自己附带、验证与内部使用；用户永远不选择或导入它。
- ECU CAN 唯一权威参数来自工程 FLASH 的 `EcuCanKbps`；实际值必须由主控 0x42/0x43 真正应用并核对，KEY CAN 继续固定 500k。
- 公共流程可以为空；波形参考可以有多份；扫码与夹具绝不是 ECU 工程内容。
- 日常编辑产生修订是正常行为；技术风险是“实际判定是否还有效”，不是“修订号变化”。默认隐藏内部 Hash/修订；需要时到诊断与追溯查询。
- 工程保存副本和内部路径由程序处理，用户只需要看到名称、内容与明确的编辑动作。
- 不要求工程创建时完成全部资源；TEST 调试不靠扫码/生产烧录前置；正式生产检查全部实际必需资源。

## 2. 工作区和 UI

### 生产检测
显示完整原始扫码编号，匹配到唯一工程后，纵向展示真实阶段：
扫码 → 固定夹具压紧 → 等待实体 START → 原生 FLASH → 全部 TEST 用例连续执行 → 记录结果 → 按安全状态释放夹具。
强调 TEST 用例结果与失败原因；FLASH 可展开阶段日志和 CAN 证据。不可在生产界面额外选 HEX、DBC、用例或测试计划。

### 测试工程
打开上次编辑的 TEST 用例；左侧是当前工程唯一 TEST 的正式用例顺序，中间是完整步骤表，右侧可伸缩的实时 CAN 监视。单击切换用例，双击步骤编辑，行旁添加，运行此步骤/用例/工程，断点、跳过、查找、撤销。减少重复文档标签和固定“参数面板”；工程名称和 DBC 名称必须直接可操作。

### 专业工具
DBC、波形、FLASH、UDS、CAN 和手动台架保持完整的真实编辑/分析/调试闭环。DBC 工具允许无工程时独立新建/打开，工程未绑定时可以新建空白 DBC 或导入已有 DBC。独立 FLASH 与工程 FLASH 共用原生参数处理和真实烧录内核，任何时候都不要求用户选择 XML 配方或安全 DLL。

### 检测记录
一次扫码建立一个 RunId，持续记录全部实际阶段事实，区分 ECU PASS/FAIL/不确定与工位释放状态。完整 CAN 底本并提取 StepOccurrence、关键 DBC 值、波形与烧录证据；独立工具和局部调试不能计入正式生产合格。

## 3. 已在 R1 提交的源代码变更（本轮）

- 固定安全文件：`FixedSafetyFile.cs` + 内嵌 `Assets/SafetyFile.dll.gz`，每次加载检查用户文件的精确 SHA；NativeFlashJobBuilder 直接使用系统固定文件，旧 `ImportSecurityAsync` 不再允许选择。
- FLASH 参数窗口：仅保留 HEX 选择和真实参数、固定安全文件；原文兼容字段折叠；保存不再显示修订和指纹，显示原固件文件名。
- FLASH 专业工具：从工程进入或独立使用均走原生参数路径；新建/更新后可用真实固件开始预检，不再由旧 XML/三文件模式决定按钮可用性；旧 UI 已退出可见工作区，后续仍需删除不可达遗留源码。
- ECU CAN：工程启动/打开和 FLASH 参数编辑后，空闲主控从同一工程值同步并读回；手动台架删除第二套波特率选择。
- DBC：资源与工程直接重命名；报文双击/F2 进入技术字段编辑；信号名可在表中直接修改；独立工具可以新建真实空白 DBC；工程内可直接新建或导入，新增解析器测试保证空白 DBC 可逐步编辑。
- 工程与生产界面：工程名不显示开发构建 SHA；收敛成“更新生产工程”并保留内部稳定工程包校验；扫码标记绑定页面隐藏用户无须管理的 SHA/修订列；TEST 状态栏不再长驻生产扫码控件。
- 原有 R1 的唯一有序 TEST 工作区、动态左侧用例列表、公共流程导航、右侧 CAN、双击步骤等已由此前重构建立，本轮沿用和进一步精简。

## 4. 未完成/不得伪称已完成

**工程实测的阻断：**
- 当前环境不能执行 Windows WPF 编译；只有源代码 XAML 结构、C# 括号、事件名称与 GitHub 提交检查。
- 生产 `ProductionPhysicalStation` 真实 Desktop 适配、实体 START/STOP、夹具到位条件及释放恢复闭环仍未完成真实验收。GPIO ACK 不等于机械状态。
- TEST 跨用例周期 CAN、KEY_SIM 保持与 WAVE 真实时序准确性需要现场用 ECU 验证。
- 独立 FlashLab 的旧 XML/三文件处理函数虽然不再出现在可见工作流，仍有不可达遗留代码待删除；这不等于已完成所有旧代码的全面清理。
- 已保存的旧 TEST/DBC 依赖可能仍要求技术变更后审查；需要后续将“语义未变的普通修改自动采用”和“影响实际信号解释的改动需核对”严格区分，禁止简单按 SHA 触发用户重新绑定。
- DBC 扩展语法的安全回写范围仍受既有 parser 限制，不允许因为 UI 可编辑便静默丢失原生扩展内容。
- 工位正式 FLASH 仍只确认 HydEPB 参考烧录方法，其他 ECU 不得套用未验证算法/地址或使用假模拟。

## 5. 必须执行的验收路径（Windows + 真实工位）

1. 从 `R1` 拉取最新源码，Release 编译与启动，查看 WPF 初始化、资源载入和 UI 错误日志。**本地 Codex 只做拉取编译启动，代码问题在 R1 修复。**
2. 创建与重命名工程；新建空白 DBC、增加报文和信号、直接编辑名称、自动保存后关闭重开；工程可绑定一份当前 DBC。
3. 导入 HEX，修改 ECU CAN 250/500 kbit/s，关闭/重开，真实 USB 读回正确波特率；没有安全 DLL 选择入口，实际使用同一个已验证文件。
4. 独立 FLASH 工具使用工程原生参数，Start 只在物理连接且原生配置到位时可用；现场观察真实进度、APP/Boot/UDS 日志和失败状态。
5. TEST 行编辑、查找、步骤插入、断点、运行步骤和用例、跨用例连续硬件状态、CAN 监视/波形证据。
6. 生产完整原始扫码、固定标记匹配、真实压紧/START/FLASH/TEST/RECORD/释放全部闭环；硬件不满足时应清楚阻断，绝不能显示假 PASS。
7. 反复启动退出、切换工程、改 DBC/HEX、打开关闭浮窗，不丢数据、不闪退、不出现多余保存提示。

本记录是**重构设计与实施事实**，不等于 Windows 编译通过或整机交付验收。
