# CR-KEYSIM-001｜现场按键机制发现 → 分层影响分析（演示候选）

> 状态：`DRAFT / UNDER_INVESTIGATION`；**尚未批准对正式 SAEF 需求或设计的任何修改**。本文件不是实际测量报告，不能用于放行按键/IGN/夹具操作。

## 1. 发现（L6 → L1/L2）

- **原始反馈**：2026-11-09 用户现场说明 KEY_SIM 的 20 Key 是电阻网络组合开关，不是 20 路独立数字输出；由组合闭合得到 5 路模拟电压输出；开关可同时闭合并保持；不同 ECU 型号的电压通道/识别区间不同。
- **事实等级**：`FIELD_REPORT`（负责人陈述、尚需现场电气量测验证具体状态/电压/冲突组合/固件行为）。
- **既有需求**：`AT-SYS-011` 规定模拟输入必须在经验证的能力范围内控制，不能把五路电阻网络当任意 DAC；并非否认组合保持。
- **现有总体架构参照**：`G2-01` 记录按键板、主控 CAN 和 DUT 的边界；`G1-05 IF-06` 记录外部模拟输入；`G1-07 B4` 要求现场电气证据。
- **原始源码/正式现役固件**：须在明确固件版本、实际烧录镜像及运行环境后复核；目前本变更单未包含可靠的实际电气测试结果。

## 2. 不是直接让 AI 改代码

如果设备工作台把 20 Key 表示为“20 路数字输出”或认为任意设置五路电压，可能产生错误的产品行为与验收标准。**先核对需求和物理事实，确认技术方案，再批准代码修改。**

## 3. 分层影响候选（尚未校准的边）

| 层级 | 待核对象 | 所需操作 | 验证/关闭条件 |
|---|---|---|---|
| L0 | 不同 DUT 按键输入场景 | 补充真实型号输入/电压条件 | 有型号码/电压识别场景 |
| L1 | `AT-SYS-011`、相关 Profile/能力要求 | 判断现有文字足够，还是需新增“组合、保持、按型号配置”的可验证要求 | 产品负责人批准修订范围 |
| L2 | `G2-01`、`IF-03`、`IF-06` | 复核 PC/主控 CAN/KEY_SIM/DUT 的电气和控制职责，防止逻辑模型错误 | 现场连接与通信映射证据 |
| L3 | Station/Keypad/Controller Profile | 复核开关组合状态、锁定与释放、资源冲突及异常恢复 | 边界和数据所有者明确 |
| L4 | Keypad 控制合同与配置/状态机 | 定义组合掩码、可保持/撤销、允许组合、目标通道/区间、超时/UNKNOWN | 明确实际固件支持的合法操作 |

## 4. 需要做的决策（不擅自替负责人决定）

1. 表达模型：仅在 UI 提供 Key 组合/保持，还是同时定义按 DUT Profile 的物理电压区间与预期映射？
2. 参数边界：是否允许使用者任意组合开关，或限制为该型号已验证组合？无法确认前不能宣称任意可达电压。
3. 清理/断连：设备确认收到命令、按键网络真实电压变化和 ECU 识别成功，分别采用哪些证据？
4. 对已有架构影响：保留 KEY_SIM 的 CAN 控制责任，还是经过实验确实需要新的协议/固件改动？
5. 实验优先级：先 B4 实测固件/组合掩码/实际输出，再批准完整电压 Profile 的设计。

## 5. 候选设计与非目标

- **候选**：采用与 DUT 型号相关联的 `KeySimulationProfile`，列出按键/组合状态与电压输出的已测映射。控制指令表达实际继电/开关组合而非任意 DAC 数值；上层可要求某个受认证的模拟输入动作。
- **不承诺**：可生成任意五路连续电压、20 路数字输出、ECU 已正确识别每种组合、失联后所有键已经释放、只凭 USB ACK 就判定现场动作成功。
- **需要查证**：实际固件帧 ID/掩码、合法组合同步行为、上电默认状态、重连、释放、各输出端电压、不同型号 ECU 识别区间。

## 6. 变更影响触发及准入

- 若 `AT-SYS-011` 更新版本，所有直接依赖这一修订的已批准设计进入 `POTENTIALLY_IMPACTED`；由审查确认每条是 `NO_CHANGE / REVISE / RETIRE / INVESTIGATE`，不能自动全判失败。
