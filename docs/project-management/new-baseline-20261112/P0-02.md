# AutoTest｜P0-02 项目目标与近期交付范围

**版本：** v0.1（新基线）
**状态：** 项目负责人已明确批准本文内容；落档与范围见 APPROVAL_RECORD.md。
**上游依据：** P0-01 v0.2 产品定义

## 一、项目总体目标

建立一套能够实际用于不同 ECU 测试工作的工程系统，将测试硬件、专业工具、工程资源与自动化测试程序有效集成。

系统不仅要能够独立使用各类测试工具，还应能够根据测试程序的需要协调这些能力，实现复杂测试流程的自动化。

## 二、近期核心目标

当前研发以已有真实硬件和 Windows 上位机软件为基础，优先建立能够实际运行的 ECU 自动测试闭环。

这一闭环应当支持：

1. 创建、管理和配置 ECU 测试工程。
2. 使用图形化测试程序编辑器编写、保存、修改和调试测试程序。
3. 调用真实硬件及适用的专业工具施加测试条件和外部激励。
4. 获取 ECU 的实际响应数据，进行数据处理、逻辑控制和结果判定。
5. 正确处理测试中的超时、通信异常、失败及清理操作。
6. 保存完整的运行过程、实际数据、测试结论及相关证据。

该目标必须通过真实设备和真实 ECU 验证，不能用 Mock 运行或界面演示代替。

## 三、专业工具集成目标

已有测试硬件、专业工具及相关开发成果属于项目需要调查、继承和持续完善的工程资产。

系统需要支持专业工具的独立使用，并逐步建立这些工具与测试工程、测试程序及统一设备资源之间的协作关系。

新增工具与硬件能力应能够通过受控扩展融入系统，而不需要针对每一种 ECU 重新开发整套上位机。

## 四、整体产品交付范围

项目整体交付应覆盖以下业务能力：

- ECU 测试工程与资源配置管理。
- 外部条件模拟、通信交互及响应采集。
- 可编辑、可执行、可调试的自动化测试程序。
- 独立使用及集成调用的专业工具。
- 测试数据分析、结果判定和证据记录。
- 面向生产检测的产品识别、配置匹配、自动测试及追溯工作流程。

具体工具清单、硬件能力边界、功能优先级和验收指标由后续需求研究确定。

## 五、实施原则与成功判断

研发应优先复用经过核实的真实工程成果，避免无必要的重复开发。

近期首先验证实际 ECU 测试闭环，随后依据工程依赖逐步完善各专业能力和整体工作流程。这是验证与集成的优先顺序，不代表将其他已确定的产品能力排除在交付范围之外。

项目是否取得进展，以可复核的工程成果和相应级别的真实验证证据为依据，不以代码数量、模拟测试通过或界面完成情况代替实际能力。
