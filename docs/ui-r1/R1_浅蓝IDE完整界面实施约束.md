# AutoTest R1｜浅蓝 IDE 全界面重构与验收基准

> 用户已选择 2026-11-11 生成的 AutoTest 浅蓝色 IDE 设计组图作为产品方向。本约束只管**视觉和交互**，不是系统能力、 ECU 实际物理行为或受控工程审批的新权威来源。

## 不可变的产品使用逻辑

- 主窗口：统一工程、测试程序编辑、自动测试运行。顶端直接“连接设备”，扫描匹配主控板、单设备自动选择，多设备选择窗口、失败就地显示；不跳进设备调试页。连接不触发 ECU 供电、 IGN、 CAN 发送、夹具或 KEY_SIM。
- **独立最大化窗口**：手动台架、DBC、控制器与按键配置、UDS、CAN 烧录、波形分析、扫码与生产、运行记录与报告、操作审计、设备高级诊断。不可将这些工具再次塞入中心 TEST 文档区，也不得各自创建第二条硬件会话。
- 主框架固定：顶部工程与主任务栏、左侧窄图标轨与工程资源树、中心实际文档；自动测试编辑有步骤层级、步骤属性、结果；运行有用例范围、实时步骤事实、详情、证据。
- **统一配色**：背景 #F5F8FD，卡片 #FFFFFF，浅蓝高亮 #E8F3FF，边界 #D7E3F2，正文 #202D3F，文字辅助 #607185。操作强调蓝色，不出现绿色的引导块或连接指示；涉及真正危险动作的红色/警告语义仍须保留。
- 标签、菜单、空状态、错误提示使用操作人员可理解的中文；CAN、DBC、UDS、ISO-TP、HEX、KEY_SIM、IGN 等必要行业词汇允许保留。

## 每屏对象与实际代码

| 设计稿界面 | WPF 实际目标 | 关键工作区 | 已有能力底线 |
| --- | --- | --- | --- |
| 测试程序编辑 | `LabTestWorkspaceView` | 测试步骤层级、结构阶段、属性、结果 | 继续使用唯一 TEST Program/JSON/工程版本 |
| 自动测试运行 | `R1ProjectRunView` | 左侧运行范围、中间真实步骤事实、右侧详情、底部事实 | 未有 ECU 实际响应不得产生 PASS |
| 手动台架 | `BenchWorkbenchView`（独立） | CAN1 发送、KEY_SIM 动作、IGN/夹具、CAN1 接收、底部真实操作日志 | 20 个组合开关不是 20 路电压； CAN0 通按键板、 CAN1 通 DUT |
| 控制器与按键配置 | `ControllerConfigToolView`（独立） | 控制器、状态、K01～K20 实际可编辑掩码、五路电压窗口与人工测量 | 配置不会自动触发真实物理输出 |
| DBC 编辑器 | `DbcToolView`（独立） | 报文、信号、属性、离线解码预览 | DBC 编辑与手动发送是不同任务，工程 Revision 仍需发布 |
| UDS 诊断 | `UdsToolView`（独立） | 服务目录、请求编辑、真实响应解释、诊断会话及追踪 | 只有实际支持的服务才可操作，响应与 ACK 不混淆 |
| CAN 烧录 | `FlashToolView`（独立） | 固件/配置、预检、阶段、真实进度、授权、诊断证据 | 不把演示镜像/SeedKey 算法当成实际 ECU 允许擦写条件 |
| 波形分析 | `WaveWorkbenchView`（独立） | 采集、信号选择、曲线、双游标、参考、判定 | 采样率依真实设备数据来源，禁止捏造图上的 100 kHz 能力 |
| 扫码与生产 | `LabProductionToolView`（独立） | 条码、规则、正式 TEST、运行状态 | 扫码重复不得被统计为新增合格出厂 |
| 记录与报告 | `RecordsView`（独立） | 搜索、真实运行事实、报告、统计 | 离线数据不得与真实生产记录混计 |
| 操作审计 | `OperationsView`（独立） | 操作事件、来源、追踪导出 | 保留机器诊断细节但用户界面中文 |
| 设备高级诊断 | `DeviceLabEmbeddedView`（独立） | USB 详情、CAN 通道、错误码、Trace | 非普通连接流程必要页面 |

## 本分支实际改造与验收界限

- 全局旧配色与主要任务语言更换；独立工具仍用现有真实后端。
- 删除 Shell 中“双标签资源树/运行计划步骤”混叠，运行范围已经移入真正的自动测试运行页。
- TEST 步骤树新增名称/类型列，它是原有持久化节点的投影，不建立第二套运行模型。
- DBC 改成三栏编辑加底部解码预览，所有控件绑定原有命令。
- 控制器状态加入真实 K01～K20 位掩码编辑；保存到原配置会话，开关勾选不会发实际按键板命令。
- 手动台架底部从原有操作事件生成日志视图；主控 ACK 与 ECU 响应继续分开。
- 不会为了贴合设计稿中的“发动机 ECU / 12.02V / 通过 5/5”等**示例数据**而在正式 WPF 内硬编码虚假的硬件能力或运行结果。

### 本地必须执行的验证

对精确 PR HEAD 完成 Windows Release 编译和 Desktop/Devices 测试；逐页打开每个独立窗口，检查 100%/125%/150% DPI、最小尺寸、鼠标左右键、展开折叠、滚动、关闭窗口及配置保存/重开。按安全流程复测真实 USB 连接、主控失联、多设备、CAN1、按键组合、IGN、夹具、UDS、FLASH。**静态 XAML 语法检查不等于 WPF 编译成功或真实 ECU 验收。**

任何设计稿中展示、但现有后端没有实现的功能，必须真实开发并测试或明确不可用，不能伪造按钮、波形、测量结果、通过判定或展示纯演示数据。
