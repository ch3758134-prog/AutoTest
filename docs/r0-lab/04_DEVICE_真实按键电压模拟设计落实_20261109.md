## 已确认，不得再问用户

当前真实 ECU 的按键通过检测**对应输入通道电压范围**识别；现役 KEY_SIM 的 **20 Key 是电阻网络组合开关，而非真实按键**。某个目标电压可以由多个 Key 同时闭合持续保持。模拟板五路模拟电压输出适配不同 ECU/版本的输入通道、阈值和按键定义。**真实台架应操作真实控制器/按键/状态**；20 Key 只在高级映射配置和 DEVICE 原始诊断区出现。自动测试和手动使用同一可版本化映射。

## DEVICE 本轮范围（先核对现役源再在自身范围实现）

1. 阅读现役主控 `EPB_Test_Keil.zip / Project`、按键板 `KEY_SIM.zip / WS/EPB_EOL` 及 Git 当前 `src/AutoTest.Devices/**`、设备调试工具和 tests。**以实际编译进固件的源为准**，不要误把存在但未编译的候选协议当成现役协议。核对 USB 0x40 → 主控 CAN0 的 KeySim 路径、按键板 `0x730`/DLC8/`0x01` 完整 20-bit mask/`0x80` 释放、CAN1 DUT 角色。
2. 设备层提供受控的 **SetCompleteKeyMask / Release / ReadTrace** 或复用既有设备能力；不要自行定义正式跨模块 Contracts。每次设置完整目标 Mask，支持**多 Key 组合保持**，WAIT 不能隐式释放，释放必须是新物理操作；禁止无证据地把多个业务按键 Mask 相加或 bitwise OR。
3. 独立设备调试 UI 可直接输入 20-bit Mask 验证电压合成，但须标明 “底层 KeySim 调试”，显示五路**目标/人工实测/未测**，并记录实测仪表、供电、接线、负载和 ECU/Profile；不得把人工录入伪装为板载 ADC。首次受控电压测试按已有 B3 准入、隔离 DUT，不能仅因本文件而永久开放任意物理 CAN Tx。
4. 把请求状态、USB 请求/响应、CAN0 实际发送、ACK、SessionGeneration、错误码、时间线、原始帧、超时、取消/断线/重连、导出分开表示。**ACK≠按键板已动作≠五路电压正确≠DUT 已识别**。如果没有板端动作 ACK/电压传感器，只显示 `TransportAccepted` 和 `PhysicalObserved=UNKNOWN`。
5. 对失联/超时/取消/重连，不准把先前的 KeyMask 或“五路电压”继续显示为已确认，也不能宣称已经自动释放；必须进入 UNKNOWN/UNCERTAIN 并要求可信恢复证据。
6. 向 PROJECT / BENCH / TEST / INTEGRATION 交付**现有可用的设备调用合同及精确增量需求**：按 Controller/State/Revision 解析 Mask 属于 PROJECT；真实台架动态业务按键 UI 属于 BENCH/UI；共享 Session/公共接口属于 INTEGRATION；测试编排属于 TEST。DEVICE 不以自行修改这些专业私有文件、公共 Contracts 或固件来“完成整个功能”。
7. 增加自动验证：20-bit 多位组合、完整状态覆盖、保持/显式释放、两 ECU Profile（资源层提供测试替身）、未授权物理 Tx 拒绝、SessionGeneration/超时/重连、ACK≠Measured、导出丢失告警、并发资源冲突。Release Build/Test 和真实 B3 五路电压实测必须分开报告。
