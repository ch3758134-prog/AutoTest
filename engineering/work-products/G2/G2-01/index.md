# G2-01｜系统边界与现役实物（架构候审 v0.7）

## 一句话设计决定

**AutoTest 是完整测试台架系统；ECU 是外部 DUT，现役双板 PCB 不重设计，主控/按键固件与新 HOST 属于可持续迭代的软件资产。**

## 物理与软件对象

| 物理对象 | 已知链路 | 软件责任 | 未核事实/禁止误判 |
|---|---|---|---|
| 工位 PC | Windows、主控 USB、Honeywell 扫码枪 USB | 唯一 HOST，设备会话、工程与测试、工具与生产 | 扫码设备 Windows 模式待实测 |
| 主控板 | USB↔PC；两路物理 CAN；IGN 驱动；电磁阀 | 现役主控固件协议与受控设备能力 | 不把历史电源角色当 MCU 供电开关 |
| 按键板 | 经主控板 CAN 控制；20 键/五路电阻输出 | 按键固件解析码并产生实际输出 | KEY16 和 20 路有效性需要 B4 核实 |
| DUT（EPB ECU） | 经线束接 CAN、IGN、按键模拟及供电 | 仅是受测对象；HOST 不拥有 DUT 固件设计 | 夹具 ACK/CAN 报文不等于机械锁定 |
| 外部 12V/24V | 台架电源供相应型号 ECU 和设备使用 | 工位前置条件检查 | 不假设 HOST/主控可切换供电 |
| 电磁阀/夹具 | 主控输出 → 气路/机械 | 受控命令和操作留痕 | 当前没有夹具到位传感器 |
| Honeywell 扫码枪 | USB 直接插 PC | 原始扫码输入，不走 MCU | HID/串口等设备模式待实测 |

## 真实与模拟的区分

- `Station` 是 HOST 管理设备能力的逻辑边界，可接虚拟站点或实物站点；两者共用上层资源/测试接口。
- B0～B6 复验现役板卡，不在 G2 宣称新 HOST 已控制硬件。
- 前期源码中存在 `dut.power` / `keypad.power` 命名，但现役台架不因名称就具有 MCU 软件供电控制。
- 夹具和 DUT 端电气状态需独立观察，设备 ACK 的含义限定为固件通信事实。

## G3 接收

`G3-A1/A2` 接收两个 CAN 逻辑角色、设备身份/固件版本约束、USB/IGN/夹具/按键可操作能力与现场安全前置；`G3-E1` 接收 PC USB 扫码事实。实际引脚映射和命令字节须依据已批准 G0 原理图与参与编译固件核对，不能由 G3 重创。

## 验证与禁止项

B0 记录供电、线束、版本身份与危险操作许可；B1 验 USB；B2 验两路 CAN；B3 验 IGN/夹具；B4 验按键；B5/B6 联动回归。不得在 B0 前测试危险输出。来源：M2 `G0-01..G0-09`、用户后补 Honeywell USB 实物信息。
