# G1-08｜需求一致性、开放问题与 Gate 预审（M2 候审）

## 一、来源链与审批对象

本次从已批准的 P0 历史、G0 技术事实候审/此前内容批准材料、负责人最近说明以及旧 `src` 研究中整理 46 条候审要求。**源码只证明旧设计存在，不替代用户需求，也不证明现场测试通过**。未来 G2 的 12 ICD、UI 模块、扫码生产 Session 都应对 G1 要求和待验证假设有明确映射，不能仅从模块清单反推功能。

M2 一次集中评审的内容包括 P0 八项修订、G0 九项事实档案、G1 八项需求及其两个索引；**不包括自动批准 Gate、认可 32 次现场测试结果、允许实际固件/ECU 烧录或允许新 HOST 编码**。

## 三、检查到的主要设计边界

- **供电**：有 12V/24V 工位供电，但不要求主控软件控制电源。必须区分 ECU 额定电压核验与实际自动开关能力。
- **夹具**：电磁阀控制的实物与外部反馈分开；当前没有夹紧到位硬件输入。只收到 CAN 不能证明夹具已夹紧。
- **扫码**：DUT 实物码由用户团队设计，扫码枪外部输入到 HOST。匹配字段可编辑，真实码样本、唯一性、冲突与身份锁定行为待 H4 验证。
- **旧 `src`**：必须利用资源绑定、测试编排与运行、DBC、记录、视觉和交互研究；但旧供电假设、Shell 集中职责和受限 UDS 不能原样宣称新 HOST 规范或完成功能。
- **自动测试/UI**：既要统一程序编辑、运行和判定语义，也要在 G2 建立视觉系统、组件库、布局、信息与交互合同，在 G3 细化到可运行 WPF 组件和文件职责。
- **持续迭代**：G1/G2 设计基线可受控修订；G3 对工作包滚动详设，G4 提供真实反馈，质量状态、进度与 Gate 分开记录。

## 四、G1 Gate 候审准出建议

G1 正式准出应检查需求来源、冲突、成熟度、验证方法与近期 H3/H4 的范围足以驱动 G2。**开放问题允许保留，但必须有关闭证据、最晚节点以及不可越过的风险边界**；危险输出、烧录身份与初始电气状态等不得“带未知直接实施”。

真实本地快照：P0 八项 `ACCEPTED` 但 P0 Gate `NOT_REVIEWED`；G0/G1 均 `NOT_STARTED`。因此 G1 当前只是一份内容候审，尚不能据此宣布 Gate PASS。若负责人认可内容，应按 M1 受控修订路径分别登记 P0，再经 G0/G1 原生 `apply`、审查与独立 Gate 决定。没有本机 M1 工具安装回执，本包也不允许自动开启旧版修订。
