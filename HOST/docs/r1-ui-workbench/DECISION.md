# AutoTest R1 — ECU 测试工作台 UI 重构决策与验收边界

状态：R1 工程实施决策（不是生产实物验收报告）

## 一、产品定义

AutoTest 是单 PC、单工位、真实设备驱动的 ECU 集成测试工作台；不是通用代码 IDE，也不是只有 PASS/FAIL 的产线 HMI。

软件有三个可直接理解的任务：
- **生产检测**：扫码 → 显示完整原文并唯一匹配工程 → 工位夹具及实体 START → 工程 FLASH → 工程完整 TEST → 证据与结果 → 下一台 ECU。
- **测试工程**：定义检测流程、TEST 用例、公共流程、FLASH、DBC、WAVE；直接编辑并在同一真实工位调试；将检查后的工程用于生产。
- **检测记录**：按完整扫码编号查询历次检测、步骤结果和物理证据。

专业工具通过工具菜单和相关编辑上下文进入：手动台架、UDS、独立 FLASH、DBC、WAVE。工位设置与固定扫码标记路由属于设置，不属于 TEST。

## 二、对象边界

1. 一台 ECU 只扫一个完整码；固定标记精确匹配唯一的已安装生产工程版本；完整扫码原文是 ECU 身份。模糊关键词或另设型号/序列号作为人工生产输入的做法已废弃。
2. ECU 工程内部拥有 FLASH、TEST 有序调用、DBC、WAVE；扫码规则不复制 TEST 或烧录设置。
3. 真实工位拥有主控 USB、CAN、KEY_SIM、IGN、夹具和实体 START；工程测试定义不得取代工位物理准入验证。
4. TEST 用例定义与“检测流程中按顺序调用的实例”分离。开发期勾选只决定临时运行范围，不改变正式生产。
5. 工程开发可自动保存；生产必须使用校验后的不可变资源快照。更改工程不允许悄悄改变正在执行或已冻结的生产版本。
6. 每次执行均形成独立运行身份，复检不能省略工程定义的 FLASH；重复完整扫码编号不得当作新增 ECU。PASS 需要真实、可归档的证据。

## 三、导航与布局

- 顶层只有三个任务按钮：**生产检测 / 测试工程 / 检测记录**。
- 文件、编辑、调试、工具菜单仅在适当上下文出现；不再叠加“开发模式/工程/视图/运行”等多套导航语义。
- 测试工程侧边按检测流程、用例库、公共流程、工程资源、工程检查组织。用例库为可收起的定义入口。
- TEST 以表格为主要工作对象；同一结构显示运行结果，保留断点、单步、运行此步骤、运行用例、停止等真实执行器操作。CAN 发送完整数据显示，DBC 辅助不替代原始字节。
- 参数面板默认不占据整列；复杂步骤使用明确“完成 / 取消”的事务编辑窗口，点击窗口外不应隐式提交或关闭。
- 生产顶部显示**完整扫码原文**、匹配工程及明确的物理状态。中间纵向呈现 FLASH 和完整测试用例，诊断证据按需显示。没有实体执行适配时不得呈现虚假进度或通过。

## 四、本轮代码触达

- MainWindow.xaml：一级任务导航，调试/工具/设置语义分组；删除重复入口；工程“用于生产”入口。
- MainWindow.xaml.cs：参数面板默认收起，可显式打开。
- MainWindowViewModel.cs / ProjectExplorerView.xaml：检测流程与用例定义入口区分。
- AutomaticTestHomeView.xaml：完整扫码身份与工程匹配/设备状态分开显示。
- ProductionProjectCatalog.cs：工程本机采用内部临时打包、严格校验并安装不可变版本；不要求用户自己导入导出。
- MainWindowViewModel.Production.cs：使用当前工程时安装到生产库，进而提示固定标记关联；保留所有原有硬件执行安全门控。
- ProductionProjectLibraryWindow.xaml：固定标记路由优先；外部工程包入口降为跨电脑操作。
- TestEditorView.xaml(.cs) / TestStepInspector.xaml：步骤属性编辑必须明确完成或取消；误点背景不得结束事务。

## 五、禁止回归

- 禁止再次以通用 IDE 术语组织产品或额外增加独立 TEST 执行计划。
- 禁止把扫描枪接收成功等同于工程匹配成功，更禁止将扫码等同于实体 START。
- 禁止将 USB 命令 ACK 当作夹具机械到位、ECU 接收 CAN 或 FLASH 成功的证明。
- 禁止把只读预览、Mock、源码静态检查或编译通过视为实际生产验证。
- 禁止为了重构外观篡改已确定的 KEY_SIM 保持、工位 CAN 通道和 ECU 波特率语义。
- 禁止替代工位真实安全门控或在生产运行时让诊断工具抢占设备所有权。

## 六、验收路径

1. Windows 发布：主窗口启动，进入生产与测试工程，打开记录、工具、设置；所有 XAML 和事件正确加载。
2. 工程编辑：新建/打开工程；检测流程、用例库、公共流程；添加 CAN/KEY_SIM/WAIT 步骤；参数窗明确完成/取消；自动保存后重启恢复。
3. 本机生产安装：工程配置完成且资源检查通过后“用于生产”；无需人工 ZIP 导出/导入；生产库出现不可变版本；关联固定扫码标记；检查唯一匹配结果与完整扫码原文。
4. 真实工位：COM 扫码，主控 USB、CAN 码率回读、夹具压紧及物理到位、实体 START、工程 FLASH、完整 TEST、异常停止及释放。
5. 检测记录：同一完整编号多次检测形成独立 Run 和证据；PASS/FAIL/UNKNOWN 不混淆；断电/掉线/失败禁止虚假通过。

**当前状态**：本轮完成源代码层的 UI 与本机工程库重构；没有在 Windows 运行发布程序，没有主控/扫码枪/夹具/ECU 联调验收。生产完整链路必须仍按真实硬件准入通过后才能宣布可用。
